# 회부 — 자염(煮鹽)의 다음 층 (2026-09-01 · T3)

재민 확정 ①에서 시작한 배치다. 부패·보존 배치가 절임을 다 만들어 놓고
*"소금이 이 세계에 없다"* 에 막혀 회부한 그 조달을 닫았다.

아래는 **구현하지 않고 넘긴 것**과 **재민 판단이 필요한 것**이다.

---

## ★★A. 지시서에서 벗어난 자리 하나 — 바닷물이 아니라 **짠물(함수)** 이다 【보고】

지시서: *"염도 3% → 바닷물 10kg → 소금 0.3kg"*.
그대로 두면 산수가 이렇게 된다:

| | |
|---|---|
| 소금 1단위 무게 | **1.00kg**(econ 정본 `specialty.RESOURCES.salt.weight` — 우리가 정한 값이 아니다) |
| 3% 로 소금 1을 얻으려면 | 바닷물 **34되 = 34kg** |
| 적재 상한 | **25kg**(과적 바닥 ×0.35) |
| 병 34개를 만들려면 | 박 34개 = 밭 6칸 |

⇒ 해안에서 가마까지 **34kg 을 비틀거리며** 나르고, 그걸 위해 **34번 같은 입력**을 반복한다.
그건 §2 가 금지한 **"진행바"** 다(판단도 위험도 손맛도 없다).

★그리고 **실제 자염이 그렇게 하지 않았다.** 조선 자염은 바닷물을 바로 끓이지 않는다 —
갯벌 흙에 바닷물을 부어 거른 **함수(鹹水, 15~20%)** 를 끓였다. 바닷물 직통은 연료가 감당이 안 돼
역사적으로도 안 한 일이다. **"자염 = 함수를 끓이는 것"** 이 원래 뜻이다.

⇒ 갯벌에서 뜨는 것을 **짠물(함수 · 15%)** 로 잡았다. 채수 한 번이 곧 갯벌 여과다.
지시서에서 벗어난 유일한 자리이고, **고증 쪽으로** 벗어났다.

**되돌리려면 손잡이 하나다**: `SALT_BRINE_PCT=0.03`. 그러면 한 솥이 34되가 된다.
⇒ **재민 판단.** 15% 가 기본값이고, "갯벌 농축"을 별도 단계로 떼고 싶으면 D-3 을 보라.

## ★★B. 소금은 econ 에 닿지 않는다 — 그리고 표 한 줄로는 안 된다 【실측】

지시서 전제: *"사건 장부의 단골 부족 품목 소금"*. **실측은 그 반대였다.**

랩 시드 1020 · 800일 · 51마을:

| | |
|---|---|
| 소금 재고 합 | **0** (보유 마을 0/51) |
| 생산 EMA | **0** |
| 소비 EMA | **0** (`_consEMA` 19종에 salt 없음) |
| 캐러밴 교역 중 소금 | **0건** (총 5,000건) |
| `STOCK_SHORTAGE` 소금 | **0건** |
| `PV_DEPOSIT_MAP` 에 소금 | **없음** ⇒ 게시판·거래소가 소금을 못 다룬다 |

★소금은 econ 재화로 **실재한다**(baseValue 5 · subsistence 0.3 · happiness 0.5).
`sim/economy-sim.js:2050` 에 `addProduce('salt', oAmt * 0.05)` 도 있다.
그런데 **실지도 51마을에서 재고로 남지 않는다.**

### ★★B-0. "왜 재고 0 인가"를 실측했다 [T17 §0 · 2026-09-02]

위 줄은 *"왜인지는 econ 층 진단이라 이 카드 밖"* 이라고 닫아 뒀다. **그 진단을 했다.**
`sim/` 을 임시로 계측해 실지도 랩(`scripts/econ-lab-real.js` · `tickWorldV2` · 19마을 · 800일)을
돌렸고, 잰 뒤 원상복구했다(`git diff --stat sim/` 비어 있음 · 번들 8/8).

| 물음 | 답 |
|---|---|
| 생산 코드에 **닿는가** | **닿는다.** 200일에 1,732회(광부 oAmt 계산 호출과 **같은 수** — 한 번도 안 걸렀다) |
| `oAmt <= 0` 로 걸러지나 | **아니다.** 0회. `_metalGlut` 평균 **0.000** |
| 포화 배수가 죽이나 | **아니다.** `satMul('salt')` = **1.0000** (ore 는 0.1709 로 실제 감산 중) |
| 800일 누계 생산(세전) | **1,113.9** — 광산 마을 **5곳**(어촌1·광산4·광산2·광산6·임업2) |
| 800일 끝 창고 재고 | **0.000** (키는 5/5 마을에 **있다** — 값이 0인 것이지 없는 게 아니다) |
| 국고(세금 몫) | **37.436** — 여기만 남았다. 쓰는 곳이 없다 |
| 생산 **직후** 창고 잔량 | 평균 **0.0894** (표본 1,732) — 하루 안에서도 안 쌓인다 |

⇒ **"재고 0"은 '없다'가 아니라 '남지 않는다'였고, 남지 않는 이유는 산출이 미미해서다.**
한 번 캘 때 0.05 단위(광부 사건당 실측 0.052)이고, 그게 매일 비워진다.
소비 EMA 가 0 인 것도 맞다 — `contributes` 는 **재고 기반 stat**(`_computeVillageStats`)이지
소비가 아니다. 즉 소금은 **먹히지도 않고 쌓이지도 않는다.**

⇒ 그래서 `PV_DEPOSIT_MAP` 한 줄로는 안 되는 이유가 더 분명해진다:
**표를 고쳐도 곳간에 소금이 서지 않는다.** 부족 의뢰는 재고 0 을 상시 부족으로 잡을 수도 있어
(게시 건수 기준선이 그쪽으로 움직인다) **한 줄의 파급이 곡물 품목화보다 크다.**
⚠이건 **econ 재화의 산출·소비를 건드리는 일**이다 — 지금까지 모든 배치의 절대 규칙(econ 무수정)과
정면으로 만난다. **재민 판단 없이 착수하지 않는다.**

⇒ **"소금 부족 마을에 납품"은 지금 구조적으로 불가능하다.** 두 겹으로 막혀 있다:
1. `PV_DEPOSIT_MAP` 에 `salt: 'salt'` 한 줄이 없다 → 플레이어가 낼 수도 팔 수도 없다.
   ⚠그 한 줄이 `events.buildDeliverable` 을 파생시켜 **게시 건수 기준선이 움직인다**
   (곡물 품목화 전례: 1,561/1,487/1,535 → 1,647/1,583/1,679).
2. 그 줄을 넣어도 **마을이 소금을 안 쓴다**(소비 0) → 부족이 안 생기고, 넣으면 그냥 글럿이 된다.

⇒ **순서 권장**: ⓐ econ 이 소금을 실제로 생산·소비하게(왜 재고 0 인지부터) → ⓑ `PV_DEPOSIT_MAP` 한 줄 ·
단일 손잡이 A/B · 3시드 800일로 게시 건수 이동 측정 → ⓒ 해안 마을 specialty 로 NPC 자염.
전부 **T17 ECON 웨이브**다.

## ★★C. 한반도는 반도가 아니다 — 자염은 원정이다 【실측 · 재민 판단】

| 변 | 이웃 | 해안선 침입 깊이 |
|---|---|---|
| 서 | 하란 북부(육지) | 5,728px |
| 동 | 아사기 열도(육지) | 5,600px |
| 북 | 눈벌 동토(육지) | **0** |
| 남 | **동창해(바다)** | 8,960px |

바다는 **남쪽 하나**뿐이다(해안선 타일 393,686개가 전부 남쪽 띠에 있다).

| 바다까지 | 마을 수 |
|---|---|
| 960px(도보 15초) | **3/51** — 어촌6 20px · 농촌12 426px · 농촌21 644px |
| 9,600px(도보 150초) | 4/51 |
| **시작 광장(농촌22)** | **61,746px = 도보 16.1분** |

⇒ 자염은 **동네 일이 아니라 원정**이다. 이건 고증으로는 맞다(소금길이 있었던 이유가 그것이다).
다만 **게임 리듬으로 맞는지는 재민 판단**이다. 갈래 셋:
1. **그대로 둔다** — 소금은 귀하고, 해안 마을 셋이 소금 산지가 된다. 가장 싸고 고증에 맞다.
2. **서·동 해안선을 살린다** — 지금 서·동 변에도 해안선 띠(5,600~5,728px)가 있는데
   그 안에 마을이 없다. 마을 배치를 안 건드리고 **띠만 두껍게** 하면 닿는 마을이 는다
   (`COASTLINE_BASE` — ⚠지형·콜라이더가 같이 움직인다. 큰 수술이다).
3. **소금을 교역으로** — B 가 열리면 내륙 마을은 사서 쓴다. **가장 econ 스러운 답**이지만 B 선행.

## ★D. 이 배치가 스스로 유도한 수 — 전수 목록 【확인 대상】

> 규약: *조용히 정한 수는 나중에 아무도 못 고친다.* 전부 env 손잡이이고 실기 전엔 안 건드린다.

| 유도 | 값 | 근거 |
|---|---|---|
| 갯벌 함수 염도 | **15%** (`SALT_BRINE_PCT`) | 조선 자염 함수 15~20% 의 **아래끝**. A 참조 |
| 한 솥 짠물 | **7되** | ★유도가 아니라 **계산**이다: `ceil(1.00 / (1.00 × 0.15))` — 표에 안 박았다 |
| 짠물 한 되 무게 | **1.00kg** | `weights.water_bottle` 1.00 과 **같아야** 한다(병↔짠물이 서로 바뀐다) |
| 소금 한 단위 무게 | 1.00kg | ★우리가 안 정했다 — econ 정본 `RESOURCES.salt.weight` |
| 한 솥 땔감 | **2단(6.0kg)** | ★추정: 물 6kg 증발 × 잠열 2.26MJ ≈ 13.6MJ ÷ 장작 15MJ/kg ÷ 노천 효율 0.15 ≈ 6.0kg |
| 한 솥 시간 | **0.5게임일 = 12분** | 실제 벌막은 한 솥에 8~10시간. 제련 2분과 말리기 3일(72분) 사이 |
| 소금가마 건축 | 석재 4 + 통나무 3 | ★유도 — 작업대(통4+석2)·건조대(통2+풀4)보다 무겁다(불을 오래 때는 물건이라 돌이 몸통) |
| 물병 | 박 1 → 병 1 | ★유도가 아니다 — **카탈로그가 박을 "조롱박·표주박(그릇)"이라 적어 뒀다** |
| 채수 쿨다운 | 없음(채집 것) | ★손잡이를 두 개 만들지 않았다 — `FORAGE_COOLDOWN_MS` 그 값이다 |

### D-1. ⚠클라 무접촉의 값 — **짠물이 화면에 영문 키로 뜬다**

`brine` 은 클라의 `ITEM_ICONS`·`ITEM_LABEL` 표에 없다. 그 표는 **클라 하드코딩**이고
서버가 채울 통로가 없다(작물만 `applyCropPayload` 로 채운다). ⇒ 제작창 비용 칸에
`🫙 7` 대신 **`brine 7`** 이 그대로 뜬다(`itemIconHtml(k, 18, k)` 의 폴백).

**404 는 안 난다**(아이콘 프리로드는 `ITEM_ICONS` 키만 훑는다 — `e2e-salt` ⑤가 확인).
**한 줄이면 끝난다**: 클라 `ITEM_ICONS` 에 `brine: '🫙'`, `ITEM_LABEL` 에 `brine: '짠물'`,
`ICON_NO_RENDER` 에 `'brine'`, `item_salt_kiln: '🧂'`·`'소금가마'`.
⇒ **클라 무접촉 조건 때문에 안 했다.** T0 계열 세션이나 재민이 한 줄 넣으면 된다.

### D-2. ⚠보존 행이 "보관 N일"을 무조건 찍는다

자염은 클라의 **보존 갈래**를 빌려 쓴다(`preserve: true` — 그래야 클라 수정 0).
그 갈래는 `· 보관 ${shelfDays}일` 을 조건 없이 찍는데, **소금은 안 썩는다.**
⇒ 숫자를 넣으면 거짓말이라 **`'∞'`** 를 넣었다 → 화면엔 "보관 ∞일".
뜻은 맞지만 어색하다. 클라 한 줄(`shelfDays != null` 가드)이면 지워진다.

### D-3. 갯벌 농축을 **별도 단계**로 떼는 안

지금은 채수 한 번이 곧 여과다. 실제 자염은 ⓐ 갯벌 갈기 ⓑ 바닷물 붓기 ⓒ 함수 거르기 ⓓ 끓이기
넷이다. 떼면 **동사가 하나 늘고**(갯벌을 간다) 자염이 "자리를 만드는 일"이 된다.
⇒ 재미 층 판단. 지금 떼면 판단·위험·손맛 없이 **단계만 하나 는다**(진행바 위험).

## F. 용기 체계 — 물병 하나로는 모자란다

`water_bottle` 은 **죽어 있었다**(무게표·라벨·아이콘·상자 허용목록에 다 있는데 서버 레시피가 없었다).
이 배치가 첫 쓸모를 줬지만, 아직 **짠물만** 담는다.

- **물을 못 담는다.** 갈증은 여전히 물가에서 즉시 회복이고 인벤에 물이 없다 —
  물병을 들고 사막을 건널 수 없다(`FOOD_EFFECTS` 에 물병이 없다).
- 술·기름도 같은 그릇이 필요해진다(술 빚기는 이미 회부에 있다).
- **토기**가 없다. `clay`(진흙)는 econ 재화이지만 **플레이어 채취 경로가 없다** —
  그래서 소금가마를 "돌·점토·통나무"로 지으라는 지시를 **돌·통나무**로 줄였다(새 재료 금지 규칙이 이겼다).
  ⇒ 진흙 채취 + 토기 굽기가 열리면 그릇 층이 제대로 선다(가마가 이미 있으니 붙일 자리도 있다).

## ★G. 바닷물을 마시면 갈증이 회복된다 【신체 영역 회부】

이 배치가 만든 결함은 아니다 — 바다는 원래 있었다. 다만 **바닷가를 목적지로 만든 건 이 배치**라
이제 사람이 실제로 그 자리에 선다.

`tryGather` 는 곁이 물이면 갈증을 30 회복한다. 바다인지 강인지 **안 가린다**.
⇒ 지금은 **병을 들고 있으면 채수가 먼저**라 눈에 잘 안 띈다(그 순서를 그렇게 잡았다).
병 없이 목마른 채로 바닷가에 서면 바닷물을 마신다.

고칠 방향은 셋인데 **전부 설계 판단**이라 안 건드렸다:
ⓐ 거절("바닷물은 못 마신다") ⓑ 갈증이 **더** 심해진다(고증 · 일관성 원칙에 가장 맞다) ⓒ 그대로.
⇒ **B-신체서버 영역 · 재민 판단.**

## H. 그 밖

- **H-1. 소금가마 스프라이트가 없다.** 지금은 벡터 발판 도형이다(건조대·작업대와 같은 상태).
- **H-2. 갯벌이 눈에 안 보인다.** 바다에 접한 뭍이면 어디서나 뜰 수 있는데 **표시가 없다** —
  플레이어는 "물가에서 E" 를 눌러 보고 알게 된다. 지형 시각화(E)와 같은 자리.
- **H-3. 한 솥씩만 건다.** 대기열은 5칸이라 다섯 솥까지 쌓을 수는 있지만 **수량 선택 UI 가 없다**
  (보존 배치가 남긴 같은 회부 — `amount` 는 서버가 받는데 클라가 늘 1 을 보낸다).
- **H-4. 소금가마도 남의 것은 못 쓴다.** "남의 시설 사용권"은 제작창 배치가 이미 회부했다.
- **H-5. 짠물은 상자에 넣을 수 있다**(`CHEST_ALLOWED_ITEMS`). 소금도 마찬가지다.
