> 재민 원문: *"지급 아이템은 없어야 할 거 같은데"* · *"돌멩이를 줍고 나뭇가지를 줍고"*
> 이번 배치가 심은 것: 시작 지급 0(로그인 수도꼭지 2개 철거) · 맨손 동사 보장 ·
> 조잡한 석기 3종(맨손 제작) · 이미 렌더된 자연물에 채집 판정만 얹기(개체별 lazy 고갈) ·

## A. 재민이 명시적으로 회부한 것 (구현 금지)

### A-1. 자연물 시각 변화 — "훑은 덤불이 성글어 보이는가"
개체별 고갈은 **숫자로는 있고 그림으로는 없다**. 지금은 다 훑은 자리에 서면 공지로만 안다
(`🤏 … 여긴 다 훑었다`). 캐논이 원하는 "손에 잡히는 세계"라면 덤불이 성글어지고 갈대가 눕는 게 맞다.
★붙일 자리: `Forage.left(key, now)` 가 이미 **0~4의 연속값**을 돌려준다 — 클라에 그 비율만 실어 보내면
그림은 순수 렌더 판단이 된다(서버 규칙 변경 0). 다만 **비파괴 자연물에 상태를 실어 보내는 첫 사례**라
청크 전송량·동기화 규약을 정해야 한다. ⇒ 재민 판정.

### A-2. 수색 모드 (좀보이드식 forage 오버레이)
"주울 게 있는 자리"를 **눈으로 찾게** 할 것인가, 지금처럼 **몸으로 부딪혀** 알게 할 것인가.
지금은 후자다 — 아무 데서나 E 를 누르면 `🤏 여긴 주울 게 없다 — 덤불·물가·숲을 찾아라` 가 뜬다.
전자로 가면 첫 30분의 마찰이 크게 줄어든다(아래 C-1 의 실측이 그 마찰의 크기다). ⇒ 재민 판정.

### A-3. 마을 공유지 반경
"마을 앞 채집장은 누구 것인가". 지금은 **아무 규칙도 없다**(토지 클레임은 자원 개체에만 걸리고
지형 채집에는 안 걸린다). 마을 반경 안의 채집을 주민 우선으로 할지, 완전 공유로 둘지. ⇒ 재민 판정.

### A-4. 맨손 낚시 여부 · 조잡한 낚싯대
지금 낚시는 **Shift+F 로 열리지만 도구 요구가 없다**(맨손으로도 던진다). 빈손 시작과는 맞지만
"조잡한 석기는 만들어야 하는데 낚싯대는 필요 없다"는 비대칭이 남는다.
⇒ ⓐ 맨손 낚시를 막고 `crude_rod` 를 넣을지, ⓑ 지금처럼 둘지. **낚시 손잡이는 실기 판정 대기**라 손 안 댔다.

### A-5. 시설 제작창 (§8.5 "맨손 = 소목록"의 나머지 절반)
`doCraft` 에는 **시설 게이트가 없다** — 화톳불도 대장간도 없이 무엇이든 만들어진다.
이번 배치는 "조잡한 석기는 맨손으로"만 실증했고, **정품이 시설을 요구하는가**는 안 건드렸다.
⇒ 사다리의 둘째 단이 "마을에서 산다" 하나뿐인 채로 남아 있다(자작 정품 경로 없음). 재민 판정.

### A-6. 온보딩 대본 ("나루터에서 온 이방인")
지급을 없앤 자리에 **말**이 없다. 지금 새 사람은 빈손으로 빈 광장에 떨어지고 아무도 아무 말도 안 한다.
캐논 §9 가 원한 건 굶주림이지 침묵이 아니다. ⇒ 첫 30분의 대사·유도는 재민 대본이 있어야 한다.

### A-7. 지게 · 부패 곡선 · 플레이어 간 거래 · NPC 캐러밴 무게(M) · MSY A/B
전부 `회부_무게_다음층.md` · `회부_거래소_다음층.md` 에 그대로 살아 있다. **이번 배치도 한 줄도 안 건드렸다.**
(특히 M: `CARGO_PER_TRIP=100` flat 유지 · econ 교역 경로 무수정.)

## B. 만들며 드러난 판단거리 — 값이 아니라 **설계**라 손대지 않았다

### ★★B-1. 스폰 광장에는 **주울 게 하나도 없다** (실측)
`scripts/emptystart-metrics.js` ⓪ — 새 사람이 실제로 눈 뜨는 자리(`ZONE.mainSquare` = 농촌22 광장):

```
  반경      잔가지  자갈   풀 (지형 칸) │ 덤불  나무  바위 (개체)
  300px        0     0     0          │   0     0     0
  600px        0   141    21          │   0     4     0
  1200px       0   363    71          │   0    14     0
  2400px       0  1428   287          │   8    49     2
```

읽는 법: **반경 300px 안은 완전한 공백**이다(캐논 "스폰 광장이 첫인상 — 소품 밀도 낮게"의 결과이기도 하다).
자갈·풀은 600px(≈9초)에서 잡히지만 **잔가지는 2,400px 까지 나가야 처음 나온다**(덤불 8개).
조잡한 돌도끼는 잔가지 1이 필수라 ⇒ **첫 도구까지 최소 편도 2.4k px ≈ 37초 직선 이동**,
그것도 **어디로 갈지 아는 사람 기준**이다.

⇒ 판단: ⓐ 이게 §9 가 원한 마찰인가(그러면 A-6 대본이 반드시 필요하다) ·
ⓑ 스폰 반경에 잔가지 소스를 하나 놓을 것인가 · ⓒ A-2 수색 모드로 찾는 비용을 줄일 것인가.
**셋 다 설계 판단이라 구현하지 않았다.**

### B-2. 지형 술어가 **전부 아니면 전무**로 답한다 (실측)
마을 51곳 · 반경 300px(274칸) 채집 자리 수:

```
  채집 사막(0자리)      20곳 / 51   (광산1·2·3·6·7 · 농촌6~11 · 13~21)
  한 종류 이하만        33곳 / 51
  중앙값                82자리 · 최대 274자리(=274칸 전부)
  세 재료가 1,600px 안에 다 있는 마을   2곳 / 51
```

원인은 규칙이 **지역 단위 술어**라서다 — `forestMult > 1.5`(숲 전체) · 물 인접(해안선 띠) ·
바위/물 링(암반대). 그래서 마을은 숲 **안**이거나 **밖**이고, 그 사이가 없다.
⇒ 반독점 규약("옆 자리가 있다")은 **자리가 있는 마을에서는 넉넉히 성립**한다(중앙값 82자리, 3분 리필).
그러나 **없는 마을에서는 자리 자체가 0**이라 반독점 이전의 문제다.
⇒ 판단: 소스를 더 다종화할지(예: 풀밭 = 풀), 마을 시딩이 채집원을 고려할지, 아니면 지역차를 그대로 둘지.

### B-3. 덤불 전리품 표가 **두 벌**이다
`zone.js` 의 플레이어 채집(4702줄)은 이번에 `{berry 2, fiber 1, twig 1}` 로 고쳤는데,
**NPC 채집(1931줄)은 여전히 `{berry 2, fiber 1}`** 이다 — 같은 덤불이 누가 뜯느냐에 따라 다른 걸 낸다.
★이번엔 **안 고쳤다**: NPC 는 잔가지를 쓸 데가 없고, 고치면 NPC 인벤에 안 쓰는 품목이 쌓인다
(그건 econ 이 아니라 zone 의 일이지만, 그래도 "왜 넣었나"를 답할 수 있어야 한다).
⇒ 판단: 표를 하나로 합칠지(그리고 NPC 잔가지를 어디에 쓸지), 아니면 **두 벌인 이유를 주석으로 못 박을지**.

### B-4. 조잡한 석기가 정품보다 **무겁다** (파생 kg 확인 요청)
`crude_axe 1.40 · crude_pick 1.50 · crude_blade 1.10` vs 정품 `tool 1.20 · weapon 1.50`.
근거: 다듬지 않은 자갈 날 + 짧은 나뭇가지 자루 → 균형이 나쁘고 날 몫이 두껍다.
고증표 §11-b 에 근거와 함께 등재했고 **전부 "추정" 태그**다. ⇒ 재민 확인 대상.

### B-5. 맨손은 **평생 산출이 무한**이다
```
  맨손          배수 1 · 내구 없음 · 평생 산출 ∞    (느리지만 막히지 않는다)
  조잡한 돌도끼  배수 2 · 내구  25 · 평생 산출  50
  정품 도끼      배수 3 · 내구 100 · 평생 산출 300   (조잡의 ×6.0)
```
"도구는 문이 아니라 능률"을 지킨 결과이자, **자급자족 병 방지선**의 근거다(정품 한 자루가 조잡 6자루 몫).
⚠다만 지금은 **정품을 자작할 수 없다**(A-5) — 사다리 둘째 단이 구매뿐이라, 마을이 멀면 조잡한 석기를
계속 다시 만드는 게 합리적 선택이 된다. 손잡이(`CRUDE_EFF_FRAC=0.5` · `CRUDE_DURA_FRAC=0.25`)는
**실기 판정 대기**라 손 안 댔다.

### B-6. 갈대 문턱을 **갈증 95%** 로 열었다 (보고)
물가 E 는 원래 "목이 마르면 물, 아니면 갈대"였는데 `>= THIRST_MAX` 로 걸어 두니
**갈증이 매 틱 조금씩 줄어 정확히 100인 순간이 거의 없어서** 실클라에서 갈대가 **한 번도** 안 잘렸다.
⇒ `>= THIRST_MAX * 0.95` 로 열었다. 이건 값 튜닝이 아니라 **죽은 갈래를 살린 것**이지만,
"물이 갈대보다 먼저"라는 우선순위 자체는 설계다. ⇒ 재민 확인.

## C. 검증 족보에 추가한 것

- **(62) 지형 술어를 쓰기 전에 분포부터 재라.** 1차 실장은 `getStoneMultiplier` 로 자갈 자리를 갈랐다가
  풀이 한 번도 안 나왔다 — 실측하니 이 세계의 `stoneMult` 는 **어디서나 1.00 고정**이었다(3,000표본 min=max=1.00).
  죽은 신호를 읽는 규칙은 **조용히 한쪽으로만 답한다**.
- **(63) "그 자리가 채집원인 것"과 "거기서 채집이 열리는 것"은 다른 명제다.** 숲 바닥 좌표엔 **나무 개체**가
  서 있어서 `tryGather` 가 그걸 먼저 집는다. ⇒ 하네스는 **여러 자리를 밟아 보고** 판정한다(후보 일소).
- **(64) 좌표계를 섞지 마라 — 도착 판정에서도.** `teleport_debug` 는 존 로컬, `__getMyAbs()` 는 월드 절대다.
  섞으면 멀쩡한 워프가 전부 "미도달"로 찍힌다. 오프셋은 **정본**(`zone-config.js`)에서 읽는다.
- **(65) 공지로 세지 마라(재확인).** `__notices` 는 40칸 링버퍼라, 채집 공지만으로도 포화된다 —
  그러면 `slice(n0)` 가 늘 비고 **성공이 실패로 찍힌다**. 상태(장비 수)로 센다.
- **(66) 대조는 "덜 움직였다"가 아니라 "안 했으면 안 움직인다"로 세워라.** `e2e-trade ⑤` 의 대조는
  "무관 품목이 **전부** 움직였으면 날이 흐른 것"이라고 읽었는데, 그림자 가격은 **바구니 전체를 한꺼번에**
  푸는 값이라 큰 거래 하나면 무관 품목도 같이 움직인다. 뽑히는 품목에 따라 통과·실패가 갈렸다.
  ⇒ **널 거래**(아무것도 안 하고 같은 시간 대기)로 0 이동을 요구한다 — 독립성 가정을 안 쓴다.
