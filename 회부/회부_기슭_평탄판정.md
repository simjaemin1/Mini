# 회부 — `e2e-mtfoot` ⑤ 「기슭은 산보다 납작하다」 [2026-08-31 밤 · 규명 완료, **미수리**]

> 이 실패는 **2026-08-26 러너 통합 때부터** 인계 1847줄에 실려 왔고, 그때 이미
> 배치 **전** 커밋(`b6ba2cb`)에서도 **수치까지 똑같이** 재현됐다.
> 이번 밤에 **왜 안 넘는지**를 분포로 규명했다. **판정은 손대지 않았다** — 산 아크 설계 소관이다.

---

## 1. 판정과 실측

```js
// scripts/e2e-mtfoot.js:115
ok('⑤ ★기슭은 산보다 납작하다', mf < mm * 0.72, …)   // mf=기슭 vy 중앙값, mm=산(L/M) vy 중앙값
```

```
기슭    n=58   min 0.252 · p25 0.305 · 중앙 0.337 · p75 0.367 · max 0.407
산(L/M) n=186  min 0.300 · p25 0.300 · 중앙 0.450 · p75 1.067 · max 1.257

판정: 0.337 < 0.450 × 0.72 = 0.324  →  실패 (실제 비 0.750)
```

## 2. ★원인 — 기준(분모)이 **쌍봉 분포**다. 중앙값은 그 골짜기에 떨어진다

```
MT_VY_MIN(0.30) 에 바닥이 눌린 개수:  기슭 0/58 (0%)  ·  산 78/186 (42%)
```

* **기슭은 안 눌렸다.** 설계 범위(`MT_FOOT.vy0..vy1 = 0.26..0.52`) 안에서 제대로 납작하다.
* **산의 42%가 하한 0.30 에 눌려 있다.** `_mtFitVy` 의 맞춤 상한(`(dNW+MT_FIT_TOL)/upCells`)이
  바위 경계 근처 산 스프라이트를 눌러 버린 것들이다 — **서 있는 산이 아니라 이미 납작해진 산**이다.
* 그래서 산 vy 는 **0.30 무더기 + 1.0 이상 무더기**의 쌍봉이 되고, **중앙값 0.450 은 두 봉우리 사이**에
  떨어진다. 쌍봉의 중앙값은 통계 중 가장 불안정하다 — 눌린 비율이 몇 %만 움직여도 `mm` 이
  0.30 쪽과 1.0 쪽 사이를 널뛴다. **그 위에 고정 문턱 0.72 를 얹은 게 이 판정이다.**

## 3. ⇒ 설계 의도 자체는 **지켜지고 있다**

"기슭은 작은 산이 아니라 납작한 산"이라는 원 설계와 비교하면:

| 비교 대상 | 비 | 문턱 0.72 |
|---|---|---|
| 기슭 중앙 0.337 vs 산 **중앙** 0.450 | 0.750 | ✗ |
| 기슭 중앙 0.337 vs 산 **p75** 1.067 | **0.316** | ✓ |
| 기슭 중앙 0.337 vs **안 눌린 산**(58%)만 | **≈0.3** | ✓ |

**눌리지 않은 진짜 산과 견주면 기슭은 3분의 1 높이다.** 그림은 설계대로다.
깨지는 건 **하네스가 고른 기준 통계**이지 기슭 구현이 아니다.

## 4. 선택지 (내가 고르지 않았다)

1. **기준을 안 눌린 산으로** — `vy > MT_VY_MIN + ε` 인 세그먼트만 분모에 넣는다.
   가장 뜻에 맞다("서 있는 산보다 납작한가"). 대신 "눌린 산도 산이다"라는 반론이 가능.
2. **기준을 p75 로** — 쌍봉의 위쪽 봉우리를 대표로 삼는다. 한 줄 수정, 뜻도 근접.
3. **문턱을 실측에 맞춘다**(0.72 → 0.80) — ⚠**권하지 않는다.** 이건 원인을 안 고치고 **바를 낮추는 것**이고,
   분모가 쌍봉인 한 다음에 또 널뛴다. 이 레포 문화(자명 통과 금지)와 정면으로 어긋난다.
4. **하한 `MT_VY_MIN = 0.30` 을 손본다** — ⚠산 렌더 전체에 영향. 판정 하나 때문에 건드릴 자리가 아니다.

내 의견: **1번**(불가하면 2번). 어느 쪽이든 **판정의 뜻을 적어 두는 주석**이 같이 가야 한다 —
"분모는 눌리지 않은 산이다. 눌린 산을 넣으면 쌍봉의 중앙값을 재게 되고, 그건 아무것도 안 재는 것이다."
