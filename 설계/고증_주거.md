### ⓑ 환산식 — 새 수 0(기존 `server/hut-stages.js` 그대로)

이 카드는 새 kg·새 그루 값을 하나도 만들지 않는다. `server/hut-stages.js`(읽기만 함, 무변)의 기존 레시피를 그대로 식으로 편 것뿐이다.

* 기둥 1개 = 통나무(wood) **3**단(`HUT_RECIPES.pillar: { from: { wood: 3 }, to: { pillar: 1 } }`)
* 서까래 1개 = 통나무(wood) **0.5**단(`HUT_RECIPES.rafter: { from: { wood: 1 }, to: { rafter: 2 } }` → 2개당 1단이므로 1개당 0.5단; 게임은 배치 단위로 올림하므로 실제 소모는 `⌈서까래수/2⌉`단)
* **총 통나무(그루·단) = 기둥수 × 3 + ⌈서까래수 / 2⌉**
* 통나무 1단의 kg = `server/weights.js` `CORE_KG.wood = 3.00`(고증표 앵커 — 이 카드가 만든 수 아님) ⇒ **총 kg = 총 통나무단 × 3.00**
* 굴립주 기둥 1개의 완제 kg(참고 — 그루 수 계산에는 안 씀) = `DERIVED_KG.pillar = 6.00`(통나무 3단을 깎은 몫), 서까래 1개 = `DERIVED_KG.rafter = 1.50`

**검산(서버 현재값 재현):** 기둥6·서까래8 → 6×3 + ⌈8/2⌉ = 18 + 4 = **22단** — `hut-stages.js`의 `hutRaw()`가 실제로 내는 `wood: 22`와 **정확히 일치**(§3에서 코드로 재확인). 이 식이 이미 서버가 쓰는 식임을 확인했을 뿐, 이 카드가 새로 정한 게 아니다.

**추가 확인(읽기만 · T497 무접촉) — 이 계산이 T497 자신의 함수와도 일치한다:** `server/hut-stages.js`에는 이미 T497(세션4)이 만든 `HUT_PILLARS_ATTESTED = [2, 4]`와 `hutRawPillars(n)`(기둥 수만 바꿔 원자재를 유도하는 함수 · `T497_HUT_COST` 팔로만 읽힘·기본 꺼짐)이 있다. 이 카드가 실행만 해서 값을 읽었다(코드 0 — 한 글자도 안 고쳤다): `hutRawPillars(2)` = `{wood:10}` · `hutRawPillars(4)` = `{wood:16}` · `hutRawPillars(6)` = `{wood:22}` — 위 손 계산(10·16·22)과 **한 자리도 안 틀리고 일치**한다. 즉 T497이 이미 짜 둔 식과 이 카드가 출토 표에서 다시 편 식이 같은 결론을 낸다(서로 다른 두 갈래가 같은 답을 낸 것이지, 이 카드가 T497 코드를 보고 베낀 게 아니다 — `HUT_RECIPES`는 T488 이전부터 있던 표다).
