## 1. 열 — 걸음 안에서 실제로 읽고 쓰는 `npc` 필드 전수

★**형의 기본은 `Float64Array`** 다. 게이트가 *"1,000틱 뒤 좌표 바이트 동일"* 이라, JS `number`(IEEE754 binary64)와
한 비트라도 다른 표현을 쓰면 그 자리에서 빨강이다. **줄이는 것은 근거가 있을 때만** — 아래 '줄일 수 있나' 열.

### ⓐ 커널이 **읽고 쓰는** 열 (핫 · C 가 직접 만진다)

| 열 | 형 | 읽기 자리 | 쓰기 자리 | 줄일 수 있나 |
|---|---|---|---|---|
| `x` | `Float64Array` | `:2439` `:11400` `:11451` … | `:11525` `:11529` | ✗ — 좌표. 바이트 게이트가 f32 를 금지한다 |
| `y` | `Float64Array` | 〃 | 〃 | ✗ |
| `vx` | `Float64Array` | `:11426` | `:2444` `:2450` `:11421` | △ f32 가능(속도는 게이트 밖) — 그런데 `x += vx*dt` 라 f32 로 줄이면 **좌표가 갈린다**. ✗ |
| `vy` | `Float64Array` | 〃 | 〃 | ✗(위와 같은 이유) |
| `targetX` | `Float64Array` | `:2467` `:2469` `:2648` | (결정이 쓴다 — JS) | ✗ |
| `targetY` | `Float64Array` | 〃 | 〃 | ✗ |

### ⓑ 커널이 **읽기만** 하는 열 (JS 가 쓴다 · 결정의 출력)

| 열 | 형 | 무엇 | 자리 |
|---|---|---|---|
| `speedMult` | `Float64Array` | `behavior==='flee' ? 2.5 : 0.6` × `_huntSpd` — **결정의 출력 한 수로 접는다**(커널은 `behavior` 를 모른다) | `:2645` `:2646` |
| `floor` | `Uint8Array` | 벽·나무 판정의 층(0/1) | `:11455` `:11458` `:11475` |
| `rdMul` | `Float64Array` | 답압 길 배속(§16 · 셀 변경 시만 갱신) | `:11429` |
| `isNpc` | `Uint8Array` | 핸드오프 갈래를 가른다(NPC 는 클램프) | `:11444` `:11527` |
| `active` | `Uint8Array` | `isPositionActive(x,y)` 의 결과를 **JS 가 미리 채운다**(문자열 키 Set 은 안 옮긴다) | `:422` |

### ⓒ 걸음이 만지지만 **커널 밖**에 남는 것 (결정·경로·상태기)

| 필드 | 왜 밖인가 |
|---|---|
| `behavior` · `nextDecisionAt` · `fightTarget` · `gatherTarget` | 결정(`decideNpcBehavior`) |
| `path` · `pathIndex` · `_pathFor` · `_pathAt` | A* 경로 — 배열의 배열이라 열이 아니다. 커널은 **현재 웨이포인트 한 쌍**만 받는다 |
| `_stuckPos` · `_stuckN` | stuck 상태기(`detectStuck` · `:2466`) — 객체 하나를 들고 있다. 열로 펴면 `stuckX`·`stuckY`·`stuckAt`·`stuckN` 넷 |
| `npcHomeX/Y` · `npcBedX/Y` · `simLonOff` · `simEvacUntil` | 야간 귀가·대피 — 결정 쪽 |
| `canadiaTask` · `canadiaVillage` · `simVillageId` | 소속·특수 상태 |
| `onStairId` | 계단 축 고정 — 드문 갈래(건물 안) |
| `inventory` | 걸음이 아니라 채집이 만진다 |

⇒ **핫 열은 열한 개**(ⓐ 여섯 + ⓑ 다섯)다. 1,464명이면 `Float64Array` 아홉 × 8B + `Uint8Array` 둘 = **약 107KB** —
L2 에 들어간다. 10,000명이면 730KB(L2~L3 경계).

## 2. 주민 색인 — **조밀 슬롯**

`pid` 는 색인이 아니다(구멍이 생기고 열이 성기어진다). 슬롯 규칙 한 줄:

> **슬롯은 0..N-1 로 꽉 찬다. 주민이 죽으면 마지막 슬롯을 그 자리로 옮기고 N 을 하나 줄인다(swap-remove).**
> `pid → slot` 는 `Map` 하나가 들고, 옮긴 주민의 항목만 고친다.

⚠순서가 바뀌면 **부동소수 합의 순서**가 바뀌는 자리가 있나 — 걸음은 사람마다 독립이라 **없다**(커널은 사람 간 합을 안 한다).
⚠그래도 `_walk` 같은 누적 계측은 순서에 민감할 수 있다 — 계측은 정수 카운터라 무관(확인).

## 3. 세계 쪽 입력 — 세 격자

| 입력 | 꼴 | 어디서 오나 | 비고 |
|---|---|---|---|
| **지형** | 셀당 비트 · `Uint8Array` (32px 셀) | T333 이 이미 굽는 그 상자(`server/terrain-tilecache.js` `prebake`) | 지금 4비트(물-계산됨/물-값/바위-계산됨/바위-값). 커널에는 **값 비트 둘**만 넘기면 된다 · **다리·환호**가 붙으면 비트 둘을 더한다 |
| **벽** | 셀당 1바이트 · `Uint8Array` (32px 셀) | 건물 격자에서 유도(`findEdgeWall` 의 N·E 두 변) | `edgeBlockedStep` 이 네 갈래를 이 둘로 접는다(W = 왼쪽 셀의 E · S = 아래 셀의 N) |
| **나무·바위** | 중심 `x`·`y`·충돌반경 `R` 세 열 + **균일 격자 CSR** | `qtResources` 대신 격자(64px) | 반경 28 조회라 3×3 셀이면 충분 · 쿼드트리보다 커널에서 싸다 · **답은 같다**(같은 거리 필터) |

★**나무는 셀 경계를 넘을 때만 묻는다**(T345 §4) — 이 계약도 그 규칙을 그대로 쓴다.

## 4. 커널 경계 — 무엇이 한 번에 건너가나

```
walk_init(지형비트, 벽격자, 나무열+격자, 주민열 일곱, N, zoneW/H, dt, MOVE_SPEED)   // 한 번
walk_ticks(n)                                                                      // n 틱을 통째로
```

⚠**한 틱에 한 번만 건넌다.** 사람마다 건너면 경계 비용이 걸음 값을 삼킨다(WASM 호출 ≈ 수십 ns × 1,464 × 30Hz).
⚠메모리는 **공유**다 — WASM 은 JS 가 넘긴 `WebAssembly.Memory` 위에 열을 놓고 JS 도 같은 뷰를 쓴다(복사 0).
   N-API 는 `napi_get_typedarray_info` 로 같은 버퍼를 가리킨다(복사 0).

## 5. 산술 규약 — 바이트가 갈리지 않으려면

| JS | C | 주의 |
|---|---|---|
| `Math.floor` | `__builtin_floor` | 같다 |
| `Math.hypot(a,b)` | `sqrt(a*a+b*b)` | ★**`Math.hypot` 은 스케일링을 한다** — 마지막 비트가 갈릴 수 있다. ⇒ **JS 쪽 팔도 `Math.sqrt(a*a+b*b)` 로 맞춘다**(제품은 `hypot` 그대로 · 이 차이는 보고 §2-ⓑ 에 적는다) |
| `a*b + c` | 같은 순서 | 결합법칙 금지 · `-ffast-math` 금지 |
| `number` | `double` | 축약 금지 |

## 6. 확정이 더한 것 셋 [T356 ②]

### 6-ⓐ `active` 열 — 문자열 키 Set 에서 **유도**한다

`isPositionActive(x,y)` 는 `activeChunkKeys`(`Set<"cx_cy">`) 조회다. 커널은 문자열을 모른다.
⇒ **JS 가 틱마다 한 번** 그 Set 에서 `active` 열(`Uint8Array`)을 채운다. **원천은 그 Set 하나다**
(T333 이 `WATER_TILES` **에서** 비트 색인을 유도한 그 규율 — 정수 키로 바꾸는 것은 이 계약 밖이다).

| | 값 |
|---|---|
| 형 | `Uint8Array(N)` — 주민 슬롯당 1바이트 |
| 채우는 자리 | 결정 문 순회 **앞**(그 틱의 활성 청크가 확정된 뒤 · `updateActiveChunks()` 다음) |
| 비용 | 주민당 조회 하나 — 지금 **걸음마다 두 번** 하던 것을 **틱마다 한 번**으로 줄인다 |

### 6-ⓑ `_stuckPos` 열 넷

`detectStuck` 이 객체 하나(`{x,y,at}`)와 `_stuckN` 을 든다. 열로 펴면 넷이다:

| 열 | 형 | 비고 |
|---|---|---|
| `stuckX` `stuckY` | `Float64Array` | 마지막으로 '안 막혔던' 자리 |
| `stuckAt` | `Float64Array` | 그 시각(ms · 벽시계라 f32 불가) |
| `stuckN` | `Uint8Array` | 연속 막힘 수(상한 3 — `unstuckNpc` 가 센다) |

⚠`stuckAt` 은 **벽시계**다 ⇒ 두 프로세스 게이트가 서면(T350 §3-ⓒ 회부) 여기가 먼저 갈린다. 그때 틱 수로 바꾼다.

### 6-ⓒ 옮기는 순서 — **해부 표가 정한다**

| 순서 | 무엇 | 왜 이 순서인가 | 상태 |
|---|---|---|---|
| **1** | **지형 = 셀당 막힘 비트 하나** | 걸음당 6.2회 · 한 번이 술어 넷 + `floor` 여덟 · 답은 `(tx,ty)` 의 순수 함수 · **A\* 의 `straightPathClear` 도 같은 술어를 쓴다**(낮 19.3 %의 일부를 같이 깎는다) | **T356 ② 착지**(`T356_SOA`) |
| 2 | 나무 = 균일 격자 CSR | 걸음당 4.0회 · 쿼드트리 하강을 3×3 셀 훑기로 | 다음 카드 |
| 3 | 벽 = 셀당 1바이트(bit0 N · bit1 E) | 걸음당 5.0회 — 그런데 **열에 아홉이 같은 셀 조기 반환**(T345)이라 값이 작다 | 다음 카드 |
| 4 | 좌표·속도 열 순회 | T352 실측 **×1.13** — 열로 펴는 것 자체는 거의 안 는다 | 다음 카드(2·3 뒤) |
| 5 | C 커널(WASM) | T352 ×1.8 · 단 **걸음 문만**이라 틱 전체로는 4.3 % | #53 재민 |

★**4가 마지막인 이유**: T352 가 잰 ×1.13 이다. **열이 이기는 게 아니라 격자가 이긴다** — 제품의
이동 문 1.56 µs 대 T352 평평한 판 0.42 µs 의 차는 **자료 구조**지 순회 꼴이 아니다.
