# 설계안 — 삼원 합금(Cu·Sn·Pb) 연속 물성 + 광종별 밀도

> 재민: "플레이어로 하여금 주조를 금속 3개까지 합금을 자유롭게 할 수 있으면 어때?
> 그거에 따른 성질을 화학적으로 잘 게임으로 반영할 수 있을까..? 값에 따라 연속적으로 말이야..
> 변수가 3개인 함수라 좀 어려우려나..?
> 그리고 마을이 주석 산지이다 아니다를 꼭 이분법적으로 정할 필요가 있어..?"

**둘 다 된다. 그리고 둘이 서로 맞물려서, 같이 넣으면 오히려 코드가 줄어든다.**

---

## 1. "변수 3개라 어렵나" — **아니다. 자유도는 2다.**

Cu + Sn + Pb = 1 이므로 조성은 **삼각 다이어그램 위의 한 점**이다.
슬라이더 두 개(또는 삼각형 위 커서 하나)면 전부 표현된다. 3차원 함수가 아니다.

그리고 물성이 전부 **단조·연속**이라 게임 함수로 옮기기 좋다. 근거:

| 사실 | 출처 |
|---|---|
| Sn **15 wt%까지 경도가 체계적으로 상승**, 그 이상은 취성이 제한 요소 | PatSnap 재료DB |
| Sn 15% 이하는 α상(구리 고용체), 초과 시 **δ상(Cu₃₁Sn₈) 취성상** 형성 | Xometry |
| 경도 60 HB(연질) ~ 180 HB(합금) · 인장 350~850 MPa | PatSnap |
| 일반 청동 = Cu 87% + Sn 8~12.5% | Xometry |
| Pb 첨가 → 가공성·주조성(융점↓·유동성↑) 개선, 강도는 희생 | Xometry |

## 2. 물성 모델 시안

```js
s = Sn 비율,  b = Pb 비율,  Cu = 1 − s − b

경도    H(s) = 1 + 1.60 × min(s, 0.15) / 0.15         // 1.0 → 2.6, Sn 15%에서 포화
인성    T(s) = s ≤ 0.10 ? 1 : 1 / (1 + ((s−0.10)/0.075)²)   // δ상 나오며 급락
강도희생 L(b) = 1 − 0.80 × b                           // 납은 구리와 불용 — 입자로 남아 강도를 깎는다
주조성  C(b) = 1 + 1.20 × b / 0.15                     // 융점↓·유동성↑ — 복잡한 형상이 가능해진다
광택    G(s) = min(1, s / 0.35)                        // 은백색 반사

무기 성능 = H × T × L
거울 성능 = G × C
```

### 검증 — 모델이 고르는 최적 배합 vs 실제 유물

| | 모델 최적 | **실제 유물** |
|---|---|---|
| 무기(검) | Sn **12%** | 세형동검 Sn 13.6~18.7% |
| 거울 | Sn **35%** | 다뉴세문경 Sn **34.3%** |

거울은 소수점까지 맞았다. 무기도 실측 구간 바로 아래다.
**한 모델에서 "검엔 12%, 거울엔 35%"가 저절로 갈린다** — 이게 이 설계의 핵심이다.

### 무기 성능 곡선 (Pb 10% 고정)

| Sn% | 경도 | 인성 | 성능 | |
|---|---|---|---|---|
| 0 | 1.00 | 1.00 | 0.92 | ← 순동 |
| 5 | 1.53 | 1.00 | 1.41 | |
| 10 | 2.07 | 1.00 | 1.90 | |
| **12** | 2.28 | 0.93 | **1.96** | ← 최적 |
| 15 | 2.60 | 0.69 | 1.66 | |
| 19 | 2.60 | 0.41 | 0.98 | |
| 34 | 2.60 | 0.09 | 0.21 | ← 거울 배합. 검으로는 최악 |

**중간에 최적점이 생기는 게 요점이다.** 주석을 넣을수록 좋은 게 아니라, 너무 넣으면 깨진다.
플레이어가 실험하다 "12% 근처가 제일 낫다"를 스스로 발견하게 되고, 그게 실제 고고학 데이터다.

### 지금 코드를 이 모델로 평가하면

| | Sn 비중 | 무기 성능 |
|---|---|---|
| 현행 `copper .3 : tin .12` | **29%** | **0.36** ← 거울 배합. 검엔 최악 구간 |
| 제안 5:1 | 17% | 1.45 |
| 순동 | 0% | 1.00 |

순동/청동 = **0.69**. 내가 앞서 손으로 정한 `MAT_GRADE.copper = 0.70` 과 거의 일치한다(우연이지만 좋은 교차검증).

### ⚠ 모델의 미비 — 납의 역할

모델은 무기 최적 Pb를 **0%**로 고르는데, 실제 세형동검엔 **Pb 6.9~15.7%** 가 들어 있다.
모델이 납을 "성능 깎는 것"으로만 보기 때문이다. 실제로 납은 **성능이 아니라 제작 가능성**의 문제다 —
융점을 낮추고 쇳물을 잘 흐르게 해서, 청동기 기술로 **얇고 복잡한 주물을 부을 수 있게** 한다.
납이 없으면 아예 못 붓는 형상이 있다.

⇒ 모델에 축을 하나 더 얹어야 실제 배합이 재현된다:
```
주조 성공률 = clamp(C(b) × 형틀난이도⁻¹, 0, 1)     // 형상이 복잡할수록 납을 요구
최종 품질 = 성능 × 주조 성공률
```
이러면 검도 Pb 10% 근처를 고르게 되고, 세문경 같은 정교한 물건은 납을 더 요구한다.
(같은 이유로 지금 모델이 의기·방울을 거울과 구분 못 한다 — 실제는 Sn 17~19% · Pb 12~13%.)

## 3. "산지이다/아니다" 이분법 — **없애야 한다. 그리고 없애는 게 더 단순하다.**

### 지금 구조의 문제

```js
land.tin = _tinDepositFor(opts)     // score ≥ 1.28 이면 0.6~1.4, 아니면 0
```
- **이진 스위치**다. 주석이 조금 나는 마을이라는 개념이 없다.
- 문턱이 **랩 스케일**(광산촌 ore=1.5)이라 본게임(최대 1.06)에선 전멸했다.
- 산출이 `0.46 × land.tin` **마을당 정액** — 광부 수·광맥 셀·품위 전부 무관.
- 생성 시 한 번 정해지고 **영원히 안 바뀐다**(고갈에 반응 없음).
- 그리고 광석 부산물이 `{copper .22, iron .03, silver .05, gold .02, gem .01}` **고정 dict** 라
  **금맥 옆 마을이나 철맥 옆 마을이나 같은 비율로 나온다.** 지도의 광종이 경제에 안 닿는다.

### 제안 — `land.ore` 하나를 **광종별 밀도 벡터**로

```js
// 노동권(150셀) 안 광맥 셀을 광종별로 세서 그대로 밀도로 쓴다
land.oreMix = { iron: 0.31, copper: 0.44, tin: 0.06, gold: 0.11, jade: 0.05, obsidian: 0.03 }
land.ore    = Σ oreMix                                  // 총 광맥 밀도(광부 정원 — 지금과 동일)

광부 1인 일일 산출:  amt[m] = 1.5 × land.ore × oreMix[m] × skillMul × toolBoost
```

이 한 줄이 위 다섯 문제를 **동시에** 없앤다:

| 없어지는 것 | 어떻게 |
|---|---|
| 산지 이분법 | `oreMix.tin` 이 연속량. 조금 나는 마을·많이 나는 마을이 자연히 생긴다 |
| `TIN_DEPOSIT_ORE_SCORE` | **상수 자체가 필요 없어진다.** 문턱 튜닝 문제도 같이 사라진다 |
| 랩↔본게임 스케일 불일치 | 밀도는 둘 다 같은 방식으로 계산된다 |
| 고갈 미반영 | `_oreFeedback` 이 `oreMix` 전체에 걸린다 — 광부가 몰리면 주석도 마른다 |
| 광종이 econ에 안 닿음 | 고정 dict 폐기. **지도의 광종 배분이 드디어 경제가 된다** |
| `_bronzeCapable` 문턱 | 폐기. 주석이 있는 만큼 청동, 없으면 순동(§4) |

### 광부 정원과의 관계 (재민 질문)

문턱은 그대로 두고 **점수 쪽이 내려가는** 되먹임이 이미 있다:
```js
_oreFeedback:  land.ore = 기준값 × (0.4 + 0.6 × oFrac)     // oFrac = 노동권 광맥 셀 잔여 재고
```
광부↑ → 재고 소모↑ → `oFrac`↓ → `land.ore`↓ → 광부 정원↓.
실측 평형(마을 40): 대형 광맥 재고 100%·광부 27.9명 / 중형 89%·14.6 / 소형 32%·4.6 / 자잘 0%·1.1.

⇒ **"광부가 많아지면 문턱이 높아져야 한다"는 이미 성립한다.** 다만 `land.tin` 에는 안 걸려 있다.
`oreMix` 로 바꾸면 광종별로 전부 걸린다.

## 4. 두 변경이 맞물리는 지점 — NPC 배합

플레이어만 배합하고 NPC는 정액을 태우면 축이 둘로 갈린다. 그런데 `oreMix` 가 있으면 자동으로 풀린다:

```js
// NPC 대장장이는 **마을 재고 비율대로** 배합한다
const s = tin / (copper + tin + lead);
const 품질 = weaponScore(s, b) / weaponScore(0.12, 0.10);    // 최적 배합 대비
```

- 주석이 넉넉한 마을 → Sn 12% 근처 → 좋은 검
- 주석이 조금 나는 마을 → Sn 4% → 무른 검(순동보다는 낫다)
- 주석이 없는 마을 → Sn 0% → 순동검
- **`_bronzeCapable` 도, 순동검 분기도 따로 필요 없다.** 하나의 연속 함수가 셋을 다 덮는다.

⇒ 청동검/순동검/석검의 **이산 분기 3개가 연속 곡선 하나로 대체된다.** 코드가 줄어든다.
그리고 "주석 교역로를 쥔 마을이 좋은 검을 쓴다"가 상수 없이 창발한다.

## 5. 규모와 위험

| 변경 | 파일 | 규모 | 위험 |
|---|---|---|---|
| `oreMix` 산출 | `server/villages.js` `sustain.js` | 중 | 낮음 — 이미 광종을 세고 있다(`oreMinerals`) |
| econ 산출을 `oreMix` 기반으로 | `sim/economy-sim.js` | **대** | **높음** — 부산물 dict·주석 특례·`_bronzeCapable` 를 걷어낸다 |
| 합금 물성 함수 | `server/specialty.js` (신설) | 소 | 낮음 — 순수 함수 |
| 플레이어 주조 UI·레시피 | `server/zone.js` `public/client.js` | 중 | 중 — 단일재료 전제(`doCraftEquipment`)를 배합으로 |
| NPC 배합 | `sim/economy-sim.js` | 중 | 높음 — 무기 품질 EMA·병기고 배분에 파급 |

**"econ 엔진 수정 금지" 규약에 정면으로 걸린다.** econ 쪽은 재민 승인 없이 손대지 않는다.

### 권하는 순서

1. **합금 물성 함수만 먼저** (`specialty.js`, 순수 함수, 위험 0) — 랩에서 곡선을 눈으로 확인
2. **플레이어 주조** (배합 UI + 레시피) — econ 안 건드리고 플레이어층만으로 완결된다
3. `oreMix` **산출까지만** (`villages.js`) — econ 은 아직 `land.ore` 만 읽게 두고 병행 배치
4. econ 을 `oreMix` 로 이관 + 이산 분기 3개 제거 — **여기가 진짜 공사다. 별도 승인.**

1·2 만 해도 플레이어는 삼원 합금을 실험할 수 있고, 3까지 하면 지도가 경제에 닿기 시작한다.
4는 econ 회귀 테스트(랩 시드 전수)를 붙여야 안전하다.

# 부록 — "모든 금속을 다 되게" (재민 재질문)

> "주석·구리·납뿐만 아니라 **금·철·은 등 모든 광물**을 가능하게 하자는 거였어..
> 이래도 잘 작동하게 할 수 있어..?(이래서 3변수 함수라 했던 것)"

**된다. 그리고 조합 수만큼 일이 늘지 않는다.**

## 규모

| 방식 | 필요한 저작물 |
|---|---|
| 조합마다 곡선을 짠다 | N=8 이면 C(8,3) = **56가지** × 각각 2변수 곡면 — 불가능 |
| **원소 상수 + 물리 규칙** | 원소당 8개(반지름·구조·전기음성도·원자가·융점·경도·밀도·광택) = **64개**<br>+ 고용 한도 표 **32개**(기지 4 × 용질 8) = **96개** |

**선형으로 늘어난다.** 금속을 하나 더 넣으면 상수 8개 + 표 한 줄이지, 곡선 20개가 아니다.

## 쓰는 물리

```
① 고용 한도        각 기지에 용질이 얼마나 녹아드나 (실측 상태도)
② 고용 강화        ΔH = K · δ^(4/3) · √x        δ = 원자반지름 불일치
                   ← "합금이 순금속보다 단단한" 이유. Fleischer 근사
③ 제2상            한도를 넘으면 남는다
                     금속간화합물(Cu31Sn8 등) → 더 단단, 대신 부서진다
                     액상 분리(Cu-Pb, Cu-Fe)  → 층이 갈린다. 강도 급락
④ 공융 강하        섞으면 융점이 내려간다(혼합 엔트로피) → 주조성
```

## ⚠ 첫 시안은 실패했다 — 기록해 둔다

Hume-Rothery 4규칙만으로 고용도를 **추정**했더니:
- Cu-Sn 을 2.3%로 봤다(실제 **15.8%**) → 청동이 순동만큼 무르게 나왔다
- Cu-Fe 를 18%로 봤다(실제 **0.3%**) → **"구리 50 + 철 49"가 최적 무기**로 뽑혔다

원인: **Hume-Rothery 는 필요조건이지 충분조건이 아니다.** 실제 고용도는 혼합 엔탈피가 정하고
그건 4규칙으로 계산이 안 된다(Miedema 모형이 필요하다).
⇒ 고용 한도만 실측 표로 바꿨다. 그래도 여전히 "조합 곡선"이 아니라 **숫자 하나씩**이다.

## 그리고 층이 셋으로 깔끔하게 갈린다

모델에게 "최적 무기 배합"을 물으면 답이 세 번 바뀐다:

| 제약 | 답 | |
|---|---|---|
| 물성만 | 구리 52 · **금 46** | 물리적으로 맞다. Au-Cu 고용체는 정말 단단하다 |
| + 가격 | 구리 45 · 주석 16 · **아연 39** | 아연이 싸고 고용도가 커서 유리 |
| + **제련 가능성** | **구리 80 · 주석 16 · 은 4** | ← 실제 세형동검 Cu 74·Sn 14·Pb 11 |

- 금을 안 쓰는 건 **물성이 나빠서가 아니라 비싸서**다.
- 아연을 안 쓰는 건 **907℃에서 끓어 증발하기 때문**이다. 순수 아연 분리는 중세 인도다.
  철도 마찬가지(융점 1538℃ — 청동기 노가 못 낸다).
- ⇒ **"청동기 시대"라는 이름의 실질이 이것이다.** 시대가 배합 공간을 자른다.

세 층이 각각 다른 코드에 산다:
```
물성  = specialty.js 순수 함수 (원소 상수 + 물리)
가격  = econ 그림자 가격 (이미 있다)
시대  = 제련 가능 금속 목록 (기술 해금)
```

## 남은 보정

- 거울 최적이 Sn 59% 로 나온다(실제 34%). 거울 점수 함수가 광택 편중이다 — 연마 가능성·인성 가중 필요.
- 의기 최적이 Pb 41% 로 나온다(실제 12~13%). 납 과다에 벌점이 없다.
- 납은 **성능이 아니라 제작 가능성**이다. "주조 성공률 = f(형상 복잡도, 유동성)" 축을 넣어야
  검에도 Pb 10%가 들어가는 이유가 재현된다.

검증 스크립트: `scripts/proto-alloy.js` (실행하면 위 표가 그대로 나온다)
