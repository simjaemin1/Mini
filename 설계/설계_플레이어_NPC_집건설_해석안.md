# 백로그 "랩 쪽 플레이어 NPC 집 건설" — 해석안 + 공통 기반 정리

작성: 9차 야간(2026-07-29). **구현하지 않았다** — 항목의 정의가 코드·문서 어디에도 없어서, 규칙 §1-9(설계
판단은 구현 전에 올린다)에 따라 해석안과 재사용 지점만 정리한다.

## 0. 왜 정의부터 확인해야 했나

백로그 문구는 "랩 쪽 플레이어 NPC 집 건설" 한 줄뿐이고, 레포 문서(DESIGN_DOC/PHASE_NOTES/DEVELOPMENT_LOG/
CHECKLIST)에는 이 문구도, 대응하는 설계도 **없다**(전수 grep 0건). 랩에도 '플레이어가 짓는다'는 코드가 없다.

## 1. 지금 실재하는 것 (전수 확인)

### 랩(`~/Mini/전쟁실험실.html`) — NPC 마을 성장만 있다
| 조각 | 위치 | 내용 |
|---|---|---|
| 집터 추가 | `addHouseSite(s)` (6140행) | 영토 내 짝수격자·중심 r≥HALL_CLEAR·농지 회피·물가 페널티 K/d²·곳간 비겹침(granClear)으로 자리 선정 |
| 크루 노동 | `L_BUILDSEC=4600`(인·초/층) · `L_BUILDCAP=0.35`(일 상한) (6096행) | `h.built += max(h._crewD/L_BUILDSEC, 기본 25%)` — 현장 체류 초가 진척 |
| NPC 상태 | `a.state==='build'` (8059행) | 집터로 걸어가 머물며 짓고, 완공·황혼이면 귀가 |
| 완공 | 7928행 | `builtFloors++` → 첫 층 완공 시 `buildWalls` 재구축(콜라이더 갱신) |
| **플레이어** | 66곳 언급 전부 **전쟁 지휘 층** | 동원 비율·WASD 지휘·전투 관전. **건축 주체로서의 플레이어는 랩에 없다** |

### 본게임 — 두 경로가 따로 논다
| 경로 | 주체 | 코드 |
|---|---|---|
| 플레이어 움집 | 플레이어가 곡괭이로 터파기 → **본인이 클릭·자재로** 4단계 진행 | `tryHutStart`/`tryHutAdvance`(zone.js 4167·4207), `HUT_STAGES`(4161), `placementMode.special='hut_site'` |
| 마을 신축 | 마을 인구가 차면 자동 집터 → **NPC 크루가** 실걸음 노동 | `_lifeAddHouseSite`/`_lifeAdvanceSite`/`_lifeCompleteHouse`(villages.js), `LIFE_STAGE_PDAY`·`LIFE_CREW` |

★**교차점이 없다**: NPC 크루는 `vil._site`만 짓고, 플레이어 `hut_site`(`data.owner=playerId`)는 쳐다보지 않는다.
반대로 플레이어는 마을 신축을 도울 수 없다.

## 2. 해석안 3가지 (재민 판단 필요)

### (A) 랩에 '플레이어 주도 집터'를 넣는다 — 문구 그대로의 최소 해석
- 내용: 랩에서 사용자가 클릭으로 집터를 놓으면 그 마을 NPC 크루가 기존 규칙(L_BUILDSEC·crew)으로 짓는다.
- 장점: 새 메커니즘 0(전부 기존 조각 재사용). 랩에서 건설 속도·크루 규모를 눈으로 튜닝할 수 있다.
- 단점: 게임에 곧바로 주는 이득이 적다(게임엔 이미 플레이어 건축이 있다). 랩의 '플레이어'는 지휘 층이라
  개념이 하나 더 늘어난다.

### (B) NPC 크루가 **플레이어의 집터**를 지어 준다 — 고용/품앗이 (게임 가치가 가장 큼)
- 내용: 플레이어가 마을 영토 안에 터를 파면, 그 마을 NPC가 크루로 붙어 단계를 올린다. 대가는 자재 선납
  또는 곡물/노임(econ 무접촉 원칙상 **자재 물리 소비**가 안전).
- 규칙 4 준수: 랩에 먼저 넣는다 = 랩의 `state==='build'` 크루가 '마을 소유가 아닌 집터'도 대상으로 삼도록
  대상 선택만 일반화(진척 공식·상태머신 불변).
- 장점: "마을이 살아 있다"는 감각이 플레이어에게 직접 닿는다. 곳간②·징발과 같은 결의 물리 상호작용.
- 단점: 남의 노동을 쓰는 값(자재·시간·호감도)을 정해야 한다 — **경제 설계 판단**이 필요.

### (C) 플레이어 소유 NPC(가솔)가 짓는다
- 내용: 플레이어에게 종속된 NPC 개체를 두고 그들이 집을 짓는다.
- 문제: '소유 NPC' 개념이 랩·게임 어디에도 없다 → 신규 메커니즘 발명(규칙 4 위반 소지). 권장하지 않음.

## 3. 어느 안이든 공통으로 재사용할 지점 (발명 금지 목록)

1. **자리 선정**: 랩 `addHouseSite`의 하드 필터(영토·짝수격자·HALL_CLEAR·농지 회피·물 이격·granClear) —
   서버 `_lifeAddHouseSite`가 이미 동형 이식본이다. 플레이어 배치도 **같은 필터를 통과**해야 마을 기하가 안 깨진다.
2. **진척 규약**: 랩 `h._crewD/L_BUILDSEC`(현장 체류 초) ↔ 서버 `_lifeAdvanceSite` + `LIFE_STAGE_PDAY`.
   7차에 확인된 정합식(`min(크루, 인구) × 단계/일`)을 그대로 쓴다.
3. **단계 정의**: `HUT_STAGES`(터파기·굴립주6·도리서까래·이엉) — 8차에 **단계별 3D 스프라이트**까지 붙었다
   (`hut_s1~s3`). 어떤 안이든 시각 표현은 이미 준비돼 있다.
4. **완공 실체화**: `_lifeCompleteHouse`(집채 6×4·마당·텃밭·침대 명부) — 플레이어 집도 이 경로를 타야
   침대·마당 규약이 일관된다.
5. **크루 상태머신**: 랩 `state==='build'` / 서버 `npc._lifeTask.k==='build'`. **대상 포인터만** 확장 대상이고
   진척·귀가·야간 규칙은 건드리지 않는다.

## 4. 재민 판단 필요

1. **어느 해석인가** — (A) 랩 자체 기능 / (B) NPC가 플레이어 집을 지어 줌 / (C) 소유 NPC(비권장).
2. (B)라면 **대가 설계**: 자재 선납만? 곡물 노임? 마을 호감도? — econ 엔진 무접촉을 지키려면 자재·물리 소비가 안전.
3. (B)라면 **크루 배정 우선순위**: 마을 자체 신축 vs 플레이어 의뢰 중 무엇이 먼저인가(마을이 손해 보면 안 됨).
