# 설계안(회부) — 강제소개와 "이주 폐지"의 경계

> ## ⏸ 보류 — 소멸 0 달성 시 불필요(재민, 2026-08-02c)
>
> 재민 확정: 사람 화물 캐러밴(소개 이송)은 **소멸 0 이 달성되면 필요 없다.**
> 따라서 이 설계는 **최후 안전망**으로만 유지한다 — 구현하지 않는다.
> 되살릴 조건은 하나다: 튜닝으로 소멸 0 을 만들지 못한다는 것이 3시드 800일 실측으로 확정될 때.
>
> ★그리고 그때도 **순간이동(`npcs.pop()/push()`)은 절대 금지**다(재민 확정).
> 사람은 캐러밴 화물로, 실제 거리·시간·약탈 위험을 지나 이동해야 한다 — 그게 이 문서 §3 의 골자다.

> 2026-08-02b 배치 ⑤. **재민 승인은 났지만, 이주 폐지 결정(2026-07)과의 정합을 먼저 문서로**
> 확정한 뒤 다음 배치에서 구현한다. 이 문서가 그 정합 설계다. **구현 금지 유지.**

---

## 1. 무엇이 충돌하는가

2026-07 에 **이주(`tickMigration`)를 폐지**했다. 그 결정의 근거는 일관성 원칙이다:

> "모든 NPC = 일관된 물리 엔티티(순간이동·소멸·추상화 금지)"

`tickMigration` 은 매 틱 마을 간 인구를 **숫자로 옮기는** 함수였다. 걸어가지 않고, 길도
안 보고, 도적도 안 만난다. 그건 사람이 아니라 **엑셀 셀 이동**이다. 그래서 껐다.

`tickForceEvacuation`(economy-sim-v2.js:1338)은 **같은 방식**으로 인구를 옮긴다:

```js
while (v.npcs.length > 0) { const npc = v.npcs.pop(); target.npcs.push(npc); }
```

한 줄로 순간이동한다. 그러므로 **지금 모습 그대로 켜는 것은 이주 폐지 결정을 되돌리는 것**이다.
승인이 났다고 이 코드를 그냥 켜면 안 된다 — 켜야 하는 건 "기능"이지 "이 구현"이 아니다.

## 2. 두 개념의 경계 — 무엇이 다른가

| | 상시 이주(폐지됨) | 소멸 직전 1회 구제(승인됨) |
|---|---|---|
| 빈도 | 매 틱, 전 마을 | 마을 일생에 **한 번** |
| 계기 | 임금·기회 차이(경제적 최적화) | **죽는다**(인구 ≤4 + 척박 + 수입 미달) |
| 규모 | 조금씩 상시 | 남은 전원(1~4명) |
| 서사 | "더 나은 데로 옮긴다" | **"마을을 버리고 떠난다"** |
| 일관성 | 순간이동 = 위반 | **걸어가면 위반 아님** |

⇒ 핵심은 **빈도가 아니라 물리성**이다. 소멸 직전 구제라도 순간이동이면 위반이고,
상시 이주라도 걸어가면 위반이 아니다. 다만 상시 이주는 재민이 별도로 폐지했으므로
여기서 되살리지 않는다.

## 3. 설계 — "폐촌 행렬(abandonment caravan)"

**이미 있는 물리를 쓴다. 새 이동 개념을 만들지 않는다.**

세계에는 이미 마을 사이를 **실제로 걸어가는** 몸이 있다: 캐러밴이다.
경로(A\* · 지형 · 다리)를 타고, 며칠 걸리고, 도적을 만나고, 호위를 데려간다.
폐촌 행렬은 **화물이 사람인 캐러밴**이다.

```
조건 판정(마을 일생 1회) → 행렬 편성 → 경로 이동(캐러밴과 같은 층) → 도착 → 편입
```

### 3-1. 조건 (기존 tickForceEvacuation 술어를 그대로 살린다)

```
30일마다 · day ≥ 100 · 인구 ≤ 4 · max(fertility, water, game) ≤ 1.2
· tradeStats.foodImported ≤ N×100   (교역으로 살고 있으면 살려 둔다)
· ★추가: v._abandoned 도장이 없을 것 (일생 1회)
· ★추가: 목적지가 **경로상 도달 가능**할 것 (getRoute — 강 건너 못 가면 못 떠난다)
```

### 3-2. 목적지

기존 코드는 `인구 최대 마을`을 골랐다. 그건 사람이 아는 정보가 아니다.
⇒ **교역 상대 중** 가장 가깝고 큰 곳(이미 `_near20` 이웃 캐시가 있다). 그 마을은 실제로
오간 적이 있어서 길을 안다 — 서사도 옳다.

### 3-3. 이동 — 캐러밴 층 재사용

| 항목 | 값 | 근거 |
|---|---|---|
| 속도 | 캐러밴과 동일(`travelDays`) | 같은 다리를 건넌다 |
| 약탈 | **당한다**(`banditRouteRisk` 그대로) | 피난민이 제일 취약하다(고증) |
| 호위 | 데려갈 수 있으면(전사) 데려간다 | 기존 escort 로직 |
| 짐 | 곳간 재고 일부를 지고 간다(`CARRY` 상한) | 나머지는 폐촌에 남아 썩는다 |
| 손실 | 약탈 시 사람도 잃는다(포로/사망 — 기존 `_raidScrum` 계약) | 순간이동이 아니라는 증거 |

### 3-4. 도착

- NPC 를 목적지 `npcs` 에 편입. `counts` 캐시 무효화(기존 코드와 동일).
- 숙련은 **그대로 간다**(사람이 옮긴 것이니까).
- 출발 마을은 `_abandoned = { day, to }` 도장 + 인구 0. **건물은 남는다** — 폐허가 콘텐츠다
  (회부_마을소멸_시딩 (라) 의 세계관을 버리지 않는다).

## 4. econ 접점 목록 (구현 시 건드리는 곳 — 전부)

| # | 파일 | 함수 | 성격 |
|---|---|---|---|
| 1 | `sim/economy-sim-v2.js` | `tickForceEvacuation` | **재작성** — 즉시 이동 → 행렬 편성 |
| 2 | 〃 | `tickCaravansV2` | 화물 종류에 `people` 추가(도착 처리 분기 1곳) |
| 3 | 〃 | `tickWorldV2` | 호출 활성화(현재 주석) |

| 5 | 〃 | 캐러밴 몸 배선(`_caravanBody`) | 사람 화물 캐러밴의 시각화 — **생활층 접점** |

**회귀 위험**: 3(호출 활성화)이 전부다. 1·2 는 OFF 인 동안 죽은 코드다.
⇒ **손잡이 `FORCE_EVAC=0` 을 기본으로** 넣고, 3시드 A/B 로 켠 뒤 채택 판정.

## 5. 열린 질문 (재민 결정 필요)

1. **폐촌을 되살릴 수 있는가?** 플레이어가 폐허에 정착하면 마을이 되살아나는가, 아니면
   영원히 폐허인가. (내 의견: 되살릴 수 있어야 콘텐츠다. 다만 그건 별개 기능이다.)
2. **행렬이 약탈당해 전멸하면?** 마을도 사람도 사라진다 — 그게 맞는가.
   (내 의견: 맞다. 그게 "순간이동이 아니다"의 값이다. 다만 서버 로그엔 남겨야 한다.)
3. **목적지가 없으면?**(전부 작거나 길이 막힘) 그냥 그 자리에서 소멸하는가.
   (내 의견: 그렇다. 강제소개는 **구제 시도**지 보장이 아니다.)
4. **땅맞춤 부존 채택 후에도 필요한가?** 소멸이 6.0 → 2.7 로 줄었다. 남은 2.7 곳을 위해
   이 기계를 만들 값이 있는가 — **이게 가장 중요한 질문이다.**
   (내 의견: 지금은 값이 낮다. 폐촌 행렬은 "소멸을 막는 장치"로는 비싸고,
    **"마을이 죽는 장면을 보여 주는 장치"** 로는 값이 크다. 후자로 평가하길 권한다.)

## 6. 권고

**구현은 하되 우선순위는 낮다.** 소멸 자체는 부존 채택으로 이미 −55% 줄었고, 남은 소멸은
"나쁜 자리에 대한 세계의 정직한 판정"이라는 세계관과 충돌하지 않는다.
폐촌 행렬의 값은 **소멸을 막는 것이 아니라 소멸에 서사를 주는 것**이다 —
그 값을 인정하면 만들고, 아니면 (라)안(소멸을 그대로 수용)이 여전히 유효하다.
