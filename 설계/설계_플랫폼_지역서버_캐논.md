# 설계 — 플랫폼·지역 서버 캐논 [재민 확정 2026-09-03 · 재론 금지]

> 이 문서는 재민이 두 번 말한 것을 PM 이 처음으로 파일에 적은 것이다(이전 세션에서 한 이야기가 기록되지 않았다).
> 캐논은 §1 이다. §2 는 현황, §3 은 그 캐논이 요구하는 검증과 순서. 충돌하면 §1 이 이긴다.

## §1 캐논 (재민 확정 · 문장 그대로)

1. **26개 존 서버는 실제 그 지역에 둔다.** 유로파 존은 유럽 서버가 구동하고, 닛폰은 일본 서버가 구동한다.
   한반도 → 닛폰으로 넘어가면 **실제 위임 서버가 바뀌고**, 핑의 변화가 **실제 지리적 거리 차를 따라간다**.
   인접 서버로 넘어갈 땐 어색함이 줄고, 걸어서 중국·중동·유럽까지 넘어가면 **핑은 점진적으로 튄다**. 그것이 의도다.
   — 일관성 원칙(순간이동·소멸·추상화 금지)의 **네트워크판**: 거리는 지워지지 않는다.
2. **먼 존은 못 할 정도여도 괜찮다.** 게임이 세계적으로 퍼지면 **한국인은 한반도 서버에, 유럽인은 유로파 서버에 자연스럽게 모인다.**
   전쟁이 일어나도 **핑 제약이 과도한 팽창을 막는 제동** 역할을 한다 — 규칙 없이 지리가 국경을 만든다.
3. **브라우저에 IP 로 접속하는 지금 방식은 "플래시게임 같다".** 스팀에 올리거나(롤처럼) 전용 사이트·런처로 간다. (스팀/자체 — 결정 대기)
4. 나중엔 **26개 존 전부** 연다 · 플레이어 수용량은 지금보다 커야 한다 · 전용 DB 가 필요한지는 아래 §3.

**기각된 PM 의견**: "서버 위치는 허구의 존 국적이 아니라 실제 플레이어 위치를 따른다"(2026-09-03) — 재민이 §1-1 로 기각.

## §2 현황 (레포 실측 2026-09-03)

* 런타임 Node · `express` + `ws` · 클라는 브라우저(캔버스 + DOM 패널) · 30Hz 고정 스텝 · 예측/보정(`public/move-model.js` 공유).
* 프로세스: `server/central.js`(계정·players · `central.db`) · `server/dispatcher.js`(존 라우팅) · `server/zone.js`(존당 1프로세스 · `world-<zone>.db`) · `server/marketplace.js`.
  `scripts/launch-all.js` 가 26존 이름을 안다(`ENABLED_ZONES`). **라이브는 hanbando 단독**(Vultr 1대 · Docker + Caddy · `scripts/redeploy-hanbando.sh --central` 재민만).
* DB: **SQLite**(`node:sqlite` · `better-sqlite3`) — 존마다 파일 하나, **단일 작성자**. 전용 DB 서버 없음.
* 존 핸드오프: T47 이 몸 직렬화 함수 하나로 저장·핸드오프·재접속을 통일. 게스트 영속 토큰. 계정은 비밀번호("첫 입력 = 가입").
* 흔적: `fly.korea.toml`·`fly.japan.toml`·`fly.russia.toml` — 옛 다지역 실험. §1 방향의 첫 시도였다.

## §3 캐논이 요구하는 것 (PM · 순서)

* **신뢰성 ≠ 난이도.** §1-2 로 "300ms 에서 낚시·전투가 되나"는 검증 항목이 아니라 설계의 일부다. 남는 검증은 **끊기지 않는 것**뿐:
  300ms 급 RTT 에서 접속·핸드오프·저장·채팅이 타임아웃·재접속 경합(N.11 류)으로 **고장 나면 안 된다**. `tc netem` 지연 주입 부하 카드로 먼저 잰다.
* **팽창 제동은 방어자 우위다.** 양쪽에 사람이 있을 때 선다(저핑 쪽이 이긴다). 빈 존은 초기 유저 분포 문제지 설계 결함이 아니다.
  전쟁 층(§4 유예) 설계에 **"핑 = 보급선"** 축으로 적는다.
* **리전 매핑표.** 클라우드 DC 가 없는 존(사하라·베링·시베리아·중동 일부)은 가장 가까운 리전으로. 26존 → 실제 리전 표가 필요하고, 제공자는 **리전 수**로 고른다(AWS/GCP > Vultr).
* **클라는 웹 기술 그대로, Electron/Tauri 로 감싸 스팀에**(Vampire Survivors 선례) — 게임 코드 재작성 0 · 스팀 로그인 = "스팀 티켓 어댑터" 백로그 항목.
* **수용량은 리전·DB 가 아니라 존 프로세스 하나의 틱이 정한다**(T1·T41·T42 — 생활층 80% · RTT p95 목표 미달 잔존). 부하 실측 카드가 먼저.
* **DB.** 존 세계 상태는 단일 작성자라 SQLite 가 맞고 지역 분산과 정확히 맞는다(존 파일이 그 지역 기계에 있다). 백업은 스냅샷(Litestream 류).
  **central(계정·players·marketplace)** 은 한 리전에 두고 로그인·핸드오프 때만 닿는다 — 다중 호스트로 갈 때 Postgres. 그 시점 = 플랫폼 로그인 붙일 때 → **한 카드**.
* **순서**: 실기 "재미있다" → 소수 실플레이어 라이브(런북) + 부하·지연(신뢰성) 실측 → 리전 매핑표 → 스팀/자체 결정 + 계정 DB 이전 한 카드 → 존 추가 개방.
  지금 인프라 이전은 조기다 — 7세션이 기대는 `redeploy-hanbando.sh` 흐름까지 깨진다.
