## 1. ★★1차 판의 결함 — 캔버스는 토큰을 **조용히 버린다**

색을 토큰 하나로 모으려고 클라 전역을 훑었다. 그 판은:

```
  style.css      241 hex → var · 80 rgba → rgba(var(--x-rgb), a) · 61 모서리 → 0 · 그림자 23 삭제
  클라 JS        color 리터럴 → var(--…)   ← ★여기가 틀렸다
```

`ctx.fillStyle = 'var(--accent)'` 는 **예외를 안 던지고 콘솔에도 안 뜬다.** CSS 색으로 파싱되지
않으면 대입이 **무시**되고 앞에 칠하던 색이 그대로 남는다. 그래서:

```
  10-r1-terrain  물가 입술 두 색이 하나로      20-r2-visibility  플레이어 팔레트 8색 → 4색
  34-m-renderloop 지형 타일·사유지·마을 채움   36-r2-building    층별 색 · 문 열림 · 면 넷이 전부 한 색
  40-r2-sprites  작물 다섯 단계가 한 색        80-bigmap         지형 5색 + `_hexRgb('var(--bg)')` = NaN
  00-const       미니맵 다이아 · SITE 표 · `myColor`(= 서버로 가는 `?color=`)
```

**하네스 88개가 전부 초록이었다.** 캔버스 색은 아무 하네스도 안 재고 있었기 때문이다.
`e2e-ui ⑫`("서버로 간 색은 유효한 값이다")만 `var(--accent)` 를 물고 빨개졌는데,
그 한 줄이 없었으면 이 배치는 **부서진 세계를 초록 88/88 로 밀어 넣었을 것이다.**

### 수리 ⓐ — 색의 자리는 **둘**이고 규칙이 서로 반대다

```
  판(DOM)      값 = style.css :root 토큰 18개 하나.        색 리터럴 0
  세계(캔버스)  값 = 리터럴(#f0c674 · rgba(90,154,224,.18)).  토큰 0
```
베이스의 리터럴을 **자리별로 되돌렸다**(같은 토큰이 여러 색을 삼켰으므로 역매핑이 불가능 —
베이스 줄과 짝지어 색 조각을 순서대로 복원하는 스크립트로 59곳). 되돌린 뒤 diff 는
`10-r1-terrain` 0줄 · `20-r2-visibility` 1줄(이모지) 만 남는다 — 색 변경 0 이 증명된다.

### 수리 ⓑ — **실행으로** 잰다 (`e2e-ui ⑪ⓕ`)

소스 어림짐작(같은 줄에 `fillStyle` 이 있나)으로는 `tileColor = …` 같은 줄을 못 가른다.
⇒ 문서가 열리기 **전에** `CanvasRenderingContext2D` 의 `fillStyle`·`strokeStyle`·`shadowColor`
세터와 `CanvasGradient.addColorStop` 을 가로채, **실제로 들어간 값**을 모은다.

```
  ✓ ★★⑪ⓕ 캔버스에 들어간 색에 `var(…)` 0 — 세계 렌더는 리터럴이다   0건
  ✓ ★⑪ⓕ 자명 통과 금지 — 일부러 토큰을 넣으면 바로 잡힌다
```
여기까지 오는 동안 지형·건물·사람·전투·큰지도가 전부 여러 판 그려진 뒤의 값이다.
