## 1. ① 놓은 것 — 필드 하나와 **자리 둘**

```js
const T375_ACTIVE_FLAG = process.env.T375_ACTIVE_FLAG === '1';
let _t375Gen = 0;
function _t375Refresh(withMobs) {
  if (!T375_ACTIVE_FLAG) return;
  _t375Gen++;
  for (const p of players.values()) { p._active = isPositionActive(p.x, p.y); p._activeGen = _t375Gen; }
  if (withMobs) for (const m of mobs.values()) { m._active = isPositionActive(m.x, m.y); m._activeGen = _t375Gen; }
}
function _isActive(e) {
  return (T375_ACTIVE_FLAG && e._activeGen === _t375Gen) ? e._active : isPositionActive(e.x, e.y);
}
```

* **정본은 `activeChunkKeys` 그대로다.** 값은 **오직 `isPositionActive` 를 불러서** 채운다 — `_active` 는 사본이 아니라 그 틱의 유도다(T333 이 `WATER_TILES` 에서 비트를 유도한 그 규율).
* **★자리가 둘인 이유 — 카드의 "그 자리 뒤에 다시 계산".** 청크 집합은 틱 안에서 안 바뀌지만 **몸이 움직인다**: 결정 문·이동 문·`sepNpcs` 가 x·y 를 바꾼다. 한 번만 적으면 이동 뒤 순회 셋(계단·낙하·HP)이 **이동 전 답**을 본다. ⇒ 틱 머리(`updateActiveChunks()` 직후 · 주민만 — 이 갱신을 쓰는 건 바로 아래 공간 인덱스 하나뿐) · 이동 문 직후(주민+몹).
* **세대(`_activeGen`)** — 새로 고친 뒤에 들어온 몸(접속·스폰·핸드오프)은 세대가 달라 읽는 쪽이 **자동으로 종전 길로 떨어진다**. "빠뜨린 몸" 이 원리상 없다.
* 읽는 자리는 **다섯**: `rebuildSpatialIndex`(주민) · `stepStairFor`(몹) · `processFalling`(주민·몹) · HP 회복(주민). **결정 문·이동 문·진단의 `isPositionActive` 는 안 만졌다**(카드 밖).
* **`stairCellCache` 문자열 키 · 순회 넷 한 바퀴로 합치기 — 둘 다 안 했다**(카드 지정 · §4 회부).

* ★**계측기는 `git worktree add --detach HEAD` 로 사본을 뜬다** — 재기 전에 **먼저 커밋해야** 잰다. 첫 판에서 안 커밋된 제품을 잴 뻔했다(앉히고 다시 돌렸다). 계측기 머리에 적어 둘 일이다.
