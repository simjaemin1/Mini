* 야간 10-26 "첫 갈림 날 64"는 그 밤 상자에서 날 뜀 ≈ 58(≈ 15초)이었다는 뜻이다.

### 기전 — 진단 존 로그(같은 저장 판 · 묶은 상자)

```
[T731] 현지 자정 정산 — … econ 날 6
[T728] 재기동 영속 — 마을 곁 칸 51 · 메타 날 3 ≠ econ 날 6 — 번호만 앞으로(…) · 날 뜀 2799(econ 날 3 → 2805 …)
```

1. `_t728Restore` ⑥(재민 10-14 캐논 "멈춘 동안의 시간은 따라잡지 않고 버린다")은 econ 날을 셈한다.
   * 식: `앵커 날 + (지금 벽시계 날 − 앵커 벽시계 날 g)`
   * 벽시계 날 하나 = `VILLAGE_DAY_MS` 250ms 다.
   * 하네스는 끔 · 켬 두 판을 `Promise.all` 로 나란히 띄운다. 그래도 부팅이 그 줄에 닿는 순간은 판마다 다르다(묶은 상자에서 수 초~수십 초 차이). 그래서 **두 판이 다른 날로 뛴다.** 날이 다르면 그 뒤 곳간 · 사람 지문이 다 갈린다.
2. 앵커(메타 행)는 **저장 큐가 다 빈 순간**에만 적힌다(`_t728SaveMeta` — 마을 51행을 한 틱에 하나씩).
   * 빠른 상자: 하루(250ms)마다 큐가 다시 차서 6날 안에 한 번도 안 빈다. 메타 행 0 → 날 뜀 0 → 종전 초록.
   * 느린 상자: 하루 마감이 수 초라 그 사이 큐가 빈다. 메타 행이 남는다(날 3) → 날 뜀 → 빨강.
   * 새 저장 6판의 메타 유무 = 초록/빨강과 **6/6 맞는다.**
3. 제품은 캐논대로 돈다. 운영에서 재기동은 실제로 시간이 흐른 뒤이고, 그 시간은 버린다. 하네스가 재는 것은 "같은 DB 로 이어 돌면 끔 = 켬"인데, 벽시계가 그 사이에 끼었다.

### 고침 — 하네스 탐침(`scripts/test-econ-fast.js` PROBE 글자) 한 덩이

```js
let _bootAt = null;   // 저장 DB 에 T728 메타 행이 있으면 = epoch + g × 하루(앵커의 벽시계 날 경계)
… const a = m && JSON.parse(m.data).anchor; if (a && Number.isFinite(a.g) && a.dayMs > 0) _bootAt = (a.epoch || 0) + a.g * a.dayMs;
Vm.init = function () { const _dn = Date.now; if (_bootAt != null) Date.now = () => _bootAt;
  let r; try { r = init0.apply(this, arguments); } finally { Date.now = _dn; }   // 부팅 동안만
```

* 세운 시계면 "지난 벽시계 날 = 0"이다. 두 판이 다 **안 뛴다.** 메타 행이 없는 판(종전 초록 판)과 같은 뜻이 된다: 저장한 날에서 바로 이어 돈다.
* 부팅이 끝나면 진짜 시계로 돌아간다(첫 틱부터 종전).
* 메타 행이 없으면 아무것도 안 한다. 종전 글자 그대로다. 새 세계 판(③ 전쟁 판)은 DB 가 없으니 늘 그 갈래다.
* **견줌은 통째 그대로다.** 30날 · 지문 · 여덟 수 · 사전 모드 줄 모두 무변이다.
* ⚠처음에는 앵커 순간(`anchor.at`)에 세웠다. 그 판은 날 뜀 5로 12..40(29날)이 되어 `≥ 30` 줄에 걸렸다. 그래서 앵커 **날 경계**(`g × 하루`)로 바꿨다(날 뜀 0 · 7..40 34날).

## §2 `e2e-fishing` "★★대조군 — 얼린 화면은 거의 안 움직인다" — 대조군에 비가 내린다

### 재현

* 묶은 상자 20판 중 **15판 빨강**이다. 대조군은 1,343~1,730px 였다.
* 1~5판은 0px 초록이다. 빨강은 6~20판(03:34~03:52)에 **이어서** 났다. 상자 부하는 1~20판 내내 같았다. 판이 아니라 **시각**이 가른 것이다.
* 대조군 두 장의 차이 그림은 **빗줄기**다(화면 전체에 사선 획). 맑은 판(1판)은 HUD 글자만 다르다(판정 상자 밖).
* 야간
  * 10-25: 319px
  * 10-28: 263px, 그리고 **단독 재실행도** 338px 빨강. 그 밤 비 오는 시각에 다시 돈 판이다.
  * "단독이면 초록"이 늘 맞지 않는 까닭이 이것이다.

### 기전

* 이 하네스는 시계를 얼리지 않는다(머리 주석: 시간이 주제다).
* 존 날씨(`myWeather.precip`)는 실시간 게임 날짜를 따른다.
* ⑦ 은 `freezeT` 로 물결만 세우고 대조군 A · B 를 찍는다. 그 **뒤**, C 바로 앞에서야 `__rainForce({ precip: 0 })` · `windOff` 를 켰다.
  * 그 시각에 비가 오면 A · B 에 빗줄기가 남았다.
  * 또 `windOff`(풀 텍스처를 종전 선명한 꼴로)가 **C 에만** 걸렸다. 그래서 종전 "던진 뒤" 화소(2,686~6,774px)의 대부분은 찌가 아니라 풀 텍스처 차이였다.

### 고침

* 같은 두 줄(`__rainForce({ precip: 0 })` · `windOff = true`)을 `froze` 바로 다음, **대조군 앞으로 옮겼다**. 이제 세 장이 같은 하늘 · 같은 풀이다.
* 문턱 · 판정 상자 · 판정은 그대로다.
* 덧(같은 판에서 드러남): ② 던짐 기다림의 끝이 "31번 물어 안 던져졌으면 그만"(≈1.6초)이었다. 고친 뒤 첫 판본 4판 중 1판이 ② 넷 빨강(던짐 null)이었다. 그래서 **시간 상한 10초**(안전망)로 바꿨다. 던져지면 그 순간부터 종전이다.

### 고침 — 기다림 조건(판정 조건이 설 때까지 · 상한 15초 = 안전망 · 고정 대기는 최소로 그대로 둠)

1. ① 끝: R 짐(`inventory.meat_cooked`)에 고기가 보일 때까지.
2. ③: 알림 "먹였다" + A 허기 오름(> 1)이 설 때까지. C(미끼)는 기다린다고 오르지 않으니 ★★★ 줄은 더 엄해진다.
3. ⑦: 바닥 물건이 R 묶음(`groundItems`)에 보일 때까지.
4. ⑬ 거래: 거래소 탭 열림 + 시세 답(`__tradeBoard`)이 올 때까지.
5. ⑬ 게이트 밖: `__evNearVid` 가 비워질 때까지.
6. ⑧ "멎은 뒤엔 메뉴가 멈추기라고 안 한다":
   * 문제: 메뉴(`l2`)는 멎기 **전에** 열린 것일 수 있다. 고친 뒤 첫 판본 1판이 `["벌목 멈추기", …]` 로 빨갰다.
   * 고침: 그 메뉴가 "멈추기"였으면 멎은 것을 본 **뒤** 메뉴를 한 번 더 연다(`tapUntilMenu` 상한 5초).
* 단언 글자 · 판정은 무변이다. `test-harness-lint` 68/0 · `test-e2e-src`(T964) 76/0.
