## §1 만든 것 — 접근자 하나 · 곱 하나 · 수 하나

```
server/wind.js   coverAt(x, y) → cellTerms(⌊x/32⌋, ⌊y/32⌋).fsh      // 그대로. 계수 안 곱한다
server/body.js   COVER_MAX 0.22 (BODY_COVER_MAX) · COVER_ON (T114_COVER)
                 coverMult(cover) = 1 − clamp(cover)·COVER_MAX      // wetMult 와 같은 모양
                 wetStep: pr *= coverMult(c.cover)                  // ★한 줄
server/zone.js   coverOf(p) → Wind.coverAt(p.x, p.y)                // 전달만. 계수 모른다
                 Body.tick ctx 에 cover · weatherFor 응답에 cover
public/client/44-h-hud.js   ` · 나무 아래`  (precip > 0.01 && cover > 0.15)
```

**새 수는 `COVER_MAX` 하나뿐이다.** `T114_COVER` 는 되돌림 손잡이지 수가 아니다.
문턱 둘(0.01 · 0.15)은 **마을 낱말이 이미 쓰던 눈금을 빌린 것**이지 새로 잰 값이 아니다(→ 회부 5②).

★**계수를 `wind.js` 에 안 뒀다.** 접근자는 "숲이 얼마나 빽빽한가"만 낸다.
"그 빽빽함이 비를 얼마나 막는가"는 **쓰는 축이 소유한다** — 그래서 바람은 `1 − FOREST_W·fsh`,
젖음은 `1 − COVER_MAX·fsh`. 같은 정본 하나에 축마다 제 계수를 곱하는 것, 그게 사본 0 의 모양이다.
하네스가 `wind.js` 에 강수 계수가 **없음**을 못 박는다(`⑳ⓓ3`).

1. 비 오는 날 숲으로 들어가면 덜 젖는가 — HUD 배지에 ` · 나무 아래` 가 뜨고, 흠뻑 젖은 상태에서
   숲에 오래 있으면 젖음이 **광장 바닥(비 세기)보다 22% 낮은 자리까지** 마른다.
2. 마을 광장에선 그대로 젖는가 — **트인 광장이면 그렇다.** 다만 **임업 마을 여섯은 숲 안**이라
   광장에서도 ` · 나무 아래` 가 뜬다(§0-ⓐ). 그건 결함이 아니라 그 마을이 실제로 숲 안에 있다는 뜻이다.
