1. **추측이 맞았다 — 그리고 사건 순서가 그걸 그대로 보여 줬다.** `mouseleave(0)` 가 `_aimOff` 를 부른다.
2. **그보다 나쁜 것도 같이 나왔다**: 패널 위로 끌면 **`pointerup` 이 캔버스에 아예 안 온다**(패널이 가져간다). 즉 `mouseleave` 를 지우기만 해서는 **뗀 줄도 모르는** 조준이 남았을 것이다.
3. ⇒ **포인터 캡처가 둘을 한꺼번에 푼다.** 누른 순간 캔버스가 포인터를 잡으면 밖으로 나가도 모든 사건이 캔버스로 온다.
4. **`mouseleave` 리스너는 지웠다**(그게 끄던 유일한 이유였다). **`blur` 는 남겼다** — 탭이 바뀌면 풀리는 게 맞고 캡처는 창을 못 넘는다.
5. **캡처는 반드시 돌려준다**(`releasePointerCapture`) — 안 돌려주면 다음 클릭이 캔버스에 묶인다. `pointercancel` 도 같은 길로 푼다.
6. ⚠**첫 판이 동사 메뉴를 죽였다 — 자가 못 잡았다.** `pointerdown` 에 `preventDefault()` 를 걸었더니 브라우저가 **호환 마우스 사건을 아예 안 만들었다**(`mousedown(2)`·`mouseup(2)` 이 로그에서 통째로 사라졌다).

## ⓐ 무엇이 범인이었나

```js
canvas.addEventListener('mouseleave', _aimOff);   // ← 이 한 줄
```

패널(HUD·미니맵·사이드)은 **캔버스 위에 덮인 DOM** 이다. 포인터가 그 위로 가면 캔버스는 `mouseleave` 를 받고, 그 줄이 조준을 끈다 — 카메라가 제자리로 돌아온다. 창 밖도 같다.

**한 겹 더 있었다**: 패널 위에서 손을 떼면 `pointerup`/`mouseup` 이 **패널로 가고 캔버스엔 안 온다**(ⓐ 의 고치기 전 로그가 `mouseleave(0)` 에서 끊긴다). `mouseleave` 만 지웠다면 조준이 켜진 채로 **떼어도 안 꺼지는** 상태가 됐을 것이다. 캡처가 그 둘을 한꺼번에 푼다.

## ⓑ 고침

```js
canvas.addEventListener('pointerdown', (e) => {
  if (e.button !== 2) return;
  _aiming = true;
  try { canvas.setPointerCapture(e.pointerId); } catch (err) {}
  // ⚠여기서 preventDefault 를 부르면 호환 마우스 사건이 사라진다(아래 ⓒ)
});
const _aimRelease = (e) => { /* 캡처 반납 + _aimOff */ };
canvas.addEventListener('pointerup', (e) => { if (e.button === 2) _aimRelease(e); });
canvas.addEventListener('pointercancel', _aimRelease);
canvas.addEventListener('mouseup', (e) => { if (e.button === 2) _aimOff(); });  // 캡처 없는 판의 뒷길
// mouseleave 리스너 — 지웠다
window.addEventListener('blur', _aimOff);                                       // 탭 전환은 풀린다(맞다)
```

**조준 중 패널 클릭은?** 캡처 중이라 좌클릭도 캔버스로 간다 = **조준 중 좌클릭 = 공격**이 의도대로 산다(조준 중엔 패널을 누를 일이 없다). 캡처는 **떼는 순간 끝난다**(`lostpointercapture`) — 평소 패널 조작은 무변.

1차 고침은 **조준 단언을 전부 통과했다**(12/0). 메뉴가 죽은 것은 **사건 로그를 눈으로 보고** 알았다 — `mousedown(2)`·`mouseup(2)` 이 통째로 사라진 것을 보고. ⇒ 그 자리를 `ⓓ-2` 단언으로 못 박았다: **호환 사건이 로그에 있어야 한다.**
