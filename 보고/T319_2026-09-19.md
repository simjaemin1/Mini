| 차례 | 쓰기 | 언제 |

## 1. §0-ⓑ ② `?as=` — `DEV_AS` 뒤로

### 무엇이 열려 있었나

`server/onboarding.js:906 httpStartInfo` 가 `?as=<이름>` 을 받아 `friendVidsByName`·`memberVidByName` 을 태워 준다.
**열쇠 없이 이름만으로** 남의 벗 마을과 소속 마을이 읽혔다. 그 주석이 이미 알고 있었다:

> *"게스트 토큰으로 물으면 안 된다(그건 열쇠다) ⇒ 이름으로 묻고 세는 건 서버가 한다."*

열쇠를 피하려다 **이름이 열쇠**가 됐다. T310 이 라우트 정본에서 그 줄이 `공개·회부9` 임을 확인했고(T245 가 닫은 적이 없다),
이번 카드가 재민 결정으로 닫는다.

### 어디를 고쳤나 — **문 하나 · 한 칸**

```js
// server/zone.js — 라우트 한 줄
if (req.url && req.url.startsWith('/startinfo') && req.method === 'GET')
  return Onboarding.httpStartInfo(_devAsGate(req), res);

// 그 겹 — `as` 한 칸만 지운 url 을 가진 얇은 겹(Object.create(req))
function _devAsOn()   { return process.env.DEV_AS === '1'; }   // ★부를 때 읽는다(T88·T121)
function _devAsGate(req) { … }
```

| 규약 | 어떻게 |
|---|---|
| **문은 그대로 공개** | 막은 것은 `?as=` **한 칸**. `/startinfo` 는 두 판 다 **200**(실측 ⓔ7) · 시작 화면 그대로 뜬다 |
| **`onboarding.js` 무접촉** | 정책은 **문에서** 정한다. 온보딩은 제 일(시작 화면 조립)만 한다 — 0 줄 변경 |
| **62 라우트 무변** | 갈래는 `공개` 그대로 · 판정만 `회부9` → `닫힘DEV_AS` ⇒ **남음 2 → 1 · 회부됨 2 → 1** |
| **다른 칸은 안 건드린다** | `?as=x&z=1` → `?z=1` (실측 ⓔ5) · `as` 가 없던 요청은 **한 글자도** 안 달라진다(ⓔ6) |
| **부를 때 읽는다** | 모듈 상수면 손잡이 하나 보려고 존을 한 판 더 띄워야 한다 |

### 두 팔 — 실측

```
ⓔ4 DEV_AS=1  /startinfo?as=%EC%9E%AC%EB%AF%BC  → 그대로      · ?as=x&z=1 → 그대로
ⓔ5 (없음)    /startinfo?as=%EC%9E%AC%EB%AF%BC  → /startinfo · ?as=x&z=1 → ?z=1
ⓔ6b 자명 통과 금지 — 두 팔이 실제로 다른 값을 낸다(손잡이가 부를 때 읽힌다)
ⓔ7 /startinfo 두 판 다 200 — 공개 문 그대로
```

### 그 칸을 **쓰는** 하네스 셋은 손잡이를 켜고 띄운다

`e2e-friends`·`e2e-guild`·`e2e-onboarding` 이 `?as=` 를 쓴다. 셋의 존 기동 env 에 `DEV_AS: '1'` 한 줄을 넣었다 —
**켜야 그 검사가 성립하고, 안 켜면 조용히 자명 통과가 아니라 빨개진다**(그게 맞는 신호다).
실측: `e2e-guild ⑦g` *"`startInfo?as=<이름>` 이 그 사람의 소속을 답한다"* → **1**(97/0) · `e2e-friends` 93/0.

## 2. §0-ⓒ ③ `/health` 칸 둘

T310 의 결론: `/perf` 는 **안 문**(T225)이라 바깥에서 못 읽고, 그 때문에 *"마을이 몇 곳 살아 있나 · 틱이 얼마나 걸리나"* 도
같이 안 보였다. ⇒ **그 둘만** 바깥 판으로 낸다. 나머지 `/perf` 는 안 문 그대로다.

| 칸 | 어디서 오나 | 왜 그렇게 |
|---|---|---|
| `villages` | `SimVillages.clientVillages()` 에서 `pop > 0` 인 곳을 **센다** | 존이 **이미 클라에 보내는 그 목록**이다(인구는 하루 틱이 갱신). 목록을 여기서 다시 만들지 않는다 — 사본 0 |
| `tickP50Ms` | `_tickMsStats(false).p50` — `/perf` 의 `tick.ms.p50` 과 **같은 함수** | p50 을 두 벌로 짜면 그게 사본이고, 언젠가 갈린다 |

### 규약 넷

1. **수만 낸다**(T225 투영). 마을 이름·좌표·id·열쇠 칸이 **한 개도** 없다 — 하네스가 정규식으로 문다(ⓕ4).
2. **영점 조정을 안 한다**(`_tickMsStats(false)`). 안부를 묻는 일이 계측 창을 지우면 안 된다(ⓕ6·ⓕ9b).
3. **없으면 `null`, 0 이 아니다.** 마을 층이 안 서면 `villages: null` — `0` 은 *"다 죽었다"* 는 거짓말이다(ⓕ2).
4. ★**표본이 0 이면 `tickP50Ms` 도 `null`.**

### ★넷째가 이 카드에서 한 판단

`_tickMsStats` 는 빈 창에서 `p50: 0` 을 낸다. `/perf` 는 `n` 을 같이 실어 주니 읽는 쪽이 *"표본이 없다"* 를 안다.
`/health` 엔 그 칸이 없다 — 그대로 `0` 을 내보내면 **틱이 0ms 라는 없는 말**이 된다.
실측이 그 자리를 보여 줬다(마을 50곳이 도는 판인데도):

```
HEALTH  … "villages":50, "tickP50Ms":0 …        ← 고치기 전
PERF    tick.ms {"n":0,"p50":0,"p95":0,"max":0} ← 표본이 0 이다(한가한 존은 본문 없이 조기 반환한다)
```

⇒ **수를 새로 짓는 게 아니라 없는 수를 말하지 않는다.** `villages` 의 `null` 과 같은 뜻이다.
하네스도 그 기준으로 대조한다: `n === 0` 이면 `/health` 가 `null` 이어야 하고, 아니면 **같은 수**여야 한다(ⓕ9).

### 실측 — 마을 층을 켠 판

```
{"zone":"hanbando","players":400,"humans":0,"cap":150,"observers":0,"resources":0,
 "buildings":2153,"mobs":449,"claims":0,"villages":50,"tickP50Ms":…,"latency_ms":0,"uptime":408.0}
```

`villages: 50` — **정수다**(null 갈래가 자명 통과가 아니다). 옛 칸 열하나는 **그대로**다(더한 것이지 갈아치운 게 아니다 · ⓕ8).
