## 1. §0 재실측 — 지시서와 다른 게 셋

| 항목 | 지시서 전제 | 실측 |
|---|---|---|
| IIFE 개수 | 둘 | **셋** — 소형 `preloadCropSprites`(L32–L40)가 앞에 하나 더 |
| IIFE-1 | L56–L15245 | 같음. 본문 15,188줄 · 깊이1 선언 **822**(function 301 · let/const 521 · var **0**) |
| IIFE-2 | L15250–L15945 | 같음. 깊이1 선언 48(function 18 · let/const 30) |
| 진짜 최상위 | 13문장 | 같음 = 선언·문장 10 + IIFE 호출문 3 |
| ⓑ 충돌 | 0 | **0** — 다른 classic 스크립트 최상위 60 · 진짜 최상위 9 · **실제 Chromium 전역 964** · 자기 중복 |
| ⓒ IIFE-1 ∩ IIFE-2 | (미상) | ★**2개 — `canvas`, `ctx`** |
| ⓓ `var` | 목록만 | **0개** |
| ⓔ 암묵 전역 | 목록만 | **1개 — `needsRedraw`** |

**ⓒ 가 이 배치에서 가장 값진 실측이다.** 지시서는 "겹침이 0 이어도 IIFE-2 를 감싼 채 둬라"고 했는데
실제로 0 이 아니었다. 둘을 한 스코프로 합쳤으면 `let` 중복 = **SyntaxError** 로 페이지가 통째로 안 뜬다.
껍데기 유지 판단이 예방이 아니라 **필수**였음이 숫자로 확인됐다.

### 껍데기 제거로 달라지는 것 / 안 달라지는 것

| | |
|---|---|
| **달라진다** | `function` 선언 **301개**가 `window` 프로퍼티가 된다 |
| **안 달라진다** | `let/const` 521개 — 전역 렉시컬이라 `window` 에 안 붙는다 |
| **안 달라진다** | `var` 0개 — 승격 대상이 아예 없다 |
| **안 달라진다** | `this` — 화살표 IIFE 라 전후 모두 `window` |
| **안 달라진다** | `'use strict'` 없음 → strict 전환 없음 |
| **안 달라진다** | 암묵 전역 `needsRedraw` — 선언이 IIFE-1 에 없으니 전후 모두 `window.needsRedraw` |

### ★지시서 ⓐ~ⓔ 에 없던 위험 둘 — 재서 찾았다

껍데기 제거의 진짜 위험은 "이름이 window 에 붙는다"가 아니라
**"지금까지 IIFE-2 가 못 보던 822개 이름이 갑자기 보인다"** 였다.

* **위험 ①** IIFE-2 의 자유 식별자 16개 중 IIFE-1 이 선언하는 것 **1개 = `conns`**.
  IIFE-1 이 `const conns = new Map()`(L5749)로 선언하고 `window.conns` 대입은 **없다**.
  IIFE-2 의 사용처는 L15828 한 곳 —
  `if (window._rN >= 30) { if (window._renderDbg) { … for (const c of conns.values()) … } }`
  ⇒ **오늘까지 그 줄은 `ReferenceError` 를 던졌다**(`_renderDbg` 를 켜면 미니맵 계측이 죽는다).
  제거 후 정상 해석된다. 평상시엔 그 플래그가 꺼져 있어 관측 가능한 차이가 없다.
  **재민 허용 — 기록만.**
* **위험 ②** IIFE-1 **앞**(L5–55) 코드가 그 이름들을 쓰면 전역 렉시컬 TDZ 로 죽는다. 실측 **0개**.

### `needsRedraw` — 회부 유지 (고치지 않았다)

IIFE-1 에서 **32회 전부 대입, 읽기 0**. 읽는 곳은 IIFE-2 의 자기 `let`(L15703)뿐이다.
두 클로저가 **이름만 같고 다른 변수**다 — IIFE-1 의 32회는 아무도 안 읽는 `window` 프로퍼티에 쓰고 있다.
껍데기 제거로 달라지지 않는다(선언이 IIFE-1 에 없으므로). **재민 지시대로 손대지 않았다.**

  껍데기 제거 전            13건       0    동일            ─

**대조군이 결론을 냈다.** 아무것도 안 바꾼 두 실행이 변경 전후보다 더 다르다 ⇒ 관측된 차이는 전부
실행 간 잡음이고 껍데기 제거는 그 바닥 아래다. 콘솔 문구 차이도 같은 성격이었다 —
`welcome 처리 20ms↔25ms`(타이밍)와 GPU 컨텍스트 id. 같은 빌드 쌍에서도 똑같이 난다.

★**이 대조군이 없었으면 "0.03% 다르니 뭔가 바뀌었다"고 잘못 읽었을 자리다.** 살아 있는 세계
(NPC·게임일·연출)를 상대로 픽셀 diff 를 절대값으로 읽으면 **없는 회귀를 본다.**

## 4. 검사기 둘 — 자기가 실패할 줄 아는 것을 먼저 보였다

```
  bash scripts/split-verify.sh              → identical
  bash scripts/split-verify.sh --selftest   → 조각의 `const` 한 글자를 바꾸면 differ (확인 후 원복)
  node scripts/test-client-globals.js       → 12/0
     픽스처: 두 조각에 같은 `const` → ① 이 잡음 · `function open(){}` → ② 가 잡음
             99-main 밖 최상위 실행문 → ③ 이 잡음 · ★깨끗한 픽스처는 통과(항상 실패 아님)
```

★**결합 검사기가 처음 두 번 틀렸고 둘 다 「끝 개행」이었다.** ⓐ 조각마다 `split('\n')` 이 남기는
인공 빈칸을 실제 줄로 세어 조각 수만큼 빈 줄이 섞였다 ⓑ 분할기도 같은 이유로 마지막 조각에
없는 빈 줄을 하나 만들었다. **결합 diff 가 아니었으면 둘 다 조용히 지나갔다** —
그리고 그 상태로 배포됐다면 원인을 찾기 매우 어려웠을 것이다.

★`split-verify.sh` 는 조각 **순서를 자기가 적지 않고 `index.html` 에서 읽는다.** 적으면 두 정본이 된다.

★그리고 **정본 커밋 해시도 안 박는다.** 처음엔 `BASE=95c873c` 로 박아 뒀는데, 푸시 직전
리베이스로 그 해시가 바뀌었다. 로컬엔 옛 객체가 dangling 으로 남아 **검사기가 그대로 통과했고**,
새 클론에서만 죽었을 것이다. ⇒ `public/client.js` 를 **지운 커밋의 부모**를 스스로 찾게 고쳤다.
(해시를 박은 검사기는 리베이스 한 번에 조용히 거짓말쟁이가 된다)

`scripts/client-src.js` — 클라 소스를 문자열로 읽던 하네스 11개를 한 곳으로 모았다(사본 금지).
반환값이 분할 전 정본과 **바이트 동일**함을 확인.
