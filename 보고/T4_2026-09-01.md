## 2. 작업 ① — 바람 노출 모델 (재민 확정 ④)

`server/wind.js` (신설 · 순수 모듈 · 지형은 **주입**).

```
  X(셀, 날) = |s| · 풍상 트임 · 풍하 막힘 · (1 − 0.75·숲) · (1 − 마을 완충)      ∈ [0, 1]
  합성      t *= (1 + 0.6 · X)                                                ← 항 하나
```

* **계절 탁월풍** `s(day)`: 최한일 +1(북서풍) · 최난일 −1(남동풍) · 봄가을 0.
  두 방향이 **정확히 반대**라 각도 보간이 성립하지 않아, 방향이 아니라 **부호 붙은 세기**로 이었다.
  |s|=0 을 지나므로 뒤집히는 순간에도 X=0 ⇒ 계단이 없다(실측 최대 도약 **0.0086 / 0.5일**).
  s 는 econ 연주기 코사인 **그 자체**의 정규화라 `wind.js` 에 날짜 상수가 **0개**다.
* **기울기 대신 레이 둘**: 1,600px 를 10표본, 가중 `1/i`. 부호가 저절로 맞는다 —
  평지 0 · 풍하 기슭 0 · 골 0 · 풍상 기슭 큼.
* **평지 = 0 앵커**: 노출은 더하기만 한다. 그래서 기존 기준선이 보존된다(하네스가 항등으로 확인).
* **마을 이중 적용 금지**: 마을은 감액을 새로 만들지 않고 X 를 사그라뜨린다. 한복판이면 X=0 →
  노출 항이 **정확히 ×1** → 추위를 깎는 일은 종전 `COLD_VILLAGE_SHELTER` 한 곳 몫 그대로.
* **고도 감률과 독립**: 감률은 `outdoor` 안에서 ℃ 로 걸리고, 노출은 그 결과를 배율로 키운다.
  노출을 켜도 고도 스윕은 여전히 단조다(1.4845 → 2.1085).

**비용 — 틱 0**
```
  새 셀 689µs  ·  캐시 적중 **0.55µs**  ·  걸어서 하루(24분·초당 2셀) ≈ 1.98초 CPU, 그 뒤로는 0
  ★셀 캐시는 계절과 무관한 몫만 담는다({bNW, bSE, fsh} 셋) — 날이 바뀌어도 캐시가 안 죽는다.
  `/perf` 표식 `wind_exposure`(≥5ms 일 때만 · 실측으론 안 찍힌다).
```

## 3. 작업 ② — 삼베옷 하향 (재민 확정 ⑤)

**데이터 한 줄** — `player-items.js CLOTH_WARMTH_CAP`(env `CLOTH_WARMTH_CAP_FIBER`, 채택 **26**).
`q`(품질)는 그대로라 내구·가격·판매 넛지·이름이 전부 불변이고 **방한만** 천장에 눌린다.

* **왜 `MAT_GRADE` 가 아닌가**: econ `CLOTH_Q_MAT` 과 **동일값 계약**이라 = econ 수정.
* **왜 배율이 아니라 상한인가**: 배율이면 조잡 베옷 15 → 10 아래로 떨어져 `WARMTH_MIN` 문턱에서
  **단열 0** = 사다리 첫 칸이 사라진다. 상한은 아랫칸을 두고 윗칸만 자른다.
  고증도 이쪽 — 삼베·모시는 통기성 좋은 여름 옷이라 솜씨가 늘면 곱고 질겨지지 **따뜻해지지 않는다**.
* **왜 삼만이 아니라 식물 섬유 전부인가**: 삼만 막으면 장인이 **모시**로 옮겨 56(갖옷보다 높다)이 되어
  **고친 게 없어진다.** 같은 물성은 같은 천장을 받는다.

```
  방한 (Lv0/5/10)   삼베 15/26/26 · 모시 22/26/26 · 가죽 21/37/53 · 모피 25/43/62
  ⇒ 삼베 ≤ 가죽 < 모피 **전 구간 단조** · 아무리 잘 짜도 26 < 37
```
