## §1 재 보니 — 주기 저장은 한 마리도 안 적었다(카드의 전제를 고친다)

* **T954 회부 2 의 전제가 틀렸다(내가 적었다)** — "화살만 저장 표를 안 세운다(사람 공격 · NPC · 먹이는 세운다) → 화살만 맞은 몹은 주기 저장이 안 적는다"고 했지만, 저장 표를 읽는 쪽(주기 저장 — mx `zone.js` 4770 ~ 4783)이 죽어 있었다:
  * 그 글자 `const txn = db.db.transaction(() => { … }); txn();` — `db.db` 는 node:sqlite `DatabaseSync`(zone-local-db.js 23 · 운영 `node:22-alpine` · 이 상자 `v22.23.4`) · `DatabaseSync` 에는 `transaction` 이 없다(`typeof db.db.transaction === 'undefined'`) → TypeError → `catch (e) { /* lock 잡혔으면 다음 라운드 */ }` 가 조용히 삼킨다 → 10초마다 그렇게 돈다.
  * 들어온 커밋 `3e03fabb`(2026-06-25 "mob저장 트랜잭션(이벤트루프 블록 제거)") — better-sqlite3 꼴 글자다. 그 앞은 표마다 따로 썼다(그래서 고쳤다는데 그 뒤로 0).
  * 실측(탐침 — 존 한 프로세스 · 몹 하나 hp −3 · 표 세움 · 11초): 끔 = DB hp 100 그대로 · 표 `true` 그대로 · 저장 줄 0 / 켬 = DB hp 97 · 표 `false` · 저장 줄 1.
* **그래서 지금 운영에서 몹 상태(자리 · hp · 길들임)가 DB 에 닿는 길은 종료 flush 하나다**(낳기 · 죽음 행은 따로 — `insertMob` · `deleteMob`) — `_shutdownFlush`(SIGTERM · SIGINT)가 표와 상관없이 몹 전부를 적는다(zone.js 16175 `db.updateMobState(m.dbId, m.x, m.y, m.hp)`). ⇒ 우아한 재기동(배포 `docker stop`)이면 화살 피해도 남고, SIGKILL(메모리 부족 · `docker kill` · 호스트 재부팅 · 정지 한도 넘김)이면 **갈래를 가리지 않고** 마지막 우아한 종료 뒤의 몹 hp · 자리 · 길들임이 다 사라진다.
* **⇒ 카드 ① 의 화살 저장 표는 주기 저장 없이는 아무 일도 안 한다** — 그래서 같은 손잡이(`T967_MOB_HP`)에 주기 저장 고침을 넣었다(판정이 아니라 카드 ② "켬 초록"이 서는 유일한 길 · 주석과 이름이 말하던 일 · `=0` 이면 종전 그대로). 이 묶음이 맞는지는 회부 ①.
* 주기 저장 켬의 무게 — 몹 전부(303마리 · 존 부팅이 낳은 그대로)에 표를 세우고 한 번 적은 시간 0.7 ~ 0.8ms(재기동 하네스 두 판 · 트랜잭션 하나 — 종전 주석의 "표마다 따로 쓰기 → 수십~수백 ms 막힘"은 트랜잭션이 없던 때 얘기). 운영에서는 움직인 몹(한 틱 2px 넘게)이 표를 세운다 — 10초마다 그만큼 · 로그 한 줄 `mob 상태 저장 N건 (txn)`(종전엔 한 번도 안 찍혔다).

## §2 ③ 그림자 하한 1 · 먹이 상한 maxHp — 뜻(안 바꿈)

* **그림자 하한 1**(wildlife.js 795 `Math.max(1, Math.round(lm.hp × 10))`) — **뜻 있음**: 랩 hp 가 정본이고 랩의 죽음은 `lm.hp <= 0` 이다. 랩에서 살아 있는 짐승(0 < `lm.hp` < 0.05)도 ×10 반올림이면 0 이 되는데, 존은 hp 0 몹을 죽은 것으로 읽는다(몹 걸음 `_stairStepM` · `_fallStepM` · 몹 한 바퀴 `if (m.hp <= 0) return/continue` · 표적 `t.hp <= 0` · 클라 hp 0). 하한 1 은 그 틈을 막는다 — 죽음은 랩이 낸다(`_extKill` → 사체 · `_dropShadow`).
* **먹이 상한 maxHp**(zone.js `tryFeed` `Math.min(best.maxHp, best.hp + 5)`) — **뜻 있음**: 제 길들인 짐승에게 먹이를 주면 "hp 회복만" 한다(+5). 상한이 없으면 먹이를 거듭 줄수록 hp 가 몸의 최대를 넘어 끝없이 오른다. 사람 문(T109)의 상한(maxHp)과 같은 천장.
* 둘 다 0 밑으로 안 가니 이 카드의 하한 줄(문 안 `v < 0 → 0`)이 안 건드린다(하네스 ⓪ · ④ · ⑤ 가 그대로 초록).

1. **[PM · 판정 0 — 주기 저장을 같은 손잡이에]** 카드 ①(화살 저장 표)은 주기 저장이 죽어 있어(§1) 그것만으로는 아무 일도 안 한다 — 주기 저장 고침(`BEGIN IMMEDIATE … COMMIT`)을 같은 손잡이 `T967_MOB_HP` 에 넣었다(켬 기본 · `=0` = 둘 다 종전). 켬이면 화살뿐 아니라 **움직인 몹의 자리 · hp · 길들임 주인**이 10초마다 적힌다(종전 4개월은 종료 flush 때만) — 이 넓이를 받을지 · 손잡이를 둘로 가를지.
2. **[PM · 판정 0 — 화살로 죽인 몹이 되살아난다]** 화살 죽음 길(`stepArrows` · zone.js 13021)에는 `db.deleteMob` 이 없다(사람 공격 · NPC 죽음 길엔 있다 — 13150 · 4650). 그래서 화살로 죽인 몹은 DB 행이 남아 재기동(SIGKILL · SIGTERM 다)마다 마지막 저장 hp 로 되살아난다 — 하네스 판 넷 다 C hp 20 으로 되살아남. 화살 죽음은 다시 낳기(15초)도 없다(사람 공격 · NPC 죽음 길엔 있다). 한 줄 고침 감(`if (m.dbId) db.deleteMob(m.dbId)`) — 손잡이 감.
3. **[PM · 판정 0 — 종료 flush 가 길들임을 지운다]** `_shutdownFlush` 가 `db.updateMobState(m.dbId, m.x, m.y, m.hp)` 넷만 넘긴다 — 그 함수는 주인 칸 둘을 `|| null` 로 받아 **NULL 을 쓴다**(zone-local-db.js 238). 길들임은 저장 표 → 주기 저장으로만 적히는데 그 저장이 죽어 있어(§1) 지금 운영에서 길들인 짐승은 **재기동마다(SIGTERM · SIGKILL 다) 야생으로 돌아간다**(하네스 끔 판 둘 · 켬 SIGTERM). 켬이면 SIGKILL 은 남지만 SIGTERM 은 여전히 지운다. 한 줄 고침 감(flush 가 주인 칸 둘을 같이 넘김).
4. **[PM · 하네스]** `T973`(hp 문 검사 하나로)이 `lib-hp-src` · `test-npc-hp-door` 를 모을 때 이 가지의 `test-mob-hp-door` ⓪(판 따라 기대값)과 `lib-hp-door` 손잡이 줄을 같이 본다 — T954 · T967 이 둘 다 착지 전이다.
5. **[정보 · T917]** 존 SIGKILL 손실 창 표(T917 · 재기만)에 몹 칸을 넣는다면: 종전(끔) = 주기 저장 0 · 종료 flush 만 → SIGKILL 창 = 마지막 우아한 종료부터 전부 / 켬 = 10초.
