## ⓐ 정의 — **소득이다.** 코드 그대로

```js
    let q = 0, inc = 0;
    for (let k = 0; k < b.length; k++) { const x = e[b[k]] || 0; if (x > 0) { q += x; inc += x * ctx.w(b[k]); } }
    if (!(q > 0)) { out.push([job, gain]); continue; }         // 폴백 — 아직 실현이 0
    let g = (inc / n) * ctx.period;
```

`inc = Σ_r 실현ᵣ · w(r)` · `g = inc / 인원 × period` ⇒ **1인당 실현 소득 × period**.
**부산물은 더해진다** — 값싼 부산물이 한 직업을 깎는 일은 일어날 수 없다. T164 §3-5 는 틀렸다.

하네스 ⓢ⑤' *"바구니 절반 품목의 값을 3배 → 평균 2배(양 가중)"* 가 잠그는 것도 **소득**이다:
`Σq·w` 는 *"양가중 평균값 × 총량"* 과 **같은 수**라, 그 절 이름이 §3-5 의 오독을 불렀다.
⇒ **절 이름을 고칠 것**(회부): "바구니 소득(양가중)".

### 왜 이렇게 흩어지나 — 두 축이 겹친다

1. **종전 계수가 생산율이 아니다.** 농부 `0.4` · 나무꾼 `0.3` · 어부 `1.2` · 사냥 `0.7` · 채집 `0.25` 는
   `JOBS[j].base`(농부 1.5 · 어부 1.2 · 사냥 0.7 …)와 **다른 수**다. 종전식은 그 손튜닝 가중치로
   **모든 직업을 한 축에 올려 두었고**, 실현 소득은 그 축을 버린다.
2. **바구니 등재가 직업마다 완결성이 다르다.** 광부 바구니는 `ore` **하나**다 —
   실제로는 `salt`·`clay`·`tin`·`obsidian`·`jade` 를 더 내지만 그건 `produceSpecial` 코드가 내고
   `JOBS.miner.byproduct` 에는 없다. 어부는 일곱(소금 포함)이다.
   ⚠T164 §0ⓑ 는 *"종전식도 그 부산물을 안 봤으니 덮는 범위가 안 줄었다"* 고 적었는데 **그게 오독이었다**:
   종전식은 **모든 직업을 주산물 하나로** 매겨 공평했고, 소득식은 **등재가 고르지 않은 채로 합산**해 불공평해진다.

### 폴백 비율(실현을 못 쓰고 종전 값이 그대로 산 호출)

광부 **88~95%** · 나무꾼 14~17% · 채집꾼 14~16% · 농부 11~16% · 사냥꾼 5~13% · 어부 5~8%.
광부는 인원 0(평균 0.8명)이라 대부분 폴백인데, **폴백이 아닌 소수의 호출에서 배율이 1 근처**라 결국 안 뽑힌다.

### 실현/잠재 비는 왜 안 쟀나(그리고 안 재도 되는 이유)

`dailyProductionPotential` 은 `tickVillage` 의 **함수 지역 변수**라 밖에서 못 읽는다(코드 0 규약).
그리고 읽어도 이 물음엔 안 맞는다 — `toolBoost`·`inputMult` 는 `baseAmt` 에 들어가 **실현과 잠재 양쪽에** 있어서
그 비에 안 나타난다. 배분을 실제로 가르는 비는 **실현 ÷ 종전**이고 위 표가 그것이다.
감산의 크기는 따로 쟀다 — **도구 커버리지 평균 0.975**(종전) / 0.974(실현) · 궤적 전수 평균 0.79/0.73.
