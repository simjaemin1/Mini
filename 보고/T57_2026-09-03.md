## 1. §0 실측 — **범인을 한 번 잘못 짚었고, 원자료가 바로잡았다**

### ⓐ 지시서의 가설과 내가 처음 한 일

지시서는 "스크린샷의 격자는 **NPC 사유지 셀의 farmland facility 스프라이트**로 보인다"고 짚었고,
나는 그 층에 셀 게이트를 붙였다. 그리고 재 봤다.

### ⓑ 원자료가 아니라고 말했다

```
  e2e-nature [5] 절 원자료:  길 0셀 · **사유지 0** · 마을 50 · **경작지 42**
  새로 붙인 계측:            사유지 셀 후보 **0** · 안 본 셀 0 · 안 본 셀에 그림 0
```

**사유지는 한 칸도 없었다.** 진짜 층은 `farmland` **건물**이다 — `kind:'building'` 으로 실려
`_GATE_R.building = 4`(**4셀 후광**)를 받는다. 그 후광이 안 가본 땅까지 논밭을 밀어낸다.

★**지시서가 짚어 줘도 원자료를 먼저 읽어야 한다.** 카드가 "여기가 범인"이라고 적어도
그건 가설이다(족보 (88)의 형제). 손잡이를 뒤집기 전에 **세어 보는 것**이 첫 일이다.

### ⓒ 후광은 왜 있고 언제 빼는가 — 근거를 옮겨 적는다

후광은 **구조물 사정**이다: 벽이 시야를 막아 **내부 셀이 영영 '본 셀'이 안 되고**, 그래서
내가 지은 내 집 지붕이 사라졌다(실측 e2e-rooms 이엉 29.0% → 3.2%).
**땅에 깔린 것엔 그 사정이 없다** — 밭 한 칸을 지나가면 그 칸이 '본 셀'이 된다.
⇒ `_flat` 한 비트로 가른다. 판정 정본은 `_seenCell1`(=`_seenChunks`) 하나다.

### ⓓ 대조군을 **옛 동작 그대로** 만들었다

처음엔 대조군(`claimCellGateOff`)을 "무조건 그린다"로 짰다가 고쳤다. 옛 동작은
"무조건"이 아니라 **후광 통과**였다. 무조건으로 두면 위반 수가 부풀어 수리 효과를 과장한다 —
**계측기가 제 편을 드는 자리**다.

### ⓔ 그런데 하네스가 이 절을 **못 잰다. 그렇게 적었다**

`e2e-nature` 의 정본 프로브 자리(강가·초원)는 `probe-terrain-sites.js` 가 **지형**으로 고른
자리다. 화면(AOI 650px) 안에 논밭이 **한 칸도 없다**(cand 0).

```
  ★이 자리엔 논밭·사유지가 화면에 한 칸도 없다(AOI 650px 안) — 이 절은 이 판에서 **못 잰다**.
    "안 그렸다"가 아니라 "그릴 게 없었다"이므로 초록을 찍지 않는다. 프로브 자리 추가는 회부.
```

★**여기서 초록을 찍으면 그건 자명 통과다.** 수리는 기전으로 서고(후광을 안 받는다),
대조군 손잡이도 붙어 있지만, **재지 못한 것은 재지 못했다고 적는다.**
⇒ 회부: 논밭이 화면에 실재하는 프로브 자리(마을 사유지 고리)를 추가해야 이 절이 진짜로 잰다.

## 2. ② 논밭 크기 — **눈대중으로 키우지 않고 에셋에서 유도했다**

```
  public/assets/crops/*.png   원본 **64×64**
  흙 다이아                    x[2..61] · 가장 넓은 행 y=31~34   (stage 0 실측)
  셀 다이아                    64 × 32
```

⇒ 원본은 **폭 64 셀에 맞춰 구워졌고**, 흙 다이아의 중심이 스프라이트 중심(32,32)이다.
그런데 클라는 `drawImage(_cs, cs.x-20, cs.y-25, **40, 40**)` 로 **줄여서** 그리고 있었다.

```
  전   40×40 을 셀 다이아(64×32) 한가운데     → 다이아에 40px 짜리가 떠 있다
  후   원본 64×64 를 셀 중심에 그대로          → 흙이 셀을 채우고 작물이 위로 자란다
```

★**흙 다이아를 따로 깔지 않았다.** 지시서는 "밭 바닥이 따로 있나 — 없으면 흙 다이아를 깔라"고
했는데, **재 보니 원본 스프라이트가 이미 흙을 갖고 있다**. 따로 깔면 그게 사본이고,
두 겹이 어긋나는 순간 그 자리가 새 결함이 된다.

## 3. ③ 문간 — 바닥은 언제나, 지붕이 덮는다

종전: 밖이면 `continue` 로 **바닥 셀을 아예 안 그렸다**. ⇒ 문간·벽 틈으로 배경이 보였다(새까만 구멍).
지금: 항상 그리고, z 를 **-900 띠**로 내려 지붕 밑에 둔다.

★**z 를 손대야 한다** — 그냥 그리면 발자국 **앞쪽** 바닥이 지붕(캐리어 z+64)을 넘어 떠오른다
(움집 발자국 6×4셀 = 최대 192px). -900 은 지면 타일(-960)·길(-950) 위, 벽·지붕·사람 아래다.

### 짝 비교 — 그리고 **잡음 바닥을 먼저 쟀다**

첫 판은 손잡이 on/off 두 장만 비교해 `53px 차이`를 얻고 초록을 찍을 뻔했다. 그런데 바뀐 자리가
**[157,22,163,30]** — 화면 좌상단 HUD 였다. 시계 숫자 하나가 바뀐 것이다.

⇒ 같은 간격으로 **두 쌍**을 더 찍어 잡음 바닥을 잡고, 큰 쪽을 바닥으로 쓴다.
(한 쌍만 재면 마침 숫자가 안 바뀐 순간을 잡아 잡음을 0으로 보고, 다음 쌍의 숫자 변화가
"수리 효과"로 둔갑한다. T49 에서 배운 것과 **같은 실수**를 여기서 또 할 뻔했다.)

⚠**`e2e-rooms` 도 이 절을 못 잰다** — 그 픽스처는 **플레이어가 지은 방**이고 억제는
`data.hut`/`data.bld`(NPC 집) 전용이었다. 하네스가 스스로 세고("NPC 움집·큰집 0채") 유보한다.
⇒ 회부. `e2e-rooms` 자체는 **56 통과 / 0 실패**.

## 4. ④ 방향 — **지시서가 짚은 산식은 틀리지 않았다. 재 봤다**

지시서는 셋을 의심했다: ⑴ 월드 벡터인가 화면 벡터인가 ⑵ 시트 행이 어느 좌표계인가 ⑶ y 부호.
**셋 다 재서 셋 다 맞았다**(족보 (88) — 카드가 고치라 해도 이미 고쳐져 있는지 먼저 재라).

```
  키   월드(fvx,fvy)      화면(dx,dy)   행   시트 실루엣 폭   화면축
  ↑   (-0.707,-0.707)     0.0,-0.7      5       41          세로   ← 앞뒤(가장 넓다)
  ↗   ( 0,    -1    )     1.0,-0.5      6       34          대각
  →   ( 0.707,-0.707)     1.4, 0.0      7       13          가로   ← 옆모습(가장 좁다)
  ↘   ( 1,     0    )     1.0, 0.5      0       35          대각
  ↓   ( 0.707, 0.707)     0.0, 0.7      1       41          세로
  ↙   ( 0,     1    )    -1.0, 0.5      2       34          대각
  ←   (-0.707, 0.707)    -1.4, 0.0      3       13          가로
  ↖   (-1,     0    )    -1.0,-0.5      4       35          대각
```

**8/8.** 판정은 메타의 주장이 아니라 **시트 그림 자체**를 잰다 — 사람은 옆에서 보면 좁고(몸 두께)
앞뒤로 보면 넓다(어깨). 화면 가로로 걸으면 가장 좁은 행, 세로로 걸으면 가장 넓은 행이어야 한다.

★**여기서도 내 자가 먼저 틀렸다.** 처음엔 대각을 `1.8배` 문턱으로 갈랐는데, 이 투영은 화면 y 가
절반이라(`w2i`: y=(wx+wy)/2) **월드 축방향이 화면에서 정확히 2:1**이다. 1.8 로 두면 대각 넷이
전부 '가로'로 잡혀 **멀쩡한 판정이 4/8 로 빨개졌다**. 문턱을 기하에서 유도해 4로 고쳤다(족보 74).

### 진짜 결함 — **시트가 앞뒤를 못 가른다**

```
  마주보는 행 차이(r ↔ r+4)   2.89  3.89  3.66  1.67
  이웃 행 차이  (r ↔ r+1)     8.38  7.74  8.53  8.44      ← 마주보는 쪽이 이웃보다 안 다르다
  행별 머리 평균 밝기          101.5 104.4 100.9 88.5 99.7 102.5 100.2 89.5
                              ⇒ 어느 행도 얼굴이 없다(살색이 안 나온다). 앞모습=뒷모습.
```

동↔서·남↔북이 화면에서 구별되지 않는다. **이게 "괴리감이 심해"의 정체다** — 산식이 아니라 에셋이다.
⇒ **재렌더는 ART** (`scripts/char_render.py` 가 자산 정본 · 손편집 금지). **회부.**
8방향 표가 그 재렌더를 검증할 자를 이미 갖고 있다.

## 5. ⑤ 이름표 — 함수 하나, 두 경로가 부른다

이름표·행동 라벨이 옛 도형 경로 **안**에 있었고 호출자는 `if (!_spriteOk) drawPlayerIso(...)` 라
**시트가 성공하면 안 불렀다**. HP 바·말풍선은 호출자에 있어 살아남았고 **이름표만** 빠졌다.

⇒ 블록을 **옮겨** `drawNameTag(x,y,name,isMe,act)` 하나로 만들고 두 경로가 그 하나를 부른다.
어느 쪽이든 **정확히 한 번** 그려진다. NPC 는 넘어오는 이름이 이미 `직업 이모지 + [부족] + 이름`이라
**종전 그대로**다(새 표시를 발명하지 않았다).

### 판정도 두 번 고쳤다 — **밝기가 아니라 글자의 서명을 센다**

```
  1차   머리 위 띠의 '밝은 픽셀 수' > 20          → 32 · 20 사이를 오갔다(아슬아슬)
  2차   대조군(빈 땅)과 비교                        → 대조군이 어두운 픽셀 1767 을 냈다(땅이 어두웠을 뿐)
  3차   **글자 서명** — 밝은 픽셀 옆 2px 안에 아주 어두운 픽셀(흰 글자 + 검은 외곽선)
        머리 위 **39** vs 같은 크기 지면 띠 **0**   ← 지면엔 그런 자리가 없다
```

★**"픽셀이 밝다"는 그 자리에 뭐가 깔렸느냐에 흔들린다. 구조를 재야 흔들리지 않는다.**
