## §0 실측 — 전제 셋이 뒤집혔다 (`scripts/ev-sources.js` · 실지도 51마을 800일 3시드)

### ⓐ ★풍흉은 **이미 있었다** — 장부가 판정할 게 아니었다

지시서는 *"수확량이 기대 대비 ±얼마면 풍작인가, sev 축 재사용"* 을 물었다. 그런데 econ 은
**자기가 풍년·흉년을 선포하고 있었다**:

```
sim/economy-sim-v2.js:1246  tickYearShock(world, day)
  if (day % 365 !== 180) return;              // 가을 첫날
  roll < 0.15 → v._yearShock = { '🌾풍년', fertility ×1.30, game ×1.15, 90일 }
  roll < 0.27 → v._yearShock = { '☠️흉년', fertility ×0.70, game ×0.85, 90일 }
```

날씨도 마찬가지다(`tickWeather` — 가뭄·폭풍·풍요·안개, 일 1.5%, 7~14일).
⇒ **장부가 문턱을 발명하지 않는다.** 그 상태의 에지를 읽고, `mag` 은 **econ 이 실제로 곱하는 배수**다.
실측: 풍흉 23~27건 · 날씨 537~573건 / 800일 51마을.

### ⓑ 실체 습격 층은 **배선돼 있지 않다** — 그런데 추상 약탈은 이미 돈다

`server/bandit-raid.js`(113줄)·`server/predator-bandit.js`(208줄)는 완성돼 있는데
**`zone.js` 가 require 하지 않는다**(2파 유예 — 파일 안 주석 그대로). 실체 습격은 아직 없다.

그런데 `server/bandits.js` 는 배선돼 있고(zone.js:37), econ 에 훅을 꽂는다:
```
bandits.installHooks() → world.banditGang / world.onBanditLoot
  → economy-sim-v2.js:890 _raidScrum (호위 vs 갱 per-entity 전투)
    → c.from.tradeStats.caravansRaided++ · tradersKilled++ · cargoLost += …
```
⇒ **누계는 이미 오르고 있다.** 장부는 그 **증분**을 본다. 실체 층이 나중에 와도 이 배선은 안 바뀐다.
⚠랩(econ 단독)엔 도적 호스트가 없어 **구조적으로 0**이다 — `CARAVAN_LATE` 와 같은 자리.

### ⓒ ★★sev 축에는 **일 유형의 눈금이 없다** — 이게 이 카드의 핵심

| | sev = \|ln(mag)\| |
|---|---|
| 흉년(비옥도 0.70) | **0.36** |
| 가뭄(0.65) | **0.43** |
| 인구 붕괴(최대) | **1.99** |
| 연표 문턱 `EV_CHRON_SEV` | **2.20** |
| 소금값 9배 | 2.20 |

**일 유형은 값 문턱을 한 번도 못 넘는다**(`test-events ㉞b` 가 이 사실을 검사한다).
즉 유형만 더하고 정렬을 그대로 뒀으면 **이 배치는 아무것도 안 한 것과 같았다** —
새 유형이 전부 연표 밖으로 밀려났을 것이다.

⇒ **축을 둘로 뒀다.** `heavier(a, b)` 하나: **일이 먼저 서고, 그 안에서 sev 로 견준다.**
브리핑·게시판·연표가 전부 이 비교자를 쓴다(정렬 사본 0).
근거는 발명이 아니라 **실측된 드묾**이다 — 값 18,434건 대 일 1,021건(5.2%).
**드문 것은 걸러낼 필요가 없고, 흔한 것은 걸러야 한다.**

## 장부가 문턱을 가진 것은 **인구 축 하나**뿐

나머지 여섯은 econ 이 세운 상태의 에지다. 인구 축도 **새 문법이 아니라 가격 이탈과 같은 문법**이다:
자기평균(EMA) 대비 이탈 + 에지 + 히스테리시스(`HYST` 공유).

⚠**`bandits.js` 의 해체 판정을 베끼지 않았다.** 그쪽은 `순감 5일 && 식량<3일치 && 잔존≤피크×0.55`
인데, 그건 **도적단 결성의 조건**이고 이건 **촌장이 하는 말**이다. 두 값이 갈라져도 서로 무해해야 한다.

**채택 근거**(`ev-sources ⓒ` 스윕): 창을 30→180 으로 **여섯 배** 늘려도 건수가 **15~31 안에** 머문다.
이 신호는 드물고 뚜렷해서 손잡이가 사실상 무관하다 ⇒ 한 계절(90) · −30% 를 골랐다(24건/800일).
★독립적으로 `bandits.js` 문법(순감+식량)으로 재도 **24건**이 나왔다 — 다른 자로 재도 같은 수다.

   ⑥이 "촌장과 게시판이 다른 말을 한다"고 **없는 사본을 보고**했다
   (실제로 촌장은 `새 움집이 하나 섰네`를 말하는데 게시판엔 그 줄이 아예 없었다).
   ⇒ 칸을 비우고 **새 응답을 폴링한다** — T18 이 `askChron` 에 낸 처방과 같은 것이다.
3. **`e2e-chronicle enter()`** — 좌표를 받았다고 마을을 아는 것은 아닌데 고정 2초만 기다렸다.
   러너 아래에서 첫 워프가 30초를 다 쓰고 실패했고 ③ 넷이 줄줄이 빨개졌다.
   ⇒ **근접 틱이 실제로 돌 때까지**(`__evDbg`) 기다린다.
4. **`e2e-chronicle ④`** — ★이건 T50 의 **설계**가 드러낸 것이다. 이웃 연표에 넘어갈 줄을 고를 때
   아무거나 골랐는데, 날씨·완공·첫 물건은 `EV_DEED_FOREIGN` 밖이라 **설계상 절대 안 온다.**
   그걸 골라 놓고 기다리면 150회 폴링 끝에 빨개진다 — **제품이 옳은데 검사가 틀린 것**이다.
   ⇒ 값 유형(넘어오는 줄)을 고른다. 걸러진다는 사실 자체는 `test-events ㉞` 이 따로 검사한다.

### 그리고 하나는 **끝까지 파서** 이름을 붙였다 — `e2e-village`

러너에서 `e2e-village` 가 빨개졌다("거부 사유가 한국어 계약 메시지다 — (없음)").
T50 과 무관해 보였지만 **단독으로도 3/3 재현**됐고, 같은 폴더에서 코드만 되돌리면 **3/3 통과**했다.
그래서 워크트리를 따로 떠서 이분했다:

```
  베이스 코드(/tmp/base · 같은 하네스)         32/0  ✅
  내 코드 전체                                 31/1  ❌ (3회 재현)
  내 코드 · villages.js 만 되돌림               32/0  ✅
  내 코드 · `builds: []`(완공 사건만 안 냄)      32/0  ✅
  ⇒ **완공 사건 발화가 방아쇠**다.
```

그런데 서버에 로그 한 줄만 더해도, 브라우저에 리스너 하나만 붙여도 **통과했다**.
즉 멈춘 것이 아니라 **타이밍이었다.** 실패한 판의 서버 로그를 보면 그 5초 동안 게임일이
**30일이나 정상으로 흘렀다** — 서버는 내내 살아 있었고, 같은 하네스의 다른 알림 검사는 전부 통과했다.

⇒ 진범: 그 절은 방금 접속한 두 번째 플레이어에게 재고 요청을 **한 번만** 보내고 5초를 기다린다.
그 한 번이 연결이 앉기 전에 나가면 조용히 사라진다. **하루 경계가 조금 달라지자 그 창이 어긋났을 뿐이다.**
⇒ 재고 열람은 **읽기**라 여러 번 물어도 무해하다. 폴링마다 다시 묻게 고쳤다 — **2/2 통과.**
