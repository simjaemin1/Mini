## 1. §0 실측 — 카드의 전제가 "얕다"였는데, 실은 **어긋나 있었다**

카드와 PM 대조표는 *"서버가 랩보다 얕게 이식됐다"* 로 시작한다. 다섯 축을 다 재 보니
**빠진 것은 거의 없고, 옮겨 적는 동안 어긋난 것이 있었다.**

### ⓐ 두 표의 차 — **차집합이 없다**

| 잰 것 | 결과 |
|---|---|
| 30 ∖ 34 | **∅** — 랩 30종은 카탈로그에 **전부** 있다(랩 `벼` = `rice` "쌀(벼)") |
| 34 ∖ 30 | **4종** — 삼(대마)·쪽·뽕(잎)·차(茶). **전부 `group:'특용'`(비식량)** ⇒ NPC 식량 농사에 없던 게 맞다 |
| 생육일 차 | 셋뿐 — **보리 210↔88 · 밀 210↔90 · 마늘 210↔90** |

★**그 셋도 값 차이가 아니라 단위 차이다.** 랩 주석 7929 가 스스로 적어 두었다:

```
  // 고대 한반도 식량작물 30종(카탈로그 연동). plantMo=0=1월.
  //   grow=달력일(월동 보리·밀·마늘은 ~210=초여름 수확). yieldC≈수확량×1.7
```

랩은 **달력일**, 카탈로그는 **활동일**(`winterCrop:true` + `Crops.grownDays` 가 겨울을 안 센다).
가을 파종 → 겨울 휴면 → 초여름 수확에서 **활동일 88 + 겨울 95 ≈ 달력일 210**. 같은 것을 다르게 센 것이다.
⇒ 카탈로그가 정본이므로 `Crops.growDaysOf` + `Crops.isReady` 를 쓴다.

### ⓑ ★★★두 군데가 틀어져 있었다 — **농부가 눈밭에 좁쌀을 뿌리고 있었다**

| # | 무엇 | 근거 |
|---|---|---|
| ⓐ | 랩 `plantMo` 는 **0-based** 인데 서버 `_lMonth` 는 **1-based** 를 돌려줬다 | 랩 주석 7929 *"plantMo=0=1월"* · 랩 `lMonth` 는 `return m`, 서버는 `return m + 1` |
| ⓑ | 랩 앵커 `L_START=120`(게임일 0 = **5월**)이 econ 계절 정본(게임일 0 = **봄 첫날**)과 **두 달** 어긋난다 | `events.seasonOf`: `d<90 → spring`. 봄이 5월에 시작할 수는 없다 |

⇒ 조(랩 `plantMo [3,4,5]`)의 실제 파종창이 **게임일 304~30 = 한겨울~초봄**이었다.

### ⓒ 주사위 자리 전수 — **작물 상태기엔 하나뿐이었고, 랩의 ±20% 는 오지 않았다**

`villages.js` 의 `Math.random` **다섯**(주석 둘 제외) 중 **작물 상태기는 하나**:
`if (!e.ps && Math.random() < L_PESTP) e.ps = 1;`(병충해).
나머지 넷은 배회 스폰 셋 · 반일 퇴근 `npc._half` 하나로 **배치·스케줄·이동 층**이다(회부).

★그리고 랩 9033 의 수확 편차 `(0.8+0.4*Math.random())` 은 **서버에 이식되지 않았다** —
서버 수확은 `_crop.delete(k)` + 짐 1칸이 전부다. 카드 ②의 *"안 가져온다"* 는 **이미 참이었다**.

### ⓓ 논/밭 축 — **이분법이 아니었다**

`crops.json` 의 `field` 는 복합 표기다: `밭` · `논` · **`밭·논`** · **`물가·논`** · **`밭(뽕밭)`** · **`밭(경사)`**.
순수 `논` 은 **쌀 하나**뿐이다. ⇒ 이분법으로 자르면 논 특산이 죽는다 ⇒ `Crops.fitsField(id, field)`
(포함 여부로 묻는다). 실측: 논 후보가 달마다 0~2종, 밭은 0~22종.

### ⓔ 카탈로그의 `sowMonths` 는 **사람 글이다**

카드는 *"`sowMonths`(파종월)와 `sowSeasons` 둘 다 있다"* 고 했다. 실측: `sowMonths` 는
`"4~5·7~9월"` 같은 **문자열**이다(기계 축이 아니다) ⇒ `Crops.sowMonthsOf` 가 파싱한다. 형식 14가지.

## 2. ★★★달력 — 새 시계를 만들지 않았다

재민 확정(2026-08-30): *"원천은 econ 계절 정본 하나 — **새 시계·새 매핑 상수 금지**(사본 금지)."*
카드 ①은 *"econ 게임일 → 월 유도 함수 하나"* 를 요구한다. 이 둘이 부딪히지 않게 하는 길은 하나다:
**달을 새로 세지 말고, 계절을 더 촘촘히 읽는다.**

```js
  function monthOf(day) {                      // crops.js §6
    const cal = events.calendarOf(day);        // 계절 정본이 주는 (계절 · 계절 안 며칠 · 그 계절 길이)
    const third = floor((cal.dayOfSeason-1) / cal.seasonDays * 3);
    return ((계절ix*3 + third + ANCHOR_MONTH-1) % 12) + 1;
  }
```

* **365 도 90/180/270 도 여기 한 번도 안 적는다.** 해 길이는 `events.yearDaysOf()` 가 계절 정본에서 읽어 낸다.
* ⚠**365/12 와 365/4 로 따로 나누면 경계가 하루씩 어긋난다**(첫 판에서 실제로 그랬다 — `monthOf(90)=5월`
  인데 `seasonOf(90)='summer'`). **계절 안에서 셋으로** 나눠야 경계가 겹친다.
  한 해 전수 365일 불일치 **0건** · 달이 바뀌는 날 `0/30/60/90/120/…/270/302/334` — 계절 경계 위에 정확히 앉는다.

### ★★★앵커는 고르지 않고 **카탈로그에서 역산했다** (족보 (86) · T59 의 "세 자 일치"와 같은 결)

* **익음·생장 비율은 정본이 센다** — `Crops.isReady` · `Crops.grownDays`(활동일).
  `(오늘 - 심은날) / grow` 를 다시 쓰면 월동 작물이 겨울에도 자란다.
* **주사위를 되살리지 마라** — 결정론 해시가 필요하면 `Crops.h32`.
* 하네스는 상태기를 다시 짜지 말고 **`villages.__farmBind()`** 를 써라(테스트 전용 · 순수 export).
* **배치 b 가 남았다**: ③ 플레이어 돌보기(E 하나 · 물병 1 소비 + 빈 병 반환 · `q` 는 NPC 와 같은 함수) ·
  ④ 수확 뒤 빈 밭 유지 · ⑤ ⓖ "닿았다면 얼마인가" 표.
