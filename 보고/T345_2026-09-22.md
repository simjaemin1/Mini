## 1. ① 먼저 센 것 — 걸음 하나가 만드는 쓰레기 27개

T340 은 정적 계수로 "객체 리터럴 33" 을 냈다. 이 카드는 그 33이 **어디서 실제로 돌고 있나**를 갈랐다.
기준은 하나 — **걸음마다 불리는가**. 이동 문은 주민 전원이 틱마다 밟는다(걸음/틱 = 인구).

| 자리 | 무엇을 만드나 | 걸음당 | 왜 거기 있었나 |
|---|---|---:|---|
| `isBlockedByWall` → `cellOf(x,y)` ×2 | `{cx, cy}` 객체 | **10** | 같은 셀인지 **묻기 위해** 객체를 둘 만든다. 30Hz 한 걸음은 2.1px·셀은 32px 이라 **열에 아홉이 같은 셀** — 그 조기 반환이 이 함수의 본체인데, 본체가 객체 둘을 만들고 있었다 |
| 타일 메모 호출 `_TERR_CACHE.water(tx,ty, () => …)` | 클로저 | **5.3** | 메모의 `compute()` 가 **인수를 안 받아서** 부르는 쪽이 좌표를 가둔 함수를 매번 새로 만들어야 했다 |
| `treeBlockerAt` → `queryCircle` | 배열 **둘**(후보·걸러낸 것) | **10** | 원 질의가 항상 새 배열을 만든다. 이동 문은 나무 판정을 걸음당 최대 5회 부른다 |
| `isPositionActive` → `chunkXY` | `{cx, cy}` 객체 | **2** | 청크 좌표를 **묻기 위해** 객체 하나. 결정 문·이동 문에서 각각 한 번 |
| **합** | | **≈27** | 초당 4.4만 걸음 ⇒ **초당 120만 개** |

★**셋은 판정이 아니라 껍데기였다.** 물이냐 벽이냐 나무냐를 묻는 값은 그대로이고, **묻는 행위가**
쓰레기를 만들고 있었다. T333 프로파일의 GC 2.1% 와 `isWaterTileLocal`·`isBlockedByWall` 자기시간이 그 값이다.

## 2. ② 넷을 없앴다 — 답은 한 자도 안 바뀐다

| # | 전 | 후 | 왜 같은 답인가 |
|---|---|---|---|
| ⓐ | `const oc = cellOf(oldX,oldY); const nc = cellOf(newX,newY); if (oc.cx===nc.cx && …)` | `const _ocx = Math.floor(oldX/32) …; if (_ocx===_ncx && _ocy===_ncy) return false;` | **같은 `Math.floor`** · 셀을 넘는 걸음(10% 미만)에서만 종전 객체 꼴을 만들어 아래 경로에 그대로 넘긴다 |
| ⓑ | `water(tx,ty, () => compute(…))` | `water(tx,ty, _computeWaterCell)` — 메모가 `compute(tx,ty)` 로 부른다 | 같은 함수·같은 인수 · `prebake` 는 **이미** 그 꼴이었다(규약을 맞춘 것) |
| ⓒ | `queryCircle(x,y,28)` → 배열 둘 | `queryRect(…, _treeScratch)` 버퍼 하나 + **같은 원 필터 식** | `queryRect` 순회 순서가 같고 필터가 같으므로 **첫 적중이 같다**. `Math.hypot` 은 그대로 뒀다(`sqrt` 로 바꾸면 마지막 비트가 달라질 수 있다) |
| ⓓ | `const {cx,cy} = chunkXY(x,y)` | 나눗셈 둘을 인라인 | 같은 나눗셈·같은 키. ⚠**문자열 키는 남겼다** — `activeChunkKeys` 가 그 꼴이라 여기만 정수로 바꾸면 원천이 둘이 된다(T333 이 비트 색인을 그 Set **에서** 유도한 그 규율) |

★**전수 대조**(`test-move-soa` 24/0): 셀 판정 **6만 쌍 0 다름**(경계 ±0.5px · 정확히 경계 위 · 음수 · 큰 좌표) ·
메모 **8만 칸 0 다름**(적중·실패 수까지 일치) · 자명 통과 금지 둘(`floor`→`round` 로 비틀면 4,992쌍이 갈린다).

> **1.49배 → 1.39배.** 카드가 건 목표(사람당 0.3~0.5 µs = 10,000명 **5 ms**)에는 **한 자리 멀다.**
> ⚠그리고 위 표의 낮/하루평균은 3-ⓑ 의 편차를 그대로 물려받는다 — **밤(1.03배)만 깨끗한 수**다.

## 4. ④ 남은 것 — SoA 가 얼마를 더 줄이나 (다음 카드의 입력)

T340 §2-ⓑ 가 층 2(JS 데이터 지향)를 **0.2~0.4 µs** 로 잡았다. T345 가 그 층의 **첫 켜**(할당)를 했고,
얻은 것은 **GC −27 % · 상수 항 −3.7 %** 다. **10배는 여기 없었다.** 어디 있나 — 이 카드가 실제로 본 것:

| 남은 자리 | 지금 값 | 왜 아직 있나 | SoA·정수 격자가 지우나 |
|---|---:|---|---|
| **걸음당 호출 수** — 지형 **6.43** · 벽 **5.39** | 합쳐 11.8회/걸음 | 성분별 취소(x 따로 y 따로) · 계단·다리·물 술어가 **각각** 판다 | ★**그렇다** — 카드 ②가 노린 것. 셀당 비트 하나로 **≤ 6회** |
| **틱 본체** `zone.js:11255` | 6.79 % (8.8s/130s) | 주민 객체 1,464개를 **포인터로** 훑는다(캐시 미스) | ★**그렇다** — SoA 의 본래 값은 여기다. 지금 자로는 **못 갈랐다** |

| **지형 메모 미적중** | 0.7~3.3 % | 미리 굽기 상자 **밖**을 걸으면 난다 | 아니다 — 굽는 상자 문제(T333 §5) |

| **`isPositionActive` 의 문자열 키** | 48 B/회 · 2회/걸음 | `activeChunkKeys` 가 `Set<문자열>` 이다 | ★**그렇다** — T333 이 `WATER_TILES` 에 한 그대로(집합**에서** 비트 유도) |

★**다음 카드에 넘기는 한 줄**: 이 카드가 답한 것은 **"할당이 주인인가"** 였고 답은 **"아니다 — GC 2 %대다"** 였다.
주인은 **호출 수(11.8회/걸음)와 포인터 순회**다. 둘 다 ①②③ 이 노린 자리이고, 둘 다 **하루가 아니라 나흘**짜리다.

★**그리고 게이트가 먼저다.** `Math.random` ×15 를 씨 해시로 바꾸기 전에는 "같은 씨 같은 좌표" 가 성립하지 않는다
(§머리 한 줄 ③). ⇒ **다음 카드의 1번은 SoA 가 아니라 주사위 0** 이다. 그걸 먼저 하면 그 다음부터는
옛 루프↔새 루프를 **틱마다 전수로** 견줄 수 있고, 그때 SoA 는 위험 0 인 수술이 된다.
