## 1. §0-ⓐ — **`__w2s` 는 성했다. 재현 조건은 키 이름이었다**

T57 이 "카메라 상태를 타는 듯"이라 적고 `__s2w` 를 세 점에서 재 **뒤집어 쓰는** 우회를 넣었다.
정의를 읽으니 곧바로 답이 나왔다(`00-const.js:146~162`):

```
  __s2w(px, py)  →  { wx, wy }      화면 → 월드
  __w2s(wx, wy)  →  { px, py }      월드 → 화면
```

T57 코드는 `s1.x - s0.x` 를 읽었다. **둘 다 없는 키다** ⇒ `undefined − undefined = NaN`.

★**같은 훅을 쓰는 다른 하네스는 멀쩡히 돌고 있었다** — `e2e-zoom:146` 과 `e2e-onboarding:178` 은
처음부터 `.px`/`.py` 를 읽는다. 그 사실 하나로 "훅이 아프다"는 가설은 끝난다.

★**진짜 NaN 경로가 있는지도 확인했다**(가설을 하나만 세우지 않는다):
`_lastCamIso` 는 `null` 로 시작하지만 폴백 `myAbsPredicted` 가 `{x:0,y:0}` 로 **초기화돼 있고**,
`W0`·`H0`·`ZOOM`·`myFloor` 도 전부 수로 시작한다 ⇒ **NaN 을 낼 입력이 없다.**
지시서는 "한 줄 가드 또는 초기화 순서"를 예상했지만 **가드할 것이 없었다**(족보 (88)).

⇒ **수리는 하네스 쪽**이다: 우회를 걷고 정본을 그대로 부른다. 그리고 재발을 막는 검사를 세웠다 —
세 점 왕복(`월드 → 화면 → 월드`)에서 **유한값 3/3 · 왕복 오차 0.000px**.

## 2. §0-ⓑ — 셀 훅을 한 자리로

`__simvilCells`(`11-r1-mountain.js`)와 `__claimCells`(`34-m-renderloop.js`)가 두 파일에 흩어져 있었다.
T57 이 후자를 렌더 루프 안에서 게으르게 만든 건 **그 카드의 접촉 파일이 거기뿐**이어서다.

⇒ 넷(`__simvilCells`·`__claimCells`·각 `__*Probe`)을 **`11-r1-mountain.js` 훅 절 한 자리**로 모았다.
렌더 루프는 프레임마다 **비우기만** 한다.

★**실행문 예산을 늘리지 않았다.** 분할 규약은 "새 최상위 실행문은 `99-main.js` 에만"이고
`test-client-globals ③` 은 **총계 일치**를 본다(표를 늘려도 총계가 늘면 거기서 잡힌다 — 그 파일의 주석).
처음엔 두 줄을 그냥 더했다가 `41→43 · 총계 117→119` 로 **정확히 그 검사에 걸렸다.**
⇒ `Object.assign` 두 줄로 넷을 선언해 **종전 두 줄 = 지금 두 줄**로 맞췄다.
훅을 늘리자고 다른 규약의 예산을 쓰지 않는다.

소스 검사도 승격했다(`e2e-charsprite ⓖ`): 선언 형태 둘(`window.__X = {` · `Object.assign(window,{__X:{`)을
다 훑어 **선언이 파일 하나에만** 있는지 본다.

## 3. §0-ⓒ — ⑥ 을 비율로

```
  전   ok(perfOn.med < 60)                     ← 그날 기계가 얼마나 바빴는지를 잰다
  후   ON 을 두 번 재 잡음 바닥 → 효과비(ON중앙/OFF) ÷ 잡음비 < K
       잡음이 1.5 를 넘으면 **판정하지 않는다**("안 비쌌다"가 아니라 "못 쟀다")
       절대 60ms 는 참고 출력
```

절대 문턱이 왜 나쁜 자였는지는 실측이 말한다 — **같은 하네스가 34.0 · 38.2 · 72.4ms 를 오갔다.**
72.4 인 판은 내가 다른 계측을 같이 돌리던 판이었다. 그때 빨간 건 제품이 아니라 기계다.

**K 는 유도했다.** 이 검사가 막으려는 회귀는 "시트 경로가 도형 경로의 **두 배**로 비싸진다"이고,
두 배는 효과비 2.0 ÷ 잡음비 1.05 ≈ **1.9** 다. K=1.6 은 그 밑이라 두 배를 잡는다.

### 사보타주 — 처음엔 **너무 약해서** 안 빨갰다

`CHARSPRITE_SABOTAGE=1` 로 ON 팔에만 헛일을 얹는다. 1차는 12ms 를 얹었는데
**효과비 1.288 · 비율의 비율 1.18 로 문턱(1.6) 밑을 지나갔다.**

★그때 문턱을 내리지 않았다. 프레임 간격이 ~36ms 이므로 "두 배"가 되려면 ~36ms 를 얹어야 한다 —
**사보타주가 약했던 것이지 문턱이 헐거운 게 아니다.** 문턱을 대조군에 맞춰 내리면 거꾸로다.
⇒ 40ms 로 올리니 **효과비 2.285 · 비율의 비율 2.14 → ✗**(rc=1). 대조군이 제 일을 한다.
