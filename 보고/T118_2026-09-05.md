# 보고 — T118: 알림 자리를 캔버스대로 (2026-09-05)

## 0. §0 실측 (셋)

### ⓐ 캔버스의 알림 자리 — 화소로 쟀다

캔버스 아트보드는 **한 장(1440×900)** 이다(지시서는 "1360×600 · 1400×900 두 해상도"라 했는데,
`산그림/디자인B/` 를 재 보면 HUD 판은 `디자인B_HUD.jpg` **1440×900** 하나다 — 나머지는 판별 그림이라
해상도가 제각각이다: 화면규칙 1100×1120 · 상태 420×560 · 짐 960×560 · 쓰러짐 560×420).
**두 해상도 판정은 캔버스가 아니라 하네스에서** 했다(아래 §2 — 창을 줄여도 안 겹치는지가 진짜 물음이다).

| 잰 것 (1440×900) | 값 |
|---|---|
| 알림 판 가로 | x **536 → 1093**(폭 **558**) · 왼쪽 끝 536~538 은 **금색 강조 막대**(`--accent`) |
| 알림 판 세로 | y **17 → 66**(높이 50) |
| 글줄 피치 · 패딩 | **17px** · **11px** (T113 이 쓴 그 값) |
| 판 중심 x | **814.5** — 캔버스 중심(720)에서 **+94.5** |
| 왼쪽 이웃 | 상단 상태 줄(끝 x≈470) — **여유 66px** |
| 오른쪽 이웃 | 지도 판(시작 x 1211) — 여유 118px |

⇒ 캔버스의 뜻은 **"위 띠 · 상태 줄 오른쪽 · 지도 왼쪽"**(설계 §4 "촌장 한 줄은 상단(레일 오른쪽)에")이고,
자리는 **화면 정중앙이 아니다**(왼쪽에 상태 줄이 있어서 오른쪽으로 밀린 값이다).
§3 판정이 "알림 중심 x = 화면 중심"이라 **화면 중심**으로 세웠다 — 고정 좌표(536)는 해상도가 바뀌면
뜻을 잃는데, "띠 안 가운데"라는 뜻을 값 하나로 지키는 것이 `left:50%` 다. **캔버스와의 94px 차이는
이 표에 적어 둔다**(캔버스가 정본이라는 규약대로, 고칠지는 PM 몫 — 회부).

### ⓑ `#notice` 가 `#hud` 안에 있던 이유 · 밖으로 뺄 때 잃는 것

| 잰 것 | 답 |
|---|---|
| `#hud` | `position: fixed; top:12; left:12; flex column; gap:8; **pointer-events:none**; z-index:10` |
| `#notice` 가 얻던 것 | 고정 배치 · 세로 흐름 자리 · z 10 · **클릭을 안 먹는 성질(상속)** |
| `.hud-row` 와 다른 점 | `.hud-row` 는 `pointer-events:auto` 로 되살리는데 `#notice` 는 **아니다**(원래 안 먹었다) |
| 밖으로 빼면 잃는 것 | 위 넷 전부 — 그래서 **노드를 안 옮겼다**(아래 §1) |
| 흐름 안에 있어서 생기던 해 | 알림 줄 수가 늘면 **HUD 세로줄이 밀린다**(T113 스택 셋이면 47px) |

⇒ **노드는 `#hud` 자식으로 그대로 두고 `position: fixed` 만 준다.** `pointer-events` 상속이 살아 있고
`index.html` 을 안 건드리며, `fixed` 라 흐름에서 빠져 **HUD 가 더는 안 밀린다**(덤으로 닫힌 결함).
캔버스 렌더 층(`34-m-renderloop` 4-0 "안개 위")은 **캔버스 안의 층**이라 DOM 알림과 무관하다.

## 1. 한 일 — `style.css` 한 규칙(JS 0 · HTML 0)

```
position: fixed; top: 12px; left: 50%; transform: translateX(-50%); z-index: 10;
padding: 11px;              ← 캔버스 값(종전 6)
max-width: 560px;           ← 캔버스 558 → 눈금 16 에 맞춤(종전 320)
text-align: center;         ← 가운데 판이니 한 줄짜리가 왼쪽에 붙지 않게
#notice:empty { display:none }  ← 자리를 옮기면 따라오는 결함을 같은 카드에서 닫는다(아래)
```

`top` 은 **12** 다 — 캔버스는 17 이지만 그건 그 그림의 자체 여백이고, 실화면에서 같은 띠에 서는
`#hud`·`#minimap` 이 둘 다 12 다. 17 을 쓰면 알림만 5px 내려앉는다.

★**자리를 옮기니 드러난 결함 하나를 같이 닫았다.** `#notice` 는 `min-height:18px` + 배경이라
**비어 있어도 먹판이 하나 남는다**. 좌상 HUD 흐름 안에서는 안 보였지만 화면 위 가운데로 나오면
빈 판이 늘 떠 있게 된다 ⇒ `#notice:empty { display: none }` 한 줄. JS 는 안 건드렸다.

**T113 스택 · T110 화살·kind 표 · `__notices`/`textContent` 계약 — 전부 무접촉**(자리만 옮겼다).

**⑭ 가 재는 것 — 두 해상도에서 같은 판정**

```
1280×800   레일 ∩ 알림 = 0px²  ·  알림 x510~770 · 레일 x8~52  ·  중심 640 = 화면 중심
1024×700   레일 ∩ 알림 = 0px²  ·  알림 x382~642 · 레일 x8~52  ·  중심 512 = 화면 중심
둘 다      지도 판과도 0 · top 12 · 패딩 11 · fixed · pointer-events none · 스택 셋 그대로
빈 알림    display:none · 높이 0 (두 해상도)
자명 통과 금지  옛 자리(HUD 흐름)로 두면 겹침 **3000px²** — 이 검사가 늘 0 을 내는 게 아니다
```

★**같이 잰 것 — 상태 줄과의 여유**(회부 판단 자료 · 하네스가 매 판 찍는다)

```
1280×800   상태 줄 오른쪽 여유 **+36px**(알림 폭 260)
1024×700   상태 줄 오른쪽 여유 **−92px** ⇒ 좁은 화면에선 알림이 상태 줄 위에 얹힌다
캔버스     1440×900 에서 +66px
```
중심 맞춤과 캔버스의 "상태 줄 오른쪽"은 **좁은 화면에서 어긋난다**. 교차점은
`화면폭 ≥ 2×(상태 줄 오른쪽 474 + 알림폭/2)` — 알림이 짧으면(260) 약 **1208px**, 캔버스 폭(560)까지
길어지면 약 **1508px** 이다. 즉 1280 에서도 **긴 알림**은 상태 줄에 닿는다.
토큰만으로는 "띠 안 가운데"를 못 쓴다(상태 줄 폭을 CSS 가 모른다) ⇒ **회부**(§3).

**귀속 — `e2e-events` 는 이 상자가 흔들린다**

| 판 | 내 나무 | 깨끗한 베이스(14b82fc6 클론) |
|---|---|---|
| 1 | 59/1 (소비EMA 픽스처 미성숙) | 60/0 |
| 2 | 59/1 (들은 소식 문장) | 54/6 (**워프 25회 수렴 실패**) |
| 3~4 | `마을이 시딩됐다 (0곳)` 로 중단 | **같은 `(0곳)` 중단** |

빨간 자리가 판마다 다르고 **베이스에서도 똑같이 무너진다** ⇒ 상자(장시간 하네스 연속 실행) 것이다.
그리고 `e2e-events` 는 `__notices`(글자)와 `#boardPane` 을 읽지 **`#notice` 의 자리를 안 읽는다** —
내 diff 는 `style.css` 와 내 하네스 둘뿐이라 닿을 길이 없다.

★**공통 §2 ⑦ 새 줄(2026-09-05 · T110 실측 "UI 층 화소는 `getImageData` 로")과의 관계**:
⑭ 는 **화소를 안 잰다** — `#notice` 는 캔버스가 아니라 DOM 이고, ⑭ 가 보는 것은
`getBoundingClientRect` 의 **교집합 넓이**다(합성 순서에 안 묶인다). 그래서 그 규약의 대상이 아니다.
대조 스크린샷은 재민 실기용이지 판정 근거가 아니다.

**접점** — `#notice` 자리를 읽는 하네스는 `e2e-ui ⑭`(신설) 하나다. DOM 을 읽는 `e2e-verbs ⑫` 는
글자·아이콘만 보고 좌표를 안 본다(67/0). `--list pixel` 은 해당 없음(`@pixel` 아님 · `getBoundingClientRect` 판정).
**적재 추적**: 이 카드는 `style.css` 만 만졌다 — 랩이 무는 파일과 교집합 **∅**(자명).

## 3. 회부

* ★**띠 안 가운데 vs 화면 가운데** — 위 표대로 좁은 화면·긴 알림에서 상태 줄과 만난다.
  토큰만으로는 못 푼다(상태 줄 폭을 CSS 가 모른다). 고치려면 ① 상태 줄 오른쪽을 재서
  CSS 변수로 넣는 JS 한 줄, 또는 ② 캔버스가 알림을 화면 중심으로 옮기고 상태 줄을 줄이는 것.
* 캔버스 슬롯 셋(67px) 갱신(PM) · 캔버스 판의 **금색 왼쪽 강조 막대**(실화면엔 없다 — 자리 카드 밖).
* 그대로: `data-action` 정리 · NPC 동사(설계) · 알림 이력 패널(캐논 판정).
