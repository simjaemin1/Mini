왜 거짓인가(말이 스스로 말하는 것과 그 판):
* **E1 · CAPW**(받을 양 ≤ 상한 · 절삭 0) — 상한(N)을 까닭으로 댄다. 그런데 받을 양 W 는 N 안이다. 참 까닭은 낼 것 한 개 값(E5)이거나 절삭(E6a)이다. 예: 마을0 익힌 음식 → 생선 1개 · 상한 15 — 끔 "마을이 생선 1개를 못 내준다 — 지금 내줄 수 있는 건 15까지다" → 켬 "익힌 음식 한 개 값이 마을이 내줄 수 있는 생선 전부(15)보다 비싸다 — 이 마을은 지금 그 값을 못 치른다".
* **E6**(한 개 넘침 · `maxGive` ≥ 1) — 낼 것 한 개가 이미 마을이 내줄 몫 전부보다 비싸다. 더 내면 더 비싸다. 예: 마을0 사냥 고기 → 곡식 · 상한 169 · `maxGive` 1.
* **E6**(절삭에 깎였다 · ③ 20 줄 · ④ 16 줄) — 더 내도 같은 절삭이 깎는다(가진 것 끝까지 실제로 더 내 본 실행이 서는 것 0). 예: 마을4 익힌 음식 → 생선 3개 · 상한 2 · `maxGive` 1.
* **E6 · E5**(⑤ 상한 1) — 한 개는 마을이 다 받는다(그 한 개로는 받을 것 한 개에 못 닿는다). 둘은 상한을 넘어 절삭이 하나로 깎는다. 그래서 어느 양으로도 안 선다(1 ~ 30 개 · 서는 것 0). 끔 낼 양 축은 `maxGive` ≥ 1 이면 E6(더 내도 안 된다), `maxGive` 0 이면 E5(한 개는 다 받는다)다. 끔 화면은 까닭이 없다 — 마을0 익힌 음식 1개 → 나무(상한 1)는 "익힌 음식 2.267857183172964 나무 0" 한 줄과 시세 줄뿐이다(켬 = 그 아래 "그 양으론 한 개도 못 바꾼다").
* **S5 n > 0**(더 내면 서는 판의 2 줄) — 마을0 익힌 음식 8개 → 나무: 화면 "마을이 내줄 수 있는 건 3까지 — 2개만 받는다" 인데 실행은 "… 더 내야 한다" 로 거절한다(그 2 개로는 나무 한 개에 못 닿는다).
* **받을 양 줄**(절삭돼 못 닿는 6 줄) — 마을0 익힌 음식 → 나무 3(상한 3): "나무 3 받으려면 — 내야 할 익힌 음식 3 (낱개라 올림 · 그러면 나무 2)". 그 3 개로는 3 에 못 닿는다(받는 2 — §5-1). 켬 = 낼 양 축 두 줄 "익힌 음식 3 나무 2" · "마을이 내줄 수 있는 건 3까지 — 3개만 받는다"(실행과 같다).

## §2 고침 — 손잡이 하나 · 말 함수 하나 · 말 글자만

```js
const T988_ON = !(typeof process !== 'undefined' && process.env && process.env.T988_TRADE_WORDS === '0');   // 켬 기본 · 되돌림 `=0`
function _moreWorks(econV2, v, giveRes, takeRes, n0, maxN, unitsAt, capU, takeN) {   // 낸 낱개 n0 보다 많이(maxN 까지) 내면 한 개라도 받나
  const free = (c) => { const u = unitsAt(c); return u > 0 && planSliced(econV2, v, giveRes, takeRes, u, capU).gave >= u - 1e-9; };   // 상한 절삭 안 걸림
  if (!(maxN > n0) || !free(n0 + 1)) return false;
  let lo = n0 + 1, hi = maxN;
  if (free(hi)) lo = hi;
  while (hi - lo > 1) { const mid = Math.floor((lo + hi) / 2); if (free(mid)) lo = mid; else hi = mid; }
  return takeN(planSliced(econV2, v, giveRes, takeRes, unitsAt(lo), capU).took) > 0;
}
function _whyNot(econV2, v, giveRes, takeRes, capShow, capU, u1, more) {
  if (capShow <= 0) return `마을에 ${Events.koRes(takeRes)}이(가) 남아 있지 않다`;
  if (u1 > 0 && planSliced(econV2, v, giveRes, takeRes, u1, capU).gave < u1 - 1e-9) {
    return `${Events.koRes(giveRes)} 한 개 값이 마을이 내줄 수 있는 `
      + `${Events.koRes(takeRes)} 전부(${capShow})보다 비싸다 — 이 마을은 지금 그 값을 못 치른다`;
  }
  return more ? '그 양으론 한 개도 못 바꾼다 — 더 내야 한다' : '그 양으론 한 개도 못 바꾼다';
}
```

## §5 회부(판정 0 — PM 이 볼 것)

1. **상한의 마지막 한 개는 못 산다(값 · 이 카드 밖)** — 상한 절삭은 낼 양을 `maxGive = ⌊T⌋`(T = 마을이 내줄 몫 전부를 사는 낼 단위) 아래 낱개로 깎는다(`⌊maxGive ÷ 평균 단위⌋`). 그래서 무게가 고르면 절삭된 주문은 늘 T 보다 덜 내고 받는 몫이 상한에 못 닿는다.
   * 섞인 무게 짐(③ 판)에서도 상한에 닿아 절삭된 낼 양 거래 146 줄이 다 상한보다 덜 받는다(1 ~ 67 덜 · 큰 차는 아래 2 의 짝).

   * 받을 양이 절삭돼 못 닿는 6 줄(받을 양 3 = 상한 3 인데 받는 2)도 이것이다.
   * 말은 이제 참이다. 거래가 안 서는 판 자체는 절삭 자의 일이라 안 고쳤다.
2. **견적 상계가 참 경계에 못 닿는 짝(값 · 이 카드 밖)** — 상한 이분 탐색의 첫 상계(`⌈cap ÷ ratio⌉ × 4`)가 참 경계 T 보다 작으면 `maxGive` 가 작게 끝난다. 같은 세계에서 익힌 음식 → 곡식 넷이 그렇다(`maxGive` vs T: 마을0 356 vs 602 · 마을1 2,416 vs 3,876 · 마을3 964 vs 1,794 · 마을4 312 vs 628 · 계측 JSON `referral`). 그 짝은 상한에 안 닿는 양도 절삭이 깎는다.
