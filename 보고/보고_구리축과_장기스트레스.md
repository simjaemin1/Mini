## 1. ★먼저 — **배치 6 이 쓴 지표 하나가 틀려 있었다**

배치 7 을 시작하며 1,600일 결과의 "산골 1인당 부 18.1 → 73.8(4배)"를 보고 분해했다.

```js
  // 배치 6 ab-summary.js
  const FE = (obj) => { try { return econ.totalFoodEquivalent(obj || {}); } catch (e) { return 0; } };
  const w  = FE(v.storage) + FE(v.treasury) + (v.treasury._cash || 0);
```

`totalFoodEquivalent` 은 **마을**을 받아 `v.storage.food` 를 읽는다. 거기에 **곳간을 마을인 척**
넘겼으니 안에서 `undefined.food` 로 던졌고, `try/catch` 가 그 예외를 삼켜 **항상 0**을 냈다.
즉 저 지표는 곳간도 국고도 못 보고 **`_cash` 하나만** 세고 있었다.

그리고 `_cash` 는 엔진에서 **쓰기 전용**이다 — 증가하는 곳 2군데(`v2:995`, `v2:1052`, 둘 다 교역세),
**읽는 곳 0군데**. 클라 표시와 이 지표만 읽는다. ⇒ 배치 6 의 "산골 1인당 부"는 부가 아니라
**누적 교역세**였다. 1,600일에 4배가 된 것도 마을이 부유해진 게 아니라 세금이 계속 쌓인 것이다.

`BASE_VALUE`(식량 1.0 을 앵커로 한 노동가치 표)로 전 재화를 환산하고, 현금은 **따로** 찍는다.

배치 6 은 저 두 칸을 **+18% · +41%** 라고 적었다. 실제 재화 기준으론 **+4.4% · +2.3%** 다.
방향은 같지만 크기가 4~18배 부풀어 있었다. **결론 (가) 유지는 오히려 더 분명해진다** —

> 이 프로젝트의 하네스 실패 유형 목록에 한 줄이 는다: **"try/catch 가 형(型) 오류를 삼켜
> 항상 0을 반환하고, 그 0이 다른 항에 가려 지표가 통째로 다른 것을 측정한다."**
> `catch` 로 0을 내는 계측 함수는 **인자 모양을 assert 로 걸어야 한다.**

### 2.2 `VEINSLOT` — 하한을 지키는 광맥 슬롯 → **기각**

`VEINSLOT=N` = 하한 통과 후보 중 광맥 점수 상위 N곳을 type 다양성보다 먼저 예약.
★`VEINSLOT=1` 은 **집합이 비트 동일**하다(최고 광맥 광산4 는 이미 mining 다양성 슬롯으로 들어온다).
지도를 실제로 바꾸는 최소값이 2 라서 A/B 는 2 로 쟀다.

```
  VEINSLOT=0 : … 임업2 광산4 … (19곳)
  VEINSLOT=2 : 광산4* 광산5* … **임업2 탈락** (19곳)
```

| | 인구 | 도구 | 무기Q | 산골부 | 돌수출 |
|---|---|---|---|---|---|
| f0base | **3,424** | 5,217 | **616** | 397.1 | 5,640 |

소멸 0 · 좀비 0 은 유지되지만 **모든 판정 지표가 무너진다.** 이유는 교환의 내용이다 —
광산5(식량 2.55·땅 3.82)를 넣느라 **임업2(땅 6.70, 목재 사슬의 축)**가 빠진다. 그리고
얻은 구리는 0.195, 잃은 구리는 0.225 — **구리조차 순감**이다. 배치 3 의 교훈이 그대로 재현됐다:
**자리는 공짜가 아니고, 광산은 좋은 자리를 이길 만큼의 값을 아직 못 낸다.**

★그리고 아이러니가 하나 있다 — **광산6 은 살아남았지만 주조하지 않는다.**


즉 부얼타운이 만든 것은 "구리 산지의 주조"가 아니라 **세계 구리 공급 증가로 인한 남의 마을 주조**다.

**판정: 기각** — 배치 규칙("어떤 변경도 기준선 2줄을 깨고 채택될 수 없다. 무기Q·산골 부 포함")에

## 3. ①-2 구리 파생 투입수요 — **게이트를 두 번 뒤집었다**

회부 ② (가)안: "구리 target 에 '이 구리로 만들 무기의 한계가치 − 다른 재료비'를 더한다."
설계는 명확한데, **무엇을 '만들 능력'으로 볼 것인가**에서 두 번 틀렸다.

**1차 — 무기 커버리지 게이트.** v2 `CAP_TARGET.weapon`(=max(2, 전사×1.2)) 미달일 때만 양수.
→ 3시드 800일이 **기준선과 비트 동일**. 한 번도 안 걸린 것이다.
이유: 마을은 무기가 **모자라지 않는다**(19마을 2,017자루). 모자란 건 **좋은** 무기다.
커버리지는 마제석검과 청동검을 **같은 1자루**로 센다 — 그 잣대로는 구리의 한계가치가 안 보인다.

**2차 — 순동 품질 게이트.** "순동검이 지금 무기보다 나은가"로 바꿨더니 **영원히 거짓**이었다:

```
  순동 등급 alloyGrade({copper:1},'weapon') = 0.4661
  마제석검 등급 WEAP_Q_STONE                = 0.5
```

**모델이 옳다.** 순동은 무르고, 잘 벼린 간돌검이 더 낫다(고증도 이쪽이다 — 순동기는 단조 위주).
⇒ **첫 구리 한 덩이는 정말로 살 값어치가 없다.** 구리가 값을 하는 건 **합칠 것이 있을 때**다.

**3차(채택 형태) — 최선 배합 게이트.** 판정을 "순동"이 아니라
**이 마을이 지금 가진 다른 금속으로 짤 수 있는 최선의 배합**으로 한다.
탐색은 주조 결정과 **같은 목적함수**를 쓴다 — 그러려고 `_alloyMelt` 의 탐색부를
공용 헬퍼 `_meltSearch(st, price)` 로 뽑았다(사본 금지). 가격만 **기준가**로 준다
(시장가를 쓰면 수요가 값을 올리고 그 값이 게이트를 닫는 자기 꼬리 물기가 생긴다 — `smeltTarget` 의 그 실측).

게이트 3중:
1. **무기 노동이 실재**하는 마을만(석공 또는 대장장이 ≥1) — 구리가 없어도 참이라 순환 없음
2. **품질이 나아져야** 한다(최선 배합 등급 × `WEAP_Q_BRONZE` > 마을 `_weapQ`)
3. **채산이 맞아야** 한다(산출가 − 재료비 > 0, 기준가 판정)

`test-valuechain` ⑧ 이 이 개폐를 직접 검사한다(A/B 가 "무효과"로만 보고하는 사문을 막는 자):

```
  ✔ 주석은 있는데 구리가 없는 마을 → 파생수요 3.690 (부트스트랩 고리가 열린다)
  ✔ 합칠 것이 없으면 0 — 순동(0.466)은 마제석검(0.5)보다 나쁘다
  ✔ 무기 노동 0인 마을은 0 — 유령 수요 아님
  ✔ 구리 외 재화에는 안 붙는다
```

| f1base | **3,424** | 5,217 | **616** | 3.33 | 101 | **1.107** | 318 |
| COPPER_DERIV=1 | 3,297 (−3.7%) | 4,219 (−19%) | 524 (−15%) | **4.00 (+20%)** | **239 (+137%)** | **0.987** | 351 |

**장치는 의도대로 작동한다** — 부트스트랩 고리가 열려 주조 마을이 늘고(3.33 → 4.00),
청동 무기 생산이 **2.4배**가 된다. 회부 ②가 예측한 그림 그대로다.

**그런데 배치 지시가 정한 기각 조건에 정확히 걸린다**: *"합금 등급 평균이 1.0 밑으로 내려가면
기각(배치 4 채택분 보호)."* → **1.107 → 0.987.** 표준 청동(1.0) 아래다.

기제도 회부가 경고한 그대로다. 구리가 퍼지면 더 많은 마을이 주조하고, **주석은 그만큼 안 늘어난다**
(주석 재고 318 → 351 은 +10% 인데 주조 마을은 +20%). 얇게 편 배합이 등급을 끌어내리고,
품질보정 무기는 616 → 524 로 **−15%** — 수량이 늘어도 **석검 환산으로는 준다**.

**판정: 기각.** 다만 이것도 "작동 안 함"이 아니라 **"청동을 흔하게 만드는 대신 무르게 만든다"**는
교환이다. 회부 ②의 경고문("⚠②를 채택하면 청동이 흔해진다 … '청동 = 소수 엘리트 표지' 설계와
정면으로 충돌한다. 그래서 이건 값의 문제가 아니라 **세계관 선택**이다")이 실측으로 확인된 셈이다.
손잡이는 기본 OFF 로 남긴다 — **주석 공급을 함께 늘리는 설계**와 짝지으면 다시 잴 값이 있다(미해결 ⑬-c).

## 4. ② 노 조업 페이싱 — **상수는 옳았다. 지도에 철이 없다.**

`scripts/pace-metallurgy.js` 신설 — 벽시계를 왜곡하지 않고 사슬 한 바퀴를 돈다.
(채광의 1초/타는 **순수 대기**라 60타를 실제로 기다려 등가를 실증한 뒤 타수로 환산한다.
그 등가 자체를 assert 로 걸어 우회가 거짓말이 되지 않게 했다.)

★사슬은 **둘**이다. 한 줄로 뭉치면 "노가 사슬의 몇 %"라는 숫자가 거짓말이 된다:

| 사슬 | 단계 | 실시간 |
|---|---|---|
| **청동**(도달 가능) | 채광(구리 3개분) | **911초** (911타) |
| | 선광 | 0.0초 |
| | 단조 | 0.0초 |
| **철**(입력 없음) | 숯가마 1회분(장입→수거) | **240초** |
| | 노 1장입(장입→출탕) | **150초** |

* 청동 사슬 1자루 = **15.2분**(다른 실행에선 10.1분 — 광맥 RNG 로 10~15분 범위). **100%가 채광**이고 **노를 안 탄다.**
* 철 사슬 1장입 왕복 = **6.5분**(숯가마 4.0 + 노 2.5).
* '가득 채우기' — 통나무 40 → 13회분을 한 번에 600초(회분당 46초 — 1회분 240초보다 싸다). 배치가 이득이다.

**판정 결과**

| 기준 | 결과 |
|---|---|
| 전 사슬 ≤ 15분 | 청동 15.2분 — **경계선**(10~15분 범위) |
| 전 사슬 ≥ 3분 | ✓ |
| 숯가마 대기 ≥ 채광 한 덩이(60초) | ✓ 240초 — **다녀올 일이 된다** |
| 노 대기 ≥ 채광 한 덩이(60초) | ✓ 150초 — **다녀올 일이 된다** |
| 숯가마+노 대기 합 ≤ 15분 | ✓ 6.5분 |

⇒ **노·숯가마 상수(180/240초)는 바꾸지 않는다.** 대기는 둘 다 채광 한 덩이보다 길어
"자리를 지키는 벌"이 아니라 리듬이 되고, 합쳐도 6.5분으로 상한 안이다.
청동 사슬이 15분에 닿는 건 **채광**(1초/타·덩이당 60타) 때문인데, 그건 재민이
**"채굴 속도는 고정이다 — 1초/타 · 덩이당 60타 · 전부 레벨 무관"**으로 확정한 값이라 손대지 않는다.

### 그런데 계측이 다른 걸 잡았다 — **노에 넣을 것이 이 세계에 없다**

```
  광맥 787개 (주요 63 · 자잘 724)
  전 광맥의 광종 합집합 = { lead, silver, copper, gold }
  철이 든 광맥 = 0개
```

`tryFurnaceSmelt` 의 유일한 입력은 철 정광이고, 정광은 광맥 조성에 철이 있어야 나온다.
**채광으로는 어떤 경로로도 얻을 수 없다.** 구리 광맥·납 광맥 각 400타 실측에서도 철은 0.

같은 노를 시대만 바꾸면 이렇다:

| 시대·노 | 수율 | 철 1덩이까지 | 실시간 |
|---|---|---|---|
| 청동기 도가니로 | 3.4% | 30장입 | 75분 |
| 철기 도가니로 | 67.8% | **2장입** | 5.0분 |
| 철기 괴련로 | 88.1% | 2장입 | 더 짧다 |

즉 **시대만 열리면 사슬은 성립한다**(2장입 = 5분). 막는 것은 오직 **입력의 부재**다.
지도에 철을 넣는 것은 인계 §5 의 **구현 금지 항목**이라 → **`회부_노의_입력이_지도에_없다.md`**.

* 400일의 좀비 0.33 은 한 시드에서 신생촌 한 곳이 아직 10명 미만이라는 뜻이고, 800일엔 사라진다(성장 중).

**⇒ 800일에서 실증된 소멸 0 은 1,600일에서도 유지된다. 시간 외삽으로 드러난 결함은 없다.**
