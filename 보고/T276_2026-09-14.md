## §0-ⓑ 판정 + 근거

### ⓑ-1 `npcsprite ②′ 깜빡임` = **ⓐ 자 결함** — 닫았다

**이 존은 하루가 0.5초다**(`VILLAGE_DAY_MS: '500'`). ②′ 의 창은 4초다 ⇒ 그 사이 **게임일이 여덟 번** 간다.
옷은 T125 규약대로 **마을 곳간이 정한다**. 여드레 동안 곳간이 움직이면 옷이 바뀌는 것은 **옳은 동작**이다.
②′ 가 막으려던 것은 *"자리 해시로 고르면 걸을 때마다 옷이 바뀐다"* 이지 곳간의 변화가 아니다(그 절의 주석 그대로).
⇒ **자가 제 창 안에서 세계가 변하도록 두고 그 변화를 결함으로 읽었다.**

닫기: 재는 동안 **날을 얼린다**. 손잡이는 이미 있다(`__e2e_day_freeze` · `E2E_GIVE` 게이트 · **새 손잡이 0**).
정해진 초를 안 자고 **"게임일 정지" 통지를 세계에서 듣고** 창을 연다(T214 문법).
창의 시작점(`before`)도 **언 뒤**에 다시 뜬다 — 폴링이 길어지면 그 사이가 또 새기 때문이다.
자명 통과 금지: 한 사람의 옷 층을 바꿔 끼우면 같은 셈이 **한 명으로 센다**.

### ⓑ-3 `charsprite ⑤` = **ⓐ 자 결함** — 닫았다 (두 겹이었다)

**겹 1 — 첫 항목을 집었다.** 판정이 `Object.values(__charDbg).filter(v => !v.isMe)[0]` 였다.
`__charDbg` 는 **안 지운다**(그 파일 §⑦ 주석이 명시한다 — 시야에서 사라져도 옛 항목이 남는다).
실측이 그대로 말한다: **빨간 판(단독5)은 남이 2명이던 판**이고, 초록 판(단독1)은 1명이었다.

**겹 2 — B 를 시야 밖으로 걷게 해 놓고 멈춘 훅을 읽었다.** 겹 1 을 고치고 다시 재니 여전히 빨갰고,
그때 남긴 상황줄이 원인을 그대로 찍었다:

```
[상황] B 자기=idle · A 가 본 B=idle/0 · A 훅 시각 Δ=0ms · A↔B 290px
```

* `A↔B **290px**` — 5초를 내리 걸리면 B 는 47px 에서 290px 까지 간다.
* 80px 밖은 `coneMultEntity` 의 **시야 뿔**이 걸려 A 가 B 를 **안 그린다**(이 게임의 규약 ·
  그 절의 배치 주석이 이미 적어 둔 것 — *"뒤에 선 사람이 안 보이는 건 이 게임의 규약이다"*).
* 안 그리면 `__charDbg[B]` 는 **옛 값에 멈춘다** — `훅 시각 Δ=0ms` 가 그 증인이다.
* 그 멈춘 `idle` 을 자가 *"애니가 안 온다"* 로 읽었다. **제품은 규약대로 굴었다.**

닫기 셋:
1. **B 의 pid 로 고른다** — B 자기 화면에서 받는다. ⚠`find` 로 집으면 **또 첫 항목**이다:
   재접속 전 pid 가 `isMe` 로 남아 실측에서 `A 화면의 남: 1명(p4) — 이 중 B 는 p3` 가 나왔다.
   ⇒ **훅 시각 `t` 가 가장 큰 `isMe`**(지금 그리고 있는 것)를 고른다.
2. **반경 안에서 잰다** — 한 묶음 1.6초(≈50px)만 걷게 하고, 70px 를 넘기 전에 멈춰 자리를 되돌린 뒤
   다시 걷는다(최대 6묶음). 재는 것은 **걷기**지 텔레포트가 아니다 — 텔레포트는 자리만 되돌린다.
3. **멈춘 값은 안 받는다** — 판정은 `훅 시각 > 시작 시각` 인 값으로만 한다(§⑦ 의 문법 그대로).

자명 통과 금지: `idle` 인 **가짜 남**을 `__charDbg` 에 끼워 넣어도 셈이 B 를 읽는다
(미끼가 실제로 `idle` 로 읽히는 것까지 같이 센다 — 안 그러면 위 초록이 아무것도 안 증명한다).

### ⓑ-4 (새로 잡은 것) `charsprite` **시트 래치** = **ⓒ 기계 + ⓑ 제품 무재시도** — 표만·회부

10판 중 **7판**이 여기서 죽었다. 카드 겨냥 밖이지만 이 하네스의 실제 상시 흔들림은 이쪽이다.

| 잰 것 | 값 |
|---|---|
| 클라가 본 것 | `why=sheet:body_idle` · 90초 내내 · `char_meta.json` 은 **정상**(⓪ 초록) |
| 하네스 그물(이 카드가 새로 심은 상황줄) | 래치 판에서도 **193/193 이 `200` + 몸까지 `끝`** — `body_idle.png` 포함 |
| 서버 직접 계측 | 193장 세 바퀴 = **193/193 200 · fail 0 · 428/169/166ms** |
| 한가한 상자 · central 만 · 192장 한꺼번에 | **192/192 onload · onerror 0 · 2.0~3.0초 · `body_idle` 1.25~1.72초** |
| 정상 판의 대기 | **20~167ms** (고친 판 3판: 31·167·20ms) |

⇒ **그물은 다 왔는데 `onload` 가 안 온 판이 있다.** 서버는 면책된다(위 둘째·셋째 줄).
그리고 제품은 그 한 번을 **영영 안 고친다**:

```js
// public/client/42-r2-char.js
function charSheet(key) {
  let e = _charImg.get(key);
  if (e) return e.ok ? e.img : null;      // ← 실패도 캐시에 남아 영영 null
  const img = new Image(); e = { img, ok: false }; _charImg.set(key, e);
  img.onload = () => { e.ok = true; }; img.onerror = () => { e.ok = false; };
  img.src = '/assets/char/' + key + '.png'; return null;
}
```

`charMeta()` 도 `_charMetaTried` 로 같은 래치를 건다. 시트는 키마다 **`Image` 딱 한 번** —
재시도도, 시간 제한도 없다. 그리고 메타가 오면 **192장을 한 microtask 에서 한꺼번에** 청한다.

**판정: 방아쇠는 기계(ⓒ) · 영구화는 제품(ⓑ).** 카드 규약대로 **제품은 안 만졌다** — 표와 회부만.
**증인 하나 더 — 죽은 것은 그 `Image` 한 장이다.** 래치가 걸린 **바로 그 쪽에서** 같은 파일을
새 `Image` 로 한 장 더 청해 봤다(하네스 상황줄 · 제품 무접촉). 네 판 전부:

```
[상황] 스프라이트가 그려질 때까지 90,024ms 기다렸다 — 끝내 안 왔다(why=sheet:body_idle)
[상황] 다시 청하기: body_idle 새로 청하니 64ms 만에 왔다(436px)   ← 37 · 64 · 65 · 69ms
```

⇒ 그 순간 그물도 서버도 디코더도 **멀쩡하다**. 죽은 것은 **클라가 캐시에 남긴 그 한 장**이고,
`charSheet` 는 그 한 장을 **다시 만들지 않는다**. 방아쇠가 무엇이었든 **영구화는 제품이다**.

※ 못 가른 것: 그 한 장에서 `onerror` 가 울었는지 `onload` 가 끝내 안 왔는지는 **못 쟀다**
(클라 훅 없이는 밖에서 안 보인다 · 훅은 제품이라 이 카드가 못 단다). 회부에 그대로 적는다.
※ 재현률은 **상자 상태를 탄다** — 같은 코드로 03:10~03:44 단독 5판은 래치 0회였고,
04:10~04:30 단독 5판은 4회였다(2코어 · load avg 2.9~3.4). 그래서 ⓒ 로 센다.
