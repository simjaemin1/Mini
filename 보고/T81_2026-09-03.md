게임 행동 변경 0(그리는 층 선택과 필드 하나). 러너 전수는 안 돌렸다(공통 §2 ②).

## 0. §0 실측

### ⓐ CLOTH 기하가 여섯 옷을 감당하나 — **감당한다. 단, 갖옷만 실루엣이 필요했다**

화소 예산부터 쟀다: 옷 층은 한 프레임에 **21×29px · 불투명 363화소**다(카드의 "26px 행"이 그것).
잣대는 눈대중이 아니라 이 시트가 이미 인정한 수에서 왔다(족보 74) — **T65 가 앞뒤를 가르려고
채택한 앞섶 신호 평균 휘도차 +14.73**. ⇒ *두 옷은 |Δ휘도| ≥ 14.7 이거나 화소의 절반 이상이
눈에 띄게 다른 색이어야 한다*(휘도가 같아도 색이 다르면 갈린다 — 풀옷↔삼베가 그 경우다).

**1차(아이콘 값 그대로 + 실루엣 동일) — 세 쌍이 못 갈렸다:**

| 쌍 | \|Δ휘도\| | 다른 화소 | 판정 |
|---|---|---|---|
| 생가죽옷 ↔ 풀옷 | 9.1 | **4.4%** | ✗ 사실상 같은 옷 |
| 갖옷 ↔ 가죽옷 | 10.2 | 6.3% | ✗ |
| 모시옷 ↔ 삼베옷 | 9.2 | 37.5% | ✗ |

**처방 둘 — 그리고 하나씩 따로 쟀다(귀속을 흐리지 않으려고):**

```
  ① 갖옷에 털 두께     FUR_PAD = 0.03m(반지름에 가산)
     → 실루엣 21x29(363px) → **24x32(437px)** · 갖옷↔가죽옷 |Δ휘도| 10.2 → **16.3** ✓
     (색이 아니라 모양이라 빛·색맹·압축에 안 무너진다)
  ② 색 둘을 밀어냈다   ramie (0.795,0.775,0.700) → (0.885,0.875,0.835)
                       fiber (0.620,0.580,0.280) → (0.720,0.665,0.315)
     → 모시↔삼베 9.2 → 16.2 ✓ · 생가죽↔풀옷 9.1/4.4% → 16.0/80.2% ✓
```

**최종: 15쌍 전부 통과**(못 갈린 쌍 0). 색 출처는 아이콘 정본이다 —
`hide`·`leather` ← `icon_render.py` 의 같은 이름 재질, `fiber` ← `drygrass`(줄무늬라 아이콘 평균이 더 어둡다),
`fur`·`ramie` 는 아이콘에 원본이 없어 근거를 주석에 적었다. ⚠T77 이 만드는 공용 모듈은 **무접촉**(값만 베낌 · 회부).

### ⓑ 네트워크 필드 — `tick` 이 나르고, 문법은 `act` 와 같다

| 축 | 지금 남에게 가는가 |
|---|---|
| 이름·색·최대HP·부족·`simJob`·`npc` | 간다 — **최초 가시분만**(`isNew`) |
| 행동 라벨 `act` | 간다 — 최초 가시 + **바뀐 뒤 1.2초 창**(무상태 델타) |
| 전투 메타 `br/bt/bs/bc` · 포로 `cap` | 간다 |
| **옷** | ~~안 갔다~~ → **T81 이 태웠다**(`act` 와 같은 문법) |
| **도구** | 여전히 안 간다 — 이 카드가 닫는 축은 옷 하나다(회부) |

접점은 넷이다(서버 둘 · 클라 둘 — 카드가 센 "1줄+1줄"보다 하나 더였다):

```
  server/zone.js  sendEquipment : player._clothesAt = Date.now()            ← 창을 여는 유일한 자리
  server/zone.js  makeEntry     : if (isNew || now-_clothesAt < 1200) e.clothes = inst.mat
  public/client/30-n-net.js     : clothes: pp.clothes !== undefined ? … : prev?.clothes
  public/client/34-m-renderloop : renderables.push({ … act: o.act, clothes: o.clothes })
```

⚠**넷째 줄이 함정이다.** `renderables.push` 는 필드를 하나씩 **옮겨 적는** 자리라, `others` 에 값이
있어도 여기 없으면 화면까지 안 간다. T81 이 실제로 한 번 빠뜨렸고 하네스가 잡았다.

### ⓒ 굽는 시간 · 부분 굽기 — **이미 있었다**(족보 88)

카드는 *"`ITEMS_ONLY` 같은 부분 굽기가 있나 · 없으면 하나 만든다"* 라고 했는데
**T13 이 이미 `--layer=` 를 만들어 뒀다.** T81 이 더한 것은 둘: `--sheetdir=`(후보를 정본 밖에 굽는다)와
**실루엣 합집합을 '한 벌' 기준으로** 고친 것 — 옷이 여섯이 되면 종전 전체 합집합은 갖옷 소매를
삼베 테두리 판정에 섞는다. 옷만 굽는 판에서도 **몸을 같이 굽되 저장하지 않는다**(안 그러면 목·소매·단에 없는 선).

```
  옷 다섯 × 클립 다섯(+몸 마스크)  25장  약 40분   ← 이번에 실제로 구운 것
  후보 계측(idle × 옷 여섯)         6장  3분 35초
  한 층 한 클립(+몸 마스크)         1장  1분 28초
```

**결정론 — 셋을 실측했다**(T77 이 아이콘에서 세운 세 질문의 char 판):

## 3. 하네스가 두 번 속았다 — 기록해 둔다

`window.__charDbg[pid]` 는 **지우지 않는다**(시야에서 사라져도 옛 항목이 남는다). 그래서
"둘째 클라의 훅에 첫째가 있다"는 *지금 그리고 있다*는 뜻이 아니다.

1. 층 목록이 **있으면** 빠져나오는 폴링 → 낡은 값을 집었다.
2. 값을 **기다리게** 고쳤더니 12초를 기다려도 옛 값 → 값이 안 온 게 아니라 **B 가 A 를 안 그리고 있었다**
   (그 사이 ⓓ 가 A 를 8방향으로 걸려 놨다).

⇒ **선을 직접 떴다**(Playwright `framereceived`): B 가 받은 tick 원문에 `clothes:"fur"` 가 실려 있었다.
**제품은 멀쩡했고 하네스가 틀렸다.** 이제 ⓘ 는 ⓐ B 를 A 옆으로 데려오고 ⓑ **훅의 시각이 나아가는지**로
'지금 그린다'를 증명한 뒤에 판정한다(상황부터 잰다).
