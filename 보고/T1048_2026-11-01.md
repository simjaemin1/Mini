## §2 고침 — 다음 배포가 다시 못 빼게

* `scripts/redeploy-light.sh:66-75`: 재생성 직전에 옛 컨테이너(같은 이름)의 `ZONE_HOST_[A-Z0-9_]+=` 줄을 읽어 `-e` 로 다시 싣는다.
  * `EXTRA_ENV` 에 같은 이름이 있으면 `EXTRA_ENV` 가 이긴다(한 번만 실린다).
  * 옛 컨테이너가 없거나 그 줄이 없으면 종전과 한 글자도 같다(`test-redeploy-light` ⓐ 바이트 대조 11/0 그대로).
  * 화면엔 `[이어 싣기] durango-zone-<id> ← 옛 컨테이너 ZONE_HOST_NIPPON(값은 안 찍는다)` 한 줄(이름만).
  * 이어 싣는 것은 `ZONE_HOST_*` 뿐이다. 나머지 옛 env(`CHAR_SPRITE` 등)는 종전처럼 안 싣는다. 비밀은 종전 손잡이(셸 env → 이름만) 그대로다.
* 왜 "있어야 한다(필수)"로 막지 않았나: 한 호스트 판(리허설 · 로컬 · 26존)에는 키가 없어도 맞다. 무엇이 필수인지는 호스트 배치가 정하고, 그건 스크립트가 모른다. 그래서 스크립트는 **잃지 않게만** 하고, 필수 판정은 두 호스트를 다 보는 `update-live` 끝 줄(§3)에 맡겼다.
* `update-live.sh` ⑤ 화면 거르기에 `[이어 싣기]` 를 더했다. 도쿄 닛폰이 옛 `ZONE_HOST_*` 를 이어 실으면 보인다.
* 하지 않은 것: `redeploy-zones.sh` · `redeploy-hanbando-5.sh` 는 손대지 않았다. 둘 다 한 호스트 26존 판이라 라이브(두 호스트)에서 치면 서울에 닛폰을 하나 더 띄운다 — 빼는 키보다 큰 문제다(§6 회부 ②).

## §3 확인 줄 — `update-live.sh` 끝 `[⑧] 경계`(읽기만)

* `update-live.sh:69-99` `xhost_check`: 도쿄 존 이름 = 도쿄 `docker ps -a` 의 `durango-zone-*`(없으면 `nippon`). 서울 셸 하나에서 존마다 둘을 본다.
  1. 한반도 컨테이너 env 에 `ZONE_HOST_<ID>` 가 있나(`grep -c` — 값 0).
  2. `docker exec durango-zone-hanbando node -e …` — **존 컨테이너 안에서** 존 정본 `server/zone-config.js` 에게 그 존 주소를 묻고(`hostFromEnv` 사본 0 · 존 프로세스와 같은 망 길), `GET :<포트>/health` 를 5초 시한으로 친다(쓰기 0 · 비밀 0).
  * 주소 값은 안 찍는다. 맥 `ssh -G tokyo` 의 주소와 **같은가만** 찍는다(`주소 = 도쿄 ssh 주소` / `≠`).
* 줄 글자(하네스가 이 꼴을 읽는다):
  ```text
  [⑧] 경계 — 서울 한반도 → 도쿄 존(env 키 있음 · 존 안에서 /health 닿음)
      ✓ 경계 서울 한반도 → nippon: env ZONE_HOST_NIPPON 있음 · 주소 = 도쿄 ssh 주소 · :3021/health 200 · 27ms
      ✗ 경계 서울 한반도 → nippon: env ZONE_HOST_NIPPON 없음 · 주소 ≠ 도쿄 ssh 주소 · :3021 ECONNREFUSED · 17ms
  ```
* 판정: 키 있음 **그리고** `/health` 200 일 때만 ✓다. 키 없이 `ZONE_HOSTS` 로만 닿아도 ✗다 — 26존 표를 새로 짓는 재배포 한 번이면 서울로 돌아가기 때문이다.
  * ✗ 면 `stop` → `✗ 멈췄다 — 경계 ✗(위 [⑧] 줄) …` · rc 1 · "안 한 것: 없음 — 갱신은 다 됐다 · 남은 것은 서울 한반도 env 키 · 도쿄 포트(보고/T1048 §5)".
  * 자리는 ⑦ live-lag 뒤 · `✓ 끝` 앞이다(갱신은 이미 끝났다 — 경계만 따로 말한다).
* `--dry` 에도 `[예행 ⑧]` 로 같은 줄을 찍는다(멈추지 않는다 · rc 0). ⚠`--dry` 는 서울이 **지금 가진** update-live.sh 를 돈다 — 이 커밋이 서울에 받아진 뒤의 판부터 ⑧ 이 있다(머리 ⚠ 그대로).
* `scripts/deploy-check.sh` 에는 넣지 않았다. 그 스크립트는 "바깥에서 · 컨테이너 무접촉"이 뜻이라 서울 → 도쿄 길과 서울 컨테이너 env 를 볼 수 없다.

1. **[재민 · 읽기]** §5 S1~S7 · T1 출력을 이 보고에 붙인다(PM 이 이미 준 다섯 줄과 겹치는 것은 그 출력으로 갈음).

## §7 한계

* 레포 글자로는 "누가 언제 쳤나"를 못 박는다. 1순위는 글자(T538 재민 손 줄 · 그 줄이 빼는 키)와 시각(T538 줄 06:40 → 한반도 재기동 ~07:09 · T564 §0)의 정황이다. 지문 줄(S3 · S6 · S7)이 가린다.
* 09-30 응급 재기동(`NODE_OPTIONS`)을 어떤 줄로 했는지는 레포에 없다.
* ⑧ 은 서울 한반도 → 도쿄 존 한 방향만 본다. 도쿄 닛폰 → 서울 한반도(`ZONE_HOSTS[hanbando]` = CENTRAL_IP — redeploy-light 기본이라 맞다)는 안 본다.
* `docker exec` 가 존 컨테이너 안에서 node 를 하나 더 띄운다(수십 MB · 1초 안팎). 라이브 이미지 `node:22-alpine` · WORKDIR `/app` 을 전제로 한다(`Dockerfile.zone`).
* 로컬 재현(카드 ②의 두 존 실클라 판)은 돌리지 않았다. 대신 Ⓡ 이 env → 주소 → 접속 오류 → 알림 글자까지를 존 정본 글자로 이었다. 실클라 알림 화면은 T564 `e2e-handoff-proto` 판(V2 · `까닭=주소`)이 있다.
* 하네스는 127.0.0.2~4:3021 을 쓴다. 상자에서 3021 을 다른 판이 쥐고 있으면 `[판]` 줄이 ✗ 로 말한다(건너뛰지 않는다).
