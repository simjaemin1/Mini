| 지형 단위 | 정의 | 한반도 면적 비 |
|---|---|---|


### ★`pack-mountain.py` 의 지뢰 — **T129 가 자연물에서 밟은 그것과 같은 것**

이 스크립트는 `SRC` 에 있는 것만 담아 `mountain_anchors.json` 과 `mountain_alpha.json` 을
**통째로 다시 쓴다.** 몇 장만 새로 구워 팩하면 나머지 배포 키가 조용히 사라진다.
전수를 다시 굽는 날엔 안 터지므로 **더 위험하다.** 재현하고 고쳤다:

```
① MT_BASE 없이(옛 동작) : 한 장 팩  →  앵커 1키      ← 배포 45가 날아갔다
② MT_BASE 로 합치기     : 한 장 팩  →  앵커 46키 · 종전 45키 중 값이 바뀐 것 0
```

⇒ 손대지 않은 키는 값을 **다시 만들지 않고 그대로 둔다** — 그래야 바이트가 안 움직인다.
그리고 `test-icons ⑧` 에 **파일 ↔ 잠금표 ↔ 앵커 ↔ 알파** 네 표 대조를 걸었다(아래 §3 자가시험).

## 3. ★★뒤늦은 실측 — **라이브 산은 스프라이트가 아니다**

ⓕ 를 화소로 재려는데 이름이 441/559 장 바뀌었는데도 **화면 전체 |Δ| 0.01** 이었다.
상자를 넓혀도, 다시 칠해도 그대로였다. 창이나 문턱 문제가 아니었다 — **재는 판이 틀렸다**:

```
__mtDbg → {"mt3d": true, "mt3chunks": 30, "mt3bakeMs": 14381.7, "segs": 144, "sprites": "88/88"}
```

`11-r1-mountain.js:917` — *"[재민 2026-08-09 "이대로 본게임 ㄱ"] 기본은 3D.
손잡이 `mt3dOff` 로 스프라이트 복귀."* 그리고 `10-r1-terrain.js:1710 _mt3Field` 는
**바위 마스크 + 잡음**으로 높이장을 짓는다(`MT3_LAM` 경사 길이 · `MT3_HMAX` 마루 높이 · 값잡음).
**종(種) 개념이 한 글자도 없다.**

⇒ **카드의 전제가 한 달 낡았다.** 재민 2026-08-07 *"둥근 버전도 … 한반도는 둥근 거 위주로"* 는
스프라이트로 산을 그리던 때의 말이고, **이틀 뒤 2026-08-09 "이대로 본게임 ㄱ"** 로 산은
높이장 3D 메시가 그리게 됐다. `_mtPick`(=`ROUND_MIX` 가 사는 곳)은 그 뒤로 **폴백**이다.

**그래서 이 카드가 낸 것과 안 낸 것을 갈라 적는다:**

| | 섰나 |
|---|---|
| `mt_R*` 40 · `mt_X*` 3 자산 · 앵커 · 잠금표 | ✅ 섰다(결정론·바이트 무변·규격 전수) |
| `ROUND_MIX` 손잡이 · 자리의 함수 · 되돌림 | ✅ 섰다 — **스프라이트 판에서** 화면 24.02% 가 바뀐다 |
| **라이브 화면(3D 메시)에서 산이 둥글어 보이나** | ❌ **아니다** — 3D 경로엔 종이 없다 |

★**억지로 잇지 않았다.** 3D 쪽 산 모양을 건드리면 **모든 산의 모든 화소**가 바뀐다 —
"기존 배치 무변"과 정면으로 부딪치고, 시안·재민 판정이 필요한 다른 카드다.

### ★§3-라 회부 — 3D 메시에 둥글기를 넣으려면 (다음 카드에 넘긴다)

3D 경로에도 **모양 손잡이가 이미 있다** — 없는 건 "자리마다 다르게"가 아니라 "둥글기라는 축"이다:

```
MT3_LAM   가장자리에서 마루까지의 경사 길이(셀) — **크면 완사면 = 둥근**
MT3_HMAX  마루 높이 — **낮으면 노년기 구릉**
MT3_LAMV · MT3_HV   그 둘의 자리별 변주 폭(이미 값잡음으로 흔들고 있다)
```

⇒ 다음 카드의 모양은 `mt_R*` 40장이 아니라 **`_mt3Field` 안에서 `lamL`·`hmaxL` 을
둥글기 비율로 미는 것**이다. 그때 §0-ⓒ 의 0.8(저위산지 31.0% : 저위산악지 7.1%)이
**그대로 쓰인다** — 이 카드가 남기는 건 그 수와 그 근거다.
그리고 그날 `mt_R*` 40장은 폴백 판의 그림으로 계속 산다(지금도 `mt3dOff` 로 볼 수 있다).
