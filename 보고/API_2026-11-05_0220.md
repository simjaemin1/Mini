## 무엇을 했나
* **서명 정본** `public/terrain-sig.js`: 서버는 `require` 하고 클라는 `<script>` 로 읽는 같은 파일이다(move-model 규약 · 사본 0). JSON 글자에 두 갈래 32비트 섞기를 걸고 글자 수를 붙인다. sha1 을 안 쓴 까닭: 브라우저 `crypto.subtle` 은 보안 문맥 전용이라 http(IP)로 접속하면 없다. 서명은 판이 갈렸나만 가리면 된다.
* **클라**
  * `99-main.js` 선로딩이 **setHardcoded 앞**에서 존마다 센다. 런타임 칸이 붙기 전, 받은 글자 그대로 센다는 뜻이다.
  * `30-n-net.js` 는 그 값을 `_t1163Hf` 에 두고 존 접속 주소에 `hf=<서명>` 으로 싣는다. 선로딩 전에 붙으면 칸이 없다(종전).
  * welcome 에 `hfHit` 가 오면 그 존을 적용 존으로 적고 승격용 서명 `_t1125Ht` 를 적는다.
  * `index.html` 에 script 한 줄을 더했다.
* **서버** `zone.js` `_t1163Skip(url)`
  * 켬이고 `hf` 가 이 존의 **파일 절 서명**과 같으면, 첫 접속 · 관측 welcome 이 `hardcodedTerrain` 자리에 `hfHit: 1` 하나를 싣는다. 칸 차례는 그대로다.
  * 파일 절 서명은 파일을 따로 읽은 사본에 `restoreBakeOff` 를 걸어 센다. `T574_REGION=0` 이면 서명이 달라져 종전대로 싣는다. 배포 어긋남(존 파일 ≠ central 파일)도 종전대로다.
  * 뺀 소켓은 `_t1125Mark` 로 지형을 가진 것으로 적힌다. 그래서 그 소켓의 승격 welcome 도 지형이 0 이다.
* ⓕ 같은 절인가: 종전 welcome 이 실은 지형과 파일 절을 견주면 다른 칸 46 은 **전부 런타임 칸**(`rivers.N._segIdx` 등)이다. 지금 welcome 은 서버 색인 캐시까지 실어 보내고 있었다.
