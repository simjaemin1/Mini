## §2 ② econ 캐러밴 — `T876_CAR_FAST`('1' 만 켬)

### 2-1. 원인 — `delete` 가 아니라 `Object.assign({}, c)` 였다

T862 회부 2 는 `delete o._t732Cargo` 를 짚었는데, 저장된 세계(420날 틀의 메타 행 · 캐러밴 40)를 그대로 떠서 한 단계씩 재 보니:

| 단계 | `%HasFastProperties` |
|---|---|
| JSON 에서 읽은 캐러밴 `c`(칸 24) | 빠른 꼴 |
| `o = Object.assign({}, c)` 직후 | **사전 모드**(40/40) |
| `o.from` · `o.to` 다시 넣기 · `delete o._t732Cargo` 뒤 | 사전 모드 그대로 |
| (켬) `const { _t732Cargo, ...rest } = c` → `rest` | **빠른 꼴**(40/40) · `from` · `to` · `trader` 다시 넣은 뒤도 빠른 꼴 |

빈 리터럴에 셈 키로 칸을 스물 넘게 붙이면 V8 이 "키 저장으로 칸이 많다"며 사본을 처음부터 사전으로 짓는다. 지우기는 원인이 아니었다(그 칸은 저장 줄의 마지막 칸이라 지워도 꼴이 안 바뀐다).

### 2-2. 고침

* 켬이면 짐 레코드 칸을 거른 나머지 꼴로 사본을 짓는다(카드 "칸을 거른 리터럴"): `const { _t732Cargo, ...rest } = c; o = rest; _cg = _t732Cargo;` — 같은 칸 · 같은 차례(나머지 꼴은 원본 차례대로 싣는다 — 위 표의 판에서 `Object.keys` 같음) · 같은 값(얕은 사본 — `Object.assign` 과 같다) · 짐 레코드 칸은 사본에 처음부터 없다.
* 끔 갈래 = 종전 줄(`Object.assign` · `delete`) 그대로. `o.from` · `o.to` 를 다시 넣는 줄은 두 갈래 공통(값 · 차례 같음 — 이미 있는 칸에 넣는다).
* 하네스 문 하나: `__p3Bind` 에 `_t728Meta`(캐러밴 메타 저장 줄 — 제품 함수) 내보내기만.
