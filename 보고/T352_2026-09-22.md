### 주민 색인 — 조밀 슬롯 한 줄

> 슬롯은 `0..N-1` 로 꽉 찬다. 죽으면 **마지막 슬롯을 그 자리로 옮기고 N 을 하나 줄인다**(swap-remove).
> `pid → slot` 은 `Map` 하나가 들고, 옮긴 주민의 항목만 고친다.

⚠걸음은 사람마다 독립이라 **슬롯 순서가 바뀌어도 부동소수 합이 갈릴 자리가 없다**(커널은 사람 간 합을 안 한다).

## 2. §0-ⓑ 커널 두 판 — 빌드 표

`bench/walk-kernel/walk.c` **한 파일**(197줄)이 두 판의 산술 전부다. 껍데기만 갈린다.

| | WASM | N-API |
|---|---|---|
| 도구 | `clang --target=wasm32 -O3 -nostdlib` + `wasm-ld` | `cc -O3 -ffp-contract=off -shared -fPIC -I<node>/include/node` |
| 컨테이너 | ✅ `clang 18.1.3` · `wasm-ld` 있음 | ✅ `cc` + `/opt/node22/include/node/node_api.h` 있음 |
| `node-gyp` | 필요 없음 | **없음 — 그런데 필요 없었다**(헤더만 있으면 한 줄) |
| 산출물 | `walk.wasm` **6,576 B** | `walk.node` **26,104 B** |
| 메모리 | JS 가 넘긴 `WebAssembly.Memory` 위에 열을 놓고 JS 도 같은 뷰 — **복사 0** | `napi_get_typedarray_info` 로 같은 버퍼 — **복사 0** |

### ★두 판의 **다른 위험** — 이 카드가 실측으로 잡은 둘

| # | 무엇 | 어디서 | WASM | N-API |
|---|---|---|---|---|
| 1 | **FMA 접힘** — x86-64 `-O3` 이 `a*b+c` 를 한 명령으로 접어 중간 반올림이 사라진다 | 1,000틱을 쌓으면 좌표가 눈에 보이게 갈린다 | **없다**(wasm 에 FMA 명령이 없다) | `-ffp-contract=off` 가 **게이트의 조건** |
| 2 | **포인터 수명** — `napi_get_typedarray_info` 의 주소는 **그 호출 동안만** 유효하다. GC 가 백킹 스토어를 옮기면 다음 틱의 쓰기가 옛 자리로 간다 | 한 틱씩 부르면 멀쩡 · 사이에 JS 팔이 10,000개 객체를 만들어 GC 가 돈 판에서 **x 열의 93.7 % 가 갈렸다** | **없다**(열이 선형 메모리 안에 있고 그 메모리는 안 움직인다) | **틱마다 주소를 다시 받아야 한다**(고정 비용) |

★둘째는 처음에 `napi_ref` 를 **원시값에도** 걸었다가 **세그폴트**로 되돌아왔다 — ref 는 객체만이다.
지금 판은 배열 14개만 ref 로 붙들고 원시값은 init 때 C 값으로 굳힌다.

### 산술 규약 — 바이트를 맞추려고 한 것

| JS | C | 비고 |
|---|---|---|
| `Math.floor` | `__builtin_floor` | 같다 |
| `Math.hypot(a,b)` | `sqrt(a*a+b*b)` | ★`Math.hypot` 은 스케일링을 한다 ⇒ **JS 쪽 팔도 `Math.sqrt(a*a+b*b)` 로 맞췄다**. 제품은 `hypot` 그대로고, 이 차이는 **이 벤치 안에서만** 있다(계약 §5 에 적었다) |
| `a*b+c` | 같은 순서 · `-ffp-contract=off` | 결합법칙 금지 · `-ffast-math` 금지 |

## 6. 회부만

1. **WASM vs N-API — #53(재민).** 값은 같다. 갈리는 것은 위험의 꼴이다(§4).
   PM 의견을 굳이 적자면 **WASM** — 부동소수와 포인터 수명 둘 다 **구조적으로** 안전하고 배포물이 한 파일이다.
2. **계약 확정 — 세션3 SoA 카드.** 이 문서는 초안이다. 특히 `active` 열(문자열 키 Set 을 어떻게 미리 채울까)과
   `_stuckPos` 를 열 넷으로 펴는 일은 그 카드 것이다.
3. ★**바닥은 걸음 산술에 없다** — T345 5.48 µs 중 걸음 문은 0.42 µs 다. C 를 붙여도 **4.3 %** 다.
   다음에 잴 곳은 **결정·A*·청크**다. (이 벤치의 팔 구조가 그대로 쓰인다 — 목표열만 갈면 된다.)
4. **훑기의 한계** — 관측자 하나로는 356/1,464 만 잡았다. 관측자를 여럿 파킹하면 한 번에 덮는다(다음 카드 한 줄).
5. `NPC_CAP_PER_VILLAGE = 40`(#54) · 셀당 비트로 판정 ≤6회 설계(SoA 카드) — 그대로.

> 게이트 4/4 바이트 동일이고, WASM 과 N-API 는 값이 같으며(0.222 vs 0.218 µs), 갈리는 것은 **위험의 꼴**이다:
> N-API 는 FMA 와 포인터 수명 둘을 손으로 막아야 하고(둘 다 이 카드가 실측으로 밟았다), WASM 은 둘 다 구조적으로 없다.
