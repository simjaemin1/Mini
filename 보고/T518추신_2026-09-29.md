# T518 추신 — 도쿄가 붙은 뒤 바깥에서 읽은 것 + 서버 안 자 (세션5 · 2026-09-29 · 읽기만)

**한 줄 답:** 바깥(맥 · 경기 SK브로드밴드)에서 읽었다. 도쿄 닛폰 3021은 **healthy**다(틱 p50 1.1ms로 30번 모두 같음 · 사람 0 · NPC 191 · 마을 7). 서울 central 3010도 200이다. 그런데 **서울 한반도 3020 · 중원북 3016은 연결 거절**이다(15:09~15:10 UTC · 6/6 RST). `/zones`는 한반도를 `ws://141.164.35.114:3020`으로 내주므로, 지금 손님이 한반도에 못 붙을 수 있다 — 재민 확인 1순위. 서울 ↔ 도쿄 왕복은 바깥에서 못 재지만 삼각 부등식으로 **≥ 33ms**다(맥 → 도쿄 최소 41 − 맥 → 서울 최소 8). 그러면 유령은 평균 ~67ms 늙고, 외삽 끔이면 달리기 화살 어긋남은 T512 표의 0ms(13%)와 75ms(31%) 사이다. 서버 안의 수(서울 ↔ 도쿄 실왕복 · 틱 p95 · steal · 핸드오프 벽시계)는 재민 손이다 — 자 `scripts/xhost-rtt.sh`(새) + `lag-capture.sh`(있음) · 명령은 §3.

가지: `batch/nippon-audit-0929`(T524와 같은 가지 · 이 파일 + `scripts/xhost-rtt.sh`) · 제품 코드 0줄 · 라이브에는 **GET `/health` · `/zones`만** 보냈다(새 문 0 · 비밀 0 · 게스트 0).

**맥에서 두 호스트까지**(`/health` 20~30번 · TCP 손 왕복 = `time_connect` · 요청 왕복 = 첫 바이트 − 연결):

| | TCP 손 왕복 min · p50 · p95 | 요청 왕복 min · p50 · p95 |
|---|---|---|
| 맥 → 서울 3010 | **8.0** · 77.9 · 90.1ms | **6.4** · 17.7 · 298ms |
| 맥 → 도쿄 3021 | **38.2** · 49.2 · 69.6ms | 42.2 · 45.9 · 291ms |

- **서울은 손 왕복이 요청 왕복보다 4배 느리다**(p50 78 대 18ms). 도쿄는 두 값이 같다(49 · 46 = 망 왕복). 경기 → 서울 망 왕복은 한 자리 ms인데 SYN 응답이 늦는다는 뜻이다. 서버 쪽 의심 순서: 공유 CPU 뺏김(steal) → conntrack · 방화벽 속도 제한 → SYN 백로그. T485 회부 ④ "서울 CPU rate-limit"과 같은 줄일 수 있다 — `lag-capture` ⓐ steal로 가른다(§3).
- 비교용으로 두 호스트의 22번 포트에도 **TCP 손만** 10번 맺고 바로 끊었다(SSH 프로토콜 0 · 로그인 시도 0). 서울 p50 74.8(min 6.2) · 도쿄 42.0 — 3010과 같은 모양이라 **포트가 아니라 호스트**의 느림이다. 22번은 "SSH 시도 금지"에 가까운 자리라 다시 하지 않는다.

- `xhost-rtt.sh`는 게임 상태를 건드리지 않고 비밀도 쓰지 않는다. 상대의 바깥 문 `/health`만 두드린다. 출력은 JSON 한 줄씩이다(`meta` · `ping` · `h` · `sum` · `end`). TCP 손 왕복과 요청 왕복을 **따로** 내므로 §1의 서울 SYN 느림을 서버 안에서 다시 가를 수 있다.
- 파일이 `~/Mini/_lag/`에 떨어지면 세션5가 읽어 이 표를 실측으로 바꾼다.
