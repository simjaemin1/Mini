## §1 ① 흐름마다 — 두 호스트 흉내(`t512-flows.sh`)

**판**: 닛폰을 **제 네트워크 이름공간**(10.61.0.2)에 · 한반도·central·중원북은 바깥(10.61.0.1). 다리마다 `t498-delay-proxy`(한 방향 D ms): 한반도 → 닛폰 · 닛폰 → 한반도 · 닛폰 → central(포트가 존 표에 박혀 있어 한 이름공간에선 같은 포트에 중계를 못 세운다 · 이 상자엔 `netem` 이 없다). 다리 한 번(HTTP `/health`): D=0 → 5~12ms · D=75 → 155~160ms · D=150 → 305~312ms.

## §2 ② 100ms 주기가 150ms 왕복보다 짧다 — 밀리나 겹치나

* **밀리지 않고 겹친다** — 던지고 잊는 요청이라 앞 것이 안 끝나도 다음이 나가고(node 22 기본 에이전트는 keep-alive · 소켓이 왕복/주기만큼 늘어난다 = 2 · 4), 한 다리의 지연이 같으니 **도착 순서도 보낸 순서**다. 받는 쪽은 늘 **마지막 도착**으로 덮으므로 쌓이는 큐 0 · 버리는 것 0. 늙는 것은 나이뿐(§1).

* 민다 = 보낸 순간의 속도(`move-model.stepMove` 가 낸 px/s — 틱이 쓰는 그 값) × 나이. 나이는 0 ~ 유령 수명(`GHOST_TTL_MS`) 안 — 새 수 0.
* **끔 바이트 동일**: 스냅샷에 `t` 가 안 실리고, 저장 객체는 종전 그대로, `_ga = 0` 이면 `g.ax + g.vx·0 = g.ax`(유한한 수 · IEEE 에서 정확히 같다).
* ⚠두 호스트의 **시계가 맞아야** 한다(보낸 시각 = 보낸 쪽 시계 · 나이 = 받는 쪽 시계). Ubuntu 22.04 는 `systemd-timesyncd`(NTP)가 기본으로 돈다 — 도쿄 실측 때 두 호스트 `timedatectl timesync-status` 한 줄로 오프셋을 본다(§4). 시계가 앞서 있으면 나이가 0 으로 잘린다(끔과 같아진다 · 해는 없다).
* 클라 보간이 아니다 — 클라는 유령을 안 그린다(§0). 그래서 팔은 **서버 판정 한 자리**다.
