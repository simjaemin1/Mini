### 2-ⓐ 붙인 것 둘(이미 있는 스크립트에 · 동작 무변)

* **`redeploy-hanbando.sh --dry`** — `git fetch` 만 하고 받을 판(upstream)으로 **같은 판정**을 찍는다. 끝 줄은 `PLAN central=0|1 zone=0|1 after=<해시>` 다. pull · 빌드 · 재생성 · 스탬프는 0 이다.
  * `test-redeploy` ⑥ 다섯 줄이 이를 지킨다(17/0): 실제 판 ① · ③ · ④ 와 같은 판정, pull 0, 스탬프 그대로, 그리고 예행 아닌 판은 pull 한다는 증인.
* **`reset-world.sh <대상> --live`** — `--check` 에서 DB 수만 뺀 것이다. 열린 세계에서 DB 를 훑지 않는다. 존이 안 돌면 rc 1 이다.
  * `test-reset-world` 두 줄이 지킨다(60/0): `--check` 는 DB 줄 있음 · `--live` 는 없음, 안 돌면 rc ≠ 0. 비밀 0 자에 `--live` 출력도 넣었다.

## 6. 회부 · 알림

1. **[재민 손 · 처음 한 번]** 착지 뒤 처음 한 번은 `ssh seoul 'cd /opt/Mini && git pull --ff-only'` 를 먼저 친다. 서울에 파일이 없으면 `bash <(ssh seoul cat …)` 는 빈 글을 받아 **아무 말 없이 rc 0** 으로 끝난다. 이것은 `bash <(…)` 꼴의 성질이고 T878 · T887 줄도 같다. 맥 레포에서 `bash scripts/update-live.sh` 로 쳐도 된다.
2. **[PM · 새 파일 하나]** 도쿄 스탬프 `/srv/durango/deployed-nippon.sha` 를 새로 둔다. 서울 `deployed-hanbando.sha` 와 같은 뜻(도쿄 존이 실제로 배포된 커밋)이다. 없으면 첫 판은 도쿄 존을 다시 굽는다(안전한 쪽).
3. **[정보 · env]** 도쿄 존 env 는 §8 종전 줄 그대로 새로 짓는다. 옛 컨테이너에만 있던 env **이름**을 찍는다. 그런 이름이 생기면(예: 해안 꼴 `T588_COAST`) 이 줄은 싣지 않는다. 옮겨 실을지는 PM 몫이다. 마른 연습에서는 없음이었다.
4. **[정보]** 도쿄 존 판정은 서울의 같은 규칙을 도쿄 스탬프로 돌린 것이다. 클라 · 문서 · 스크립트만 바뀐 갱신은 도쿄 존을 안 건드린다(존은 클라를 서빙하지 않는다 — 서울과 같은 근거). 도쿄 코드는 늘 받는다.
