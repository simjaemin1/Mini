## §0-ⓑ 표 둘 — 발급기의 유일성 · 충돌 확률

`newGuestPlayerId()` = `'anon_' + crypto.randomBytes(9).toString('base64url')` (12자 · 64자 알파벳).
이름은 그 **꼬리 넷** — `여행자` + 4자 = **7자**(종전 말결 유지 · 16자 상한 안).

| 무엇 | 값 |
|---|---|
| 꼬리 넷의 경우의 수 | `64^4` = **16,777,216** |
| 게스트 1,000명일 때 생일 충돌 | ≈ 3.0 × 10⁻² |
| **그런데 실제 충돌 확률** | **0** — 발급이 **있는 재시도 루프** 안에서 이름을 확인한다 |

```js
for (let i = 0; i < 4; i++) {                    // ← 원래 pid 유니크 충돌 때문에 도는 루프
  const pid = newGuestPlayerId(), t = newGuestToken();
  const gname = `여행자${pid.slice(-4)}`;
  if (findPerson(gname)) continue;               // ← 겹치면 같은 자리에서 다시 뽑는다
  stmtInsertGuest.run(pid, gname, …);
```
**새 규약 0 · 새 컬럼 0 · 새 수 0** — 식별자도 루프도 이미 있던 것이고, 지목 술어(`findPerson`)를
유일성 검사에 그대로 재사용한다(사본 0). 네 번 연속 겹칠 확률은 1,000명 판에서 ≈ 1.3 × 10⁻¹⁷.
