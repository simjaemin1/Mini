## §2 ⓑ 되읽기 표 — 구현 안 함

T392 §2: 열린 땅 330~376ms/f 의 91~94% 가 `drawImage` 였고 부른 줄은 둘이었다. 헤드리스(소프트웨어 GL)는
"GPU stall due to ReadPixels" 를 찍는다 — GL 표면을 CPU 로 되읽어 2D 에 옮긴다.

| 자리 | 언제 | 무엇을 옮기나 | 이미 있는 것 | 캔버스 겹치기로 되읽기 0? | 안개 규격 |
|---|---|---|---|---|---|
| **물** `_drawWaterLayer` → `ctx2.drawImage(_wgl.cv, 사각형)` (10-r1-terrain.js:1147) | **매 프레임** · 화면 크기 사각형 | GL 물(셰이더 한 판) | 사각형만 옮긴다(`_wfCache.rect`) | **된다** — 물은 지면 타일 **위** · 안개 마스크 **아래**의 **납작한 한 층**이다 | 마스크가 위 캔버스에 남으므로 **그대로**(미탐사 물도 가려진다) |
| **산** `_mt3GlDraw` → `drawImage` / `readPixels`+`putImageData` (11-r1-mountain.js:255~312) | **굽기 때**(`_mt3Chunk` 캐시 · 청크당) | GL 산 메시 | 사각형 `readPixels` 경로(주석: "drawImage 는 표면 전체 스냅샷 · 호출당 15.3ms") | **안 된다** — 산 세그먼트는 **엔티티와 z 로 엇갈려** 그려진다(사람이 산 앞·뒤에 선다). 한 GL 층으로 빼면 가림이 깨진다 | 산은 게이트 면제(`_GATE_FREE.mtseg`) — 바꿀 것 없음 |

⚠빈 초지에서 산 몫이 4초에 2.7초였다 — 굽기 캐시가 도는 동안의 값인지 **매 프레임 다시 굽는지는 가르지 않았다**(회부).

### 층 순서 — 지금(캔버스 하나) 대 물 겹치기(캔버스 셋)

```
 지금 (2D 캔버스 하나 · 위가 나중)            물 겹치기 (DOM 에 캔버스 셋 · 위가 앞)
 ┌──────────────────────────────┐          ┌──────────────────────────────┐
 │ UI · 밤 · 날씨               │          │ ③ 2D 위(투명 배경)            │
 │ 안개 2차(개체 단위 게이트)    │          │   UI · 밤 · 날씨              │
 │ 엔티티 z 정렬(산 GL 굽기 포함)│          │   안개 2차 · 엔티티(산 굽기)  │
 │ ★안개 마스크(3단계)          │          │   ★안개 마스크(3단계)         │ ← 마스크는 GL 물 **위**
 │ 원경 · 자연물(마스크 앞)      │          │   원경 · 자연물 · 블록 프리즘 │

 │ 지면 타일                    │          ├──────────────────────────────┤

```

**겹치기의 대가(표만)** — ⓐ 위 캔버스는 배경을 **투명**으로(지금은 검정 `fillRect` 로 시작) · ⓑ 확대(`zoomBegin/End` 오프스크린)를 세 캔버스가
같은 변환으로 따라야 한다(CSS 배율) · ⓒ 화소를 읽는 하네스(`@pixel` 17)는 **한 캔버스**를 찍고 있다 — 물이 빠진 판을 보게 된다(`page.screenshot` 은 합성본이라 괜찮고 `getImageData` 는 아니다) ·
ⓓ GPU 크롬에서 2D 캔버스가 가속이면 `drawImage(webgl)` 은 GPU→GPU 복사일 수 있다 — **그 값이 #73(재민 맥)** 이고, 그게 작으면 겹치기는 할 이유가 없다.
