## 1. §0-ⓐ 인벤토리 — 새 체계 0

**첫 실측이 카드를 줄였다.** 카드 ①은 *"npc 에 `inventory` 를 단다"* 였는데, **이미 달려 있었다**:

```js
// server/zone.js:1705 — spawnNpc
inventory: { wood: 0, stone: 0, berry: 0, fiber: 0, meat_raw: 0, hide: 0, seed_berry: 2 },
```

마을 NPC 는 `vil.npcPids` → `players` 에 사는 **플레이어와 같은 객체**다. 그래서:

| 캐논이 요구한 것 | 부르는 정본 | 새로 지은 것 |
|---|---|---|
| 품목별 손 | `p.inventory` (zone.js:1705) | **0** |
| 무게 상한 | `carry.js` `CFG.CAP_KG` | **0** |
| 죽으면 낙하 | `_deathDrop(p)` → `_deathDropPick(p, frac)` → `_spawnGroundItems` | **0** — 그 함수가 보는 것이 `p.inventory` 다 |
| 곳간 회계 | `economy-sim.js fishToGranary`(T179 `harvestToGranary` 꼴) | 함수 하나(새 회계 0) |
| 마리 → 장부 | `kcal.js econUnitsOf('fish', 1, kg)` | **0** |

⚠**`_carry` 흡수는 안 했다.** 카드 ①의 그 절(수확 `:4439` · 곳간 `:5309` · 지게 `:5810`)은 **농부·짐꾼의 물리 짐 칸**이고,
어부 이식과 **접점이 없다**(어부는 `_carry` 를 안 쓴다). 지금 옮기면 농부 수확·지게 표시가 같이 흔들리는데
이 카드엔 그걸 되돌릴 자가 없다(밭은 이미 등가라 깨지면 바로 보인다 — T297 §1). **다음 카드로 미룬다**(회부).

## 3. §0-ⓒ 첫날 등가 — **식으로는 섰고, 세계 위에서는 못 쟀다**

식으로는 정의상 같다 — 셀당 예산 × 셀 수 = 그 마을 하루 수식(실측 예: 3.456 ÷ 137셀 = 0.025226 · × 137 = **3.456000**).

⚠**세계 위 3시드 51마을 자는 못 댔다.** 이유가 이 카드의 발견 하나다:
**기준선 자 `t17-metrics` 는 `server/villages.js` 를 안 지난다** — 제 손으로 `createWorldV2` + `trees.attachToWorld` 를
부른다(`:89`). 어부 행위는 생활층(`villages.js`)에 있으므로 그 자에는 **켜도 안 보인다**(`_t312Cells` 가 안 심겨 `fishActOn` 이 거짓).
⇒ 켠 팔의 첫날 등가와 16마을 30일은 **존 서버 위**에서 재야 한다 — ⑤ 부하와 같은 판이다. **다음 카드**(회부).
