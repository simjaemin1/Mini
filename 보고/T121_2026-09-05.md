★그리고 이건 드문 경우가 아니다. 사람이 하나도 없는 판에서 재 보면
**메모리 hut 렉트 0개 · DB hut 렉트 100개** — 세계의 움집 전부가 문간 판정에서 안 보인다.

## §0-ⓑ DB 행 모양 — 정규화는 **한 줄**

| | 키 | `data` |
|---|---|---|
| DB 행(`getBuildingsInRect`) | `id · type · owner_id · owner_name · x · y · data · created_at · village_id` | **문자열**(JSON) |
| 메모리 원소 | `id('b<id>') · dbId · type · ownerId · ownerName · x · y · data · floor` | **파싱된 객체** |

문 판정이 실제로 보는 필드는 **`type · x · y · data.hut · data.damaged`** 넷뿐이다.
⇒ 정규화 한 줄: `{ type, x, y, data: JSON.parse(row.data) }` — `data.hut` 이 없는 행은 아예 안 싣는다.
⚠**`_promoteLegacyFarm` 은 안 부른다.** 그건 밭 전용이고 **DB 쓰기를 한다**(`updateBuildingData`) —
문간을 묻는 길이 세계를 고치면 안 된다. 하네스가 소스로 못 박는다(`⑳ⓒ5`).

## §0-ⓒ 비용 — 부활 한 번당 렉트 질의 1건

| | 실측 |
|---|---|
| `getBuildingsInRect` 1건(±384px) | **0.089ms** · 행 84개 |
| 문간 한 번 전체(메모리 2,806행 훑기 + DB 질의 + 파싱) | **0.76ms** |

공짜**고, 그래서 카드가 "청크를 켜지 않는다"로 정한 것이 옳다.

## §1 만든 것 — 판정 함수 하나 · 행 수집 하나 · 손잡이 하나

```
server/zone.js
  _hutDoorFrom(rows, px, py, R)   ← 판정 **하나**. 입력이 행 배열이라 메모리든 DB든 같은 길로 온다
  _hutDoorRows(px, py, R)         ← 메모리 전부 + (메모리에 없는) DB 행. 청크를 안 켠다
  _hutDoorNear(px, py, rpx)       = _hutDoorFrom(_hutDoorRows(...), ...)      ← 두 줄
  _t121DoorDb()                   ← 되돌림 손잡이(부를 때 읽는다)
```

* **메모리가 이긴다** — DB 행 중 `dbId` 가 메모리에 있는 것은 안 싣는다(미저장 변경까지 산다).
* **렉트에 여유를 둔다** — 거리는 움집 렉트의 **중심**으로 재는데 몸통(6×4칸)이 중심에서 ~115px 뻗는다.
  상자를 딱 `R` 로 자르면 경계의 움집이 반만 잡힌다 ⇒ `R + BUILDING_SIZE*6`.
* **사다리 순서 무변** · **`nearestVillageWake` 무접촉**(`⑳ⓓ`·`⑳ⓔ`).

★**손잡이는 부를 때 읽는다** — 모듈 상수가 아니다.
T88 이 같은 자리에서 배운 것이다: 상수로 두면 스위치 하나 재려고 **존을 한 판 더 띄워야** 하고,
그게 야간 하네스에 10분을 얹고 `ETIMEDOUT` 을 냈다. 초안이 실제로 그 길로 갔고(§3 아래),
자식 부팅이 마을 없는 세계를 물어 **켠 판도 `null`** 을 냈다. `parseInt` 한 번은 비용이 아니다.
