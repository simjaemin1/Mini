## 1. §0-ⓐ `vpop` 열 — 관측만이고, 값은 안 흔든다

`t17-metrics` 의 `T17_JSON` 에 두 가지를 더했다.

```js
//   ★[T256 관측 항 · T277 에서 정식화] 마을별 끝 인구 — 짝 Δ 의 부분집합(작은/큰 17곳 · `<20명` 꼬리)과
//     홀드아웃을 **같은 판에서** 읽으려고 더한다. 계측기를 두 벌 돌리면 기계 시간이 두 배다(30판 → 60판).
vpop: world.villages.map((v) => ({ name: v.name, pop: v.npcs.length })),
//   ★[T277] 여덟 수 중 JSON 에 없던 셋 — 생곡 · 밀도 ㉮㉯. ⓚ 블록이 **이미 만든 값**을 그대로 담는다(사본 0).
eight: _eightOut,
```

* `vpop` 의 꼴은 **T256 이 `batch/lab-cargo-two-0912` 에서 쓴 그 꼴 그대로**다(그 가지는 무접촉 — 읽기만 했다). 나중에 합칠 때 같은 줄이라 다툼이 없다.
* `eight` 은 **새 계산이 아니다.** ⓚ 블록이 이미 찍던 생곡·㉮·㉯ 를 상자 하나로 내보낼 뿐이라 사본이 안 생긴다
  (그 셋만 JSON 에 없어서 러너가 콘솔을 긁어야 했다).

**비트 동일** — 시드 1020 · 800일 · 51마을, `vpop` 을 얹은 판:

**T244 넷째 판 1020 행과 열 열 전부 한 자도 안 다르다.** 그리고 러너가 매 판 거는 자기검사가 하나 더 있다 —
**`vpop` 합 = 여덟 수의 인구**(30판 전부 일치). 열이 딴 세계를 세고 있으면 여기서 걸린다.

## 2. §0-ⓑ 러너 `scripts/t17-seeds.js`

```

ARM_A='L_ALLOC_REAL=0 L_HAPPY_FLOOR1=0 L_HAPPYWORK=0' ARM_B='' node scripts/t17-seeds.js --seeds 3
```

* **시드 목록 고정**(T256 의 15) — 카드마다 다른 시드를 뽑으면 표끼리 못 견준다. `--seeds 3` 이면 앞 셋.
* **팔은 env 문자열**(`ARM_A`/`ARM_B`) — 세계 손잡이를 새로 만들지 않는다. 이 파일 자신의 손잡이만 있다(`T17S_WORK`·`T17S_FRESH`).
* **순차** · `LAB_SEEDCACHE` 기본 사용 · 판별 JSON 을 `T17S_WORK` 에 **보관하고 재사용**한다 ⇒ 다시 읽는 값은 공짜다.
* 여덟 수는 **JSON 에서 읽기만** 한다(사본 0). 소멸은 Δ% 가 아니라 **시드 수**로 센다(T252: 한 곳만 나도 유의).
* 꼬리 집합은 **기준 팔 A 로 뽑는다**(족보 204) — 팔별로 뽑으면 부호가 뽑는 방식의 말이 된다.

### 게이트 4(직업 배율) — `--spread` · **판정을 억지로 안 찍는다**

퍼짐은 **한 팔 안에서 나오는 수**라 짝 Δ 가 아니다 ⇒ T252 자를 댈 것이 없다. 그래서 러너는 대역과 **두 읽기**만 찍는다.


| 시드 | hunter | fisher | miner | forager | lumberjack | farmer | **퍼짐** | 분모→분자 |
|---|---|---|---|---|---|---|---|---|
| 1020 | 1.03 | 1.38 | 2.92 | 2.10 | 3.67 | 5.29 | **×5.12** | hunter → farmer |
| 7 | 1.09 | 1.47 | 2.46 | 2.10 | 3.82 | 5.24 | **×4.78** | hunter → farmer |
| 42 | 1.11 | 1.47 | 1.84 | 2.08 | 4.12 | 5.73 | **×5.16** | hunter → farmer |

**대역** — 중앙 ×5.12 · 최소 ×4.78 · 최대 ×5.16 · 폭 0.38
**두 읽기** — ⓐ 문자 `≤×5`(T184 가 그 판에서 관측한 최대값): **1/3** · ⓑ 한 자릿수 `<×10`(`test-lab-alloc` ⑪ 의 그 줄): **3/3**
**분모·분자** — 3시드 전부 `hunter` → `farmer`(퍼짐이 한 쌍에서만 난다)

⚠**T273 의 퍼짐보다 0.02~0.03 낮게 나온다 — 러너 쪽이 맞다.**
T273 은 계측기가 **찍은 글자**(소수 둘)를 읽어 `5.29 / 1.03 = 5.136` 을 냈고, 러너는 JSON 의 **정밀값**
(`farmer 5.2912 / hunter 1.0338`)으로 **5.118** 을 낸다. 반올림한 분모·분자로 나눈 수였다.
판정은 안 바뀐다(문자 `≤×5` 는 이 셋에서 1/3 그대로 · `<×10` 3/3). **표를 글자에서 읽으면 자가 0.02 틀린다** — 그래서 열을 만들었다.
