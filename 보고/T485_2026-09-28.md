### ⓒ 로비 · 클라 — wss 인가
* central `/zones`(`publicZoneMap`) = `${WS_PROTO}://${host}${wss면 없음 : ':포트'}` — host 는 **central 컨테이너의** `hostFromEnv`. 클라는 이 주소로 **존에 직접** 붙는다(핸드오프 토큰도 같은 주소).
* ★**라이브는 https 가 아니다**(읽기 실측 · 맥 VM `curl`): `/zones` 26존 전부 `ws://141.164.35.114:<포트>` · `https://…:443` · `http://…:80` 응답 0 · 페이지는 `http://141.164.35.114:3010`. ⇒ 도쿄도 `ws://108.160.135.177:3021` 이면 된다 · **TLS·DNS 는 지금 필요 없다**.
* 나중에 https 로 가면: 존마다 이름 + 443 리버스 프록시(Caddy) + `WS_PROTO=wss` · `HTTP_PROTO=https` — central 과 한반도가 한 IP 라 이름이 **둘** 필요하고, 존↔존도 443 으로 간다. 중앙 프록시로 묶으면 도쿄 틱이 서울을 거친다(캐논 위반) — 존마다 제 호스트에서 끝나야 한다(회부).

### ⓓ 안 문(`internal-door.js` · T217/T225/T245)
* 비밀(`CENTRAL_SECRET`)이 **있으면** 헤더 일치만 본다(사설 폴백 **없음**). **없으면** 출발지가 사설(127 · 10 · 172.16~31 · 192.168 · ULA)이면 통과 · `x-forwarded-for` 가 붙으면 거절.
* 한 호스트는 출발지가 도커 다리(172.17.x) → 통과해 왔다. **호스트가 갈리면 출발지가 공인 IP** → 거절:
| 비밀 없이 갈리면 | 결과 |
|---|---|
| 닛폰 → central `POST /player`(저장) · `GET /player`(조회) | **401 · 404** — 도쿄의 저장이 **전부 조용히 실패**(몸이 central 에 안 남는다) |
| 닛폰 → central `/tribe/npc_upsert`(부팅 마을 길드) · `/tribe/treasury` | **404** |
| 한반도 → 닛폰 `/handoff_prepare` | **404** — 경계를 못 넘는다(`handoff_prepare → nippon 실패`) |
| 한반도 ↔ 닛폰 `/ghost_sync` · `/handoff_ack` · `/cross_damage` · `/kick_player` | **404** — 유령 0 · ACK 타임아웃 정리 |
* ⚠비밀을 **central 에만** 주면 한반도 → central 도 사설 폴백을 잃어 **서울 안에서도** 401 이 난다 — 셋이 **같이** 가져야 한다.

### ⓔ 포트는 지금 어디에 열려 있나(읽기 실측)
* 서울 3010 · 3020: **공개**(맥 VM 에서 200 · 16~57ms). 3021 · 3016: **거절(RST)** — 방화벽이 떨구지 않는다(안 떠 있을 뿐).
* 도쿄 22: 열림(sshd 응답 44ms) · 3021: **timeout(DROP)** — Vultr Ubuntu 기본 ufw 로 보인다. 도커 `-p` 는 ufw 를 **우회**하므로(도커가 iptables 를 먼저 건다) 컨테이너가 뜨면 3021 은 열린다(§3 검증 줄이 본다).
* ⇒ 카드의 "3010 을 도쿄 IP 만" · "존↔존 포트 서로 IP 만"은 **하면 안 된다** — 두 포트 다 브라우저가 붙는 문이다. 막을 것은 안 문이고, 그건 비밀이 막는다.

## §3 ③ 도쿄 착지 절차서 — 재민 손(명령 한 줄씩 · 순서대로)

★비밀 값은 **어디에도 적지 않는다** — 파일 하나(`/root/.durango-secret` · 600)로만 옮긴다. `<SEOUL>`=141.164.35.114 · `<TOKYO>`=108.160.135.177.

**도쿄 준비(재민 맥 → 도쿄)**
1. `ssh-copy-id root@108.160.135.177` — Vultr 콘솔의 루트 비밀번호로 한 번 · 검증 `ssh root@108.160.135.177 true`(비밀번호 안 물음).
2. `ssh root@108.160.135.177 "grep -rl '^#\?PasswordAuthentication' /etc/ssh/sshd_config /etc/ssh/sshd_config.d/ | xargs sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' && systemctl restart ssh"` — 검증 `ssh -o PreferredAuthentications=password root@108.160.135.177` 가 **거절**.
3. `ssh root@108.160.135.177 "curl -fsSL https://get.docker.com | sh"` — 검증 `ssh root@108.160.135.177 docker ps`.
4. 코드(서울과 **같은 커밋** — 서울 사본을 그대로 옮긴다 · GitHub 인증 불필요): `ssh root@141.164.35.114 "tar -C /opt -czf - --exclude=node_modules --exclude='*.db*' Mini" | ssh root@108.160.135.177 "tar -C /opt -xzf -"` — 검증 `ssh root@108.160.135.177 "git -C /opt/Mini log --oneline -1"` = 서울과 같은 줄.

**비밀(한 번 · 서울에서 만들고 도쿄로 복사)**

## §6 회부

1. **ⓖ [PM] 게임 코드가 필요한 자리 — 0.** 비밀 + env 한 줄로 돈다. 다만 `HTTP_PROTO` 한 손잡이가 central 프로토 · 존↔존 443 강제 · 클라 wss 를 **함께** 바꾼다 — https 로 갈 때 쪼개야 할 수 있다.
2. **[PM] 핸드오프의 central 왕복**(await 저장 1회 · 서울 안이라 지금은 싸다) — 떠나는 존이 도쿄가 되는 날(닛폰 → 한반도)엔 그 await 가 **도쿄 → 서울 1 RTT** 다. T47 페이로드가 이미 몸을 싣으니 저장을 던지고 잊게 하는 카드(존 늘면).
3. **[재민] 도메인·TLS** — 지금은 필요 없다(라이브가 http/ws). 가면 존마다 이름 + Caddy(존마다 인증서 · central 과 한반도는 이름 둘).
4. **[재민] 서울 CPU rate-limit** — §4 마지막 줄 세 명령을 서울에서 한 번 · 결과를 붙여 주면 세션5 가 읽는다.
5. **[재민] 닛폰 수동 지형(판정대기 ③)** — 서울에 닛폰 DB 가 없으니 옮길 것도 없다 · 정하면 도쿄 첫 부팅 전에(한 번).
6. **[재민] 도쿄 백업 꺼짐** — 닛폰 DB 는 도쿄 한 곳 · §3 끝의 tar 한 줄 또는 Vultr 백업.
