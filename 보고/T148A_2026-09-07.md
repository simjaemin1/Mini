### ⓑ `e2e-thirst ③` 이 재던 것 — ★**벽시계였다**

| 잰 것 | 답 |
|---|---|
| 캐논이 말하는 단위 | `body.js:181` *"단위는 **HP / 게임분**"* · `zone-config.js:437` *"현실 1초 = 게임 1분"* |
| ③ 이 쓰던 눈금 | `secs = (Date.now() - t0)/1000` — **벽시계 초**를 게임분으로 그냥 대입 |
| 그 대입이 깨지는 자리 | ★`zone.js:10556` **`const dt = Math.min(0.2, (now - lastTick)/1000)`** |
| 왜 깨지나 | 한 틱이 **0.2초에서 잘리고 따라잡기가 없다** ⇒ 틱이 200ms 를 넘으면 적분된 게임분이 벽시계보다 **영구히** 뒤진다 |
| 실측한 뒤진 몫 | 부하 0 에서도 **122초에 6.5초**(5.3%) · 코어 하나 100% 부하에서 **123초에 7.5초** |
| 게임분 환산 정본 | **허기** — 같은 `Body.tick(dt)` 가 HP 빚과 허기 감쇠를 **같은 dt** 로 적분한다. 율은 `B.decayRate(h, CFG.HUNGER_SEC)` **정본 함수**(사본 0 · 이미 export 돼 있다) |
| 왜 허기가 HP 보다 나은 증인인가 | 허기는 소수 둘째 자리까지 온다(HP 는 **1 단위 양자화**) ⇒ 게임분 해상도 **≈0.19초** |
| 곱 하나 | `cm = 1 + COLD_HUNGER_EXTRA·cold` — ①이 여름 낮을 얼려 뒀으니 `cold = 0` 이다. **가정하지 않고 검사한다**(새 절) |
| 감쇠 구간 | `decayRate` 는 허기 50 에서 꺾인다. 2분에 6.25 내려가므로 **한 구간 안**이다 — 그것도 검사한다 |

⇒ ★**"게임 1.5일에 HP 100"은 게임분에 대한 주장이다.** 벽시계를 대입한 것이 틀렸다.
T140 부하 판의 `50.7분 vs 36.0분` 은 결함이 아니라 **세계가 실제로 느리게 돈 것**이었다.

## 5. 회부

1. ★**[영역 Z · 시간] 세계는 부하에서 벽시계보다 느리게 돈다 — 그리고 따라잡지 않는다.**

   122초에 6.5초(5.3%)** 가 뒤졌다. 하네스 눈금은 이 카드가 고쳤다. 남는 물음은 **제품 쪽**이다:
   하루 24분 캐논이 실기에서 24분보다 길어진다면 그건 화면이 말하는 시간과 세계의 시간이 갈리는 것이다.
   재려면 `dt` 절단 횟수·누적 지연을 세는 계측기 한 줄이면 된다(관측자 규약 · 동작 무변).
2. **[영역 하네스 · 같은 병] 다른 하네스도 벽시계로 외삽하는 자리가 있는지 훑을 값이 있다** —

   눈금과 무관하고, `e2e-tidal` 은 `TIDE_FREEZE_MS` 로 이미 얼려 있다. 나머지는 안 셌다.
3. **[영역 클라 · 남은 것 0]** T140 회부 2("선에 나가는 `feed` 는 두 뜻")는 **이 카드가 닫는다**.
