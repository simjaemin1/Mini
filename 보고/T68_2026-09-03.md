## 0. §0 실측 (셋)

### ⓐ 고르는 함수가 하나인가 — **아니었다. 사슬은 좌클릭 핸들러 안에만 있었다**

`30-n-net.js` 의 click 리스너 안에 세 덩이가 줄줄이 있었다. 우클릭이 같은 판정을 원하는 순간
**두 벌이 될 참**이었다(사본 금지). 뽑아 보니 셋 다 **AABB(네모)** 다 — 반경이 아니다:

```
  ① 바닥 물건 ±14px            → 고른 뒤 거리 ≤100 게이트
  ② 터·시설 ±48/±40 · ±34      → 거리 게이트 없음
  ③ 상자·곳간 ±20px            → 고른 뒤 거리 ≤160 게이트
  존 순회 `conns.values()` · **첫 히트에서 멈춤**
```
⚠**거리 게이트는 `pickAt` 으로 못 옮긴다.** 종전에도 그 검사는 대상을 고른 **뒤**였고, 걸리면
다음 갈래로 **안 넘어가고** 알림만 냈다. 안으로 옮기면 멀리 있는 상자가 "안 골라진 것"이 되어
사슬이 뒤로 흐른다 — 그게 행동 변경이다. ⇒ 게이트는 부르는 쪽에 남겼다.

플레이어는 그 사슬에 **없다**(R 키가 `findNearestDownedGuildmate` 로 따로 골랐다).
그래서 사람 갈래는 `{ players: true }` 일 때만 켠다 — **좌클릭은 종전대로 사람을 안 집는다**.

### ⓑ 우클릭 셋의 우선순위 — **추측하지 않고 Chromium 에 물었다**

우클릭 하나를 셋이 나눠 쓴다: 배치 회전(`contextmenu`) · 조준 홀드(`mousedown(2)`) · 그리고 메뉴.
`scripts` 밖 일회용 탐침으로 이벤트 순서를 실측했다:

```
  ① 짧게 누름 : mousedown(2) t=261 → contextmenu t=266 → mouseup(2) t=268 → auxclick(2) t=268
  ② 600ms 홀드: mousedown(2) t=274 → contextmenu t=274 → … (떼야) mouseup t=880 → auxclick t=880
```
★**`contextmenu` 는 누르는 순간 온다.** 600ms 를 눌러도 거기서 먼저 온다 ⇒ "짧게 누름 vs 홀드"를
`contextmenu` 에서는 **가를 수 없다**. 뗄 때 오는 `auxclick` 이 그 자리이고, 거기서 누른 시간과
움직인 거리를 재면 **타이머가 필요 없다**.

| 상황 | 무엇이 이기나 | 종전 대비 |
|---|---|---|
| 배치 모드 | **회전**(`contextmenu`) · 메뉴 0 | 무변 |
| 홀드 ≥250ms 또는 ≥6px 이동 | **조준** · 메뉴 0 | 무변 |
| 짧게 누름 + 커서 밑에 대상 | **메뉴** | 새것 |
| 짧게 누름 + 빈 땅 | 아무 일 없음(조준이 잠깐 켜졌다 꺼진다) | 무변 |

★지시서가 물은 "조준 사수가 쓰러진 사람 위에서 홀드하면?" — **조준이 이긴다.** 메뉴는
**짧게 누름**에만 뜬다. `_aiming` 은 한 비트도 안 건드렸다(`mousedown` 이 켜고 `mouseup` 이 끈다).

### ⓒ 대상을 지목하는 서버 동사 — `feed`·`water` 만 인자가 필요했다

```
  업기/내려놓기  `tryRescue(rescuer, downedPid)`   ★**이미 pid 를 받는다** — 서버 무변
  줍기          `pickup_item { giId }`             ★이미 지목이다 — 서버 무변
  먹이기·물     `_downedNear(rescuer)` 로 골랐다   ⇒ 여기만 고친다
```
⇒ `feed(rescuer, word, now, pid)` · `water(rescuer, now, pid)`. `pid` 는 **선택**이고 기본값은
종전 `_downedNear` — **채팅 `/먹이기`·`/물` 은 한 글자도 안 달라졌다.** 지목은 *누구를*만 정하고
거리·창(窓) 게이트는 종전 판정이 그대로 본다.

탭·대상·동사는 **서로 다른 층**이라, 어느 층이 끊겼는지 말하지 않는 실패는 다음 사람에게 아무것도 안 준다.

### ★탭 문턱을 250 → 400ms 로 올린 것도 **실측이 시켰다**

통합 러너 안에서 `e2e-verbs ②` 가 한 판 빨개졌다(단독 두 판은 초록이었다). 원인은 제품이 아니라
**문턱**이었다: 실클라 셋이 붙은 2코어 상자에서 `mousedown` → `auxclick` 사이가 렌더 루프에 밀려
250ms 를 넘겼고, **옳은 탭이 홀드로 읽혀 메뉴가 안 떴다**. 사람의 짧은 누름은 ~80ms 라 400 도
넉넉하고 조준 홀드와는 여전히 확실히 갈린다 — 그리고 **느린 기계의 사람도 같은 일을 겪는다**
(문턱이 낮으면 메뉴가 가끔 안 열린다). 하네스에는 진단 훅 `window.__rmbDbg`(누른 시간·움직인 거리·
탭인가)를 붙이고 몇 번 눌러 보게 했다 — 다음에 안 뜨면 `null` 대신 **이유**가 찍힌다.
