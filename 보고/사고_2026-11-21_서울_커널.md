## 2. 아는 것 · 모르는 것

| 아는 것(기록 · 코드) | 모르는 것 |
|---|---|
| 커널이 페이지 할당기(`__rmqueue_pcplist` — CPU 마다의 빈 페이지 목록에서 한 장 꺼내기) 안에서 죽었다. `RSI: dead000000000100` 은 리눅스 목록의 **지운 칸 표지(LIST_POISON1)** — 이미 목록에서 빠진 페이지를 다시 꺼내려 했다 = 빈 페이지 목록이 깨져 있었다 | 누가 목록을 깨뜨렸나(커널 결함 · 기계 메모리 · 다른 드라이버) |
| `Tainted: … B …` = 이 부팅에서 **앞서 나쁜 페이지(Bad page)를 본 적이 있다** · `D` = 앞서 죽은(oops) 적이 있다 | `B` 가 처음 난 시각 · 그때 줄(재민이 붙인 것은 마지막 80줄) |
| 죽은 스레드는 존의 node 스레드(`DelayedTaskSche`)였지만, 그 스레드는 **메모리를 달라고 했을 뿐**이다 — 깨진 목록은 그 전에 깨져 있었다(사용자 프로그램은 커널 목록을 못 건드린다) | 이 부팅이 며칠 떠 있었나(오래 떠 있을수록 기계 메모리 쪽이 의심) |
| 커널 기록에 `out of memory` · `killed process` · `no space` · `blocked for` · `panic` 줄 0 — 메모리가 모자라 죽은 것이 **아니다** | 같은 부팅에서 앞서 난 `Bad page state` / `list_del corruption` / `BUG:` 줄 |
| 존은 `SIGTERM 받음 — 상태 flush 후 종료...`(`server/zone.js gracefulShutdown` 첫 줄)를 **남기지 못했다** — 10초 동안 신호 처리기가 한 줄도 못 돌았다 | 그 10초에 존이 이미 굳어 있었나(커널이 먼저 반쯤 죽음) · 이벤트 루프가 막혔나 |
| 커널이 죽은 뒤에도 네트워크 쪽 커널(TCP 연결 받기)은 살아 있었다 — 그래서 핑 · 연결은 되고 답은 0 이었다(`Fixing recursive fault but reboot is needed!` — 커널이 스스로 다시 켜지 않음) | iwinv 쪽에 그 시각 기계 오류 · 이전 · 점검 기록이 있나 |
| 재부팅 뒤 존이 안 뜬 까닭: 배포 줄이 `docker stop` 을 이미 불렀다 → Docker 가 "손으로 멈춤"으로 적는다 → `unless-stopped` 는 손으로 멈춘 컨테이너를 다시 안 띄운다(Docker 문서의 그 뜻 · T1443 하네스 ③ 이 같은 꼴을 재현) | |

## 3. 가설 둘과 가르는 법

| | ⓐ 커널 `6.8.0-124-generic` 의 결함 | ⓑ iwinv 기계(하이퍼바이저 · 물리 메모리) 쪽 메모리 손상 |
|---|---|---|
| 맞으면 보일 것 | 같은 커널 판의 알려진 결함(Ubuntu 커널 변경 기록 · 버그 목록에 `__rmqueue_pcplist` · pcplist · page allocator 손상 건) · 커널을 바꾼 뒤로 재발 0 | `Bad page state` 가 서로 다른 주소 · 다른 때에 드문드문 · 커널과 무관하게(이전 커널 부팅에도) · `mce:` / `EDAC` / `Hardware Error` 줄(VM 에선 안 보일 수 있다) · iwinv 장애 공지 |
| 첫 `B` | 특정 일(그 시각의 작업)과 맞물림 | 부팅이 오래 떠 있을수록 · 일과 무관 |
| 다음 한 수 | 커널 갱신(재민 손 — 회부) | iwinv 에 그 시각 기록 문의 · 다른 기계로 옮김(회부) |

**지금은 못 가른다.** 가를 줄(재민이 서버에서 돌릴 **읽기 전용** 한 줄 · 붙여 주면 PM 이 가른다):

```bash
journalctl --list-boots --no-pager | tail -5; uname -r; cat /proc/version_signature 2>/dev/null; \
B=$(journalctl --list-boots --no-pager | awk '$0 ~ /2026-11-2[01]|Nov 2[01]/ {print $1}' | tail -1); echo "사고 부팅 = $B"; \
journalctl -k -b "$B" -o short-iso --no-pager | head -1; journalctl -k -b "$B" -o short-iso --no-pager | tail -1; \
journalctl -k -b "$B" -o short-iso --no-pager | grep -nE "Bad page|list_del corruption|list_add corruption|BUG:|Oops|general protection|Tainted:|mce:|EDAC|Hardware Error|page allocation failure" | head -40; \
for b in $(journalctl --list-boots --no-pager | awk '{print $1}'); do n=$(journalctl -k -b "$b" --no-pager 2>/dev/null | grep -cE "Bad page|list_del corruption"); [ "$n" != 0 ] && echo "부팅 $b: Bad page/list 손상 $n 줄"; done; \
zgrep -hE "linux-image-6" /var/log/apt/history.log* 2>/dev/null | tail -5
```

- 첫 `head -1` · `tail -1` = 그 부팅이 언제 떴고 언제 끝났나(며칠 떠 있었나).
- 줄 번호가 가장 작은 `Bad page` / `list_del` 줄 = `B` 가 처음 난 때 — 그 시각에 무엇이 돌았나(배포 · 백업 · 빌드)를 맞대면 ⓐ 쪽.
- 다른 부팅에도 손상 줄이 있으면(커널 판이 달라도) ⓑ 쪽.
- 커널 변경 기록(읽기만): `apt changelog linux-image-$(uname -r) 2>/dev/null | grep -inE "pcp|rmqueue|page_alloc|list corruption" | head`.

## 4. 이 사고에서 고친 것 · 남은 것

- **알림이 없었다** → 밖에서 보는 생존 확인 `scripts/live-ping.sh` + 15분 일정 워크플로(`.github/workflows/live-ping.yml`) — 연결만 받고 답 0 인 이번 꼴을 빨강으로 잡는다(하네스 ②). 실패 메일이 누구에게 가는지는 보고 T1443 §2.

- 남은 것(회부 — 재민 손): 스왑 · 커널이 죽으면 저절로 다시 켜기(`kernel.panic_on_oops` · `kernel.panic`) · `--restart` 정책 · 커널 갱신 · iwinv 문의 · ssh 비밀번호 로그인(보고 T1443 §5 · 회부).
