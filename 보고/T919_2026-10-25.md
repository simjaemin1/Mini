# T919 [승인 대기 · T919] — 갱신 앞 자동 스냅샷: `update-live.sh` 에 디스크 · 백업 묶기 (2026-10-25 · 세션6)

**한 줄 답:** `update-live.sh` 맨 앞에 ⓪ 이 섰다. ⓪ 은 둘을 한 뒤에 종전 차례(pull → 고정 → 재배포 …)로 간다.

* **디스크:** `disk-check.sh` 판정(두 호스트 빈 자리 ≥ 백업 한 벌)이 ✗ 면 그 자리에서 멈춘다. 이유 한 줄을 찍고 라이브는 무변이다.
* **스냅샷:** `backup-live.sh` 한 판을 뜬다. 이 갱신이 다시 띄울 대상이 있는 호스트만, central · 존마다, 라벨 `update-live <배포된 판> <받을 판>` 으로.

`--dry` 에도 두 줄(`[⓪ 디스크]` · `[⓪ 스냅샷]` 뜰 자리)이 나온다.

`--rollback`(과 `--rollback --dry`)은 종전대로 이미지만 되돌린다. 대신 대상마다 아래를 같이 찍는다:

* "이 갱신 앞 스냅샷" 자리 — 폴더 · 시각 · `갱신 <앞> → <판>` · 지금 이미지 커밋이 그 판이면 `= 이 갱신`
* 폴더가 박힌 되놓기 줄(T907 `--restore` 꼴) — DB 되놓기는 재민이 고르는 별도 줄이다

두 호스트 흉내 판(진짜 도커)에서 다섯 판을 쳤다:

| 판 | 결과 |
|---|---|
| ① 빈 자리 부족 흉내 | 상자 디스크를 100 MB 만 남겼다 → `✗ 멈췄다 — 디스크 ✗` · 라이브 무변 |
| ② 갱신 | 서울 central · 한반도 · 도쿄 닛폰 사본 셋(라벨 붙음)이 **pull 앞**에 생기고 끝까지 `✓ 끝` |
| ③ 다시 친 판 | 바꿀 것 0 → 안 뜬다 |
| ④ 되돌리기 | 그 자리 셋 · 되놓기 줄이 찍혔다 |
| ⑤ 찍힌 한반도 줄 그대로 | `[놓음 ✓]` · `[행 ✓]` · `/health` 17초 |

* **흉내 판이 잡은 결함 하나(고침):** 서울 판 `backup-live.sh` 를 도쿄에 `bash -s` 로 흘리면 `BASH_SOURCE` 가 비어 `set -u` 에 걸렸다.

## 1. 줄(종전 그대로 — 새 줄 0)

```sh
bash <(ssh seoul cat /opt/Mini/scripts/update-live.sh) --dry
bash <(ssh seoul cat /opt/Mini/scripts/update-live.sh)
bash <(ssh seoul cat /opt/Mini/scripts/update-live.sh) --rollback --dry
bash <(ssh seoul cat /opt/Mini/scripts/update-live.sh) --rollback
```

* 이 판이 서울 트리에 있어야 ⓪ 이 돈다. 맥 한 줄은 서울이 **지금 가진** `update-live.sh` 를 돌린다 — T892 규약 그대로.
* 처음 한 번은 이 가지가 착지한 뒤 갱신을 한 번 치고, 그다음 갱신부터 ⓪ 이 선다.
* 도쿄는 서울 판 `backup-live.sh` 를 흘려 쓴다. 도쿄 트리가 옛 판이어도 같은 판이 돈다.

* 바꿀 것 0 이면 안 뜨므로, 할 일 없는 갱신을 여러 번 쳐도 매일 사본을 밀어내지 않는다.

## 3. `--rollback` 이 찍는 것

```text
[되돌리기 · 갱신 앞 스냅샷] DB 는 안 건드린다 — 라이브 DB 도 되돌릴 때만 아래 줄(대상마다 · 재민이 고른다):
    서울 central — /srv/durango/_daily/20261025-031121-central · 2026-10-25T03:11:22Z · 갱신 e5dec10daded → 02fda993c27c = 지금 이미지 커밋(이 갱신)
      ssh -t seoul 'cd /opt/Mini && bash scripts/backup-live.sh central --restore /srv/durango/_daily/20261025-031121-central'  # 답: central
    …(한반도 · 닛폰 같은 꼴)
```

* 찾는 법은 `backup-live.sh --last <대상> update-live`(새 모드)다. 그 대상의 라벨 `update-live` 인 가장 새 사본을 고르고, 라벨 없는 매일 사본은 건너뛴다.
* 지금 이미지 커밋(되돌리기 앞)이 라벨의 받을 판과 같으면 `= 이 갱신` 이다. 다르면 다르다고 찍는다(그 갱신이 그 대상 이미지를 안 바꿨거나 그 뒤 판).
* 사본이 없으면 `갱신 앞 사본 없음` 이다(T919 앞 갱신).
* DB 를 되놓을 판은 이미지 되돌리기 **뒤**다(옛 이미지가 그 사본을 연다). 절차서 §9 에 적었다.

## 4. `backup-live.sh` 에 더한 것(T907 위)

| 줄 | 무엇 |
|---|---|
| `BACKUP_LABEL=…` | meta `label=` · ✓ 줄. 글자는 `[A-Za-z0-9 ._:-]` 만 남기고 120자에서 자른다 — 셸 · 파일에 닿는 글자 0 |
| `--dry` | 뜰 자리(대상마다 `<시각>-<대상>`) · 지금 DB 크기 · 보관 개수로 뗄 옛것 — 아무것도 안 쓴다 |
| `--last <대상> [앞머리]` | `폴더<탭>시각<탭>라벨` 한 줄 · 없으면 rc 1 |
| `--list` | 라벨이 있으면 끝에 붙인다 |
| `HERE` | `bash -s` 로 흘려도 돈다(`BASH_SOURCE` 빔 — 흉내 판이 잡았다) |

`update-live.sh` 는 서울 스탬프 자리를 `SEOUL_STAMP` env 로 받는다(기본 그대로 `/srv/durango/deployed-hanbando.sha` — 하네스용 · `TOKYO_STAMP` 와 같은 꼴).
