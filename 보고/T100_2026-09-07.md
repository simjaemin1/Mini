## 2. §0-ⓑ 앵커 — **새 수는 `N` 하나** · `k` 는 유도값

### 출처

> **Gregory Clark**, *UC Davis Econ 210A — Chapter 4 "The Malthusian Economy"* (강의노트, 『A Farewell
> to Alms』 계열): 산업화 이전 농업사회에서 **"70–80% of the population labored upon the land."**

⇒ 농부 1인이 먹이는 사람 수 `N` = 1 ÷ 0.80 = **1.25** ~ 1 ÷ 0.70 = **1.43** · 중앙 1 ÷ 0.75 = **1.33**.

### `k` 유도 표 (분모는 T117 자 실측 · 시드 1020 · 800일 · 51마을 · 경작지 12칸)

```
  실측 H = Σ harvestN 190,602 ÷ (Σ fDays 765,497 ÷ 365) = 90.88 건/농부·해
  정본 소비 DAILY_FOOD_CONSUMPTION = 1.0   (= 0.70kg × 3,500kcal ÷ DAY_KCAL 2,450 — T59/T73/T86 사슬)
  k = N × (1.0 × 365) ÷ 90.88
```

| `N` | 근거 | 농부 1인 연간 목표 산출 | **k** |
|---|---|---|---|
| 1.20 | 지시가 준 세 점 ① | 438.0 | 4.8195 |
| 1.25 | 출처 하한 (농사 인구 80%) | 456.3 | 5.0203 |
| **1.33** | **출처 중앙 (75%) — 채택** | **485.5** | **5.3417** |
| 1.35 | 지시가 준 세 점 ② | 492.8 | 5.4220 |
| 1.43 | 출처 상한 (농사 인구 70%) | 521.9 | 5.7432 |
| 1.50 | 지시가 준 세 점 ③ | 547.5 | 6.0244 |

채택은 지시대로 **출처의 중앙값** `N = 1.33` ⇒ `k = 5.3417`.

⚠**`k` 는 소스에 유도식 한 줄로만 있다.** 하네스 ①이 `N`·`DAILY_FOOD_CONSUMPTION`·실측에서
다시 계산해 대조하고, ⑦은 **`k = 1` 로 적은 변조 사본**을 실제로 만들어 자식 프로세스에 물려
①이 빨개지는지 본다(변조본은 `sim/` 옆에 잠깐 두고 부모가 지운다 — 정본 무접촉).

⚠**실측 `H` 는 자다 — 세계가 아니다.** 재측정 명령이 상수 옆에 적혀 있다.

## 3. §0-ⓓ 곳간 배선 — 닿는 자리는 **한 줄**


```js
// sim/economy-sim.js  — 산수·세금·볏짚은 전부 여기 하나
function harvestToGranary(v, n) {
  if (!T100_FIELD_YIELD || !v || !v.storage) return 0;
  const amt = ((n > 0 ? n : 1)) * T100_K;
  v._grainToday = (v._grainToday || 0) + amt;          // 볏짚 연료 밑변 — 대체로 걷어낸 자리를 그대로 메운다
  const tax = amt * TAX_RATE;
  v.storage.food = (v.storage.food || 0) + (amt - tax);
  if (v.treasury) v.treasury.food = (v.treasury.food || 0) + tax;
  …
}
```

* **품목은 일반 `food`** — 2-c(곳간 구성 = 구체 작물) 전이니 3판 규약 그대로다(곡물 9종 평균 자리).
* **대체다.** 켜면 `addProduce(jdef.output, baseAmt)` 가 **농부에게만** 막힌다. 부산물 루프
  (밀·쌀·보리·삼·모시)는 `baseAmt` 를 그대로 타고 나간다 — 곡물·섬유 사슬 무변.
* **볏짚을 안 채웠다면 결함이었다.** 옛 `addProduce('food', …)` 가 `v._grainToday` 를 채웠고
  그게 짚 연료의 밑변이다. 걷어내기만 하면 짚이 0 이 되어 땔감 수요가 통째로 나무로 몰린다.
* **부양력(prodK)도 같은 앵커를 본다** — `farmFlowPerDay` 는 켜면 `농부수 × N × 하루 1인 식량`.
  산출은 밭인데 K 만 옛 밑변이면 인구가 밭 없이 분다(3판 §2-① 실측).
* **3판 모델식은 소스에서 사라졌다** — `CELL_FOOD_PER_DAY` · `T100_GARDEN_PER_FARMER` 삭제.
  하네스 ③이 "그 이름이 소스에 없다"를 검사한다(죽은 앵커 0).

|---|---|---|

## 6. 승인 요청 — 판단거리 (A/B/C)

3시드 표는 냈다. **채택 조건(소멸 0/51)은 못 채웠다** — 켠 팔에서 3 · 1 · 3 / 51 이 죽는다.
그러나 죽는 이유는 **기근이 아니라 첫 수확까지의 골짜기**이고(§4 ⓓ), 그건 `k` 를 키워 고칠 일이 아니다.
길이 셋이다. **나는 고르지 않았다.**

| | 안 | 무엇을 하나 | 새 수 | 값 | 대가 |
|---|---|---|---|---|---|
| **ⓐ** | **지금 그대로 채택** | 손잡이를 켜고 기준선을 옮긴다 | 0 | 밭이 곳간에 **진짜로** 닿는다 · 앵커가 스스로 되돌아온다(+3~10%) · 밭을 넓히면 곳간이 는다(게임성) | 인구 −31~42% · 소멸 3·1·3 · 무기Q −33~56% · 확장셀 −53~76% |
| **ⓑ** | **창설 곳간을 첫 수확까지로** | `createVillage` 의 `storage.food = initN × 45` 를 **파종→첫 수확 소요일**에서 유도(`crops.js` 의 `growDays` 중앙값 + 파종창) | 0 (유도) | 골짜기가 사라진다 — 켠 팔이 첫 수확 전에 굶지 않는다 · 정착 고증에도 맞다(들고 온 씨앗과 곡식) | 45일이라는 기존 수가 바뀐다(끈 팔도 함께 움직인다 ⇒ **기준선 재측정 필요**) |
| **ⓒ** | **텃밭 하한을 되살린다** | 3판의 ⓑ(밭 0칸이어도 농부 1인당 `LIFE_CLEAR_PDAY` 칸분 흐름)를 **수확 없는 날의 바닥**으로 | 0 (생활층 정본 `LIFE_CLEAR_PDAY = 3`) | 골짜기가 얕아진다 · 3판에 이미 있던 장치라 새 개념 0 | "밭이 실제로 낸 것만 들어간다"는 4판의 규약에 **구멍**이 난다(하한은 실측이 아니다) |

**세 안 모두 `k`·`N`·`LAND_NEED` 를 안 건드린다** — 그게 이 표의 요점이다.
ⓐ 는 지금 커밋 그대로이고, ⓑ·ⓒ 는 각각 한 줄짜리 후속 카드다(스크린 재측정 포함).

### 승인이 필요한 것 (넷)

1. **`N = 1.33` 채택** — 출처 Clark(70~80% 농사)의 중앙값. `k = 5.3417` 은 그로부터 유도.
2. **`LAND_NEED 8 → 12`** — 손잡이 밖의 정본 변경. 끈 팔의 여덟 수는 안 움직이지만 밭은 1.5배다.
3. **`T100_FIELD_YIELD` 를 켤 것인가** — 켜면 위 대가를 치른다. 기본값은 **끔**으로 두었다(실기 0).
4. **ⓐ / ⓑ / ⓒ 중 하나** — 골짜기를 그대로 둘지, 창설 곳간으로 메울지, 텃밭 하한으로 메울지.
