## ① `crop_render` 편입 — 화소 페이로드 동일

`crop_render.py` 214줄 → 132줄. 헬퍼 한 벌(`principled`·`simple_mat`·`bumped_mat`·`box`·`cyl`·
`ico`·`plane`)과 씬 조립을 들어내고 `render_common` 을 부른다. 팔레트 8개는 그대로 두고
datablock 이름에 **`c_`** 접두(T77 §12 문법). 호출부 기본값 잠금 **7곳**(`cyl.smooth` 4 · `ico.smooth` 3).

### ★"바이트 동일" 을 잴 수 없다는 것을 먼저 알아냈다

옛 코드와 새 코드를 **같은 컨테이너·같은 bpy 5.0.1** 로 구웠는데 8장 전부 바이트가 달랐다.
청크를 뜯어 보니 화소가 아니라 **메타**였다:

```
tEXt  Date        2026/09/04 15:46:49      ← 벽시계
tEXt  RenderTime  00:05.99                 ← 굽는 데 걸린 시간
tEXt  cycles.ViewLayer.render_time …
```

블렌더가 쓴 **원본 PNG 는 같은 코드로 두 번 구워도 바이트가 늘 다르다.** 자가 될 수 없다.
⇒ 비교를 **IDAT(화소 페이로드)** 로 옮겼다:

| 대조 | 결과 |
|---|---|
| 옛 코드 vs 새 코드, IDAT sha1 (5.0.1 같은 컨테이너) | **8/8 동일** |
| 화소 전수 대조 | 8장 모두 **다른 채널 0 / 평균차 0.00** |
| 바이트를 가른 것 | `Date`·`RenderTime`·`cycles.*_time` tEXt **뿐** |

T77 의 84장이 파일 `cmp` 0 이었던 이유도 여기서 설명된다 — 그것들은 `_post_png` 와
`icons-postprocess.js` 가 **다시 쓴** 파일이라 메타가 씻겨 있었다. 굽는 자리의 원본은 다르다.
이 규약을 `icons.lock.json` 과 `인계/ART-자산.md` §13 에 박았다.
