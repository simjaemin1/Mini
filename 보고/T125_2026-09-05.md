# T125 — NPC 가 옷을 입는다: 마을 옷 재고가 세계에 보인다 (2026-09-05)

**재민 캐논: 실체는 회계를 보여 준다.** econ 은 옷을 센다 — `storage.clothes`(재봉 산출) ·
`CLOTH_TARGET_PC` 1인 1.2벌 목표 · `_clothCov` 로 한랭 행복(`COLD_CLOTHED`). 그런데 화면의 주민은
**전부 삼베**였다. T13 이 NPC 를 시트로 옮기면서 준 별도 함수(`npcCharLayers`)가 옷을
`clothes_hemp` 로 **못 박고** 있었기 때문이다. 이 카드가 그 갈래를 없앴다.

## 0. §0 실측 (셋)

### ⓐ 곳간의 옷 — **재질이 없다. 그런데 유도된다**

`storage.clothes` 는 **그냥 수**다(재질 없음). 옷은 `tailor` 가 `CLOTH_MATS` 를 **보온 가중·재고
비례**로 먹어 만든다(`economy-sim.js:2286`):

```js
let haveW = 0; for (const m in CLOTH_MATS) haveW += (v.storage[m] || 0) * CLOTH_MATS[m];
const take  = (v.storage[m] || 0) * (needW * frac / haveW);      // ← 재고 비례로 나눠 먹는다
const CLOTH_MATS = { fur: 1.5, hide: 1.0, leather: 1.0, hemp: 0.6, ramie: 0.55 };   // 보온-eq/단위
```

⇒ **"이 마을 옷의 재질"은 저장돼 있지 않지만, 곳간을 보면 유도된다** — 재봉이 오늘 먹을 그 비율이다.
이 카드는 그 비율을 그대로 쓴다. 새 규칙을 만들지 않았고, 가중표는 **econ 정본을 읽는다**(사본 0).

**마을 51곳 분포 — 랩 시드 1020 · 800일(본 게임 배선 그대로 · `scripts/econ-lab-real.js`, 랩 무접촉·읽기만):**

| | 값 |
|---|---|
| 착의율(입은 주민/인구) 분포 | 최소 **0%** · p25 81% · 중앙 **119%**(재고가 인구를 넘음) · 최대 150% |
| **전원 착의** | 37 / 51 곳 |
| **전원 맨몸** | **3 곳**(농촌14 · 광산1 · 농촌9 — 곳간 옷 0~0.9벌) |
| 부분 착의 | 11 곳 (예: 농촌20 15/105 · 광산3 30/99 · 농촌17 29/78) |
| 주재질 분포 | 생가죽 16 · 삼베 14 · 갖옷 11 · 가죽 10 · **모시 0**(모시는 수요-캡이라 안 쌓인다) |
| 재질 가짓수 | 1~5종. 농촌14 는 **삼베 하나**, 광산1 은 **갖옷 95%** 인데 옷은 0벌(재봉이 없다) |

★**가장 좋은 그림 하나**: 광산1 은 모피가 95% 쌓여 있는데 **전원 맨몸**이다 — 옷감이 있어도
재봉이 없으면 옷이 아니다. 그게 화면에 그대로 나온다.

### ⓑ NPC 엔트리 — **필드는 이미 있었다.** 갈린 것은 클라의 층 함수뿐

| | 사람 | 주민(T13~T125 이전) |
|---|---|---|
| 서버 엔트리 | `makeEntry(o, …, 'player')` | **같은 분기**(NPC 도 `players` 에 산다) |
| 옷 필드 | `e.clothes = 장비.mat` | **같은 줄이 돌지만** `getEquippedEquipment` 가 빈손 ⇒ 언제나 `null` |
| 클라 층 선택 | `charLayersFor(isMe, o)` | `npcCharLayers(job)` — **다른 함수** |
| 옷 층 | `clothLayerOf(o.clothes)` (재질 여섯) | **`'clothes_hemp'` 리터럴** ← 여기가 결함 |
| 도구 층 | `o.tool` → 실루엣 **둘**(`tool_rod`/`tool_axe`) | 직업표 `NPC_JOB_TOOL` → 실루엣 **다섯** |
| 등짐 | `o.carrier` | 없음 |

**통일 판정 — 도구는 `tool` 필드로 접지 않았다(카드 ②의 "아니면 그대로").**
직업표를 `tool` 문자열로 보내면 클라의 접기 규칙(`/rod|fish|낚/` → rod, 나머지 → axe)이
**괭이·채반·창·망치를 도끼 하나로 뭉갠다** — 다섯 실루엣이 둘이 된다. **통일이 정보를 줄이는 자리**라
안 했다. 대신 **층 함수를 하나로** 합쳐(`npcCharLayers` 삭제 · 사본 −1) 그 함수 안에서 표를 읽게 했다:
옷은 두 경로가 **같은 한 줄**을 쓰고, 도구만 출처가 둘이다.

★**"자리 해시"를 실측했다 — 지금 pid 로는 해시가 일을 안 한다.**
카드는 "NPC 자리 해시 순"을 시켰다. 정본 해시(`villages._pidHash`)에 실제 pid(`p<N>`)를 넣어 재 보니
**스폰 순서와 순위 상관 ρ = 1.0000**(p1~p40 · p120~p180 · p95~p115 · p990~p1010 네 구간 전부).
다항식 해시라 같은 자릿수 안에서 단조이고, 자릿수 경계도 안 깨진다.
⇒ 실효 규칙은 **"먼저 온 주민부터 입는다"** 다. 숨기지 않고 그대로 적는다. **그리고 그게 낫다**:
진짜 난수 해시였다면 주민이 하나 늘 때 새 pid 가 앞줄에 끼어들어 **남의 옷을 벗길** 수 있다.
지금은 안 그렇고, `test-npc-clothes ⓔ` 가 그 성질을 못 박는다(주민 10→14 명, 입던 넷 그대로).
⚠**자리(좌표)로는 절대 안 고른다** — 주민은 걸어 다니므로 옷이 매틱 깜빡이고,
`makeEntry` 의 1.2초 창이 그 깜빡임을 그대로 네트워크에 싣는다.

### ⓒ 하네스 — 카드가 지목한 둘 다 아니다. **`e2e-npcsprite` 다**

| 하네스 | NPC 그림을 재나 | 왜 |

⇒ 이 카드의 화면 검사는 **`e2e-npcsprite` 를 늘렸다**. 그리고 거기 **결함이 규격으로 적혀 있었다**:

ok(seen.every((s) => s.layers[0] === 'body' && s.layers[1] === 'clothes_hemp'),

## 1. 한 것 (셋)

### ① 서버 — `makeEntry` 의 **같은 필드**에 값을 채운다 (새 필드 0)

`server/villages.js` 에 `syncVillageClothes(vil, players, econ)` 를 더하고, **직업 재동기 바로 옆**
(`pop` 조각 · 하루 한 번)에서 부른다. 하는 일 셋:

```
누가  : npcPids 를 정본 `_pidHash` 로 줄 세워 앞에서부터 min(인구, floor(storage.clothes)) 명
무엇을: 재봉이 먹을 믹스 그대로 — storage[m] × econ.CLOTH_MATS[m] 비율로 잘라 재질을 준다
        (옷감 재고가 0인데 옷은 있으면 = 교역품 ⇒ 삼베로 떨어진다)
전송  : 값이 바뀐 순간 `_wornAt` 을 찍는다 ⇒ zone.js 의 **옷과 같은 무상태 델타 창**이 실어 나른다
```

`server/zone.js` 는 **한 줄**이다 — 출처만 갈린다:

```js
e.clothes = o.isNpc ? (o._simCloth || null) : ((getEquippedEquipment(o, 'clothes') || {}).mat || null);
```

★**econ 은 읽기만 한다.** 곳간을 한 톨도 안 깎는다 — 마모는 econ 의 `CLOTH_WEAR_PC` 몫이고
여기서 또 깎으면 이중 차감이다(`test-npc-clothes ⓕ` 가 지킨다).
★econ 파일에 더한 것은 **`module.exports` 한 줄**(`CLOTH_MATS`)뿐이다. 이 레포의 anti-사본 관용구
그대로다(`RAW_GRAINS`·`RESERVE_PC`·`_SMELT_PER_LABOR` … 이미 여럿). **틱 로직·값 무접촉.**

### ② 클라 — 층 함수를 **하나로** (사본 −1)

`npcCharLayers` 를 지우고 `charLayersFor(isMe, o)` 하나가 사람도 주민도 맡는다:

```js
const job = (!isMe && o) ? o.job : null;
const L = ['body'];
if (!(job && o && !o.clothes)) L.push(clothLayerOf(isMe ? myClothMat() : (o && o.clothes)));  // ← 맨몸
…
const jt = job ? NPC_JOB_TOOL[job] : null;
if (jt) { if (hasCharLayer(jt)) L.push(jt); return L; }                                        // ← 직업 소품
```

★**맨몸이 그려진다.** `clothLayerOf(null)` 은 삼베라 그 함수로는 맨몸을 못 그린다 —
주민이고 옷이 없을 때만 **층 자체를 뺀다**. 사람은 벗어도 삼베다(종전 계약 무변).

### ③ 계절 — **비율은 안 오른다.** 카드 전제를 실측이 뒤집었다

카드 ③: *"겨울에 옷 입은 NPC 비율이 오르면 그게 `COLD_CLOTHED` 의 실체다."*
같은 시드로 네 점을 떴다(전부 랩 읽기만):

| 점 | day | doy | 한랭 | 인구 | 옷 입은 주민 | **비율** | 1인당 옷 |
|---|---|---|---|---|---|---|---|
| 겨울 W1 | 315 | 315 | 0.667 | 3,045 | 1,715 | **56.3%** | 0.651 |
| 여름 S1 | 497 | 132 | 0.000 | 4,323 | 3,157 | **73.0%** | 0.950 |
| 겨울 W2 | 680 | 315 | 0.667 | 5,325 | 4,736 | **88.9%** | 1.311 |
| 여름 S2 | 862 | 132 | 0.000 | 7,345 | 6,618 | **90.1%** | 1.665 |

* **겨울(88.9%) < 그다음 여름(90.1%)** — 순진하게 견주면 **−1.2%p**, 오르지 않는다.
* 같은 계절 두 점의 기울기가 서로 안 맞는다(겨울↔겨울 **+32.6%p/년** · 여름↔여름 **+17.1%p/년**)
  — 곡선이 **포화**하고 있다는 뜻이다(증분 +16.7 → +15.9 → +1.2). 그래서 **선형 보정이 안 선다**:
  겨울 곡선으로 여름 862 를 예측하면 **105.2%**(불가능한 값)가 나온다.
* ⇒ **계절 항을 이 표본으로는 못 가른다.** 반년 간격 네 점으로는 포화와 계절이 섞인다.
  가르려면 한 해 안에서 하루 단위로 여러 점을 떠야 하는데 랩이 그 덤프를 안 낸다(**회부**).

**그러나 구조는 답이 분명하다.** `COLD_CLOTHED` 는 `_clothCov × coldStress` 곱이고,
겨울에 켜지는 것은 **`coldStress`(0 → 0.667)** 다. `_clothCov` 는 계절이 아니라 **재고**를 따라간다.
⇒ **화면에서 겨울에 달라지는 것은 옷 입은 사람 수가 아니라, 그 옷이 값을 하는 계절이라는 사실이다.**
"겨울에 더 많이 입는다"는 이 econ 의 물리가 아니다 — 적어 둔다.

★**`e2e-npcsprite` 의 규칙 셋을 갈아 끼웠다**(지운 규칙 0):
ⓐ `layers[1] === 'clothes_hemp'` → **곳간↔화면 일치**(`clothes` 있으면 그 재질 한 장, 없으면 **0장**),
ⓑ 소품 자리를 `layers[2]` 로 못 박던 것 → **맨 뒤 장**(옷이 빠지면 자리가 당겨진다),
ⓒ 맨손 = `layers.length === 2` → **`tool_` 층 0**(장수는 옷 유무에 달렸다).

★**`e2e-npcsprite ⑥`(프레임 비용)은 계기의 잡음이 제 문턱보다 크다 — 회부.**
세 판을 돌렸다: **+? (통과) · +12.5% (빨강) · −2.1% (통과)**. 문턱은 10% 인데 같은 코드에서
15%p 가 흔들린다. 내 변경이 비용을 늘릴 수 없다는 것은 구조로 안다 — 층 수가 **같거나 줄기**
때문이다(맨몸은 옷 층이 빠진다 · 입은 주민은 `clothes_hemp` 대신 `clothes_<mat>` 로 **같은 한 장**).
⇒ 값만 적고 회부한다. 이 계기를 믿으려면 표본을 늘리거나(짝 비교 n판) 문턱을 잡음 위로 올려야 한다.

★**실측이 잡은 결함 하나 — 하네스가 잡았다.** 1차 판은 `econ.CLOTH_MATS` 라고 적었는데
`econ` 은 이 파일의 **모듈 전역이 아니다**(함수마다 지역 이름 · 정본은 `state.econ`).
일틱이 통째로 죽었고 `e2e-village` 가 **7건 빨강**으로 그것을 잡았다. 주석에 그대로 남겼다.

★**부하가 판정을 뒤집는다 — 다시 확인.** 랩 두 판을 돌리면서 `e2e-village` 를 돌렸더니 5건이
빨갛게 나왔다(쉼터·이방인 사슬). **단독으로 돌리니 main 기준선 49/0 · 내 판도 49/0.**
2코어에서 E2E 와 무거운 것을 같이 돌리지 마라(공통 §2 규약 그대로다).

## 3. 회부

* ★**[재민 판정] 겨울 계절 항을 정말 가를 것인가** — 위 §1-③. 랩이 하루 단위 덤프를 안 내므로
  가르려면 랩에 스냅샷 훅이 필요하다(**T123 세션3 이 랩을 만지는 중이라 손 안 댔다**).
  안 가르면 "옷 비율은 재고를 따라간다"로 두면 된다 — 물리는 이미 명확하다.
* **[영역 클라/ART] 등짐·갑옷** — 주민은 `carrier`·갑옷이 없다. 등짐은 필드가 이미 있고
  (`e.carrier`), 주민 쪽 술어만 정하면 같은 자리에 한 줄이다. 갑옷은 시트가 없다.
* **[영역 ART] 도구 축 통일** — 지금은 사람 실루엣 둘 · 주민 다섯이다. 사람에게도 다섯을 주려면
  `tool` 문자열을 다섯으로 접는 표가 필요하다(§0-ⓑ). 정보가 **느는** 방향이라 할 만하다.
* **[영역 econ · 작은 것] 모시(ramie)가 주재질인 마을이 0곳이다** — 수요-캡 공급이라 안 쌓인다.
  옷 재질로서 모시는 화면에 거의 안 나온다. 시트는 있다(`clothes_ramie`).
* **[그대로]** MakeHuman 채택(재민) · NPC 갑옷·전사 병종 · NPC 업기 모션 · 16방향.
