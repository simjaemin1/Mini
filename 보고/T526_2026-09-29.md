## 1. ① 실내의 정본 하나 — 지붕 아래

### 1-ⓐ 무엇이 비어 있었나(T520 을 코드로)

* `zone.isIndoorAt(p)` = `!!Rooms.roomAt(cx, cy, floor)` 하나였다. 부르는 곳은 셋이다. 몸 틱의 `indoor`(zone.js 13097), 부패 자리 열쇠(`_placeKeyOfGround` → `indoor` · `_placeKeyOfBuilding` 궤짝 → `chest_in`), 하네스 내보냄이다.
* 방 = 벽·문으로 닫히고 바닥이 다 깔린 칸(rooms.js)이다. 마을 움집·쉼터는 남벽에 **문 개체 없는 개구 2칸**이 있다(`buildStructureRect(…, [cx−3, cx−2], { hut })` · villages.js 1001·1006·1015). 그래서 BFS 가 새고, 마을 태그 바닥은 시드에서도 뺀다(rooms.js 머리글 "마을 건물은 이 경로를 안 탄다").
* 클라는 이 빈칸을 알고 있었다. `34-m-renderloop.js` 1068~1070 에 이렇게 적혀 있다: *"문이 개구(문 개체가 없는)인 마을 움집·큰집은 서버도 방을 못 만든다 → 종전대로 발자국 렉트 태그(data.hut/data.bld)가 그쪽 실내 판정 정본이다"*. 그런데 그 정본은 **화면**(지붕 걷기 · 남·동벽 페이드 · 실내 NPC 가림)에만 쓰였고 몸은 몰랐다. ⇒ T520: 쉼터 안에 서도 실내 0/50.

### 1-ⓑ 술어 — 방 ∪ 마을 발자국

```js
// server/rooms.js (T526)
function villageRoofOf(b, cx, cy) {   // 바닥 행 b 가 마을 정형 건물의 바닥이고 (cx,cy) 가 그 발자국 안인가
  if (!b || !D || !D.isVillageTagged || !D.isVillageTagged(b) || !b.data) return false;
  const R = b.data.hut || b.data.bld || b.data.gran;
  return Array.isArray(R) && R.length >= 4 && cx >= R[0] && cx <= R[2] && cy >= R[1] && cy <= R[3];
}
function villageRoofAt(cx, cy, floor) { if (!D || !D.floorTileAt) return false; return villageRoofOf(D.floorTileAt(cx, cy, floor), cx, cy); }
function underRoofAt(cx, cy, floor) { return !!roomAt(cx, cy, floor) || villageRoofAt(cx, cy, floor); }

// server/zone.js — 손잡이 한 곳
const T526_VILLAGE_INDOOR = process.env.T526_VILLAGE_INDOOR === '1';
function isIndoorAt(p) {
  try {
    const cx = Math.floor(p.x / 32), cy = Math.floor(p.y / 32);
    if (T526_VILLAGE_INDOOR) return Rooms.underRoofAt(cx, cy, p.floor || 0);
    return !!Rooms.roomAt(cx, cy, p.floor || 0);          // 끔 = 종전 줄 글자 그대로
  } catch (e) { return false; }
}
```

**새 규칙 0인 까닭 셋:**

1. 방의 문법("바닥이 깔린 칸")을 그대로 쓴다. 문간·마당·벽 바깥은 바닥이 없어 바깥이다.
2. "마을 정형 건물인가"는 rooms.js 가 **이미** 주입받아 쓰던 술어 `isVillageTagged`(방 시드에서 빼는 그것)다.
3. 렉트는 villages.js 가 벽·바닥 전 행에 찍는 `data.hut`·`bld`·`gran` 이다(클라 `_bakeRoof` 지붕 앵커 · 실내 게이트와 같은 값). 좌표를 짓지 않는다.

* 발자국 기하(villages.js 7206~7210): 움집·쉼터 바닥 = x ∈ [cx−5, cx] × y ∈ [cy−5, cy−2](6×4 = **24칸**)다. 남벽은 y = cy−1 행의 N 변이고 개구 2칸(x = cx−3, cx−2)이 있다. ⇒ 문 칸 (cx−3, cy−1)·(cx−2, cy−1) 은 렉트 밖이고 바닥도 없어서 바깥이다. 큰집은 8×8(`bld`), 곳간은 5×3(`gran`)이다.
* `weatherFor` 는 켬이면 `indoor` 칸을 **전달만** 한다(`Object.assign(…, T526_VILLAGE_INDOOR ? { indoor: isIndoorAt(p) } : null)`). 끄면 칸이 안 생겨서 페이로드 바이트가 같다. 계측기(`t507-arrival`)가 이 칸을 서버의 말로 읽는다.
* ⚠바닥 조회 `findFloorTile` 은 **활성 청크**의 격자(`qtColl`)만 본다. 사람이 선 자리는 늘 활성이라 몸에게는 그걸로 충분하다. 아무도 안 선 쉼터를 재는 하네스는 메모리의 행으로 몸통(`villageRoofOf`)을 직접 잰다(`test-downed ㉑ⓒ`).

## 3. ③ 불 곁 × 실내 — 지금 순서 그대로

`coldTarget` 의 줄 순서(body.js 719~763)는 이렇다: ℃ 곡선(옷 `insC`) → 바람 ×(1 + 0.6·wx) → 마을 완충 ×(1 − 0.65·sh) → **실내 ×0.30** → **불 곁 min(t, 0.05)** → 하한 0.
⇒ 둘 다이면 **min(0.30·t, 0.05)** = min(실내 값, 불 곁 값)이다. 곱해 쌓지 않고 **둘 중 센 쪽**이 남는다. 0.30·t < 0.05(t < 0.167 — 겨울 밤 도착 자리엔 없다)면 실내 값이 남고, 그 밖엔 불 곁 천장이 남는다.

## 5. 회부

1. **클라 비·눈 층** — `37-r1-weather.js` 91 "지붕 아래선 안 그린다" 는 `playerIsIndoors`(= 서버 방 `cellRoomCache`)만 안다. 켜면 움집 안에서 몸은 안 젖는데 화면엔 비·눈이 내리고 빗소리가 난다(`__sfx.weather(w, indoor)`). 서버는 켬이면 게이지 `weather.indoor` 를 이미 보낸다 — 클라가 그 칸을 읽는 한 줄이면 된다(클라 소유 세션).
