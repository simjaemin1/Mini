## 1. T10-① `test-guest-rejoin` — 원인 귀속

### 먼저: 오늘은 **재현되지 않았다**

통합 러너 전수(56개, 약 2시간)에서 이 하네스는 **통과**했다(26/26).
그래서 "러너 안에서만 죽는다"를 오늘 그대로 재현하지 못했다. **그 사실을 먼저 적는다.**

러너는 이미 순차 전용이다(`for f in "${LIST[@]}"; do run_one "$f"; done` — 병렬 모드가 없다).
⇒ 지시서가 제시한 두 갈래 중 "병렬 실행"은 **애초에 없는 조건**이고, 남는 것은 **앞 하네스의 잔재**뿐이다.

### 그 조건을 만들어 확인했다

`drain()` 은 `pkill` + 8초다. 존은 SIGTERM 을 받으면 "상태 flush 후 종료"를 하므로
세계가 크면 8초 안에 안 죽을 수 있다. 그 상태에서 다음 하네스가 뜨면:

```
① 하네스가 띄운 자식 둘이 EADDRINUSE 로 즉사한다
② boot() 이 자식의 죽음을 안 본다. 게다가 stderr 를 `() => {}` 로 **버렸다** — 한 글자도 안 보인다
③ waitHttp 가 **남의 서버**에 붙어 "기동 OK" 로 통과한다
④ 그 뒤 전 검사가 **남의 세계**를 잰다. 그 세계엔 E2E_GIVE 가 없으니
   `__e2e_give` 가 아무 일도 안 하고 인벤 검사 4건이 떨어진다
```

실측(3010/3020 에 서버를 띄워 두고 옛 판을 돌림):

```
  ✗ ①a 전제: 물건을 얻었다              berry=undefined
  ✗ ★② 인벤 보존                        berry=undefined
  ✗ ★③ 인벤 보존(두 번의 획득 모두)      berry=undefined stone=undefined
  ✗ ④ 인벤 보존
  === 26건 중 PASS 22 · FAIL 4 ===
```

**화면에는 "게스트 재접속이 인벤을 잃는다"로 보인다.** 없는 회귀를 보고하는 판이다 —
`run-regress.sh` 머리말이 경고한 바로 그 함정(고정 포트)이 하네스 안쪽에 남아 있었다.

### 고침 셋 — 전부 하네스 쪽

```
ⓐ 포트를 **부팅 직전에 빈 것으로** 고른다   pid 기반 시작점 · net.createServer bind 로 실제 확인
ⓑ 자식이 죽으면 300초 기다리지 않고 **즉시** 그 사실과 stderr 꼬리를 찍고 실패한다
ⓒ 기동에 실패하면 뒤 검사를 **아예 진행하지 않는다** — 숫자가 "안 쟀다"는 뜻이 되게
```

곁가지 실측 하나: 하네스가 zone 에 주던 `CENTRAL_URL` 을 **아무도 안 읽는다**.
정본은 `zone-config.js:423~424` 의 `CENTRAL_HOST`/`CENTRAL_PORT` 다. 3010 이 기본값이라
**우연히** 맞고 있었고, 포트를 옮기는 순간 깨지는 자리였다. 읽히는 이름으로 바꿨다.

### 대조군 (`scripts/t10-stale-control.sh`)

같은 잔재 조건에서 옛 판과 새 판을 **나란히** 돌린다.

```
  잔재 있음 · 옛 방식 → PASS 22 · FAIL 4 (rc=1)   ← 인벤 검사 4건
  잔재 있음 · 새 방식 → PASS 26 · FAIL 0 (rc=0)
  ★대조군 성립
```

★옛 판은 `git show HEAD:scripts/test-guest-rejoin.js` 로 **레포에서 꺼낸다**(족보 79 — 손으로 베끼면 사본이다).
그리고 `scripts/` **안에** 꺼내야 한다. 처음에 `/tmp` 에 뒀더니 `__dirname` 이 달라져
`require('../node_modules/ws')` 가 깨졌고, 그건 "옛 방식이 실패했다"가 아니라 **내 실수**였다.
대조군 스크립트는 이제 결과줄이 없으면 `CRASH` 로 따로 세어 그 혼동을 막는다.

## 2. T10-② `e2e-waterperf` — 왜 아직 "8배 절대 문턱"인가 → **ⓒ**

### ⓐ·ⓑ는 아니다 (커밋·코드로)

* **짝 비교는 붙어 있다.** 5라운드 · 한 라운드 안에서 `slow → fast` 를 붙여서 · 라운드별 배율의 중앙값.
  파일 안에 전환 이유까지 적혀 있다(2026-08-31 재민 확정 "ms 는 기계 의존 — 같은 순간 A/B 로만").
* **베이스 워크트리 비교기도 있다.** `scripts/perf-pair.js` 가 기준선 커밋으로 워크트리를 뜨고
  `base → head → base → head` 로 번갈아 돌려 **배율의 비율**을 낸다. 기준선은 `scripts/perf-baseline.json`
  (박혀 있지 않다 · `HEAD == 기준선` 이면 자명 통과라고 **비교를 거부**한다). 다만 파일 머리에
  "⚠계측기다. **판정 러너에 넣지 마라**" 라고 적혀 있어 의도적으로 러너 밖이다.

⇒ **ⓒ 다.** 하네스의 판정에 `rMed >= 8` 과 절대 ms 문턱 둘(`fwMed < 120` · `swMed > 4프레임`)이
여전히 `ok()` 로 남아 있었다.

### 문턱을 논하기 전에 분포를 쟀다 (5회 · 러너와 같은 규약)

```
  rMed        9.36 · 9.41 · 9.54 · 9.65 · 10.66      ← 문턱 8 과의 여유 17%
  라운드 낱개  6.09 ~ 12.20                            ← 낱개는 문턱 아래로 내려간다
  rSab        1.004 ~ 1.082                           ← 같은 순간 대조 짝(수리 없음 · 참값 1)
  rMed/rSab   8.81 ~ 10.00
```

중앙값 도입이 판정량을 5.2~9.4(문턱에 **걸쳐 있던** 분포 — 파일이 기록한 종전 값)에서
9.4~10.7 로 올린 것은 맞다. **그러나 8 은 여전히 꼬리 바로 위**다.
반면 `rSab` 는 1.00~1.08 로 아주 좁다 — **같은 순간 대조가 진짜 자다.**

### 고침

```
  판정      rMed > rSab × K   (K=4 · 비율의 비율)
  참고 출력  [참고 — 판정 아님] 한 프레임 28ms(상한 120 · 안) · 대조 15.8프레임(하한 4 · 넘음)
                              · 배율 중앙값 9.3배(문턱 8 · 위)
  계기 검사  rSab < 2   (종전 8 에서 **조였다** — 실측 1.004~1.082)
```

K=4 는 재서 골랐다: 수리 있는 짝 8.81~10.00 · 없는 짝 1.0 · 로그 중앙 ≈3.0.
잡음(1.0)에서 4배 위, 실측 최소(8.81)에서 2.2배 아래.
절대값 셋은 **지우지 않았다** — 판정에서만 뺐다.

### 자기 실패 검사기 · 대조군

`WATERPERF_SABOTAGE=1` 이면 '수리' 자리에도 대조를 넣는다(기본 부팅엔 분기 자체가 없다).

```
  정상       통과 16 · 실패 0 · 비율의 비율 9.32 > 4
  사보타주   rc=1 · 비율의 비율 0.78 · 실패 5   ← 판정이 실패할 줄 안다
```

### 10회 연속

```
회차 1~10 · rc=0 · 전부 "물가 렉: 통과 16 · 실패 0"
★10회 연속 초록
```

### ⚠판정에서 뺀 것이 잃는 것 — 회부

`fwMed < 120` 은 "헤드리스가 실기보다 느리므로, 이 값 아래면 실기에서 한 프레임 안에 든다"는
**사용자 쪽 주장**이었다. 이제 이 하네스가 그 주장을 지키지 않는다(찍기만 한다).
절대 상한이 필요하다면 그건 **기계를 고정한 자리**(전용 러너·같은 하드웨어)에서 재는 게 맞다 —
`perf-pair.js` 가 이미 그 자리다. 판단은 PM.
