## §1 ① 재현 — 어느 줄에서 갈리나

빨강 줄 `[3,0,"cooked_food>wood",21,12,24,1,11,23,0]` — 마을3 · 열량 짝 끔 · 익힌 음식 → 나무 21 · 견적 12 → 24 · 실행 11 → 23 · 넘침(하나 적게 내도 닿는다).

* 갈리는 줄 = **올림의 출발점**이다. 고르기 · 단위는 견적 · 실행이 같은 함수다(T835 그대로). 출발점이 최소 위라 위로만 걷는 올림이 내려오지 못한다. 넘친 낱개 수에 상한 절삭이 각자의 평균 단위(20개 1.72 · 12개 1.878)로 걸려 둘이 다른 수가 된다 — 빨강 둘(열량 짝 끔/켬 한 쌍)이 그 꼴이다.
* 나머지 77 줄은 견적 = 실행인 채 **둘 다** 넘쳤다(가장 큰 것: 마을3 익힌 음식 → 식량 34, 66 → 50 · 최소 38 → 34 · 28개 더). 그래서 "견적 ≠ 실행" 줄은 2 지만 "켬 넘침" 줄은 79 다.

* **열넷째 판에서 안 보인 까닭**: 넘침은 첫 아이템(가벼운 생선 둘) 너머까지 낼 때만 난다. 열넷째 판 곳간으로는 받을 양 주문이 된 128 줄 중 낸 낱개 3 이상이 2 줄이었다. 열다섯째 판은 325 줄 중 121 줄이다. 곳간이 차서 큰 주문이 서니 감춰져 있던 출발점이 드러났다.
* 끔 갈래 실행도 같은 결함이다. 열다섯째 판에서 83 줄이 넘쳤다(1,109 → 617개). 둘은 실행이 거절했다(마을0 익힌 음식 → 나무 3 · 열량 짝 끔/켬). 견적 어림 낱개 8 에서 출발해 8개 16.03 단위가 상한에 닿았다. 그 평균 2.004 로 ⌊6 ÷ 2.004⌋ = 2개로 깎자 가벼운 생선 둘(1.65 단위)만 남아 "그 양으론 한 개도 못 바꾼다 — 더 내야 한다"가 됐다. 고친 뒤엔 3개 → 나무 2(마을이 내줄 수 있는 몫 · 상한)다.
* 실제 호스트 단위(`zone.js` `_unitsOfFor` — 개체 kg ÷ 기준 kg 또는 열량 · 로트는 신선도 배율)도 낱개마다 다를 수 있다. 처음 고른 낱개가 뒤 것보다 가벼우면 같은 넘침이 난다(추론 — 이 카드는 하네스 짐으로만 쟀다).

## §2 ② 고침 — 손잡이 하나

```js
const T965_ON = !(typeof process !== 'undefined' && process.env && process.env.T965_WANT_START === '0');   // 켬 기본 · 되돌림 `=0`
function _countAtOrBelow(gu, unitsAt, maxN) {   // 단위(`unitsAt(c)`)가 연속해 `gu` 를 안 넘는 마지막 낱개 c(0 ~ maxN)
  let lo = 0, hi = 1;
  while (hi < maxN && unitsAt(hi) <= gu) { lo = hi; hi = Math.min(maxN, hi * 2); }
  if (unitsAt(hi) <= gu) return hi;
  while (hi - lo > 1) { const mid = Math.floor((lo + hi) / 2); if (unitsAt(mid) <= gu) lo = mid; else hi = mid; }
  return lo;
}
```

* 견적(402): `_climbToWant((T965_ON && _G) ? _countAtOrBelow(gu, _uAt, Infinity) : Math.floor(gu / perItem), …)` — 켬 갈래(T835 · 호스트가 인벤을 넘긴 판)만 바뀐다. 끔 갈래(`_G` 없음)는 종전 글자다(T835 끔 = 한 개짜리 어림 그대로).
* 실행(463): 켬 = `_climbToWant(_countAtOrBelow(qw.giveNeededUnits, G.at, Infinity), wantTake, G.at, _tw, Infinity)` · 끔 = 종전 `_climbToWant(qw.giveNeeded, wantTake, (c) => _units(_pick(c)), _tw, have)`. 연속해 `giveNeededUnits` 는 T835 와 무관한 견적 칸이라, 실행의 출발점은 두 갈래가 같다. 그래서 실행 켬 = 끔이 된다.
* 단위 이음 `G.at`(가진 것 너머는 첫 개체 단위로 잇는다)은 견적의 `_gAt` 식을 `_giver` 로 올린 것이다(한 글자 같은 식 · 견적 · 실행이 같은 함수). 가진 것으로 못 닿으면 실행의 "… N개가 필요한데 그만큼 없다"가 견적의 낼 낱개 N 으로 말한다. 종전처럼 `have` 에서 멈추면 가진 것 전부로 절삭 셈이 돌아 그 말의 N 이 견적과 달라진다.
* 바뀌지 않은 것: `_climbToWant`(`CFG.CLIMB_MAX` 8 · `MIN_GIVE`) · `_trimToCap` · `planSliced` · `_giveForTake` · 값 · 상한 · 호스트(`villages.js` · `zone.js`) · 클라. 출발점이 "연속해 아래 마지막 낱개"라 걸음은 종전 주석이 말한 "한 칸 아래에서 출발해 올라간다" 그대로다. 이분 탐색은 올림 걸음이 이미 쓰는 전제(낱개를 더하면 단위가 는다) 위에서 정수로 끝난다. 무게가 고르면(모두 u) ⌊gu ÷ u⌋ 와 같은 수다(새 하네스 ⓓ).
