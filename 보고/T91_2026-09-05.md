`crops.js:_dormant` 가 그 `winterCrop` 을 읽는다. 즉 축→게임 환산이 **빌드 쪽에 하나** 있었고,

const LC_WINTER = '월동';

## 2. ★★★수확 뒤 처리도 정본 하나 — `cropAfterHarvest`

여태 수확은 **두 곳**에서 자리를 지웠다:

| | 종전 | 문제 |
|---|---|---|
| 마을 칸 | `vil._crop.delete(k)` | 다년생도 지워졌다 |
| 플레이어 밭 | `best.data = { crop: null, … emptiedDay }` | 같은 판단을 **두 곳**이 따로 한다 |

⇒ T58b 가 상태기를 한 벌로 만든 그 이유로, **수확 뒤 처리도 한 벌**로 만들었다(`villages.js`):

```js
function cropAfterHarvest(e, day) {
  const C = _Crops();
  if (!e || !C || !C.isPerennial(e.c)) return false;    // 한해살이 — 부르는 쪽이 자리를 비운다
  e.p = day; e.td = day; e.wd = 0;                      // 그루터기에서 다시 (q·ps·w 는 그대로)
  return true;
}
```

마을 칸(`_lifeDoTask0`)과 플레이어 밭(`zone.tryHarvest`)이 **같은 이 함수**를 부른다.
두 벌이 됐다면 *"플레이어 부추만 안 다시 나는 날"* 이 왔을 것이다.

### 설계 판단 셋 (전부 **새 수 0**)

**① 재생일 = 같은 `growDays`.** 카탈로그에 재생일 열이 없다. 없는 수를 지어내지 않았다 —
첫 해보다 짧게 두려면 **표에 열이 먼저 생겨야 한다**(회부).

**② 뿌리에 남는 것은 남긴다 — `q`·`ps`·`w` 는 이어진다.**
되돌렸다면 *"묵혔다 거두면 새 밭"* 이라는 유인이 생긴다: 품질 바닥(0.25)까지 방치한 밭을
한 번 거두면 1.00 으로 돌아오는 길이 열린다. 수확은 병을 낫게 하지도, 밭을 세탁하지도 않는다.
다시 나는 것은 **줄기**이므로 오늘로 되돌리는 것은 **성장 시계 `p` 와 김맨 차례 `wd`** 둘뿐이다
(`wd` 는 성장 비율에 물린 차례라 새 곡선을 따라야 한다).

**③ 다년생은 씨앗을 안 돌려준다.** 한해살이는 죽으면서 씨를 남기고, 다년생은 **살아서** 남는다.
둘 다 주면 부추 한 포기가 **씨앗 무한 발생기**가 된다(그루터기는 그대로 다시 여무는데 씨까지 나온다).
물리가 그대로 규칙이 됐다 — 실제 다년생도 씨가 아니라 **포기나누기**로 번진다.
