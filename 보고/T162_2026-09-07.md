**6.70 → 2.81 MB (−58.1%)**. 자산 무변 규칙이라 이 카드에서 안 바꾼다 → §4 회부.

### 로더 — 무엇을 언제

`public/client/42-r2-char.js` `charMeta()` 하나다. 메타가 오면 **그 자리에서 전 시트**를 건다:

```js
for (const key of Object.keys(j.sheets || {})) charSheet(key);   // 192장 전부, 한꺼번에
```

* **언제 시작하나** — `charMeta()` 는 `drawCharSprite`·`clothLayerOf`·`hasCharLayer` 에서만 불린다.
  즉 **로비에서는 한 장도 안 받는다**. 실측 타임라인(로컬): 클릭 0.8s → 서버 권위 위치 2.6s →
  **첫 캐릭터 그림 4.4s** ← 여기서 메타가 오고 시트 청구가 시작된다.
* **병렬 수** — 클라가 안 정한다. `new Image()` 192개를 한 번에 걸고 브라우저가 줄 세운다
  (로컬 central 은 HTTP/1.1 이라 호스트당 6). 프로덕션 Caddy 는 도메인+TLS 라 h2 이므로 이 수가 다르다.
* **순서** — `Object.keys(sheets)` = **층 이름 알파벳순**이다. 그래서 첫 프레임이 실제로 쓰는 두 장
  (`body_idle`·`clothes_hemp_idle`)이 192장 중 **30번째·66번째**에 선다. (§4 회부 ②)

### 캐시 헤더 — **매 진입마다 전부 다시 받는다**

`server/central.js` 의 정적 응답이 전부:

```
Cache-Control: no-cache, no-store, must-revalidate
Pragma: no-cache
Expires: 0
```

`Caddyfile` 은 순수 리버스 프록시다(central 블록의 `encode gzip` 뿐 — 캐시 지시어 0).
⇒ **두 번째 진입도 6.70 MB 를 다시 받는다.** 서버 무접촉 카드라 안 고쳤다 → §4 회부 ①.

## §0-ⓒ 지연 적재 자리 — 문법은 이미 있고, 폴백은 **실제로 그린다**

자리는 하나다. `drawCharSprite` 안:

```js
const img = charSheet(L + '_' + stt.clip);
if (!img) { window.__charDbg[opts.pid] = { on: false, why: 'sheet:' + L + '_' + stt.clip, … }; return false; }
```

`charSheet(key)` 는 **처음 물어보는 키면 그 자리에서 받기 시작**하고 null 을 돌린다 —
즉 지연 적재의 문법이 이미 제품에 있다(T137 "시트 안 떠 있으면 도형"). 새 상태를 안 만든다.

**화소 하나** — 폴백 구간(훅이 `on:false · why:sheet:body_idle` 인 바로 그 순간)에 화면을 떠서,
인물 칸이 **구멍인지 그림인지** 셌다. 문턱은 지어내지 않고 **같은 프레임 같은 높이 풀밭의 최소 밝기**
(L=77.1)에서 뽑았다:

| | 폴백 구간(도형) | 시트 도착 뒤 |
|---|---|---|
| 인물 칸에서 풀밭보다 어두운 화소 | **449** | 430 |
| 두 컷이 다른 화소 | **3000** | |

⇒ 폴백은 구멍이 아니다. **도형이 사람 자리를 채우고 있고**, 시트가 오면 화소로 보이게 바뀐다.
(T13 이 전 시트 선적재의 근거로 적었던 두 가지 — "도형으로 튄다" · "진단 훅이 낡는다" — 는
지금 둘 다 답이 있다: 앞은 T137 규약이고, 뒤는 위 실패 갈래가 `why` 를 **그 자리에서** 갱신한다.)

## §2 판정 — **안 늘렸다. 표만 내고 코드 0.**

카드 ③: *"늘렸다면 지연 적재 · 안 늘렸으면 표만 내고 코드 0."*

**진입에 시트 몫은 0 이다.** 구조적으로 그렇다: 시트 청구는 **입장(서버 권위 위치) 뒤** 첫 캐릭터
그림에서 시작한다(로컬 2.6s → 4.4s). 144 → 192 로 늘린 뒤에도 서버 권위 위치는 2814 → 2585 ms,
첫 그림은 4643 → 4414 ms 로 **안 늘었다**(줄어든 것은 잡음이다).

시트 구간 자체도 안 갈렸다: 로컬 스프라이트 전환 +2.5%(7181 → 7362 · 3회 낱값이 겹친다),
3G 시트 구간 −2%(101.1 → 99.0 s · 산포가 겹친다).

⇒ **진입 +0%(산포 안).** 지연 적재는 **넣지 않았다.**

**다만 PM 이 괄호에 적은 기전과는 다르다.** 카드는 "캐시·병렬로 이미 가려지면"이라 적었는데,
**캐시는 안 가린다** — 서버가 모든 정적에 `no-store` 를 붙여 매 진입마다 전부 다시 받는다(§0-ⓐ).
가리는 것은 **요청당 왕복**이다: 3G 100 초 중 바이트가 설명하는 건 25~34 초뿐이고, 나머지는
144 든 192 든 똑같이 무는 값이라 24% 바이트 차가 산포에 묻힌다. 결론은 같고 이유가 다르다.

## §3 하네스 — `e2e-charsprite` ⑧절 (제품 훅 0 · 통과 96 / 실패 0)

지연 적재를 안 넣었으므로 제품에 `__sheetsReady` 를 심지 않았다. 하네스가
**네트워크와 이미 있는 `__charDbg`** 만 읽어 셋을 못 박는다. 대조군: 이 절 없이 **90/0**, 넣고 **96/0**.

| 못 박은 것 | 이 판의 수 |
|---|---|
| **ⓐ 선적재 = 메타가 아는 시트 전부** ⚠지연 적재 카드는 이 줄을 뒤집어라 | 메타 192장 · 청구 192장 · 빠진 0 |
| **ⓑ1 첫 그림은 도형** (훅이 그 자리에서 이유를 적는다) | `why=sheet:body_idle` |
| **ⓑ2 폴백이 실제로 그린다** (풀밭 최소 밝기보다 어두운 화소) | 도형 339px |
| ⓑ3 시트 구간에도 인물이 있다 | 461px |
| **ⓑ4 전환이 화소로 보인다** | 7810px |
| **ⓒ 시트 오기 전에도 상태기는 한 상태** | `[idle]` |

진입 표(같은 판): 페이지 시계 도형 3622 → 스프라이트 4451 ms · 하네스 시계 버튼 411 · 전 시트 4650 ms ·
`body_idle` 3646 · `clothes_hemp_idle` 3656 ms.
접점: `char_meta.json` · `charMeta()` · `charSheet()` · `Image` · `fetch` · `drawCharSprite` · `__charDbg`.

**★계측기가 제품을 느리게 만든 자리 — 두 번 물렸다.** 남겨 둔다.

1. **바깥에서 150ms 마다 `page.evaluate`** 로 상태를 봤다. 이 하네스엔 클라 셋이 두 코어를 나눠 쓰고
   있어서 **그 폴링이 페이지 주 스레드를 잡아먹었다**: 시트 192장이 3초(깨끗한 판) 대신 **93초**에
   들어왔고 전환은 아예 안 떴다. 훅은 `on:false · why:sheet:body_idle` 에 멈춰 있었고, 나는 그걸
   한동안 **제품 결함**으로 읽었다(같은 URL 을 새 `Image` 로 받아 보면 즉시 뜬다 — 제품은 멀쩡했다).
   ⇒ **감시자를 페이지 안에 한 번 심고**(`setInterval` 100ms) 결과만 한 번 꺼낸다. evaluate 왕복 둘.
2. `page.screenshot` 은 "waiting for fonts to load..." 로 **30초 타임아웃**이 났다(정적이 `no-store`
   라 폰트도 매번 다시 받는다). ⇒ **캔버스에서 직접 오린다** — 인물 자리는 정본 `__w2s` 에서 받는다.

**그리고 절의 자리도 실측이 정했다.** 뒤(A·B 가 십 분 굴러간 뒤)에 두면 위 ① 이 나고,
앞으로 옮기면 셋째 클라가 ⑤(두 클라 짝)를 흔들어 "남이 걸으면 walk" 한 줄이 빨개졌다.
⇒ **다 끝내고 A·B 를 닫은 뒤 맨 끝에서 혼자 들어간다** — 사람이 처음 들어오는 순간이 그 조건이다.

## §4 회부

1. **`no-store`** — 서버가 모든 정적에 붙인다. 두 번째 진입도 26.87 MB 를 통째로 다시 받는다.
   시트만 6.70 MB. 서버 무접촉 카드라 안 건드렸다. (`server/central.js` ~1290)
2. **순서** — 첫 프레임이 쓰는 `body_idle`·`clothes_hemp_idle` 이 대기줄 30·66번째다.
   3G 에서 **80 초 동안 도형**으로 서 있다. ⚠**시트 수와 무관하다** — 144장에서도 86.7 초다.
   고치는 값은 크고(80 s → 몇 초) 비용은 한 줄인데, 이 카드의 판정 조건("늘렸다면")에 안 걸려
   손대지 않았다. **PM 판정 몫.**
3. **webp** — 무손실 재인코딩으로 6.70 → 2.81 MB(−58.1%). 산 타일은 이미 webp 다. 자산 무변 규칙.
4. **'기타 자산' 13.09 MB(48.7%)** — 첫 화면 26.87 MB 의 절반이 캐릭터도 산도 아니다. 이 카드 밖.
5. **디코드 상한 244 MB** — 지금은 브라우저가 가려 주지만(실측 차 0), 층·클립이 더 늘면
   가려 주는 쪽이 먼저 무너진다. 옛 키 정리(카드 ④)가 여기에 직접 닿는다.
6. 옛 손 포즈 키(`swing`·`aim`·`idle`) 정리 — 재민 켜기 판정 뒤 · PM. MakeHuman · T116 · 16방향 · 이송 실체.
