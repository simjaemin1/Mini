## §0 실측 — 문서의 전제가 맞았는가

문서 §0-ⓐ 가 예고한 결함 넷을 전수로 다시 쟀다. **셋은 맞았고, 하나는 문서보다 나빴고,
둘은 문서가 과잉이었다.**

### ⓐ `kind`·`guildTribeId` 가 DB 에 없다 — **맞다**

스키마는 `(id, owner_id, owner_name, x, y, w, h, created_at)` 여덟 열뿐이고
`insertClaim` 도 그 일곱만 쓴다. 부팅 로드부(`zone.js` `db.getClaims()` 순회)는 `kind` 를 **아예 안 채운다**.
⇒ **재시작하면 사람 클레임의 종류가 전부 `undefined`.** 파생 셋도 전부 확인:

| 파생 | 확인 |
|---|---|
| `countMyClaims` 의 `else p++` | ○ 하네스 ①-b 가 **고장의 모양**을 재현한다(셋이 전부 개인 슬롯 3) |
| `findGuildClaimContaining` 이 늘 `null` | ○ `c.kind !== 'guild'` 컷 |
| `listRespawnOptions` 가 자기 사유지를 못 찾음 | ○ — **그런데 이유가 하나 더 있었다(아래 ⓑ)** |

★NPC 마을 길드 영토는 이 결함을 안 맞는 것도 확인했다 —
`spawnGuildClaimsForVillage` 가 부팅마다 **메모리에 다시 만들고 DB 에는 아예 안 넣는다**.
**사람 것만 잃는다**는 문서의 진단 그대로다.

### ⓑ ★문서보다 나빴다 — 부활 지점은 **처음부터** 안 잡혔다

```js
for (const c of claims.values()) {
  if (c.ownerId !== p.playerId) continue;     // ← 클레임에 `ownerId` 라는 필드가 없다
```
사유지는 주인을 **`ownerPid`** 로만 적는다(`tryClaim` · 부팅 로드 · `countMyClaims` · `tryUnclaim` ·
`_furnaceClaimOf` 가 전부 그렇다). `undefined !== '<id>'` 는 언제나 참이므로 이 절은 **늘 `continue`** 였다.
⇒ **개인·임시 사유지는 재시작과 무관하게 한 번도 부활 지점이 된 적이 없다.**
문서 §0-ⓐ-1-ⓒ 는 "재시작 뒤엔"이라고 적었는데, 실측은 "처음부터"였다.
T8 이 본 "막다른 골목"의 크기가 그만큼 더 컸다는 뜻이다.

### ⓒ 인접 규칙 없음 · 포기 연결성 검사 없음 — **맞다**
`tryClaim` 은 겹침만 보고, `tryUnclaim` 은 주인 확인 뒤 바로 지운다.

### ⓓ `_claimFootprint` 의 `anyPersonal` · `_furnaceCanUse` — **맞다(그대로 재사용)**
시설 권한 술어는 `_furnaceCanUse` **하나**이고 호출부가 6곳이다. 승계는 주인 필드만 바꾸면 된다.

### ⓔ ★문서가 과잉이었다 — central 새 엔드포인트가 **필요 없다**

문서는 *"`last_seen` 조회 — 새 엔드포인트 1개 또는 기존 `/players` 확장"* 이라고 적었다.
실측: `GET /player/:id` 가 **`SELECT * FROM players`** 라 `last_seen` · `tribe_id` · `tools_json` 이
이미 다 온다. 존 쪽 클라이언트 `central.getPlayer()` 도 이미 있다.
⇒ **central.js 무접촉**(diff 0줄).

### ⓕ ★문서가 낡았다 — 클레임 렌더 자리가 바뀌었다

문서의 접촉 파일 표는 `public/client/32-m-render.js` 를 가리키는데,
T51(`79a5f033`)이 그 파일을 다섯으로 가르면서 클레임 그리기는 **`34-m-renderloop.js`** 로 갔다.

### ⓖ ★범위 밖이지만 여기 적어 둔다 — **판정은 bbox, 렌더는 셀**

`_furnaceClaimOf` · `findGuildClaimContaining` · 침입·분해 검사가 전부
`x >= c.x && x < c.x + c.w`(사각)로 판정하는데, **NPC 마을 길드 영토는 `cells`(유기적 폴리곤)를 갖고
화면은 그 셀만 칠한다.** ⇒ **화면에 안 칠해진 41×41 bbox 안쪽이 서버에겐 길드 영토다.**
T45 는 사람 클레임(1셀 = bbox = 셀)만 다뤄 이 갈림을 안 건드렸다 — 회부에 한 줄.

## §1 만든 것

### `server/claims.js` (신규 · 유일한 규칙 정본)

* **`cellsOf`** — 셀 집합이 정본, 사각은 파생. 길드 영토의 `cells` 와 사람 클레임의 1셀을 같은 문으로 읽는다.
* **`adjacencyOf`** — 4방 인접. **대각은 거절**(모서리로만 닿은 땅은 걸어서 안 이어진다).
* **`unclaimSplits`** — 포기하면 **더 갈라지는가**. `components(after) > components(before)` 면 거절.
* **`stageFor` / `heldByOf` / `setState` / `scanAbsence` / `restoreOne` / `onPlayerActive`** — 부재 상태기.
* **`takeableBy` / `transfer` / `succeedFacilities`** — 우선권과 승계.
* **`chestLocked`** — 보관 중 무주 사유지의 상자만 잠근다.

### `server/zone-local-db.js` (다섯 열 + 이행 + 접근자 셋)

`kind` · `guild_tribe_id` · `state` · `held_by` · `state_at`. 옛 행은 **`'personal'` 로 이행**한다 —
값을 지어내는 게 아니라 **현행 부팅이 이미 하던 해석**(`countMyClaims` 의 `else p++`)을 적어 두는 것이다.
`updateClaimState` · `updateClaimOwner` · `deleteClaim` 을 열어 zone.js 의 raw SQL 을 걷어냈다.

### `server/zone.js` (접점 — 판정 0줄)

require · `Claims.init`/`start` · **부팅 로드부에서 다섯 필드 복구** · `insertClaim` 에 종류를 실제로 넘김 ·
`tryClaim` 에 승계·인접 두 절 · `tryUnclaim` 에 연결성 한 줄 · `listRespawnOptions` 의 `ownerId` 결함 수리 ·
접속 시 `onPlayerActive` · `tryChestTake` 에 잠금 한 줄 · `GET /claimdbg` · `__testBind` 확장.

### 클라 (색 몇 줄 · 새 패널 0)

`34-m-renderloop.js` 에 상태별 색 세 줄(💤 보관 · 🕯️ 우선권 · 🕳️ 개방) ·
`30-n-net.js` 에 `claim_state` 한 절(**한 칸만 갈아 끼운다** — 레코드를 다시 안 보낸다).
**판정을 클라가 다시 하지 않는다** — 서버가 준 `state` 그대로 색만 바꾼다.

## §3 하네스가 스스로 틀린 곳 (전부 남긴다)

1. **③④⑥이 통째로 빨갰다 — 규칙을 안 지킨 건 하네스였다.** 개인 사유지는 **내 길드 영토 안에만**
   선다(종전 규칙 · T45 가 안 바꿨다). 길드 땅 없이 `tryClaim` 을 불러 놓고 "인접이 안 돈다"를 본 것이다.
   ⇒ NPC 마을 영토와 **같은 모양**(메모리 전용 · `cells` 를 갖는 폴리곤)으로 랩 길드 땅을 깔고,
   *"검사 자리가 내 길드 영토 안이다"* 를 **상황 assert 로 먼저 못 박았다**.
2. **마이그레이션을 마이그레이션이 아닌 것으로 쟀다.** 이미 새 스키마를 연 프로세스에서 옛 일곱 열
   INSERT 를 흉내 냈더니 `kind = NULL` 이 나왔다 — 그건 **이행이 아니라 그냥 NULL 삽입**이다.
   ⇒ **옛 여덟 열 스키마 그대로의 DB 파일**을 만들고 자식 프로세스가 `zone-local-db` 로 열게 했다.
   그리고 *"옛 스키마에는 종류 열이 없다"* 를 먼저 assert 한다(그 DB 가 진짜 옛것인지부터).
4. **[T11 하네스] `e2e-membership ④-0` 이 알림 링의 끝 4줄만 봤다.** 러너 부하에서 그 한 줄이
   빨개졌다 — 하루가 0.6초인 검사 존에서는 브리핑·게시판 알림이 계속 밀려들어 **방금 받은 답이
   뒤에서 밀려난다.** T11 세션이 같은 하네스의 다른 절들은 "링 전체를 본다"로 고쳐 뒀는데
   **이 한 줄만 남아 있었다.** ⇒ 같은 규약으로 맞췄다(이 커밋에 포함).
3. ★★**통제 실험이 자명 통과였다.** ⑧-a 가 `Claims.mySet` 을 monkey-patch 했는데
   `adjacencyOf` 는 **모듈 안의 것**을 부르므로 아무 효과가 없었다 — 두 답이 같아서 걸렸기에 망정이지,
   반대로 짰으면 "통제 실험이 통과했다"고 **거짓 안심**을 만들었을 자리다.
   ⇒ 정본 함수를 갈아 끼우지 않고 **실제 클레임을 세운 뒤** 그 위에서 잰다.
   (족보 ㉒ "계측기도 사본 금지"의 사촌: **정본을 갈아 끼우는 통제 실험은 통제가 아니다.**)

## §6 판정거리 (각 하나씩만 추천)

* **a. `free` 까지 실시간 42일 = 게임 6.9년이다.**
  ⓐ 유지 — 계정 시계와 세계 시계는 다른 축이고, 짧게 하면 §6(숙제 금지)이 걸린다 ·
  ⓑ `CLAIM_FREE_DAYS` 를 줄여 회전을 빠르게.
  → **추천 ⓐ.** 이 축의 값은 **사람이 실제로 얼마나 오래 안 오는가**를 봐야 정해진다. 그 데이터가 아직 없다.
* **b. 무주(`held_by = null`) 땅은 창 동안 아무도 못 가져간다 — 그동안 세계가 잠긴다.**
  ⓐ 유지(무주는 `free` 를 기다린다) · ⓑ 무주는 `pref` 를 건너뛰고 바로 개방.
  → **추천 ⓐ.** ⓑ 는 "길드도 마을도 없는 사람"만 골라 벌하는 규칙이 된다. 무소속이 죄가 되면 안 된다.
* **c. 판정은 bbox, 렌더는 셀(§0-ⓖ).**
  ⓐ 회부만 · ⓑ `cellsOf` 를 네 판정 자리에 태워 지금 맞춘다.
  → **추천 ⓐ.** 그 넷은 채집·분해·노까지 물려 있어 T45 의 접촉면 밖이다. 정본은 이미 있으니 한 카드면 닫힌다.

## §8 실기 3줄

1. 사유지를 **한 칸 놓고 그 옆에** 놓는다 → 붙는다. **모서리에만** 놓으려 하면 촌장 말투로 거절당한다.
2. 세 칸을 일자로 놓고 **가운데**를 포기해 본다 → *"1덩이에서 2덩이로 갈라진다 — 끝에서부터 걷어라"*.
3. 서버를 껐다 켠다 → 사유지 종류가 그대로고, **죽으면 자기 사유지가 부활 지점 목록에 뜬다**(전엔 안 떴다).
