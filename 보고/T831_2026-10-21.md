## 2. ② 닫힐 때 저장 자리 경합 — 결함이다

### 2-1. 무엇이 어디로 가나(코드)

* 껍데기 소켓이 닫히면 `attachPlayerHandlers` 의 `close` 가 `savePlayer(player, { last_zone: ZONE_ID, last_x: player.x, last_y: player.y })` — **출발 존 · 껍데기 좌표**를 쓴다. 출발 존 스스로 닫는 때도 같다: ACK 가 3초 안에 안 오면 시한이 `p.ws.close()` 를 부른다(`fireHandoff`).
* central `POST /player/:id` 는 `data.last_zone ?? p.last_zone` — 칸마다 **늦게 닿은 쪽이 이긴다**(존 쓰기는 fire-and-forget · 순서 보장 0).
* 다시 접속: 로비는 등록 계정이면 `/auth` 의 `player.last_zone` 으로 자동 라우팅하고(`public/client/30-n-net.js:253`), 그 존은 `last_zone === ZONE_ID` 면 `last_x · last_y` 에 세운다(`zone.js` 접속 · 14.42-a). ⇒ 껍데기 저장이 도착 존 접속 저장(`last_zone: 도착 존`) 뒤에 닿으면 **다시 접속이 출발 존 · 껍데기 자리**다. 다른 사람이 "어디 있나"를 물어도(`_elsewhereLine`) 출발 존을 말한다.
* 같은 결함의 문이 셋 더(코드 읽기 — 이 카드가 같이 막았다 · §2-3):
  - **주기 저장**(`_periodicSave` · 30초 · `last_zone: 이 존`) — 껍데기를 안 거른다(T823 의 거른 걸음 목록에 없었다). 차례가 ACK 창(받는 존 응답 + 클라가 붙는 시간 · 실측 0.4~1.5초)에 떨어지면 쓴다.
  - **종료 flush**(`_shutdownFlush` — 배포 · SIGTERM) — `players` 전원을 `last_zone: 이 존` 으로.
  - **맨 저장**(`savePlayer(p)` — 자리 칸 없이 부르는 저장) — `last_zone` 은 안 건드려도 `last_x · last_y` 를 껍데기 좌표로 쓴다(행 = 도착 존 + 출발 존 좌표 섞임). 켬이면 껍데기 입력이 안 들어와 행동 저장은 0 이지만, 입력 밖에서 부르는 자리(소속 새로고침 · 다른 사람 행동이 남을 저장하는 자리)가 남는다.
* 승격 경로(관측 소켓 → 주 소켓 `promote_to_primary` — 클라가 이웃 존을 미리 보고 있을 때의 보통 경로)는 도착 존이 **접속 저장을 안 한다** — 행 자리는 넘기기 전 저장(T47 · `last_zone: 도착 존` · 입구)이 쥐고 있다가 껍데기의 쓰기가 오면 순서와 무관하게 출발 존으로 넘어간다(도착 존 첫 주기 저장 0~30초까지).

### 2-3. 고침 — `savePlayer` 한 자리(켬 갈래)

```js
function savePlayer(player, extra = {}) {
  if (!canPersist(player)) return;
  const pt = _savePatch(player, extra);
  if (T823_FREEZE_SHELL && player.handingOff && (pt.last_zone == null || pt.last_zone === ZONE_ID)) { delete pt.last_zone; delete pt.last_x; delete pt.last_y; }
  return _saveSend(player.playerId, pt);
}
```

* 껍데기(`handingOff`)의 저장이 **이 존**을 가리키거나(닫힐 때 · 주기 · 종료 flush) 자리를 말하지 않으면(맨 저장) 자리 칸 셋을 뺀다 — central 은 빠진 칸을 그대로 둔다(`??`). 행 자리는 넘기기 전 저장(도착 존 입구) 또는 도착 존 접속 · 주기 저장의 것이다.
* 지나가는 것: 넘기기 전 저장(`fireHandoff` — `last_zone: 도착 존` · 입구 좌표 · `handingOff` 를 세운 뒤에 부른다 — 다른 존을 가리켜 그대로) · T498 쥔 행(`_savePatch` 를 직접 — `savePlayer` 밖) · 실패 뒤(`_t564HandoffFail` — `handingOff = false` → 종전대로 이 존 자리).
* 닫힐 때 저장 한 자리만 막지 않은 까닭: 같은 창의 주기 저장이 같은 출발 존 자리를 쓴다(H 판 6/10) — 한 문만 닫으면 열 판 중 여섯이 같은 결함으로 남는다. 종료 flush · 맨 저장도 같은 칸을 같은 껍데기로 쓴다. 넷이 모두 `savePlayer` 를 지나므로 그 한 자리가 문 넷을 같이 닫는다(새 칸 0 — 카드의 "이미 있는 `handingOff` 칸").
* **몸 칸은 그대로**(카드 = 자리 칸) — 언 몸 = 페이로드 = 넘기기 전 저장의 몸. 껍데기의 늦은 저장이 몸 칸을 되돌리는 것은 §4 ① 회부.
* 끔(`=0`) = 이 줄이 첫 비교에서 빠진다 — 행 바이트 종전 그대로(서버 기준선 `=0` 3/3).
* 닫힐 때 핸들러 · 손잡이 머리 주석에 한 줄씩(`savePlayer` 머리 주석을 가리킴).

1. **[재민 · 몸 칸 — 이 카드 밖]** 껍데기의 늦은 저장은 자리 칸만 빠지고 **몸 칸**(언 몸 = 넘긴 순간)은 그대로 쓴다. 도착 존이 그 사이 행동 저장을 했으면 행의 몸이 넘긴 순간으로 되돌아간다 — F · G 판 스무 번 모두 둘째 읽음의 행 생선 3(껍데기 몸) · 도착 존 산 몸 2(도착 존 내려놓기의 행동 저장이 되돌아갔다 · F 넷은 첫 읽음에서 이미 3 — 껍데기 주기 저장이 먼저 되돌렸다). 도착 존의 다음 저장(행동 · 주기 30초 · 닫힐 때)이 바로잡지만 그 사이 도착 존이 죽으면 행에서 다시 읽은 몸은 생선 3 + 땅의 1(복제). 막는 자리는 같은 한 줄(켬 갈래 껍데기 저장을 통째로 안 보냄)이지만, T498 켬 판에서 넘기기 준비 중 소켓이 닫히고 그 준비가 실패하면 닫힐 때 저장이 언 몸의 유일한 저장이다(T498 끔 기본은 넘기기 전 저장이 같은 몸을 이미 썼다) — 판정이 걸려 회부.
2. **[정보 · 넘기기 준비 중 닫힘 + 준비 실패]** 받는 존 응답을 기다리는 동안(최대 5초) 소켓이 닫히고 그 준비가 실패하면, 켬이면 행 자리는 넘기기 전 저장(T47 · 도착 존 입구)이다 — 종전은 출발 존 · 껍데기 자리였다. 사람은 도착 존에 못 들어갔고 다시 접속은 도착 존 입구로 간다. 준비가 실패해도 소켓이 살아 있으면 T47 판이 이미 같은 뜻으로 행을 쓰고(다음 출발 존 주기 저장까지) 있던 창이다 — 닫힘이 겹치면 그 창이 다음 접속까지 간다.
3. **[정보 · 승격 경로]** 도착 존의 승격 경로(`promote_to_primary`)는 접속 저장을 안 한다 — 행 자리는 넘기기 전 저장(도착 존 입구)이 쥐고 도착 존 첫 주기 저장(0~30초 · 움직였거나 몸이 변했을 때)까지 간다. T498 켬(끔 기본)이면 넘기기 전 저장도 없어 그동안 행은 출발 존 그대로다(이 카드 밖).
4. **[정보 · ACK 잃음은 실제 창]** 호스트가 갈렸는데 안 문 비밀이 한쪽에만(T245 회부) · 존 사이 끊김 — 종전엔 그때 도착 존에 들어간 사람의 행이 3초 뒤 출발 존으로 돌아갔다(G 판 그대로). 켬이면 도착 존 그대로(F 판). 출발 존 로그에는 `ACK timeout` 이 남는다.
