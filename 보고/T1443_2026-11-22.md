## 회부

1. **스왑 0**(재민 손): 만들기 `sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile && echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab` · 되돌리기 `sudo swapoff /swapfile && sudo sed -i '\#^/swapfile #d' /etc/fstab && sudo rm /swapfile`. 달라지는 것: 배포 꼭대기에 1 GB 남짓 남는 상자가 넘쳐도 OOM 대신 느려진다. 이번 사고는 메모리 모자람이 아니라 막지는 못했다.
2. **커널이 죽으면 저절로 다시 켜기**(재민 손): `sudo sysctl -w kernel.panic_on_oops=1 kernel.panic=10 && printf 'kernel.panic_on_oops=1\nkernel.panic=10\n' | sudo tee /etc/sysctl.d/99-panic.conf` · 되돌리기 `sudo sysctl -w kernel.panic_on_oops=0 kernel.panic=0 && sudo rm /etc/sysctl.d/99-panic.conf`. 이번 사고였다면: 11:22:18 oops → 10초 뒤 재부팅 → **34시간이 약 2 ~ 3분**(부팅)이 된다. 다만 존은 ③ 꼴이라 그대로 안 뜬다(회부 3 과 같이 가야 한다) · 잃는 것은 지금과 같다(마지막 저장 뒤).
3. **재부팅에 존이 다시 뜨게**(재민 · PM): §3 후보 표(`--restart always` · 이름 바꿔 두기 · env 파일) + `docker run --stop-timeout 60`(Docker 가 내릴 때도 60초 — `test-redeploy-light` 의 run 인자 바이트 문 때문에 이 카드에선 안 넣음).
4. **rm 뒤 run 앞 끊김 = env 잃음**(PM): 배포 줄이 못 되살린다 — 3 의 후보 중 하나가 필요하다. 그때 재민이 쓸 줄은 PM 이 준다(재부팅 절차 "존 컨테이너가 없을 때").
5. **가설 가름**(재민 → PM): 사고 기록 §3 의 읽기 전용 줄 결과를 붙여 주면 ⓐ / ⓑ 를 가른다 · iwinv 에 11-21 11:22 기계 기록 문의 · iwinv "Resource 모니터링" 켜기.
6. **ssh 곁눈**(재민 · 읽기만): `sudo sshd -T | grep -iE '^(passwordauthentication|permitrootlogin)'` — 그 1분에 `Failed password for root` 가 있었다. `yes` 면 끄는 것은 재민 판단(바꾸는 줄은 이 카드 밖).
7. **존 내리기 -t 60 의 값**(PM): 잰 판은 끔 세계 · 하루 20초 — 라이브(밭 켬 · 작물 · 긴 하루)에서 한 번 재면 값이 바뀔 수 있다(`docker stop` 앞뒤 시각 · 존 로그 `[T728] 종료 저장` 줄).
8. **사유지 저장 길**(PM): 강제 종료가 사유지에서 무엇을 잃는지 이 카드에서 못 찾았다.
9. **실패 메일 받는 사람**(재민): 문서 둘이 다르다(§2) — 착지 뒤 재민 GitHub 알림 설정에서 Actions 실패 메일이 켜져 있는지 · 첫 실패(손으로 `workflow_dispatch` + 틀린 `LIVE_URL` 은 못 함 — 워크플로가 env 를 안 받는다)로 한 번 확인.
10. **일정의 실제 늦음 · 배포 중 헛 알림**(PM): main 에 들어간 뒤 첫 하루의 판 시각으로 늦음을 잰다. 배포 중 존 부팅(로컬 42 ~ 51초 · 첫 시딩이면 길다)이 세 번(2분)보다 길면 실패 메일이 한 번 갈 수 있다 — 잦으면 "배포 중" 표지를 보는 길이 후보.
