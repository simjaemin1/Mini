## 2-바닥. ★★2026-09-07 [T146 2판] — **사냥터가 없는 마을은 없다**

> 전문 `보고/T146_2026-09-06.md` §2판. 정본 `server/villages.js` · 하네스 `scripts/test-hunt-port.js`.

**한 줄** — `livelihood.js:27` 이 `FLOOR.game = 0.45` 를 두고 그 이유를 적어 뒀다:
*"초지 사냥(사슴·멧돼지) — 숲이 없어도 짐승은 산다"*. 그런데 밴드는 **숲만** 셌다.
그래서 51곳 중 **19곳**은 econ 이 "짐승이 있다"고 말하는데 실체가 0 이었다 —
사냥꾼은 서는데 깎을 데가 없고 `land.game` 은 **영원히 안 내려간다**(남획이 불가능한 마을).

```
정본 — server/villages.js
  _bandMinCells(vil, candN)   최소 셀 수 = candN × land.game / livelihood.GAIN.game  (역함수 · 새 수 0)
  _bandFloorFill(vil, st)     모자란 만큼을 **반경 안 풀밭 셀**에서 자리 해시로 채운다(Crops.h32 · 주사위 0)
  _cellOfPx(px)               px → 셀 **정본 하나** — 셀 중앙 c*SZ+SZ/2 를 되읽으면 그 셀이 나온다
```

**★실측 — 19곳은 전부 `land.game` 이 바닥에 정확히 앉아 있다**

| | |
|---|---|
| 밴드 0 인 마을 | **19 / 51** · 전부 `land.game` = **0.45 = `FLOOR.game`** (추출 `huntShare` 도 0%) |
| 그 마을들의 풀밭 셀 | 7,179 ~ 11,809 (중앙 11,116) — **채울 땅은 넘친다** |
| 역함수가 요구하는 셀 | 2,155 ~ 3,007 (`candN × 0.45/1.8`) — 풀밭이 모자란 마을 **0곳** |

**★★함정 — 이 절을 고칠 사람이 먼저 알아야 할 것**

1. ★★**문자 그대로의 `huntShare` 역함수는 0 을 준다.** `share = (game − FLOOR)/GAIN` 이고
   19곳은 `game == FLOOR` 다 ⇒ 0. **바닥은 셀의 함수가 아니기 때문**이다. 그래서 역함수는
   **바닥까지 포함해** `share = game / GAIN` 으로 되돌린다(같은 환율). 그 결과가 위 표의 3,007 이다.
2. ★★**그 수는 크다.** 3,007 셀은 지금 밴드 있는 32곳 중 **21곳보다 넓다**. 즉 `FLOOR.game = 0.45` 는
   이미 "숲 25% 짜리 밴드"를 약속하고 있었다는 뜻이다 — **`FLOOR.game` 자체가 값 판정거리**(재민).
3. ★★**그래서 기본은 밴드가 0 인 마을에만 채운다**(카드 §1 "32곳 비트 동일"). 카드 ① 문자 그대로인
   `max(밴드, 최소)` 꼴은 `T146_BAND_ALL=1` 로 켠다 — 켜면 32곳 중 21곳이 움직인다.
4. ★**풀밭 셀의 K 도 숲과 같은 `L_GAMEMAX`** 다(새 수 0). 초지 K 를 따로 두는 건 회부.
5. ★**왕복 정본은 `_cellOfPx` 하나**다. `Math.round(px/SZ)` 로 되읽으면 셀 중앙이 `c+1` 로 나온다
   (1판 회부 6 이 그 자리였다). 되읽는 자리는 전부 이 문을 쓴다.

**손잡이** — `T146_BAND=0`(최소 보장 끈다 = 종전 비트 · 19곳 밴드 0) · `T146_BAND_ALL=1`(카드 ① 문자 그대로).
둘 다 **부를 때** 읽는다.

## 1-사냥. ★★2026-09-06 [T146 사냥 이식] — **마을이 짐승 장부를 갖는다**

> 전문 `보고/T146_2026-09-06.md`. 정본 `server/villages.js`(생활층 하루 틱) · 하네스 `scripts/test-hunt-port.js`.
> V-마을배치.md 3-사 에서 **옮겨 왔다**(2026-09-07 · 이 파일이 주 영역이다).

**한 줄** — 랩의 사냥 생활층을 서버 마을 생활층에 올렸다. **`vil._gameRich`** 가 그 장부다
(사냥터 밴드 셀 → 0..K). 하루 틱이 회복·차감·부존 갱신을 하고, `land.game` 이 **14일마다** 따라 움직인다.

```
정본 함수 — 전부 villages.js. 사본을 만들지 마라, 이 문으로 들어와라.
  _huntBandBuild(vil)          사냥터 밴드 구축(며칠에 걸쳐 · 커서 vil._gameScan)
  _gameKey(vil, cx, cy)        위치 → 표본 셀(밴드는 2칸 간격 샘플이다)
  huntTake(G)                  포화 수확(Holling II · T144)
  huntTakeAt(vil,cx,cy,people) 그 셀에서 뺀다 — 사냥꾼·플레이어 둘 다 이 문
  huntHunters(vil,players,day) 사냥꾼 하루치(차감 · 이동 문턱 0.12K · 분산 ±5)
  huntKillAt(px, py)           플레이어 kill 한 마리
  huntDeforest(vil, cx, cy)    벌채 = 서식지 파괴 = K 영구 감소
  _lifeGameDay(vil, day)       하루 틱(_lifeDaily 안 · 회복 7일 배치 · 갱신 14일)
  gameRichAt / gameRichSize    wildlife.js 가 몹 마릿수를 정할 때 읽는 창구
```

**★함정 넷 — 여기서 세 번 틀렸다.**

1. ★★**밴드는 2칸 간격 표본이다.** 랩은 사냥꾼 작업 셀을 `huntCells` 에서 골라 줘서 늘 격자 위에
   있지만, **서버는 몹 실좌표에서 얻는다** — 격자에서 벗어난다. 그대로 조회하면 **넷 중 셋이
   헛손질**이고 코드는 돌아가는데 세계는 안 변한다. 새 조회는 반드시 `_gameKey` 를 지나라.
2. ★★**이동 문턱은 "비었을 때"가 아니라 `G < 0.12K`** 다(랩 10823). `huntTake(g) < g` 라 셀은
   **영원히 안 빈다** — "비면 옮긴다"로 적으면 사냥꾼이 한 셀에 박제된다.
3. ★**분산 사냥**(랩 10824~10830) — 남이 쥔 자리 **±5 회피**, 다 차 있으면 argmax 공유. 빼먹으면
   전원이 한 칸에 몰린다.
4. ★**밴드 구축은 하루에 못 짓는다** — 전수 스캔이 마을 하나에 **최대 2.7초**(51곳 합 12.9초).
   `T146_BUILD_MS`(기본 20ms) 예산으로 끊고 커서를 남긴다. **다 지어질 때까지 그 마을엔 사냥이 없다**
   (중앙 2일 · 최장 임업2 135일).

**실측 — 이 영역이 알아야 할 수**

| | |
|---|---|
| 사냥터 밴드 | 마을 밖 **40~130셀** · 숲(`forestMult>1.2`) · 바위·물 제외 · 2칸 샘플 |
| 51마을 합 | **101,158 셀**(Map 항목 ≈6MB) · 중앙 453 · 최대 11,739(임업3) |
| ★**밴드가 0 인 마을** | **19 / 51** — 이 마을엔 사냥이라는 것이 **없다**(`land.game` 정적) |
| 800일 궤적 | 중앙 마을 개체 **93%**(거의 안 준다) · 가장 좁은 광산2(41셀) **2%**(무너진다) |
| 회복 속도 | 0.3K → 0.95K 에 **1,897일 ≈ 5.2게임년**(r=0.002 · 주 단위 배치) |

**손잡이** — `T146_GAME=0`(종전 비트) · `T146_BUILD_MS`(기본 20). 둘 다 **부를 때** 읽는다.

**무접촉** — econ 사냥 소득 식(`land.game × 0.7`)은 **한 글자도 안 건드렸다**. 이 카드는 **부존만
갱신**한다(대체가 아니다). kill → 곳간 실물 회계(meat)는 **다음 판**(랩이 먼저).

**주입구** — `__labProbe._huntProbe.setTa(ta)` 하나(`_distProbe`·`_memberProbe` 와 같은 규약).
하네스가 밴드 규칙을 다시 적지 않고 지형만 쥐게 한다.
