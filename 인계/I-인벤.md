## 3-바닥. ★★2026-09-05 T102 — **바닥템이 장비 개체를 그대로 싣는다**

> 전문 `보고/T102_2026-09-05.md`. 하네스 `scripts/test-inv-ground.js`(신설 · 28/0).

### 무엇이 틀려 있었나

바닥템이 실을 수 있는 건 `{item, n, kg, led, lots, tool{type,d,max}}` 뿐이었다.
그래서 **장비 개체는 떨어뜨리면 다른 물건이 됐다** — `gi.tool` 이 세 필드만 베끼므로:

| 개체가 가진 것 | 옛 `gi.tool` 이 실은 것 |
|---|---|
| `type` · `q`(품질) · `craftedSkill`(제작 숙련) · `attrs{…}`(속성표) · `mat`(재료) · `dura` · `durMax` | `type` · `d` · `max` |

⇒ **잃던 것: `q` · `craftedSkill` · `attrs` · `mat`.** 좋은 도끼를 버렸다 주우면 평범한 도끼였다.
T83 §5 가 "지게가 첫 낙하"를 못 지킨 것도, 죽음 낙하 후보에서 장비가 통째로 빠져 있던 것도 이 자리다.

### 고친 방법 — 필드를 더 베끼는 게 아니라 **베끼기를 그만둔다**

```
  gi.inst = inst        ← 정본 객체 **참조 그대로**(필드 이름을 한 개도 안 적는다)
  gi.instKind           ← 어느 서랍에서 왔나(`tool` = toolItems · `equip` = equipment). 주소지 필드가 아니다.
  gi.tool               ← 옛 읽기 호환. **저장하지 않고 `_giTool` 이 개체에서 유도**한다(두 벌이면 사본).
```
* **새 직렬화가 0이다** — `serializeBody` 가 `equipment` 를 있는 그대로 싣고(JSON 왕복 무손실),
  바닥템은 **DB 영속이 아예 없다**(메모리 Map). 실을 형식을 새로 정할 일이 없었다.
* **문이 하나다** — `_instParcel`(싣기) · `_instTake`(꺼내기). `tryDropItem`(도구·장비) ·
  `tryPickupItem` · `_deathDrop` **셋이 같은 문**을 쓴다.
* 꺼낼 때 `id` 만 새로 매긴다(남의 주소를 물려받지 않는다 — 개체 원장과 같은 규약).
  얕은 복사는 **id 를 붙이기 위한 것**이고 필드를 골라 베끼지 않는다.
* 클라 **0줄**: `gi.tool` 을 읽는 자리는 하네스 훅(`99-main.js` `window.__ground`) 하나뿐이고,
  렌더는 `gi.item` 으로 그린다.

### 낙하 자리 — 주사위를 뺐다

`_spawnGroundItems` 의 `Math.random()` 둘이 캐논("낙하물 스캐터 금지 · 주사위 금지")을 어기고 있었다.
**흩뿌림 폭과 개수는 그대로** 두고 자리만 `gid` 해시(FNV-1a)로 정한다 — 같은 입력이면 같은 자리다.

### 다음 사람에게

* 개체에 필드가 늘어도 **이 문은 안 고쳐도 된다**(이름을 안 적으므로). 하네스 ⓒ 가 그걸 지킨다 —
  개체의 필드를 **하나씩 전수로** 빼 보고 전부 빨간지 본다(손으로 하나 고르지 않는다).
* 장비 버리기 서버 문(`tryDropItem` `opts.equipId`)은 열어 뒀지만 **클라 동사는 안 만들었다**.
  인벤에서 장비를 버리는 UI 를 붙일 때 그 문을 쓰면 된다.

### ③ 인벤 3층

* **개체** — `p.kgLedger[item] = [kg, …]`(FIFO). `oreLedger` 와 같은 문법이다. 낚시가 첫 소비자다.
* **로트** — `p.lots[item] = [{d: 취득일, n: 수량}]`. 같은 날은 합치고 **다른 날은 안 섞는다**.
  신선도는 **조회 시 (오늘−취득일)** 로 유도한다(타이머 없음 · 틱 비용 0).
  ★불변식 **`inventory[item] === floor(Σ로트)`** — 수량 정본은 여전히 인벤이고 로트는 **나이 분포**를 적는다.
  로트를 안 거친 취득 경로가 있어도 `reconcile` 이 차이를 메워(오늘 것으로) **수량이 틀리는 일이 구조적으로 없다**.
  초당 1회 쓸개가 돌아 그 근사를 사실로 만든다.
* **무기한 벌크** — 그대로. 돌·장작엔 나이가 뜻이 없다.
* **부분 소비** — `doEat(p, item, 0.25)`. 회복량·무게가 **정확히 비례**한다. 소수 몫은 인벤 정수에 안 올라간다
  (`oreCarry` 규약 — "0.75 남은 곡식은 아직 못 판다").

### ★결함 ① 인벤·바닥 목록 비대칭 — 자료구조가 UI 로 새어 나온 것

재민 원문: *"바닥에 떨어진 아이템 목록과 인벤토리 안의 아이템 목록이 같은 종류의 인스턴스가 아닌가봐?"*
맞았다. 실체는 UI 취향이 아니라 **두 벌로 짜인 코드**였다:

```
           바닥                              인벤
  원본   드롭 인스턴스 배열                  품목→개수 **스칼라 맵**
         {id, item, count, kg}               {fish: 12}
  렌더   인스턴스 1개 = 1줄                  품목 1종 = 1줄
  개별kg 인스턴스마다 있음                   없음(kgLedger 가 **수의 배열**이라 FIFO 만)
```

재민 판정(ⓑ · 좀보이드 문법): *"기본적으로 한 줄로 나오되, 펼칠 수 있게. 펼칠 수 있어지면
각 줄을 따로 드롭도 가능하고, 원래 한 줄을 드래그하면 모든 아이템이 드롭되고."*

**A. 서버 — `kgLedger` 를 주소 가능한 개체 목록으로 (`server/carry.js`)**

```js
  p.kgLedger[item] = [{ id, kg, d? }, …]     // 옛 형태: [kg, kg, …] (수의 배열)
```
· `id` 는 **그 플레이어의 원장 안에서만** 유일하다(저장 blob 이 플레이어별이라 전역 유일 불필요).
  `_nextId` 는 복원 때 **최대값+1** 로 되짚는다 — 재접속 뒤 새 개체가 옛 id 와 안 겹친다.
· `takeByIds(p, item, ids)` — **FIFO 강제 해제**. 한가운데 0.4kg 물고기만 골라 뺀다.
· `_norm` 이 읽는 모든 길목에서 **옛 저장(수의 배열)을 항목 모양으로 승격**한다(호환 자동).
· `toSave` 도 항목 모양으로만 내보낸다 — 저장 전후 구조가 갈리면 "재접속을 넘어 그대로인가"
  판정이 **자기 직렬화 때문에** 실패한다(로트가 이미 겪은 함정이다).

**★불변식**: 원장이 있으면 `L[item].length === inventory[item]`.
· `reconcile` 이 **짧으면 표준 kg 으로 채우고**(무게 중립 — `peekKg` 가 어차피 표준으로 세던 몫),
  길면 자른다. **채움이 있어야 낱개마다 주소가 생긴다**(안 채우면 "표준 몫"은 골라서 못 버린다).
· `assertInvariant` 는 **쓸개보다 먼저** 돈다. 뒤에 두면 `reconcile` 이 이미 고친 뒤라
  **무엇을 검사하든 항상 통과한다 — 이빨 없는 검사다.** `CARRY_ASSERT_THROW=1` 이면 던진다.

**★★소비 정본 하나 — `consumeItem(player, item, n)`**
`player.inventory[x] -= n` 직접 차감이 **10곳**에 흩어져 있었다. 스칼라만 깎으면 쓸개가
**뒤에서 잘라** 메우므로 *"2kg 물고기를 먹었는데 0.4kg 짜리가 사라지는"* 일이 난다 —
수량은 맞는데 **무게가 틀리고**, 화면으론 절대 안 보인다. 전부 이 함수로 모았다
(먹기·요리 투입·가공·제작·건축 배치·터 선납 3곳·상자 넣기).
원장 없는 벌크에는 무해한 무동작이라 **모든 소비 경로가 써도 안전하다.**

**★★인벤 전송 정본 하나 — `sendInventory(player, where)`**
`send(ws, {type:'inventory', …})` 직접 호출 **46곳**을 전부 여기로. 스칼라·원장·로트가
**다른 메시지로 갈리면 화면이 반드시 어긋난다**(전리품 표 두 벌 사고의 전송판).
한 메시지 = 한 스냅샷: `{ inventory, ledger, lots }`.

**★"무엇이 개체형인가"는 어디에도 안 적는다 — 구조가 정의한다.**
품목 이름표를 새로 만들면 그게 두 벌째 표이고 어종이 늘 때마다 갈린다.
**원장이 있으면 개체형이다.** 원장은 `noteInstance` 로만 생기고, 그건 **실제로 잰 kg 이 있는
경로**(낚시)에서만 불린다. 바닥 왕복도 이름표를 안 쓴다 — 버릴 때 뺀 항목을 바닥템에 싣고(`gi.led`),
주울 때 그게 있을 때만 원장으로 되돌린다.
※옛 결함: 줍기가 **무조건** 원장을 만들어, 잔가지를 버렸다 주우면 벌크에 원장이 생겼다(3층 캐논 위반).

**B. 클라 — 목록 컴포넌트 한 벌 (`ulRenderRows` / `ulSend`)**

세 컬럼(내 인벤·바닥·상자)이 **같은 함수**를 쓴다. 사용법:

```js
  ulRowsMine(inventory) / ulRowsGround(gItems) / ulRowsChest(data, cid)
      → [{ item, count, kg, kids, drag }]        // 모양은 하나
  ulRenderRows(rows, col, { act, actTitle, empty })   // 렌더 — DOM 구조가 곧 계약
  ulSend(drag, target, amount|null)                    // amount=null → 그 줄 전부
```
· ▶ 는 **펼칠 것이 둘 이상일 때만** 돋는다(하나면 펼쳐도 같은 줄이라 뜻이 없다).
· 하위 줄 = 개체(개별 kg) **또는** 로트(취득일·나이). **어느 쪽인지는 서버 페이로드가 정한다** —
  원장이 오면 개체, 없고 로트가 오면 로트, 둘 다 없으면 하위 줄 없음(무기한 벌크).
· 바닥은 **덩이가 둘 이상일 때** 펼친다(실제로 서로 다른 더미가 둘이라는 사실 그대로).
· **버튼 = 1개 · 드래그 = 그 줄 전부**(부모면 전량 — 재민 확정).
· 짐 모양: `{kind, item, cid?, n, ids?, lotDay?, giIds?}`. 줄이 **제 주소를 들고 다닌다** —
  "몇 개"가 아니라 **"어느 것"** 을 말할 수 있어야 펼친 줄이 따로 움직인다.
· 펼침 상태는 `ulOpen`(Set) 에 남아 재렌더를 넘어 산다(인벤 메시지마다 패널이 다시 그려진다).
· 새 메시지 인자: `drop_item {ids}` · `drop_item {amount, lotDay}` · `pickup_item {giIds}`.
  **옛 인자는 그대로 산다**(`item`+`amount`, `giId`) — 하네스·옛 클라가 안 깨진다.

### ★결함 ③ 유령 클라 — 서버 틱 0인데 화면이 "돌아갔다"

실기 실측: `보정 0회` / 초당 틱 0 이 10초 넘게 이어지는 동안 클라 예측 + 선수신 청크로
화면이 멀쩡히 돌아갔고, **그 상태에서 매긴 판정이 전부 오염됐다**(1차의 ①·⑤).

★**왜 종전 감시가 못 잡았나 — 실측으로 갈랐다.**
`checkOrphan`(내 pid 2초 미수신)은 **정상적으로 자가 치유한다**. 탐침에서 틱을 막자 2초 만에
재연결해 새 소켓으로 틱이 돌아왔다. 못 잡는 건 **재연결해도 틱이 안 오는** 상태다 —
`checkOrphan` 은 발동하며 `lastTickWithMyPidAt = 0` 으로 **자기 자신을 끄기** 때문이다.

수리: `lastTickAt`(`checkOrphan` 이 리셋하지 않는 값)을 **상시** 감시한다.
· 문턱 `GHOST_STALL_MS`(기본 5000 · env). 넘으면 → `#netLost` "연결 끊김" 표시 +
  **입력 예측 정지**(`netStalled` 를 `_selfGone` 과 나란히 게이트) + 미ack 입력 폐기 + 소켓 강제 close
  → 기존 `ensurePrimaryConnection` 이 재연결(같은 토큰 = 같은 몸 · B-6 규약).
· 틱이 돌아오면 자동 해제·예측 재개.
