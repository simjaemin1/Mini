## 3-o. ★★2026-08-30 배치 — **가속 기반 이동 모델 + 조준 모드** (병행 세션: 인벤 정비 `f1659af` **위에 리베이스**)

> 재민 확정: **좀보이드식 관성**. 설계 근거 = 일관성 원칙의 **운동 버전** —
> *몸은 순간이동으로 최고속에 도달하지 않는다.*
> 이번 배치는 **몸만** 만든다. 전투의 살은 회부(`회부_이동조준_다음층.md`).

### ★★★이동을 고치려면 `public/move-model.js` **만** 고쳐라

```
  public/move-model.js   ← 이동 모델 **정본 하나**
     ├── server/zone.js   require('../public/move-model.js')     ← 같은 파일
     └── public/client.js <script src="move-model.js">           ← 같은 파일
```

`soil-base.js` 가 세운 그 규약이다(**사본 금지**). zone.js·client.js 는 **부르기만** 한다.
콜라이더(벽·나무·지형)는 호출자의 몫 — 모듈은 위치를 모르고 `{vx, vy, dx, dy}` 만 낸다.

★**왜 이게 급소인가**: legacy 시절에도 적분이 두 벌이었다(zone.js 7409 · client.js 7310).
곱셈 **순서**가 달라 마지막 ULP 가 어긋났지만 legacy 는 속도가 입력의 함수라 상태가 없어 안 쌓였다.
**가속 모델은 속도가 상태다** — 그 어긋남이 누적되고, 리컨실리에이션이 매 틱 되돌린다 = **떨림**.
⇒ 한 함수로 못 박았다. 이제 클라·서버가 **같은 줄**을 쓴다.

### ★§0 인벤토리 — 지시서 전제와 다른 게 셋이었다

1. **"클라 60fps 예측 vs 서버 10Hz 권위"가 아니다.** 실제는 **양쪽 다 30Hz 고정 스텝**이고,
   클라가 `PRED_STEP=1/30` 마다 입력 **1개**를 보내면 서버가 그걸 **1:1 로 재생**한다
   (Gabriel Gambetta 모델 · 틱당 최대 8개 catch-up). `moveDt = 1/TICK_HZ` 고정 — 가변 dt 가 아니다.
   ⇒ "60fps 적분 vs 10Hz 적분" 이라는 갈림 자체가 **이 코드엔 없다**.
   그래도 dt 불변 검사는 넣었다 — **프레임레이트 상수가 몰래 기어드는 걸 막는 자물쇠**로서.
2. **정본 이속은 65 가 아니라 `MOVE_SPEED = 64`** (2m/s · 32px=1m). 65.1 은 B-3 실측값이었다.
3. **배율은 이미 한 곳에 모여 있었다** — `moveMultOf(p) = Carry.combinedMove(신체, 과적)`.
   흩어져 있던 건 **곱하는 자리**(서버 1곳 · 클라 1곳)였고 그 둘이 이제 모듈 한 줄이 됐다.

그리고 **④ 공격은 무방향이다** — `tryAttack` 은 범위 안 가장 가까운 mob 을 친다(무수정 계약).
**⑤ 카메라는 `_camAbs`(월드) 하나로 15곳이 물려 있다** — 안개 원점·내 스프라이트·물 흐름·컬링이
전부 그 값이다. ⇒ 시야 밀기를 **월드에 더하면** 안개가 따라 걷힌다. 그래서 **화면 변환에만** 더했다.

### 손잡이 표 (전부 env · 기본 legacy)

| 손잡이 | 기본 | 뜻 |
|---|---|---|
| `MOVE_MODEL` | `legacy` | `legacy`(즉시 최고속 · 종전) / `accel`(등가속) |
| `MOVE_ACCEL_T` | `0.20` | 0 → **현재** 최고속 도달 초 (B-1 회부: "현재"의 뜻) |
| `MOVE_DECEL_T` | `0.15` | 키 뗌 → 정지 초 (30Hz 격자에선 실측 0.1667s — B-3) |
| `MOVE_AIM_SPEED_FRAC` | `0.45` | 조준 중 이속 배율 (64 → 28.8px/s) |

★**기본값은 legacy 다.** 회귀 전원이 legacy 로 돈다. 손맛 확정 후 **튜닝 배치**에서 전환한다.
★손잡이 표는 **서버가 `welcome.moveCfg` 로 실어 보낸다** — 클라가 표를 들면 그게 두 번째 사본이다.

### ★★보정은 위치+속도 **한 쌍**이다 (재민 질문에서 확정 → 실장)

가속 모델에서 속도는 상태다. **위치만 스냅하면 스냅 직후 두 적분 곡선이 다시 벌어져
보정이 영원히 반복된다.** ⇒ 서버 tick 이 `selfVx/selfVy` 를 실어 보내고 클라가 둘 다 앵커한 뒤
미ack 입력을 replay 한다. legacy 에선 안 보낸다(상태가 없다 — 페이로드 바이트 동일).

★실장하며 걸린 것: **33ms 정지 키프레임**. legacy 는 그걸 기록도 시뮬도 안 했다(정지 입력이
위치를 안 바꾸니 무해했다). accel 에선 **서버만 한 스텝 더 감속해 곧바로 갈린다.**
⇒ 불변식대로 기록·시뮬한다. 같은 이유로 빈 틱에서 `p.vx=0` 도 accel 에선 **안 한다**(상태를 지우면 갈린다).

### 실측 — 보정 짝 비교 (같은 각본 · 실클라 키보드)

```
                최고속      미끄러짐    보정 횟수   최종 어긋남
  legacy        64.00px/s    0.00px      200회       0px
  accel         64.00px/s    5.93px      200회       0px      ← ★같다
  accel 상승곡선  456ms:32 → 486ms:42.67 → 1071ms:64   (legacy 는 첫 표본부터 64)
```

★**accel 이 legacy 보다 나빠지지 않았다 — 떨림 없음의 실증.**
(둘 다 최종 0px 인 건 이 아키텍처가 입력 1:1 재생이라 **원래** 0 이기 때문이다.
 accel 이 상태를 들고도 0 을 지켰다는 게 이 표의 뜻이다.)

  ⇒ 방향 부호를 눈대중으로 적지 말고 **역변환을 하네스가 손으로 다시 세워** 견준다(+ 반대편 뒤집힘 검사).

| 자리 | 갈림 | 결정 |
|---|---|---|
| `zone.js` welcome | 저쪽 `ledger`/`lots`/`uiCfg` vs 내 `moveCfg` | 둘 다 — 셋 다 "표는 서버가 준다" 같은 규약이다 |

| `client.js` `predictStep` | ★아래 | ★아래 |

★**진짜 갈림은 `predictStep` 하나였다.** 저쪽이 접속 안정성으로 `netStalled` 를 `_selfGone` 옆에 세웠는데,
그 자리가 정확히 내가 **관성을 끊는** 자리다. 합친 결론: **예측이 멈추면 관성도 멈춘다.**

```js
  if (myIsDown || _selfGone || netStalled) { myVel.vx = 0; myVel.vy = 0; return; }
```
재개 첫 틱에 서버 `selfVx/selfVy` 로 다시 앵커되므로 안전하고, legacy 에선 `myVel` 이 안 쓰여 무영향이다.
같은 이유로 저쪽 `setNetStalled` 의 "쌓인 미ack 입력을 버린다" 줄에도 **관성 정지 한 짝**을 붙였다 —
거기서 입력만 버리고 속도를 남기면 재접속 순간 몸이 미끄러진다.
