## 3-b. ★2026-08-03b 배치 9 — 청동 축 종결 · 문서 유효성 점검

### 청동 희소성의 원인이 규명됐다 — **"구리가 안 움직인다"** 하나다

가설 셋(①재료 부족 ②매칭 실패 ③부트스트랩)이 **전부 틀렸다.** 실지도 3시드 800일 실측:

```
  시드   구리보유  주석보유  배합성립  관문통과  구리 발주수출  주석 발주수출
  1020     2        3        2        2         0.0          0.0
     7     1        4        1        1         0.0          0.0
    42     1        3        1        1         0.0          0.0
```

* **관문(`_smithBeatsMason`)은 안 막는다** — 구리를 가진 마을은 100% 통과(청동비용 0.006~0.084 vs 석검 337~362).
* **주석은 퍼진다** — 부존 0 인 어촌2 가 주석 219.6 보유. 주석은 병목이 아니다.
  ★배치 7 이 적은 "구리 축과 주석 유통은 짝"은 **틀렸다** — 정정했다.
* **금속은 발주 교역에 안 나온다**(3시드 전부 0). `exportBy` 키가 전부 식량·원료다.
  금속은 **귀환화물(대금)로만** 움직이는데, 구리 산지는 캔 구리를 **전량 주조에 써서** 글럿이 안 나고,
  글럿이 없으면 대금 후보(`ratio = pFrom/pTo` 최대)로도 안 뽑힌다. 주석은 남으니까 실려 나간다.
* ⇒ **구리는 산지에서 태어나 산지에서 죽는다.** 회부 ①의 선택지 (다) *"청동은 산지의 독점,
  교역은 완제품(청동검)으로만"* 이 **이미 실현된 상태**다. 고를 것이 없다.
* 배치 7 의 두 기각(COPPER_DERIV·BOOMTOWN)도 이걸로 설명된다 — 둘 다 구리를 **더 만들거나 더 원하게**
  했지 **움직이게** 하지는 않았다. 상세: `회부_구리부존과_원석적체.md` §⑤.

### ★§0 잔무 — B-3 "걸음이 정본의 47%"는 **계측기의 사실이었다**

배산임수 배치가 남긴 회부 B-3(기준의 단위를 px 로 둘지 초로 둘지)을 먼저 갈랐다.
세 갈래(ⓐ 지형·경로 ⓑ 계측기 ⓒ 신체·무게 오적용)를 탐침으로:

```
  ① 정본 배율(빈손 새 플레이어)  신체 1.0 · 과적 1.0 · 합산 1.0    ⇒ ⓒ 아님
     플레이어는 길 배속(_rdMul)에서 **명시적으로 제외**된다 — 지형 속도 배율 자체가 없다  ⇒ ⓐ 중 '배율' 없음
  ② **키보드로** 탁 트인 땅 12초: 66 64 66 64 66 64 66 64 66 64 64 66 px/s
     정상 구간 평균 **65.1px/s = 정본 64 의 102%** (rAF 47fps — 30Hz 고정 스텝에 충분)
  ③ 하네스가 쓰던 **수동 입력**: 30px/s → 어떤 판에선 **0px/s**
```
원인: 클라는 키가 안 눌린 동안 **33ms마다 정지 입력**을 보낸다
(`if (!moving && now-lastInputSentAt>33) sendStepInput(seq,0,0)`). 손으로 쏜 입력이 그것과 **번갈아** 들어가 상쇄됐다.
⇒ **ⓑ 계측기.** `e2e-forage-village.walkTo` 를 **키보드**로 고쳤다(2.1/6.6/7.9초 · 평균 52px/s = 82%,
남은 18%는 8방향 양자화 + 경로 우회). **감사 기준 960px = 도보 15초는 그대로 맞다** — 단위를 바꿀 이유가 없다.
★족보 (70): **하네스는 클라의 입력 루프와 싸우지 마라 — 사람이 하는 대로(키보드로) 시켜라.**

### ★§0 인벤토리 — 지시서 전제와 다른 게 넷이었다

1. **정품 자작 경로가 "없다"는 건 틀렸다.** `doCraftEquipment` 가 **이미 있었고**,
   `EQUIPMENT_RECIPES.tool.accepts` 에 `stone` 이 들어 있어 **돌 3개로 정품 도구가 나왔다**.
   문제는 경로의 부재가 아니라 **① 시설 게이트가 없고 ② 즉석이며 ③ 장비 서랍에 묻혀 있다**는 것이었다.
   (빈손 배치 회부의 "정품 자작 경로가 아예 없다"는 **오진**이었다 — 여기서 정정한다.)
2. **작업대만 없었다.** 화덕(`campfire`)·노(`furnace`)·숯가마(`charcoal_kiln`)는 다 있고 **플레이어가 짓는다**
   (노·숯가마는 사유지 필수 + 다단 공정 + 조업까지 실장돼 있다). 도구를 만드는 시설만 없었다.
3. **품질 정본은 하나다** — `PlayerItems.craftItem(type, 숙련, 재료)` = `qSkill(lvl) × matGrade(재료)`.
   구매는 `materializeFromVillage(type, 마을Q)`. **같은 타입·같은 속성 구조**라 "플레이어제" 별도 품목이 없다.
4. **★도구는 econ 재화가 아니다.** `specialty` 에 `tool`/`weapon` 이 없고 `PV_DEPOSIT_MAP`(14종)에도 없다 —
   즉 **거래소에서 도구를 사고팔 수 없다**. 지시 D의 "같은 정본 가격으로 거래된다"는 전제가 성립하지 않는다(회부 B-1).

```

  제작 시간    요리 20초 · 도구 3분 · 제련 2분 (전부 env · **벽시계**다)
  대기열       시설에 붙는다 · 하나씩 만든다(뒤엣것은 앞엣것 뒤에) · 상한 5개

               ⇒ **오프라인에도 진행된다**(가마는 밤새 탄다) · 수령만 접속해서
```
· **작업대**(신규 건물 · 통나무 4 + 석재 2 · **망치 불필요** — 빈손 사다리가 끊기지 않게 · 20kg).

· **제작창 UI**(`facility` 패널 · Shift+K · **시설에 들어서면 저절로 열리고 나가면 닫힌다** — §8.2 의 유일한 예외).
  정렬은 서버가 낸다: **가능 → 재료 하나 모자람 → 나머지**. "하나 모자람"이 오늘의 할 일이고 장에 갈 이유다.
· **재료 선택 = 판단**: 같은 도구라도 `stone 24% / iron 34% / bronze 40%` 로 **예상 품질이 화면 값**이다
  (품질 공식을 다시 쓰지 않고 `craftItem` 을 미리 한 번 돌려 보여 준다).
· **제작 이력** `player.craftLog = {tool:{n,bestQ}}` 영속(`tools_json` 블롭) — §8.4 스킬 패널이 읽을 씨앗.

### ★★자작 vs 구매 손익 (상호의존 방어선 — `scripts/craft-metrics.js`)
