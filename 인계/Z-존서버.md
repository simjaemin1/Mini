## T47. ★★2026-09-01 — **몸의 정본은 한 곳, 직렬화는 한 함수** (존 핸드오프 소실 수리)

재민의 부하 실측이 잡은 라이브 결함(`KNOWN_ISSUES.md` N.6): **존을 넘으면 도구가 영구히 사라진다.**
28회 왕복 전부 재현. 원인은 필드 하나가 아니라 **복원 코드가 두 벌**이었다는 것이다.

### 규약 — 새 필드를 몸에 더할 자리는 **한 곳**이다
```
  serializeBody(p)          몸 → 객체.  저장·핸드오프가 **둘 다** 이걸 쓴다.
  parseBody(raw, {vitals})  객체 → 몸.  일반 접속·핸드오프 도착이 **둘 다** 이걸 쓴다.
                            옛 형식(`{axe:3}`) 변환도 이 안에 있다.
```
⚠`savePlayer` 나 도착 경로에 **직접 필드를 쓰지 마라.** 그렇게 하면 T47 이 고친 그 결함이 되돌아온다.
필드를 하나 더하면 저장·핸드오프·재접속이 **동시에** 따라간다 — 그게 이 규약의 값이다.

| 갈래 | vitals | 왜 |
|---|---|---|
| `savePlayer` → `tools_json` | (저장은 다 한다) | 블롭이라 스키마 변경 0 |
| 일반 접속 복원 | **false** | 로그아웃 후 재접속의 **풀피는 정책**이다 — 죽음 설계(T8) 소관. 이 배치가 안 바꿨다 |
| 핸드오프 도착 | **true** | 존을 넘는 건 **한 접속의 연속**이다. 같은 존 안에서는 `_takeover` 가 이미 HP 를 잇고 있었다 |

### 핸드오프 흐름 · 출처 규칙
```
  출발: await savePlayer(...)        ← ★기다린다(종전 fire-and-forget). 행이 먼저 최신이 되게.
        payload.body = serializeBody(p)   ← 같은 스냅샷을 페이로드에도(안전망)
  도착: pending.body 가 있으면 그것.  없으면 central 행 `tools_json`.
```
★**시각 비교를 안 한다.** 행과 페이로드가 `serializeBody` **한 번의 같은 스냅샷**이라 중재할 경합이
없기 때문이다. 행 폴백이 필요한 경우는 **몸을 안 싣는 옛 존에서 넘어올 때**(롤링 배포 창) 하나뿐이고,
그때는 떠나기 직전 저장한 행이 유일한 진실이다. ⇒ 그 갈래는 픽스처로 **실제로 밟아 검사한다**
(`E2E_HANDOFF_NO_BODY=1` · `E2E_GIVE` 게이트).

### 몸의 정본이 있는 곳 (실측 §0-ⓒ)
**central `players` 행 하나뿐이다.** 존 로컬 DB 에는 플레이어 몸이 없다(건물·자원·마을만).
그래서 "도착이 행을 안 읽는다"가 곧 소실이었다.

### 전/후 (`scripts/test-handoff-body.js` 18/0 · 2존 실서버)
```
  수리 전  도구 axe/100+pickaxe/100 → 도착 **(없음)** → 재접속 **(없음)**  = 영구 소실
           kg원장 fish[2·0.4·1.1]  → 도착 **(빈)**
  수리 후  내구 부분(도구·장비·슬롯·숙련·제작이력·원석장부·어획·kg원장·로트) **비트 동일**
           신체 cold 0.7994 → 0.7939 (이어짐) · HP 43 → 52.85 (이어짐 + 도착 후 회복분)
           재접속 여전히 풀피 = **정책 무변**
```

### 곁가지 — N.8 수리 (`ZONE_TEST_INV` 가 central 살아 있으면 무력화되던 것)
그 값은 `inventory` 의 **초기값**으로만 얹혀 있었고 계정 행 복원이 변수를 통째로 덮었다.
이제 복원 **뒤에** 없는 키만 채운다(idempotent · env 미설정이면 0회 = 운영 무변).

`GET /bodydbg?name=` — `serializeBody` **그 자체**를 내준다(읽기 전용 · `E2E_GIVE=1` 게이트).
welcome 은 몸의 일부만 싣는다. 왕복 전후로 13가지가 다 같은가를 재려면 정본을 봐야 한다(사본 금지).

### 규약 — "못 찾은 자리는 기억한다"
**언제 다시 찾아도 되는가 = 후보가 늘어날 수 있을 때만.** `reject` 가 보는 상태 여덟 중 여섯은
줄기만 한다(= 더 거부된다). 늘릴 수 있는 사건은 셋뿐이고, 그것이 곧 표지가 서는 자리다:

| 사건 | 부르는 것 | 왜 |
|---|---|---|
| `_terrGrow` 가 셀을 더했을 때 | `lifeSiteDirty(vil)` | 새 셀 = 새 후보. **거부 캐시는 유지**(옛 거부는 안 뒤집힌다) |
| `_psite`(의뢰 집터) 소멸 | `lifeSiteReset(vil)` | 반경 18 이 다시 열린다 — 마을 집과 달리 `_houseCells` 에 안 들어간다 |

| `_potSet` 에서 **삭제만** 하는 두 곳(의뢰 터·집터 선점) | `lifeSiteReset(vil)` | strict `farmAt` 이 false 로 뒤집힌다 |

★**새 상태를 만들 때 이 표를 갱신해라.** 표지를 놓치면 집이 안 지어지는 **조용한 결함**이 된다 —
그래서 안전망이 있다: `LIFE_SITE_RESCAN_DAYS`(7)마다 표지를 무시하고 전수로 돈다.

| `tryVillageDeliver` | `Onboarding.onDeliver` **다음** 한 줄 `Membership.onDeliver` — 기여가 오른 뒤라야 문턱을 정확히 본다 |
| `tryVillageBrief` | `player._memberNearVid = vid` (근접 브리핑이 곧 "여기 있다"는 신호 — 채팅 `/인출` 이 이걸 본다) + `Membership.orderBrief(player, r)` (소속 마을 사건 앞줄 · **가시성은 안 바꾼다**) |
| `tryVillageTrade` | `r.member = _memberLine(...)` — 거래소 payload 에 한 줄 얹는다(새 창구 0) |
| `chat` 분기 첫 줄 | `if (Membership.handleChat(player, text)) return;` — 명령은 말이 아니므로 **방송하지 않는다** |
| `tryVillageWithdraw` / `_afterWithdraw` | 인출 뒤 `Lots.reconcile` → `Carry.reconcile` → `savePlayer` → `sendInventory` → 알림 → 거래소 창 갱신 |
| `VILLAGE_BOOK_MSG` | `'village_withdraw'` 추가 — 인출도 마을 장부라 일틱 조각 창에서 **미뤄졌다 흘러야** 한다 |

⚠**새 존 로컬 테이블을 안 만들었다.** 소속은 몸에 실린다 — 존 로컬 표에 두면 존을 넘는 순간
없던 일이 된다(T47 이 도구로 겪은 그 결함의 소속판). `zone-local-db.js` 는 **무접촉**이다.

⚠`_afterWithdraw` 는 `_memberNearVid` 가 있을 때만 거래소 창을 다시 보낸다 — 창이 안 열려 있으면
보낼 데가 없다. 화면이 낡은 남은 몫을 들고 있으면 그게 거짓말이라, 거래소 실행과 **같은 규약**이다.
