### ★족보 (79): **해시를 박은 검사기는 리베이스 한 번에 조용히 거짓말쟁이가 된다 — 검사기는 정본을 스스로 찾는다.**

`split-verify.sh` 가 비교 기준 커밋을 `BASE=95c873c` 로 **박아** 두고 있었다.
로컬에선 통과했다 — 리베이스로 그 커밋이 밀려났는데도 **객체가 dangling 으로 남아 있어서** 였다.
다른 사람이 클론하면 그 해시는 없다. 검사기는 `differ` 가 아니라 **에러로 죽거나, 더 나쁘게는
아무것도 비교하지 않고 통과**한다.

⇒ 기준을 **관계로** 말하게 고쳤다 — "`public/client.js` 를 지운 커밋의 부모":
```bash
DEL="$(git log --diff-filter=D -1 --format=%H -- public/client.js 2>/dev/null)"
[ -n "$DEL" ] && BASE="${DEL}^"
```
같은 결의 것들: 목록을 손으로 든 러너(→ `// @regress` 자동 발견) · 베이스 커밋을 박은 성능 하네스 ·
"정본은 저 파일"이라고 주석에만 적어 둔 사본. **검사기가 아는 것은 규칙이어야 하고 값이면 안 된다.**

### ★족보 (80): **살아 있는 세계의 픽셀·ms 를 절대값으로 읽으면 없는 회귀를 본다 — 같은 빌드 두 번의 잡음 바닥을 먼저 잰다.**

NPC·게임일·연출이 도는 세계에서는 **아무것도 안 바꿔도** 화면이 다르다. 그래서
"변경 전후 223화소가 다르다"는 문장은 그 자체로 아무 뜻이 없다. 실측:
```
  껍데기 제거 전후  223화소(0.032%)   vs  같은 빌드 두 번  290화소(0.041%)   ← 변경 쪽이 **더 적다**
  분할 전후        622화소(0.089%)   vs  같은 빌드 두 번  527화소(0.075%)   ← 같은 자릿수
```
잡음 바닥을 안 쟀으면 둘 다 "회귀"로 보고했을 것이다.
ms 도 같다(`welcome 20ms↔25ms` 는 같은 빌드 쌍에서도 흔들린다). 콘솔은 문자열이 아니라 **에러 개수**를 봐라.

⇒ 규약: **살아 있는 세계를 재는 판정은 반드시 대조 쌍을 같이 낸다.**
`A vs B` 가 아니라 `(A vs B) / (A vs A')`. 절대 문턱은 참고 출력으로만 남긴다.
