## T187. ★★2026-09-12 — **심은 나무 둘째 판** (씨앗은 표에서 · 햇수는 제 종의 것)


**왜 이게 사본이었나.** 시더는 벤 자리에 종을 넘겨 왔다(`chunk.js:462`). 심은 자리만 안 넘겨서

**하네스 손잡이(돌연변이).** 밤과 도토리를 **같은 날** 심고 밤의 문턱을 넘긴다 —
밤은 서고 참나무는 아직 묘목이어야 한다. 종을 안 넘기면 둘 다 성목이라 그 줄이 빨개진다.

## T170. ★★2026-09-11 — **열매 비트** (`fruitNow` 가 선을 타고 온다)

> 한 줄: T148-B 가 `fruitNow` 를 받을 준비를 해 뒀고, **이제 세계가 그걸 실어 보낸다.** 클라는 0줄 고쳤다.

`fruitNow` 는 개체 행(`resource`)의 **한 비트**다 — "지금 이 나무에 열매가 달렸나". 값의 정본은
`server/trees.js fruitSettle`(볼 때 정산)이고, `zone.js _fruitStamp` 이 그 답을 행에 찍기만 한다(사본 0).

```
  실리는 자리 셋 — 매 틱 0
    ① 스폰 방송(`resources_spawn` · 청크 켤 때)      ← "볼 때 정산"의 그 "볼 때"
    ② 따간 직후(`resource_spawn` 재방송 · 그 행만)
    ③ **해+철**이 바뀌는 날 한 번(`resources_spawn` · 바뀐 행만)
  열매가 안 여는 종엔 **비트 자체가 없다**(`undefined`) — 소나무 그림은 무변
  철(`fs`) 판정은 서버 종 표가 정본이다. 이 비트는 철을 다시 말하지 않는다
```

**갱신 문법을 왜 `resource_spawn` 으로 골랐나.** 클라의 `resource_update` 는 **`hp` 한 칸만** 받는다
(`30-n-net.js:1114`). `resource_spawn` 은 `set(id,row)` 라 **행 전체 덮어쓰기**고, `_shapePlantedAll`(`zone.js:1425`)
이 이미 같은 뜻으로 쓰고 있다 ⇒ 새 메시지 유형 0 · 클라 0줄.

**낡은 자리 하나(회부).** 심은 나무(`_liveResourceRow`)는 종을 `r.species` 에 담고 시더는 `r.sp` 에 담는다.
⇒ 심은 나무는 종별 그림도 열매 비트도 **못 받는다**. T148-B 부터 있던 구멍이다.

## 걸음은 **모캡**이다 — 사인은 가랑이를 옆으로 벌리고 있었다 (T96)

★★**§0 실측이 카드의 진단을 고쳤다.** 카드는 *"사인 함수로 흔든 것이라 시계추처럼 걷는다"* 로 봤는데,
`depsgraph` 로 재 보니 그보다 나쁘다 — **앞뒤 성분이 정확히 0** 이었다:

```

      사지 뼈  rx=+30° → (0, +.577, −.816)      rz=+30° → (−.577, 0, −.816)
      몸통 뼈  rx=+30° → (0, −.577, +.816)      rz=+30° → (−.577, 0, +.816)
      ry → 변화 0(뼈 축 비틀기).  .577/.816 은 리그 z 압축(ZSQ .8165) — 되돌리면 정확히 30°.
  캐릭터는 +x 를 본다(메타 "d=0 은 +x" · 어깨·엉덩이가 ±y · 오른손이 −y).
  ⇒ **rx = 좌우(관상) · rz = 앞뒤(시상)**. 사인 걸음은 다리를 `rx` 로만 흔들었다 = **좌우로 벌린 것**.
```

`_pose_swing`·`_pose_aim` 도 같은 축을 쓴다 — 이 카드 밖이라 안 건드렸다(**회부**).

★**리타깃은 회전을 옮기지 않는다 — 방향을 옮긴다.** BVH 관절 회전을 그대로 넣으면 휴식 포즈 차
(BVH 는 T 포즈 · 우리 리그는 팔이 아래)를 따로 빼야 하고 그 차가 어디서 틀렸는지 안 보인다.
⇒ BVH 를 **전방기구학으로 풀어 마디의 월드 방향**을 얻고, 그 방향을 리그의 (rx, rz) 로 **정확히 역변환**한다:

```
  사지: d = (−sinα·cosβ, sinβ, −cosα·cosβ)     α = atan2(−dx,−dz)   β = asin( dy)   rz=+α
  몸통: d = (−sinα·cosβ, −sinβ, +cosα·cosβ)    α = atan2( dx, dz)   β = asin(−dy)   rz=−α
  둘 다 rx = β · ry = 0.   부모 대비는 각 평면에서 빼서 낸다(지금 포즈 함수와 같은 문법 · 평면 근사).
```

## 축 규약 — **사지 `rx` = 관상(좌우) · `rz` = 시상(앞뒤)** (T107 2026-09-05)

포즈 함수를 쓸 때 **시상(앞뒤)은 `rz` 다.** 사지 뼈는 `rx` 로 흔들면 좌우로 벌어진다.
몸통(`root`·`spine`·`head`)은 `rz` 가 시상이되 **부호가 반대**다(T96 표 참조):

```
  사지(휴식=아래)  rx=+ → 캐릭터의 **왼쪽**   rz=+ → **뒤**
  몸통(휴식=위)    rx=+ → 캐릭터의 **오른쪽** rz=+ → **뒤로 젖힘**
```

T96 이 걸음에서, T107 이 `swing`·`aim` 에서 같은 결함을 닫았다. 실측(T107 §0-ⓐ):
도끼를 든 꼭대기에서 `uarmR` 월드 방향이 **(앞 0.018, 왼 −0.999, 위 −0.04)** — 수평으로 옆이었다.

★**한 규칙으로 못 고친다.** 망가진 축이 **서로 다른 두 뜻을 한 값으로 뭉개고 있었다**:
`swing` 의 `−118` 은 *"들어올림(뒤·위)"*, `aim` 의 `−58` 은 *"앞으로 내밈"* 인데 축·부호가 같았다.
⇒ 부호는 **그 함수가 제 문장으로 말한 뜻**에서 가져온다(`swing` 은 `rz=−rx_old`, `aim` 은 `rz=+rx_old`).
크기는 둘 다 그대로다. 사지의 옛 `rz` 상수(팔을 몸에서 띄우던 −8/+10/−26/+30)는 `rx` 로 옮겼다.

## T169 (2026-09-10) — 오디 여름판 `tree14_s` · 종 표에 **철 이름 칸**

(성목에서 다른 철 잎판을 뺀 수). 접미 없는 키는 어느 철에나 선다. 걸러진 종이 0 이면 옛 규약과
같은 말이라 자명 통과이므로, **걸러진 종 수를 전제로 따로 잰다**(지금 1 — 산뽕).

**틀은 안 넓어졌다** — `tree14_s` 는 `tree14_a` 와 571×561 · 앵커 (261.34, 546.1) 로 **같다**.
열매 씨앗식이 같아 오디가 같은 자리에 달리고, 잎 재질만 갈린다(겹치는 화소 평균 |Δ|RGB 15.3/255).
수관 꼭대기 `oy` 553.1 은 성목판과 같다 — **열매는 매달리지 자라지 않는다**(T129 규약 그대로).

⚠**남은 것**: `tree14_a` 에는 가을 잎에 오디가 달려 있다. 성목판으로 셈하지만 세션4가 성목판을
철로 고르면 가을에 오디가 보인다. 닫는 길은 회부(보고 §4) — 새 수 0 인 쪽은 클라가 `_a` 를 가을에만 쓰는 것이다.

## T175 (2026-09-11) — 퇴역판: 구웠으나 어느 칸에도 없는 그림

**`slot=None` = 어느 칸에도 안 싣는다.** T169 가 `tree14_a` 를 `sprites`(성목판)에 넣었는데,
클라(T148-B)는 **칸 이름으로만** 고르고 키의 접미(`_a`·`_s`)를 안 읽는다 ⇒ 여름에도 "가을 잎 + 오디"
산뽕이 성목판으로 뜰 수 있었다. 접미를 클라가 읽게 하는 길은 굽기 문법의 **사본**이라 못 쓴다.
⇒ 표에서 내린다. **세계에 없는 나무는 표에 없다.** 파일·잠금표는 남긴다(다시 굽지 않으려고).

★`kw.get('slot')` 이 아니라 **`'slot' in kw`** 로 가른다 — `None`("싣지 마라")과 "지시 없음"은
다른 말인데 `get` 은 둘을 같게 본다. 이 한 글자가 규약의 표현력이다.

**`_퇴역` 은 표가 적는다.** `build_species_table()` 이 `slot=None` 인 키를 모아 `tree_species.json._퇴역`
으로 내고, `nature-postprocess.py` 가 그것을 읽어 **배포 앵커에서 그 키를 내린다**(사본 0 · 멱등).
⚠T129 가 세운 "앵커는 덮어쓰지 않고 **합친다**" 는 **더하기만** 한다 — 표에서 내린 키가 앵커엔 영원히
남는 구멍이 있었다. 배수구가 이제 났다. 그 덕에 `e2e-nature` 는 한 줄도 안 고치고 32 ↔ 32 로 맞는다.

**굽기 0 으로 표만 다시 쓰는 길이 이미 있다**: `nature_render.py -- <굽는 표에 없는 키>`.
`ONLY` 가 두 렌더 루프를 전부 건너뛰고 종 표만 쓴다(실측 36초 · CPU 1초 = bpy import 뿐 ·
`nature_raw_anchors.json` 바이트 무변 · 배포 PNG 33장 sha1 무변). 표 규약만 고치는 카드는 이 길을 쓴다.

**"파일 N ↔ 표" 를 세는 자가 셋인데 기준이 다르다** — 한 장을 표에서 내리면 갈린다:
`test-icons ⑧`(잠금표 ↔ **파일**)은 **옳은 채로 초록** · `test-props` 수 검사(앵커 ↔ **굽는 표**)와
`e2e-nature [0]`(앵커 ↔ **종 표**)는 "구운 것 = 세상에 선 것"이라는 낡은 전제로 빨개진다.
고칠 자리를 고를 때 **무엇과 무엇을 대는 자인지** 먼저 보라.

**규약의 전제가 뒤집혔다** — T169 의 *"이 자가 실제로 거른다"*(성목판에서 철 잎판을 걸러 낸 종 ≥ 1)는
`tree14_a` 가 성목판에 있을 때의 말이다. 이제 같은 자리가 **반대 문장**이다:
**성목판엔 다른 철 잎판이 아예 없다**(`sprites` 안의 `_a`·`_s` 접미 0 · 돌연변이 둘로 자가 무는지 확인).

## T182 (2026-09-12) — 나무 종 이름의 정본은 **그림 표**다

`tree_species.json.ko` 가 나무 종 이름의 정본이다. 굽기가 적고 클라가 읽는 표이므로,
**서버도 그것을 읽는다**(`server/trees.js koOf`). 종전엔 `server/trees.json.ko`(랩에서 구워 오는 칸)를
읽었고 여덟 중 **넷이 갈려 있었다**: `밤/밤나무 · 개암/개암나무 · 산뽕/산뽕나무 · 버들/버드나무`.

★**사본을 없애는 길이 "고치기"가 아니라 "안 읽기"인 경우가 있다.** 그 칸은 랩에서 구워 오는 것이라
여기서 못 고친다(월드 데이터 손편집 금지). 그래서 고치는 대신 **읽지 않는다** — 그리고 표가 없거나
종이 빠지면 **아이디를 그대로** 낸다(옛 칸으로 되돌아가지 않는다 · 되돌아가면 갈림이 조용히 산다).
하네스가 "서버가 표를 실제로 읽었나"(`koSourceSize`)를 전제로 먼저 재고, 그다음 전수 일치를 잰다.

★**나무 이름과 열매 이름은 다른 것이다**(`밤나무` ↔ `밤`). 정본이 둘인 게 맞고, 규약은
"정본을 하나로"가 아니라 **"둘 사이에 사본이 0"** 이다. 하네스가 둘이 **같아지면** 빨개진다 —
같아졌다면 둘 중 하나가 남의 이름을 베낀 것이기 때문이다.

⇒ `tree_species.json` 을 고치는 카드는 **서버 알림 문장도 같이 움직인다**(「밤나무에서 밤 4」).
그 표는 이제 그림만의 것이 아니다.

## T188 (2026-09-12) — 사본은 **원천까지** 지워야 끝난다

T182 는 `trees.json.ko` 를 **안 읽게** 했고(갈려 있어도 그림 표를 따랐다), T188 이 **갈릴 자리 자체**를
