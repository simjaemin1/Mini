# 라이브 재부팅 절차 — 서버가 멎었을 때 (T1443 · 2026-11-22)

서버가 안 될 때 재민이 이 순서대로만 따라 하면 된다. 서버 설정은 하나도 안 바꾼다.

## 0. 정말 멎었나 — 맥에서 한 줄

```bash
bash scripts/live-ping.sh
```

- `생존 ○` 이면 서버는 산다. 렉이면 `bash <(ssh seoul cat /opt/Mini/scripts/live-lag.sh)`.
- `생존 ✗` 이 세 번(60초 간격) 다 실패해서 나온 것이다. 까닭 줄을 본다.
  - "답 없음 — 연결만 받고 답 0 꼴" → **서버가 굳었다**(2026-11-21 사고 꼴). ssh 도 안 될 것이다 → 1 로.
  - "연결 거절" · "이름 못 찾음(DNS)" → 서버가 꺼졌거나 주소(DuckDNS)가 문제 → 1 로(DuckDNS 만이면 iwinv 콘솔의 IP 로 핑).
  - "존 hanbando: …" 만 ✗ 이고 게임 주소 · central 은 ○ → 서버는 살고 **존만 죽었다** → 2 로 바로(재부팅 말고).
  - "인증서 …" 만 ✗ → caddy 가 인증서를 못 갱신 — 급하지 않다(PM 에 붙인다).

## 1. iwinv 에서 다시 켜기

1. iwinv 콘솔 → 서버 `mini-hanbando` → **재시작**(안 되면 "강제 재시작").
2. 2 ~ 3분 기다린 뒤 맥에서 `ssh seoul echo ok` 가 `ok` 를 찍으면 2 로.
3. (가능하면) 재부팅 **앞**에 콘솔 화면(검은 화면에 찍힌 커널 줄)을 사진으로 남긴다 — 왜 죽었는지 가르는 데 쓴다(사고 기록 §3).

## 2. 무엇이 떴나 — 한 줄

```bash
bash <(ssh seoul cat /opt/Mini/scripts/update-live.sh) --status
```

- `두 호스트 다 앞 배포가 끝까지 갔다` → 다 떴다. 4 로(밖에서 확인).
- `✗` 줄이 있으면 그 줄 끝의 `⇒` 가 할 일이다. 보통은 셋 중 하나:

| 화면 | 뜻 | 할 일 |
|---|---|---|
| `durango-zone-hanbando 이 돌지 않는다(exited …)` · 스탬프가 옛것 | 배포가 존을 멈춘 뒤 끊겼다(11-21 사고 꼴) — Docker 가 "손으로 멈춤"으로 적어 다시 안 띄운다 | 3 의 배포 줄(마저 한다) |
| `durango-zone-hanbando 이 돌지 않는다` · "스탬프가 이미 새것" | 배포는 끝났는데 존만 죽었다 | `ssh seoul 'bash /opt/Mini/scripts/redeploy-hanbando.sh --zone'` |
| `… 은 새 판으로 도는데 스탬프는 옛것` · `이미지는 새로 구웠는데 컨테이너는 옛것` · `코드는 새 판을 받았는데` | 배포가 중간에 끊겼다(존은 돌 수도 있다) | 3 의 배포 줄 |
| `durango-zone-hanbando 컨테이너가 없다` | 배포가 옛 존을 지운 뒤 새 존을 띄우기 전에 끊겼다 — **배포 줄로는 못 띄운다**(옛 컨테이너와 함께 설정(env)도 사라졌다) | 아래 "존 컨테이너가 없을 때" |
| `caddy 가 돌지 않는다` | https 가 안 된다 | `ssh seoul 'docker start $(docker ps -a --format "{{.Names}} {{.Image}}" \| awk "tolower(\$2) ~ /caddy/ {print \$1}")'` |

## 3. 배포 줄(끊긴 배포를 마저)

```bash
bash <(ssh seoul cat /opt/Mini/scripts/update-live.sh)
```

- 첫 줄에 `⚠ 상태 ✗ 앞 배포가 끊긴 흔적 …` 이 찍히면 정상이다(앞이 끊겼다는 알림 — 하는 일은 평소 배포와 같다).
- 존 부팅은 최대 15분 기다린다(그동안 생존 확인이 빨강을 한 번 낼 수 있다).
- 끝나면 2 의 `--status` 를 한 번 더 — `끝까지 갔다` 가 나와야 한다.

## 4. 밖에서 확인

```bash
bash scripts/live-ping.sh --line
```

`생존 ○ 게임 200 · central ok · 존 hanbando 날 … · nippon 날 …` 이면 끝. 브라우저로 한 번 들어가 본다.

## 존 컨테이너가 없을 때(드묾 — 배포가 `rm` 과 `run` 사이에서 끊김)

옛 컨테이너에 있던 설정(env — 비밀 포함)은 컨테이너와 함께 사라졌다. 배포 줄은 "컨테이너 없음 — 최초 생성은 …"으로 멈춘다.
**혼자 고치지 말고 PM 에 붙인다**(`--status` 화면 그대로). PM 이 그때 쓸 줄을 준다(서울 비밀 파일 자리 · 존 env 목록 — 이 문서에 값은 안 적는다).

## 하지 말 것

- 2 를 안 보고 `docker start durango-zone-hanbando` 부터 치지 않는다 — 11-22 21:05 에 이렇게 해서 **옛 이미지** 존이 새 central 과 함께 떴다(스탬프 · 이미지가 어긋남). `--status` 가 무엇이 어긋났는지 먼저 말한다.
- 재부팅 도중(1 의 2 ~ 3분)에 배포 줄을 돌리지 않는다.
- 서버 설정(스왑 · sysctl · sshd · 방화벽)은 이 절차에 없다 — 보고 T1443 회부(재민 판정 뒤 따로).
