# 조사 — 말(馬) 사역은 어디까지 배선돼 있나 (구현 없음 · 보고서)

> 2026-08-02 배치 C13. **조사만** 한다(구현은 `era.canTame('horse')` 가 early_iron 이라 아직 잠김).
> 결론 먼저: **길들이기는 이미 열려 있고(게이트가 안 걸려 있다) 사역 소비처는 하나도 없다.**
> 그리고 한반도에는 **말이 아예 스폰되지 않는다.**

---

## ① 종 데이터는 있다 — `server/animals.js`

```js
horse: {
  ko: '말', hp: 100, speed: 8, size: 'large',
  aggressive: false, pack: 2, breeding: true,
  produces: {},                       // ← "노동 (운송) 별도 시스템" (주석)
  feed: 'oats',
  drops: { meat_game: 6, leather: 4, horn: 1 },
  spawn_biome: ['plains'], spawn_density: 0.02,
}
```

`wildlife.js`(5종 생태 블록 — 사슴·토끼·멧돼지·늑대·호랑이)에는 **말이 없다.** 말은 `animals.js`
쪽 mob 카탈로그(36종)에만 있다. 두 계통이 다르다는 것부터 알고 있어야 한다.

## ② ★한반도에는 말이 안 나온다

`zone.js` 부팅 스폰은 `huntableInBiome(ZONE.biome)` 로 종을 고른다. **hanbando 의 biome 은
`forest`** 이고, 말의 `spawn_biome` 은 `['plains']` 다.

```
huntableInBiome('forest') = wolf, bear, moose, deer, wild_boar, red_fox, pheasant, quail, tiger
  → horse 포함 안 됨
```

⇒ 지금 이 세계에는 말이 **0마리**다. 시대를 열어도 그대로다.

## ③ ★길들이기 게이트는 **안 걸려 있다**

`zone.js:583` 이 `animals.js` 카탈로그에서 MOB_DEFS 를 자동 생성한다:

```js
tameFood: a.breeding ? (a.feed || 'wheat') : null,
tameNeed: a.breeding ? 3 : null,
```

`breeding: true` 인 13종 전부가 **먹이 3번이면 길들여진다.** 시대 검사가 없다 —
`era.canTame()` 는 정의만 돼 있고 **호출부가 한 곳도 없다**(전수 grep 확인).

⇒ 말이 스폰되기만 하면 **청동기에도 즉시 길들여진다.** 지금 안 되는 이유는 게이트가 아니라 ②다.
   (era.js §"한반도 기마 문화는 삼국시대 — 송국리기엔 없다" 의 의도가 코드로는 안 지켜지고 있다.)

## ④ 길들인 뒤에 할 수 있는 게 없다

`tryFeed` 성공 시 하는 일 전부:
- `mob.tameOwner = playerId` · `tameOwnerName`
- 어그로 해제, 이후 늑대 무리 어그로 대상에서 제외(`zone.js:599`)
- 재차 먹이면 HP +5

그게 끝이다. **탈것·운반·견인·번식·산출 — 어느 것도 없다.** 전수 grep 으로 `mount`/`riding`/
`운송`/`짐말` 계열 소비처가 서버·클라 어디에도 없음을 확인했다.
`produces: {}` 이라 `breeding` 산출(우유·양털 계통)에도 안 걸린다.

## ⑤ 먹이(`oats`, 귀리)를 플레이어가 못 얻는다

`specialty.RESOURCES.oats` 는 있다(`harvest: 'farming'`, baseValue 0.8). 그런데 플레이어 농지
(`farmland`)는 **베리(seed_berry)만** 심는다. 귀리는 NPC 경제 쪽 작물이라 플레이어 인벤에
들어올 경로가 없다. ⇒ 스폰과 게이트를 다 통과해도 **먹일 수가 없다.**

### 사역 소비처 후보 (전부 새 시스템 — 설계 회부 대상)

| | 내용 | 접점 |
|---|---|---|
| 가 | **탈것** — 이동 속도 ↑ | 플레이어 이동(넷코드 K19 "입력 1개 = 1스텝")과 직결. 속도 상수 하나가 아니라 **동기화 규약**을 건드린다 |
| 나 | **짐말** — 운반 상한(`CARRY_MAX_KG` 28kg) ↑ | 가장 값싸고 가장 게임적이다. 광석 원정(왕복 효율 `haulEff`)과 정확히 맞물린다 |
| 다 | **NPC 캐러밴 견인** — 교역 화물량·속도 ↑ | econ 접촉. `CARGO_PER_TRIP`·`travelDays` 를 건드리므로 회귀 위험이 크다 |
| 라 | 번식·산출 | `produces: {}` 를 채우면 되지만 말은 원래 산출이 없다(고증) |

**내 의견**: 1번(게이트 연결)은 지금 해도 되는 위생이고, 4번은 **(나) 짐말**이 값이 가장 크고
접점이 가장 좁다 — 채광 원정의 왕복 효율이 이미 모델에 있어서 말이 그 식에 자연스럽게 들어간다.
(가)·(다)는 각각 넷코드와 econ 을 건드리므로 별도 회부.
