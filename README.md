# 듀랑고 미니 (durango-mini)

[![regress-unit](https://github.com/simjaemin1/Mini/actions/workflows/regress-unit.yml/badge.svg)](https://github.com/simjaemin1/Mini/actions/workflows/regress-unit.yml) — push 마다 단위 회귀 23종(약 3분) · 전수 120종은 야간 1회

**청동기 후기 한반도에서, 51개 NPC 마을이 스스로 살아가는 세계에 이방인으로 도착하는 오픈월드 생활·경제 시뮬레이션.**
그리고 그 세계를 **여러 서버 프로세스가 지역별로 나눠 돌리는** 분산 존 서버 프로토타입.

> 시대 배경은 **청동기 후기(송국리 문화기)** 다. 움집은 지상 통나무 벽에 맞배 이엉 지붕, 곳간은 고상식.
> 지도는 한반도 하나(존 70,016 × 130,016px · 1셀 = 1m), 바다는 남쪽에 하나뿐이고 51개 마을 가운데
> 바닷가에서 도보 15초 안인 곳은 셋이다. 그래서 소금은 원정과 교역의 재화다.

## 무슨 게임인가

플레이어는 **나루터에서 온 이방인**이다. 빈손으로, 배고픈 채 도착한다. 지급 아이템은 없다.
마을에 들어서면 연기가 오르고 주민이 일하고 곳간이 서 있다 — 세계는 플레이어가 오기 전부터 돌고 있었다.
촌장이 "요즘 ○○이 달려"라고 말하는데, 그 대사는 대본이 아니라 **그 마을 곳간의 실제 재고**다.

첫 30분의 뼈대는 이렇다: 결핍을 느끼고 → 내 행동에 세계가 반응하는 것을 보고(내가 낸 물건이 곳간에 실제로 쌓인다)
→ 갖고 싶은 것이 생긴다(며칠 일손을 보태면 빈터를 내어준다 — 내 움집). 잠자리는 공용 쉼터 → 일해서 얻은 빈터 →
직접 짓는 내 집, 세 단이다. 튜토리얼 팝업도 퀘스트 화살표도 없다 — 안내는 전부 세계 안에서 온다.

그 뒤로는 마을 사람이 되어 간다. 의뢰를 채우면 기여가 쌓이고, 열두 번쯤 채우면 마을 소속이 되어 곳간에서
신용 한도만큼 꺼내 쓸 수 있다. 겨울은 실시간 6일마다 38시간씩 돌아오고, 마을은 가을에 쌓고 겨울에 먹는다.
플레이어가 더하는 것은 마을의 생존이 아니라 **여유와 이름**이다 — 연대기에 남는 것은 "마을이 살아남았다"가 아니라
"그해 겨울 누가 보탰다"이다.

## 설계 원칙 (캐논)

이 프로젝트의 결정은 거의 전부 아래 몇 줄에서 나온다. 정본은 `인계/공통.md` 와 `설계/설계_게임성_사건레이어_TODO.md` 다.

* **일관성 원칙** — 순간이동·소멸·추상화 금지. 캐릭터는 발생하지 않고 **도착**한다. 소식은 순간 전파되지 않고
  행상인 속도로 퍼진다(이웃 마을 사건은 며칠 뒤에야 들린다 — 정보 비대칭이 곧 콘텐츠). 이동에는 관성이 있다.
* **주사위 금지** — 판정은 실측 문턱이다. 부패는 시간과 온도의 함수지 확률이 아니다. 상한 것을 먹으면 확정적으로 탈이 난다.
  "없는 물고기를 주사위로 만들지 마라."
* **경제가 진짜다** — NPC 마을 경제(`sim/economy-sim-v2.js`)가 세계의 단일 원천이다. 사건은 각본이 아니라 그 경제의
  **에지**에서 창발한다(재고 바닥 = 의뢰, 흉년·가뭄·인구 붕괴·약탈 = 촌장이 하는 말). 작가가 필요 없다.
* **숙제 금지** — 일일 보상·출석·주간 리셋 없음. **오프라인 감쇠 없음**(접속 안 한 동안 굶지 않는다). 대신 세계는
  오프라인에도 흐른다: 가마는 밤새 타고, 건조대는 마르고, 농지는 자란다(전부 lazy · 새 틱 0). 부재는 손실이 아니라
  **뉴스**다 — 돌아오면 촌장이 "자네 없는 동안…"을 들려준다.
* **판단·위험·손맛** — 입력이 매번 같고 결과가 확실하면 게임이 아니라 진행바다. 루프마다 셋 중 하나는 있어야 한다.
  차등의 근거는 세계의 실제 데이터(번영도·강 폭·계절)여야 한다.
* **대시보드 금지 · 새 패널 0** — 상태와 사건은 UI 가 아니라 세계로 번역한다(촌장 말풍선·HUD 한 줄·게시판 토스트).
* **도구는 관문이 아니라 능률** — 맨손 ×1 · 조잡 ×2 · 정품 ×3. 무엇이든 맨손으로 시작할 수 있다.
* **정본은 하나** — 가격 사본을 만들면 그 순간 실패다. 이동 모델은 서버와 클라가 같은 파일을 읽는다. 사건을 보는 문은
  하나(`events.visibleEvents`), 무게 비교자도 하나(`heavier`), 시계도 하나(econ 게임일).

## 실행 방법

```bash
npm install
npm start                                        # central + dispatcher + 26개 존
ENABLED_ZONES="hanbando,nippon" npm start        # 일부만
```

`npm start`(= `node scripts/launch-all.js`)는 **zone-config.js 의 ZONES 를 그대로** spawn 한다 — 설정과 프로세스 목록이
어긋날 수 없다. 브라우저에서:

```
http://localhost:3000        # dispatcher (정적 파일 + 존 라우팅)
http://localhost:3010        # central (계정·신원·존 목록 /zones)
```

존 서버는 3001~3030 범위의 각자 포트를 쓴다(`zone-config.js`). 라이브는 hanbando 존 하나(:3020)만 돈다.

### 무거운 층 끄기

세계 시뮬(마을·야생·도적)은 부팅과 tick 비용의 대부분이다. 개발·측정용으로 끌 수 있다:

```bash
ENABLE_VILLAGES=0 ENABLE_WILDLIFE=0 ENABLE_BANDITS=0 npm start   # ENABLE_WILDLIFE=0 은 적대 개체 전부 OFF
```

### 성능 플래그 (기본 꺼짐)

지형 통행 판정(`isPointInRiver` 등)이 존 tick 과 부팅 비용의 지배적 항목이다. 같은 답을 내는 두 가지 가속이 들어 있다:

```bash
TERRAIN_SEG_INDEX=1     # 강·능선 선분을 512px 격자로 색인 — "처음 묻는 질문"을 줄인다
TERRAIN_TILE_CACHE=1    # 타일 단위 메모(4비트/타일) — "다시 묻는 질문"을 없앤다
```

실서버 실측(`BENCHMARK.md` §3-B): 같은 세계에서 `tick_avg` **454~888ms → 15~28ms**, 클라 관측 p50 **515 → 34ms**,
부팅 **13분 51초 → 7분 10초**.

### 검증

```bash
bash scripts/run-regress.sh --selftest    # 러너 자신부터
bash scripts/run-regress.sh               # 하네스 전원 — 파일 머리에 `// @regress` 가 있으면 자동 발견(70종+ · ~2.5시간)
node scripts/ev-density.js 800 1020       # 3시드 800일 기준선(인구·소멸·무기Q·게시 건수 · 시드 1020/7/42)
```

**기준선 다섯 수**(51마을 800일 · 시드 1020/7/42): 인구 6,280/5,993/6,072 · 소멸 0/51 · 무기Q 821/755/784 ·
게시 1,647/1,583/1,679. econ 을 안 건드린 배치는 이 수가 **비트 동일**해야 한다 — 열두 배치에서 그렇게 확인했다.

**클라이언트는 한 파일이 아니다.** `public/client/*.js` 조각들을 `index.html` 이 순서대로 로드한다. 새 기능 = 새 파일 +
등록 1줄. 최상위 실행문은 `99-main.js` 에만 둔다. 이름 충돌은 `node scripts/test-client-globals.js` 가 검사한다.

**좌표계는 셋이다** — 서버 메시지는 존 로컬 px, 렌더러는 절대 월드 px, econ 은 셀×2.5. 마을 거리·캐러밴 시계는
전부 econ 좌표다(px 를 넣으면 12.8배 틀린다).

## 데이터

* **SQLite** (`node:sqlite` / `better-sqlite3`). 메모리 저장이 아니다.
  * `central.db` — 계정·게스트 영속 신원·마지막 존
  * `world-<zone>.db` — 존별 건축물·자원·클레임·몹·마을 상태·사건 장부·연대기
* 존은 자기 DB 만 쓴다. 존 사이의 공유 상태는 central 을 거친다. 플레이어의 **몸**(인벤·도구·소속·마지막 본 날)은
  `serializeBody` 하나로 직렬화되어 저장·핸드오프·재접속이 같은 함수를 쓴다.

## 핸드오프 (존 경계 넘기)

1. 출발 존이 대상 존에 `POST /handoff_prepare` — 토큰 + 플레이어 상태
2. 출발 존이 클라에 `{type:'handoff', targetZone, token}`
3. 클라가 대상 존에 `?handoff_token=…` 로 재접속
4. 대상 존이 출발 존에 `POST /handoff_ack` → 출발 존이 옛 몸을 정리 (3초 안에 ACK 없으면 fallback 정리)

경계 양쪽 **256px 는 겹침 띠**(`HANDOFF_COMMIT`)다. 그 안에서는 핸드오프하지 않으므로 경계에 서서 왔다갔다 해도
재접속 핑퐁이 없다(`BENCHMARK.md` §4-C: 경계선 71회 통과 · 핸드오프 0회). 핸드오프에서 도구가 사라지던 결함(N.6)은
몸의 직렬화 함수를 하나로 통일하며 닫혔다(28회 재현 → 0).

## 실측 (`BENCHMARK.md`)

실서버(1 vCPU · 1.9 GiB) 한 존(NPC 1,566 · 몹 449 · 마을 50):

```
                        서버 tick_avg      클라 p50      수용 인원(무릎)
  NPC 없음·플래그 끔       2.4 ~ 11 ms        33 ms          5명
  NPC 있음·플래그 끔      454 ~ 888 ms       515 ms        1명 미만
  NPC 있음·플래그 켬       15 ~  28 ms        34 ms      10명에서도 p50 62ms
```

사람이 0명인 존은 tick 본문을 통째로 건너뛴다(idle skip) — 빈 존의 CPU 는 3.9%다. 세계 시뮬 비용은 **누군가 접속하는
순간** 청구된다. econ 일틱은 마을 단위로 여러 프레임에 쪼개져 돈다(일틱 슬라이서 · `scripts/test-tick-slicer.js` 가 검사).

## 개발 방식

여러 Claude 세션이 **카드** 단위로 병행 작업한다(태스크보드 · 영역당 세션 1 · 새 기능은 새 파일 + 접점 1줄 ·
econ 카드는 웨이브당 하나 단독). 세션은 §0 실측 → 구현 → 하네스 → 기준선 → `보고/T<카드>_<날짜>.md` 와 함께
main 까지 푸시한다(force push 0). 배포만 사람이 한다: `bash scripts/redeploy-hanbando.sh --central`.
지시서의 전제도, 하네스도, 회부에 적힌 진단도 전부 **가설**이다 — 실측이 늘 앞선다. 그 족보는 `인계/공통.md` 검증 원칙에 쌓인다.

## 주요 설계 선택

**왜 클라이언트가 직접 존 서버에 붙는가** — 디스패처가 메시지를 중계하면 디스패처가 병목이 된다. 클라이언트가 직접 존
서버에 붙고, 디스패처는 라우팅 정보만 알려주는 게 분산 구조의 핵심.

**왜 권위는 존 서버에 있는가** — 같은 지역 안의 플레이어들끼리 상호작용할 때 단일 권위 서버를 거치는 게 일관성 유지에
가장 단순.

**왜 핸드오프는 WS 재연결로 처리하는가** — 존 간 직접 통신 대신 클라이언트를 통한 리레이가 프로토타입에선 훨씬
간단. 지금은 재연결 한쪽만 클라를 거치고 상태 이전은 zone↔zone HTTP 다. 본격 운영 시에는 존 간 백엔드 메시지
버스(Redis pub/sub, NATS) 추가 권장.

**왜 클라이언트 예측이 있는가** — 서버 tick 주기(30Hz) 때문에 즉시 반응이 안 보인다. 입력 즉시 클라가 예측하고, 서버
권위 좌표와 어긋나면 위치+속도 한 쌍으로 보정한다.

**왜 NPC 마을이 플레이어 없이도 사는가** — "내가 없어도 내 것이 자란다"는 요구에 대한 세계 내적 답이다. 마을은
플레이어 없이 800일을 소멸 0 으로 산다. 플레이어는 그 위에 여유와 이름을 더한다.
