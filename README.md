# 미니 (durango-mini)

[![regress-unit](https://github.com/simjaemin1/Mini/actions/workflows/regress-unit.yml/badge.svg)](https://github.com/simjaemin1/Mini/actions/workflows/regress-unit.yml) — push 마다 단위 회귀 · 전수(367종)는 야간 러너가 하루 한 번

**청동기 후기 한반도, NPC 마을들이 스스로 살아가는 땅에 이방인으로 도착하는 오픈월드 생활·경제 시뮬레이션.**
그리고 그 세계를 **구역(존)마다 다른 서버가 돌리는** 분산 존 서버. (이름은 아직 임시 — "미니")

> 세계는 하나의 지구다. `server/zone-config.js` 가 지구를 **26개 구역**으로 나눈다(hanbando · nippon · jungwon · europa …).
> 각 구역은 제 서버 · 제 DB · 제 마을을 갖고, **구역 서버는 실제 그 지역에 둔다** — 존을 넘으면 핑이 지리적 거리를 따라간다(의도).
> 지금 살아 있는 구역은 **한반도(서울 서버)** 와 **닛폰(도쿄 서버)** 이다. 한반도 구역은 70,016 × 130,016 px(**1셀 = 1 m**) ·
> NPC 마을 51곳이고, 아래 실측은 전부 이 구역의 것이다.
>
> 시대 배경은 **청동기 후기(송국리 문화기)**. 움집은 굴립주에 이엉 지붕, 곳간은 고상식, 마을 둘레엔 환호와 목책.
> 바다는 남쪽에 하나뿐이라 소금은 원정과 교역의 재화다.

접속: **https://mini-gate.duckdns.org** (브라우저 · wss)

## 무슨 게임인가

플레이어는 **나루터에서 온 이방인**이다. 빈손으로, 배고픈 채 도착한다. 지급 아이템은 없다.
마을에 들어서면 연기가 오르고 주민이 일하고 곳간이 서 있다 — 세계는 플레이어가 오기 전부터 돌고 있었다.
촌장이 "요즘 ○○이 달려"라고 말하는데, 그 말은 대본이 아니라 **그 마을 곳간의 실제 재고**다.

첫 30분: 결핍을 느끼고 → 내 행동에 세계가 반응하는 것을 보고(내가 낸 물건이 곳간에 실제로 쌓인다) → 갖고 싶은 것이 생긴다
(일손을 보태면 빈터를 내어준다 — 내 움집). 잠자리는 공용 쉼터 → 일해서 얻은 빈터 → 직접 짓는 내 집. 튜토리얼 팝업도
퀘스트 화살표도 없다 — 안내는 세계 안에서 온다(「지금 할 일」 한 줄 · 촌장 말 · 게시판 · 마을 화면).

그 뒤로는 마을 사람이 되어 간다. 의뢰를 채우면 기여가 쌓이고, 소속이 되면 곳간에서 신용 한도만큼 꺼내 쓴다.
**하루는 실제 24분, 한 해는 365일 — 실제 약 6일.** 겨울은 해마다 실제 38시간쯤 이어지고, 마을은 가을에 쌓아 겨울을 난다.
사람은 나이 들어 죽고(자연사), 행복이 출생과 일의 능률을 움직인다.

**NPC 마을에서 사는 것은 시작일 뿐이다.** 플레이어는 **제 마을을 세운다.** 기존 마을에서 떨어진 땅에 회관을 착공하면
터 다지기 → 환호 → 굴립주 세 단계 뒤 마을로 등록된다(`foundPlayerVillage`). 곳간에 식량이 쌓이면 사람이 는다 —
NPC 마을과 **같은 인구 모델**이 그대로 돈다. 촌장은 곳간 문을 잠그거나 열고, 「이방인 받기」를 켜면 다른 플레이어가
새 캐릭터로 내 마을에서 시작한다. 플레이어 마을엔 NPC 마을이 받는 기근 보호막이 없다 — 세운 만큼 위험하다.

## 설계 원칙 (캐논)

결정은 거의 전부 아래 몇 줄에서 나온다. 정본은 `인계/공통.md` 와 `인계/족보.md`(재민 판정 기록)다.

* **모든 NPC 는 언제나 몸이 있다** — 세계의 모든 사람은 늘 몸으로 세상 위에 있고, 마을 사람의 일은 **몸이 실제로 한 것만**
  센다. 순간이동 · 소멸 · 추상화 금지. 캐릭터는 발생하지 않고 **도착**한다. 소식은 행상인 속도로 퍼진다.
* **플레이어와 NPC 는 같은 활동을 같은 규칙으로** — 밭 갈기 · 영토 넓히기 · 직업 · 숙련이 둘에게 같다. 플레이어만 빠른 길은 없다.
* **고증이 먼저, 게임적 허용은 마지막** — 수확 kg/ha · 일손 시간 · 몸무게 · 썩는 햇수 같은 수는 출처가 있는 값에서 온다.
  출처가 없으면 "미확인"이라고 적는다. 고증이 재미를 막는 것이 확인된 뒤에만 허용을 판정한다.
* **식량의 단위는 열량** — 포만감은 kg × kcal/kg 에서 나온다(하루치 = 2,450 kcal).
* **주사위 금지** — 판정은 실측 문턱이다. 부패는 시간과 온도의 함수다. 같은 입력이면 같은 답(결정론 · 시드 재현).
* **경제가 진짜다** — NPC 마을 경제(`sim/economy-sim-v2.js`)가 세계의 단일 원천이다. 사건은 각본이 아니라 경제의
  **에지**에서 창발한다(재고 바닥 = 의뢰 · 흉년 · 가뭄 · 인구 붕괴 · 약탈 = 촌장이 하는 말).
* **숙제 금지** — 일일 보상 · 출석 · 주간 리셋 없음. 세계는 오프라인에도 흐른다(가마는 밤새 타고 밭은 자란다).
  부재는 손실이 아니라 **뉴스**다 — 돌아오면 촌장이 "자네 없는 동안…"을 들려준다.
* **도구는 관문** — 벌목 · 낚시 · 공격은 도구나 무기가 있어야 한다. 나뭇가지로 만드는 급조 도구로 일찍 열 수 있다.
* **정본은 하나** — 사본을 만드는 순간 실패다. 이동 모델은 서버와 클라가 같은 파일을 읽고, 시계도 하나(econ 게임일)다.
* **랩이 목표다** — `lab/마을실험실.html` · `lab/전쟁실험실.html` 에서 만든 것이 지향점이고, 서버가 랩보다 얕으면 결함이다.

## 실행 방법

```bash
npm install
npm start                                        # central + dispatcher + 26개 존
ENABLED_ZONES="hanbando,nippon" npm start        # 일부만
```

`npm start`(= `node scripts/launch-all.js`)는 **zone-config.js 의 ZONES 를 그대로** spawn 한다 — 설정과 프로세스 목록이
어긋날 수 없다. 브라우저에서:

```
http://localhost:3000        # dispatcher (정적 파일 + 존 라우팅)
http://localhost:3010        # central (계정·신원·존 목록 /zones)
```

### 무거운 층 끄기

세계 시뮬(마을·야생·도적)은 부팅과 tick 비용의 대부분이다. 개발·측정용으로 끌 수 있다:

```bash
ENABLE_VILLAGES=0 ENABLE_WILDLIFE=0 ENABLE_BANDITS=0 npm start   # ENABLE_WILDLIFE=0 은 적대 개체 전부 OFF
```

### 성능 플래그 (기본 꺼짐)

지형 통행 판정(`isPointInRiver` 등)이 존 tick 과 부팅 비용의 지배적 항목이다. 같은 답을 내는 두 가지 가속이 들어 있다:

```bash
TERRAIN_SEG_INDEX=1     # 강·능선 선분을 512px 격자로 색인 — "처음 묻는 질문"을 줄인다
TERRAIN_TILE_CACHE=1    # 타일 단위 메모(4비트/타일) — "다시 묻는 질문"을 없앤다
```

실서버 실측(`BENCHMARK.md` §3-B): 같은 세계에서 `tick_avg` **454~888ms → 15~28ms**, 클라 관측 p50 **515 → 34ms**,
부팅 **13분 51초 → 7분 10초**.

### 검증

```bash
bash scripts/run-regress.sh --selftest    # 러너 자신부터
bash scripts/run-regress.sh               # 하네스 전원 — 파일 머리에 `// @regress` 가 있으면 자동 발견
node scripts/server-baseline-check.js 계측/서버기준선_2026-11-08c.json --vclock --plan 1020:400   # 서버 기준선 대조(시드 하나 · 약 15분)
node scripts/t17-metrics.js 800 1020      # 랩 기준선 계측기
```

**서버 기준선 정본 `계측/서버기준선_2026-11-08c.json`**(가상 시계 · 400날 · 시드 1020 / 7 / 42): 인구 3,867 / 3,891 / 3,517 ·
빈 마을 0 / 0 / 2. **랩 게이트**(800날): 5,929 / 6,642 / 6,171. 새 손잡이를 끈 판은 이 수와 **비트 동일**해야 한다(날 지문 ·
여덟 수 · 마을 칸 지문). 정본 표는 `인계/공통.md` 기준선 절이다(판이 바뀌면 거기서 갱신 · 이 줄은 요약).

세계를 움직이는 카드는 손잡이 뒤(끔 기본)에 들어오고, 켬 판 표를 보고 재민이 켬 기본을 판정한다. 켜면 새 기준선을 3시드로 만든다.

## 구조

```

├── server/
│   ├── zone-config.js       # 존 토폴로지(26개) · 월드 배율 · 시계 — 모든 프로세스의 공통 정본

│   ├── dispatcher.js        # 정적 파일 + 존 라우팅

│   ├── body.js weather.js wind.js spoil.js lots.js crops.js salt.js forage.js facility.js fishing.js
│   ├── trade.js weights.js carry.js bandits.js wildlife.js roads.js soil.js rooms.js …
│   ├── terrain.js           # 지형 판정 정본 (+ terrain-segindex.js / terrain-tilecache.js)
│   └── zone-local-db.js     # 존별 SQLite(world-<zone>.db)
├── sim/                     # econ 정본(economy-sim-v2.js) — 랩(마을실험실)과 서버가 같은 파일을 읽는다
├── public/
│   ├── index.html style.css move-model.js
│   └── client/              # 클라이언트 33조각 (00-const … 99-main) — 고전 스크립트, 번들러 없음
├── scripts/                 # 하네스(`// @regress` 자동 발견) · 계측기 · 빌드(지형·작물) · 배포
```

**클라이언트는 한 파일이 아니다.** `public/client/*.js` 조각들을 `index.html` 이 순서대로 로드한다. 새 기능 = 새 파일 +
등록 1줄. 최상위 실행문은 `99-main.js` 에만 둔다. 이름 충돌은 `node scripts/test-client-globals.js` 가 검사한다.

**좌표계는 셋이다** — 서버 메시지는 존 로컬 px, 렌더러는 절대 월드 px, econ 은 셀×2.5. 마을 거리·캐러밴 시계는
전부 econ 좌표다(px 를 넣으면 12.8배 틀린다).

## 무엇이 어디서 도나

존 서버는 3001~3030 범위의 각자 포트를 쓴다(`zone-config.js`). 라이브는 한반도 존(서울 서버 · :3020)과 닛폰 존(도쿄 서버) 둘이다.

존은 자기 DB 만 쓴다. 존 사이의 공유 상태는 central 을 거친다. 플레이어의 **몸**(인벤·도구·소속·마지막 본 날)은
`serializeBody` 하나로 직렬화되어 저장·핸드오프·재접속이 같은 함수를 쓴다.

**왜 클라이언트 예측이 있는가** — 서버 tick 주기(30Hz) 때문에 즉시 반응이 안 보인다. 입력 즉시 클라가 예측하고, 서버
권위 좌표와 어긋나면 위치+속도 한 쌍으로 보정한다.

## 데이터

* **SQLite** (`node:sqlite` / `better-sqlite3`). 메모리 저장이 아니다.
  * `central.db` — 계정·게스트 영속 신원·마지막 존
  * `world-<zone>.db` — 존별 건축물·자원·클레임·몹·마을 상태·사건 장부·연대기

## 핸드오프 (존 경계 넘기)

1. 출발 존이 대상 존에 `POST /handoff_prepare` — 토큰 + 플레이어 상태
2. 출발 존이 클라에 `{type:'handoff', targetZone, token}`
3. 클라가 대상 존에 `?handoff_token=…` 로 재접속
4. 대상 존이 출발 존에 `POST /handoff_ack` → 출발 존이 옛 몸을 정리 (3초 안에 ACK 없으면 fallback 정리)

경계 양쪽 **256px 는 겹침 띠**(`HANDOFF_COMMIT`)다. 그 안에서는 핸드오프하지 않으므로 경계에 서서 왔다갔다 해도
재접속 핑퐁이 없다(`BENCHMARK.md` §4-C: 경계선 71회 통과 · 핸드오프 0회). 핸드오프에서 도구가 사라지던 결함(N.6)은
몸의 직렬화 함수를 하나로 통일하며 닫혔다(28회 재현 → 0).

* 큰 인구 · 전쟁 판의 느린 날은 "가장 가까운 적 찾기"였다 — 고친 뒤 720날 판 CPU −35%(T1235).
* 옛 측정(1 vCPU Vultr · 2026-09)은 `BENCHMARK.md`.

## 개발 방식

여러 AI 세션(Claude · GPT)이 **카드** 단위로 병행 작업하고, PM 세션 하나가 판정 정리 · 다음 카드 · 착지(main 합치기)를 맡는다.
세션은 §0 실측 → 구현 → 하네스 → 기준선 대조 → `보고/T<카드>_<날짜>.md` 와 함께 가지를 올린다. PM 은 모든 가지를 훑어
land 가지로 합치고, 끈 판 기준선 · 랩 · 바뀐 하네스를 다시 돌려 통과한 것만 main 에 fast-forward 로 민다(force push 0).
하네스 전수와 빨강 원인 찾기는 하네스 담당 세션이, 매일 밤 전수는 야간 러너가 돈다.

* 값은 실측 · 고증 표에서만 온다("새 수 0"). 값을 고르는 것은 사람이다 — 판정 기록은 `인계/족보.md`, 기다리는 판정은 `인계/판정대기.md`.
* 지시서의 전제도, 하네스도, 회부의 진단도 전부 **가설**이다 — 실측이 늘 앞선다.
* **배포는 재민만 한다** — 맥에서 한 줄: `bash <(ssh seoul cat /opt/Mini/scripts/update-live.sh)` (`--dry` = 미리 보기 ·
  배포 앞 DB 백업 · 서울 → 도쿄 · 렉 판정까지).

## 주요 설계 선택

**왜 클라이언트가 직접 존 서버에 붙는가** — 디스패처가 메시지를 중계하면 디스패처가 병목이 된다. 클라이언트가 직접 존
서버에 붙고, 디스패처는 라우팅 정보만 알려주는 게 분산 구조의 핵심.

**왜 권위는 존 서버에 있는가** — 같은 지역 안의 플레이어들끼리 상호작용할 때 단일 권위 서버를 거치는 게 일관성 유지에
가장 단순.

**왜 핸드오프는 WS 재연결로 처리하는가** — 존 간 직접 통신 대신 클라이언트를 통한 리레이가 프로토타입에선 훨씬
간단. 지금은 재연결 한쪽만 클라를 거치고 상태 이전은 zone↔zone HTTP 다. 본격 운영 시에는 존 간 백엔드 메시지
버스(Redis pub/sub, NATS) 추가 권장.

**왜 NPC 마을이 플레이어 없이도 사는가** — "내가 없어도 내 것이 자란다"는 요구에 대한 세계 내적 답이다. 마을은
플레이어 없이 800일을 소멸 0 으로 산다. 플레이어는 그 위에 여유와 이름을 더한다.
