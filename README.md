# 미니 — 청동기 오픈월드 경제 시뮬레이션 MMO

[![regress-unit](https://github.com/simjaemin1/Mini/actions/workflows/regress-unit.yml/badge.svg)](https://github.com/simjaemin1/Mini/actions/workflows/regress-unit.yml)

> 청동기 후기 한반도. NPC 마을 51곳이 플레이어 없이도 먹고, 일하고, 교역하고, 늙어 죽는 세계에
> 플레이어가 빈손의 이방인으로 도착합니다. 세계는 구역마다 다른 서버가 돌리는 **분산 존 서버** 위에서 움직입니다.

- **접속** https://mini-gate.duckdns.org (브라우저)
- **규모** 한반도 구역 약 2.2 × 4.1 km(1셀 = 1 m) · NPC 마을 51곳 · 주민 수천 명 · 작물 34종 · 짐승 37종
- **운영** 한반도 존(서울) · 닛폰 존(도쿄) 두 구역이 실제 서버에서 돌고 있습니다
- **이름** "미니"는 임시 이름입니다

---

## 어떤 게임인가

- **살아 있는 세계.** 마을마다 곳간과 시세가 있고, 주민은 각자 몸으로 걸어가 밭을 갈고 나무를 벱니다. 촌장이 "요즘 소금이 달려"라고 말하면, 그건 대본이 아니라 그 마을 곳간의 실제 재고입니다.
- **같은 규칙.** 플레이어와 NPC는 같은 활동을 같은 규칙으로 합니다. 밭 갈기, 영토 넓히기, 숙련 모두 둘에게 똑같습니다.
- **고증 기반.** 하루는 실제 24분, 한 해는 365일(실제 약 6일)입니다. 수확량(kg/ha), 일손 시간, 썩는 시간은 출처가 있는 값을 씁니다. 식량은 열량(kcal)으로 계산합니다.
- **창발하는 사건.** 흉년, 가뭄, 굶주림, 약탈 같은 사건은 각본이 아니라 경제 상태의 경계에서 생깁니다. 소식은 행상인 걸음 속도로 퍼집니다.
- **내 마을.** 플레이어는 NPC 마을에서 일손을 보태 소속이 되고, 나중에는 직접 마을을 세웁니다. NPC 마을과 같은 인구 모델이 플레이어 마을에서도 돌아갑니다.

## 기술적으로 풀어 온 문제

### 1. 분산 존 서버와 핸드오프
- 지구를 26개 구역으로 나누고, 구역마다 독립된 서버 프로세스와 SQLite DB를 둡니다. 구역 서버는 실제 그 지역에 배치해 핑이 지리적 거리를 따라가도록 설계했습니다.
- 경계를 넘을 때는 토큰 기반으로 핸드오프합니다(`handoff_prepare` → 클라이언트 재접속 → `handoff_ack`, 3초 타임아웃 fallback).
- **문제:** 경계 위를 오가면 재접속이 반복되고, 넘어갈 때 도구가 사라졌습니다.
  **해결:** 256 px 겹침 띠(히스테리시스)를 두어 경계를 71번 오가도 불필요한 핸드오프가 0번이 되게 했습니다. 플레이어 상태 직렬화를 함수 하나(`serializeBody`)로 통일해 도구 유실을 28회 재현 → 0회로 없앴습니다.

### 2. 지형 판정 병목
- **문제:** NPC를 켜면 서버 tick이 454~888 ms까지 늘어 접속자 1명도 감당하지 못했습니다. 프로파일링해 보니 강과 능선의 통행 판정이 지배적이었습니다.
- **해결:** 선분을 512 px 격자로 색인하고, 같은 질문은 타일 단위(4비트) 메모로 캐시했습니다.
- **결과:** tick 454~888 ms → **15~28 ms**, 클라이언트 p50 515 ms → **34 ms**, 부팅 13분 51초 → 7분 10초(1 vCPU 기준).

### 3. 결정론적 경제 시뮬레이션과 회귀 지문
- 판정에 주사위를 쓰지 않습니다. 같은 시드면 같은 세계가 나옵니다.
- 시드 3개로 400일을 돌린 결과(인구, 날마다의 곳간·사람·집 지문, 마을 칸 지문)를 **회귀 지문**으로 삼았습니다. 기능을 끈 상태에서 이 지문이 한 글자라도 바뀌면 통과시키지 않습니다.
- **문제:** 같은 코드인데 판마다 결과가 달랐습니다. 원인은 벽시계 시간이었습니다.
  **해결:** 가상 시계로 바꿔 재현성을 확보했습니다.

### 4. 성능
- **클라이언트 예측:** 서버(30 Hz)와 클라이언트가 같은 이동 적분기 파일을 읽고, 위치와 속도를 한 쌍으로 보정합니다.
- **econ 일틱 쪼개기:** 하루치 경제 계산을 마을 단위로 여러 프레임에 나눠 틱 지연을 없앴습니다.
- **전쟁 몸 탐색:** "가장 가까운 적 찾기"가 반경의 세제곱으로 커지던 고리 탐색을 몸 목록 탐색으로 바꿨습니다. 결과는 같고, 호출 1회 1,415 µs → 7 µs, 720일 판 CPU −35%입니다.
- **진행 중:** 이산 사건 시뮬레이션(DES). 출발·도착·작업 종료만 우선순위 큐에 넣고 그 사이는 계산하지 않습니다. 몸의 위치는 언제든 정확히 구할 수 있습니다.

### 5. 테스트
- 하네스 367종을 파일 머리 표식(`// @regress`)으로 자동 발견합니다. push마다 CI가 단위 회귀를 돌리고, 전수는 야간 러너가 하루 한 번 돌려 실패를 커밋 단위로 추적합니다.
- 하네스에는 "자명 통과 금지" 원칙이 있습니다. 검사 대상을 일부러 망가뜨린 미끼로 하네스가 실제로 실패를 잡는지 함께 확인합니다.

### 6. 에셋 파이프라인
- Blender 모델 → 8방향 스프라이트 시트 → webp까지 스크립트로 굽습니다.
- BGM은 국립국악원 공공누리 음원으로 만든 샘플러와 Web Audio 엔진으로 연주합니다.

## 아키텍처

```
브라우저(Canvas · 예측/보정)
   │  wss
   ├── central      계정 · 영속 신원 · 존 목록           central.db
   ├── dispatcher   정적 파일 · 존 라우팅
   └── zone ×N      한 구역의 권위 서버(30 Hz)          world-<zone>.db
          ├── villages   NPC 마을 · 생활 층(몸 · 일과 · 집 · 밭)
          ├── econ       경제 정본 sim/economy-sim-v2.js (실험실 HTML과 같은 파일)
          ├── events · rumor   사건 장부 · 소문 전파
          └── war-live · battle-core   마을 전쟁 실체
   zone ⇄ zone  HTTP 핸드오프
```

**기술 스택** Node.js · Express · ws · SQLite(better-sqlite3) · Canvas · Web Audio · Docker · Caddy(HTTPS/wss) · Python(Blender 파이프라인)

## 개발 방식

여러 AI 코딩 에이전트(Claude · GPT)를 병렬로 돌리고, PM 에이전트 하나가 작업 지시서 발행, 결과 통합, 검증 게이트를 맡는 구조로 개발합니다.

- 기능은 끈 상태(기본값)로 들어옵니다. 회귀 지문이 그대로임을 확인한 뒤 합치고, 켬 여부는 결과 표를 보고 사람이 정합니다.
- 모든 수치는 실측 또는 고증 출처에서 옵니다. 결정 기록은 `인계/족보.md`에 쌓입니다.
- main은 fast-forward만 허용하고 force push는 하지 않습니다. 배포는 사람이 스크립트 한 줄로 합니다.

## 실행

```bash
npm install
npm start                                   # central + dispatcher + 존 전체
ENABLED_ZONES="hanbando" npm start          # 일부 존만
```

`http://localhost:3000`(dispatcher) · `http://localhost:3010`(central)

```bash
bash scripts/run-regress.sh                 # 하네스 전수
node scripts/server-baseline-check.js 계측/서버기준선_2026-11-13.json --vclock --plan 1020:400   # 회귀 지문 대조
```
