# 긴 판의 이전 stop 덤프 압축 보존

여섯 세계의 임시 자료가 누적되므로 정본이 더 이상 읽지 않는 예전 루트 `stop-N.json`만 압축 보존했다. `t1308-long-run.js`는 재시작 때 현재 `ck/stop-N.json`을 읽고 다음 마디의 새 stop 파일을 만든다. 진행 체크포인트와 이진 체크포인트 양쪽보다 엄격히 이전이며 정상 종료한 마디의 끝인 파일만 대상으로 삼았다.

`scripts/t1411-pack-old-stops.py`는 원본 전체 SHA256을 구한 뒤 workspace scratch에 gzip을 쓰고, 압축을 풀어 읽은 전체 SHA256이 같은지 확인한다. 파일 크기·수정 시각이 유지됐는지도 확인하고 보존 경로·해시를 기록한 다음에만 `/tmp`의 중복 원본을 지운다. 라이브 DB, 현재 `ck/`, 현재/미완성 stop, 계측 장부·마을 지문·로그·물자 스냅샷은 건드리지 않는다. 실제 세계를 띄우지 않는다.

이번에는 켬45개·끔46개, 원본2,846,226,351바이트를287,024,781바이트로 보존했다. 내용 기준 약2.38GiB를 줄였고 모든 파일의 압축 전/후 SHA256이 일치했다. 즉시 반복 실행은0개·0바이트로 끝났다. 켬460날·끔470날 이진 체크포인트 묶음의 모든 파일 해시와 제품 소스 해시가 작업 전과 같음을 `summary.json`에 보존했다. 각 파일의 원본 해시·보존 경로는 팔별 manifest에 있다.

이 gzip들은 예전 stop 관측 덤프이며 독립 복구용 DB 체크포인트를 새로 만든 것이 아니다. 정상 복구는 계속 현재 `ck/` 또는 중단 시 별도 보존한 이진 묶음을 쓴다. CPU 비교의 첫100날 원본/후보 실행 이후에 한 저장 공간 관리이며 경제 규칙·몸 상한·시계·계측기는 바꾸지 않았다.

```sh
python3 scripts/t1411-pack-old-stops.py --runs /tmp/t1411/worlds --out /workspace/scratch/t1411/old-stop-dumps
```
