# 1020 양팔의 닫힌 첫500날 · 마을 ID 연결 점검 빨강

진행 중인 같은 두730날 세계의 확정50마디씩만 읽었다. 독립500날 실행이나730날 완료가 아니다. 양팔100마디의 실제 존 종료 코드·가상 시계 오류는 모두0이다. 100·200·300·365·400날 지표는 이전 보존본과 그대로 같고, 실행 원자료와 이번 압축 복사본의 경제·모든 마을 필드는 각각500/500날 같았다. 이는 보존 무결성 검사다. 고침 전/후 의미 보존 지문 범위는 별도100/100날이다.

**마을별 사람 ID 연결 점검은 빨강이다.** 켬의 몸/인구 최솟비는1이고 전체 몸 수는 유지됐으나, 467날 광산3의 n437·490날 광산3의 n439가 해당 마을 몸 ID 집합에 없었다. 두 날 모두 광산3은 몸이1 적고 임업6은1 많았다. 다음 날 장부의 누락 수는 각각0이다. 정확한 원인과 실제 몸의 소속은 아직 확인하지 못했으며, 고침 전 비교 판은100날까지만 있어 T1411에 귀속하지 않는다.

`resident-link-audit.json`에 두 날의 마을별 관측과 원자료 파일명을 보존했다. 최초 보존 도구는 `maxMissingResidents == 0` 조건에서 실제로 멈췄으며 `strict-prefix-check.log`가 그 기록이다. 단언을 낮추지 않았다. 원자료 압축은 이미 끝나 있었으므로 경제·마을 지문의 압축 보존 무결성 검사만 별도 실행해 확인했다. 몸 ID 점검까지 초록으로 보고하지 않는다. 엄격 최종 집계의 같은 조건도 아직 해결되지 않았다.

양팔 몸 상한Infinity·하루24분·10날 정본 체크포인트·제품 소스는 유지했다. 실제 종료 실패와 네 차례 환경 복구 및 세계를 유지한 감독 재접속은 분리한다. CPU 평균에는 채택한 마디를 한 번씩 넣고, 버린 부분 장부의 CPU 관측 하한10,320.075324초는 복구 자료에 따로 둔다. 이500날의 끔 팔은 네 번째 복구 전에 이미 닫혔다.

이탈은 t1075Emigrate 마을 이주 수락 횟수다. 완공0은 당일 몸 완공 증가가 없는 마을 수이며 끔 팔에는 해당하지 않는다. 500날 켬의 당일 완공0과 직전10날 내내 완공0은 모두49마을, 시작 후 한 번도 완공하지 않은 마을은0이다. 빈 마을은 켬0·끔1이다. 원시 bodyStarve·debtDeaths 계수를 더해 고유 사망자 수로 해석하지 않는다.
