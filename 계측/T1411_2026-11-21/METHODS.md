- 베이스 = main land1087 뒤 `1aa63e637f24c0cdde4e6b7988f7c013a23301a8`.
- 가지 `batch/terr-body-cpu-1121`. 현재는 해부 단계이며 완료·채택 판정이 아니다.
- Node 22.23.0, 같은 ABI의 SQLite 의존성, 고정한 별도 런타임 사본으로 실행한다. 실행 중 제품 소스를 바꾸지 않는다.
- 먼저 ON/1020 네이티브 CPU 프로파일 30날과 같은 소스의 비프로파일 대조 100날을 동시에 실행한다. 최대 두 세계다. 10날 정본 체크포인트와 guard resume을 쓴다.
- ON = T1358 최종 A와 같은 조건: T325_WOOD_ACT, T1207_TERR_REAL, T1238_TERR_V2, T1283_WOOD_DEMAND, T1297_BIRTH_FOOD, T1306_MIGRATE_FOOD, T1302_TERR_BODY, T1329_TERR_CREW, T1358_STAKE_REQUOTE 켬.
- 공통 = VILLAGE_DAY_MS 1440000, NPC_CAP Infinity, 집 행위·농사 몸 끔, 캐러밴 상한 0, T1244_BODY_MS 10000, T1221_EVERY 10, T1259_WOOD_CAP 0. 전체 조건은 launch.json에 남긴다. 새 경제 수를 만든 것이 아니다.
- t1411-profile-hook.cjs는 정본 러너가 띄우는 zone 자식에만 --cpu-prof를 더하고 실제 종료 코드를 기록한다. 제품 변환·호출 치환은 없다. 기존 T1358 관찰기는 동일하게 사용한다.
- V8 표의 가중치는 표본 사이 **경과 시간**이다. 포함 시간은 겹치며 OS CPU로 부르지 않는다. 실제 CPU 초/날은 process.cpuUsage의 사용자+커널 차로 따로 낸다. 프로파일/비프로파일 30날 세계 지문도 대조한다.
- 261.2초/날은 옛 T1358 400날 전체 평균이다. 새 main의 첫 30날 수를 그 수와 같은 조건의 전후라고 부르지 않는다. 같은 나이·같은 소스·같은 관찰 조건의 전후를 별도로 비교한다.
- **끔 팔:** T1358의 전신체 OFF도 400날 평균 222.3초/날이었다. 카드의 2~3초/날 기준선 자는 몸 상한 등 조건이 다르다. 730날은 T1358과 같은 양팔 몸 상한 없음으로 진행한다. 공식 끈 판 기준선 400날 검증은 별도로 수행한다. 켬 기본은 내지 않는다.
- 수정 후보의 제품 소스는 `768d740b0783ee815342a404b4c754e8dc5c4e61`에서 고정했다. `candidate-manifest.json`에 원본·후보·관찰기 해시를 남겼다. `T1411_TERR_FAST=1`은 T1358 묶음이 켜져 있을 때만 유효하고 기본은 끔이다.
- `t1411-campaign.py`는 원본 프로파일/비프로파일 30날 일치 → 필수 집중 게이트 → ON/1020 시작 → 원본/후보 30날 일치 → 남은 730날 팔 순서로 진행한다. 원본 비프로파일 100날 판까지 포함해 세계는 둘을 넘지 않는다. 판 실패는 자동 재시도로 숨기지 않는다.
- `t1411-census.cjs`의 깨어 있음은 장부 시점의 실제 낮·몸 일과 창이다. 하루 평균·실제 일한 몸 수와 구분한다. 몸 수·좌표·타이머를 바꾸지 않는 관찰기이며, 동일성 비교에서 마을 필드를 제외하지 않는다.
- 원본 배선 게이트는 실패 0·기존 경고 2. 샌드박스의 spawnSync EPERM으로 실패한 시도는 실제 제품 빨강으로 세지 않고 정상 실행 환경에서 재확인했다.
