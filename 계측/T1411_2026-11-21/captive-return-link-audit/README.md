# 포로 귀향과 마을 ID 연결 누락 · 회부1

실제 켬1020의467·490날은 계속 **RED**다. 전체 몸 수가 인구와 같아도 마을별 ID 연결은 다르다. 490날 보존 SQLite 묶음을 임시 사본으로 읽었고 원본 해시 불변을 확인했다. 임시 사본은 삭제했다. 실제 세계를 추가 실행하지 않았다.

`evidence.json`:490날 n439 경제 소속=광산3, 몸p23005 소속=임업6. 전쟁 로그에서 n437/n439의 귀향 도착이467/490날이다. 마을 몸 동기화 뒤 전쟁 일과가 경제 소속을 바꾸는 코드 순서도 포함했다.467날 몸 이진 상태를 직접 읽은 것은 아니다. 전쟁/관찰기 코드가 원본과 같다는 사실만으로 T1411의 발생 기여를 배제하지 않는다. 제품은 고치지 않았다.

`check-reporting.py/json`: 실제500날 자료로 기본 엄격 검사 실패, 명시적 보고 모드의 passed=false/RED, 기존 모든500날 수치 불변, 미완료730날 판의 미완료 유지를 검사했다. 첫400날의 엄격 ID 검사는 통과한다.

`check-finisher.py/json`: 격리된 가짜 입력만으로 최종 보고의 ID 빨강/회부1, 실제 종료7·120날 실패 유지, 자동 커밋/푸시 없음 확인. 가짜 수치는 실제 계측에 포함하지 않으며 임시 폴더는 삭제한다.

`--report-link-gaps`는 최종 자료 보존을 위한 명시적 선택이다. 기본 엄격 ID 검사는 유지하며 이 옵션으로도 빨강은 통과가 되지 않는다. 다른 몸 수·물자·시계·마디·완료 조건은 유지한다. 역사적500날 엄격 실패 로그는 pair-1020-500에 남아 있다.
